# Movement workflows

These are reusable instructions. Evidence and progress belong in [research](../research/README.md), implementation in the product repository, and recordings in the authorized lab. Implemented behavior is documented in Change source comments; research retains permanent findings and current relevant state.

1. [Discovery](discovery/README.md): shared rules plus separate source, Minecraft Wiki and MCPK Wiki procedures.
2. [Implementation](implementation/README.md): implement accepted deltas independently, then integrate them.
3. [Testing](testing/README.md): establish recording/playback reliability before comparing historical and emulated movement.
4. [Orchestration](orchestration/README.md): coordinate bounded work, authority, ownership and budgets.

Creating this structure does not authorize a campaign, tests or runtime launches.
