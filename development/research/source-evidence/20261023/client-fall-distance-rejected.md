# Landing fall-distance reset is skipped for client-controlled players in 1.21.4

1.21.3, Mojmap: `1.21.3/mojmap/net/minecraft/world/entity/Entity.java`, `move` 639-672 and `checkFallDamage` 1216-1231; `LivingEntity.java`, `checkFallDamage` 341-373; `Player.java`, `maybeBackOffFromEdge` 1066-1119 and `isControlledByClient` 2146-2148; `LivingEntity.java`, `maxUpStep` 3588-3591; `Attributes.java`, `STEP_HEIGHT` 81-83; `LocalPlayer.java`, `isEffectiveAi` 478-480.
1.21.4, Mojmap: `1.21.4/mojmap/net/minecraft/world/entity/Entity.java`, `move` 647-682 and `checkFallDamage` 1237-1252; `LivingEntity.java`, `checkFallDamage` 339-371; `Player.java`, `maybeBackOffFromEdge` 1069-1122 and `isControlledByClient` 2166-2168; `LivingEntity.java`, `maxUpStep` 3599-3602; `Attributes.java`, `STEP_HEIGHT` 81-83; `LocalPlayer.java`, `isEffectiveAi` 483-485.

Difference: Both versions accumulate airborne fall distance in `Entity.checkFallDamage` using `fallDistance -= (float) movementY` when the collision is not grounded. On grounded movement, the same method calls `resetFallDistance()`, assigning `0.0F`. The movement callback gate changed: 1.21.3 calls it when the level is client-side and `isControlledByLocalInstance()` is true; for LocalPlayer, `isEffectiveAi()` returns true and `Entity.isControlledByLocalInstance()` therefore returns true. In 1.21.4, `Entity.move` adds `&& !this.isControlledByClient()` to that gate. `Player.isControlledByClient()` returns true unconditionally in both releases, so a client Player's grounded callback is skipped in 1.21.4. `LivingEntity.checkFallDamage`'s server-only particle branch does not run on the logical client; the inherited `Entity` reset is the relevant state write. The accumulator and reset retain their float storage and the double-to-float cast on both sides.

Movement meaning: `Player.maybeBackOffFromEdge` is called before collision resolution in the ordinary `Entity.move` path. With flying, vehicle, climbable, liquid, slow-falling/levitation, bubble-column, teleport/correction, and special block-reset paths absent, an ordinary local player can fall onto a full floor from a height greater than `maxUpStep()`, then walk off without crouching toward a lower floor. While airborne just above that lower floor, hold shift and make a small horizontal `SELF` move. `Player.isStayingOnGroundSurface()` is `isShiftKeyDown()`, and `isAboveGround(step)` is `onGround() || fallDistance < step && !canFallAtLeast(0, 0, step - fallDistance)`. Choose the ordinary floor geometry so `onGround()` is false and the lower floor prevents falling the remaining `step` distance. The 1.21.3 landing reset leaves a short new descent distance below `step`, so this predicate passes and the 0.05-step edge-backoff loop tests/reduces the horizontal move against the floor. The 1.21.4 landing retains the earlier distance; if `checkSlowFallDistance` applies its `1.0F` cap, that is still above the vanilla player `STEP_HEIGHT` default of `0.6` (the player is not a passenger). Thus the `fallDistance < step` clause fails and the edge-backoff loop is skipped. This is a direct player movement-state consequence, independent of damage calculation. It requires no item, entity, special block behavior, changed server-produced state, spawn, or teleport; start the compared sequence from the same local position/velocity/input and let only the grounded callback establish the fall-distance divergence. The exact first observed differing stable source in this assigned pair is 1.21.4; the inspected pair establishes the boundary only between 1.21.3 and 1.21.4.
