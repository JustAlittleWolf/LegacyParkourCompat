Difference: Keyboard sneak input multiplies both horizontal movement floats by `0.3` in each release. In 1.8.9, the local camera player's `abilities.flying` branch only changes vertical velocity for sneak/jump; it forwards the sneak-reduced horizontal inputs unchanged to the usual `LivingEntity.moveRelative` path. In 1.9.4, when `abilities.flying && isCamera()` and sneak is held, the caller first assigns each horizontal input to `(float)(input / 0.3)` and then applies the same vertical descent. For ordinary keyboard input this compensates the earlier sneak slowdown before travel, restoring horizontal relative input while flying and sneaking. The division is double arithmetic followed by a float cast; preserve that operation if emulated.

Movement meaning: For an airborne local player with flight enabled, camera control active, sneak held, and no item-use slowdown, a held horizontal key enters the 1.8.9 travel method at `0.3F` versus approximately `1.0F` after the 1.9.4 compensation. The 1.9.4 `mobTick` override applies this division before `super.mobTick`; inherited `LivingEntity.mobTick` then reads input in `serverTickAi`, applies its existing `0.98F` travel multiplier, and calls `moveRelative` (1.8.9 lines 1424-1450; 1.9.4 lines 1684-1711). The shared `updateVelocity` normalization then applies its usual threshold and length normalization. This is a distinct client movement caller change from the yaw-to-radians expression above.

The paired source proves this behavior exists by 1.9.4. The exact earliest stable 1.9 release is not established because no 1.9.0 source was assigned; the introduction boundary remains open. The nearby 1.9.4 fall-flying branch is independent and excluded from this finding.
