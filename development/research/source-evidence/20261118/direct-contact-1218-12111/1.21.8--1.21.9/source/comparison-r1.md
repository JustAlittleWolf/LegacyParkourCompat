## Comparison

- **Honey slide:** `HoneyBlock#entityInside` calls `doSlideMovement` when `isSlidingDown` is true, then delegates to the superclass. Both releases use the same gates and constants: not grounded; entity Y no higher than block Y + 0.9375 − 1.0E−7; reconstructed old vertical speed below −0.08; and the same edge-distance test. Both compute old Y speed as `deltaY / 0.98F + 0.08`, use the strict `< -0.13` branch for horizontal scaling, replace vertical velocity with `(−0.05 − 0.08) * 0.98F`, preserve horizontal velocity otherwise, and reset fall distance. Equal callback state produces the same conditional horizontal multiplier and writes in the same order. (`HoneyBlock.java`, 1.21.8 lines 63–70, 73–114; 1.21.9 same members/logic.)
- **Web:** `WebBlock#entityInside` starts with `(0.25, 0.05F, 0.25)` and uses `(0.5, 0.25, 0.5)` only for a living entity with WEAVING; it then calls `makeStuckInBlock`. Both releases are identical. (`WebBlock.java`, lines 27–33.)
- **Sweet berry bush:** `SweetBerryBushBlock#entityInside` applies only to living entities other than foxes and bees and calls `makeStuckInBlock(state, (0.8F, 0.75, 0.8))`. The following server-only age/movement test can cause damage and is excluded; it does not change the preceding local movement write. The local direct effect and its order are identical. (`SweetBerryBushBlock.java`, lines 81–100.)
- **Producer and consumer:** `Entity#applyEffectsFromBlocks` checks the movement path, invokes each block’s `entityInside`, and applies the step collector before returning. For an ordinary single contact (at most 16 intersected blocks in the 1.21.9 bounded scan), both releases reach the same callback. All three effects either set velocity directly (honey) or call `Entity#makeStuckInBlock`, which resets fall distance and stores the stuck-speed multiplier. On the next ordinary nonzero `Entity#move(MoverType.SELF, request)`, both releases multiply the request by that multiplier when its squared length exceeds `1.0E-7`, clear the multiplier, and zero delta movement before collision handling. Equal pre-move inputs therefore produce the same multiplier application and write order. `LivingEntity#handleRelativeFrictionAndCalculateMovement` supplies an ordinary SELF move on the dry, non-flying branch.

## Verdict and limits

No sustained direct-contact difference found in these three operations for the stated equal-input ordinary path; no canonical finding is warranted. This bounded source comparison is not proof of equal end-of-tick trajectories or complete pair coverage. The 1.21.8/1.21.9 entity block-intersection traversal implementations differ outside this narrow ordinary path; long/complex traversal, geometry/support, fluids, and all other movement areas were not audited. Exact official versioned inputs are recorded for 1.21.9, though its provenance omits a top-level exact-run record.
