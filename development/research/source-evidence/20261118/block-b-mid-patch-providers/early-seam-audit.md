## Verdicts by adjacent edge

**1.17.1 → 1.18 — no candidate-output difference on the shared ordinary `getBlockCollisions` path under the stated stable-loaded-chunk seam bound.** `CollisionSpliterator` (`1.17.1`, `world/level/CollisionSpliterator.java:40-101`, especially `:61-100`) became `BlockCollisions` (`1.18`, `world/level/BlockCollisions.java:30-96`, especially `:34-95`). Both initialize a `Cursor3D` from `floor(min - 1.0E-7) - 1` through `floor(max + 1.0E-7) + 1` on X/Y/Z, ask that cursor in X-fastest, then Y, then Z order, skip type 3 corners, admit type 1 faces only for `hasLargeCollisionShape`, and admit type 2 edges only for moving pistons. With `onlySuffocatingBlocks=false`, the new leading predicate short-circuits true and is equivalent to the old default predicate. Both obtain the state at the same cursor position, call `getCollisionShape(collisionGetter, pos, context)`, use the same full-block `box.intersects(cell bounds)` special case, and otherwise return the translated shape only if it intersects `Shapes.create(input AABB)`.

The meaningful scanner refactor is chunk lookup caching: old `getChunk` (`CollisionSpliterator.java:96-101`) resolves `getChunkForCollisions` for each scanned coordinate; new `BlockCollisions.getChunk` (`BlockCollisions.java:49-62`) caches the last `ChunkPos`. Both convert block X/Z to section coordinates. `Level.getChunkForCollisions` is `getChunk(x,z,ChunkStatus.FULL,false)` in 1.17.1 (`Level.java:570-574`) and 1.18 (`:569-573`), so for already-loaded FULL chunks with unchanged states the cache does not change candidate outputs, including when the cursor crosses a chunk seam and refreshes its cached position. This verdict does not cover changing chunk/state observations or null/unloaded results.

Provider witnesses are unchanged in the compared collision semantics. Generic `BlockBehaviour.getShape` is `Shapes.block()` and its collision-shape default delegates through state shape (`1.17.1 BlockBehaviour.java:282-289`; 1.18 `:278-285`). `SlabBlock` yields bottom/top 8/16-high boxes or full block for DOUBLE (`1.17.1 SlabBlock.java:29-30,48-58`; 1.18 same method lines). `FenceBlock` is a `CrossCollisionBlock(2,2,16,16,24)` (`FenceBlock.java:30-36`); collision shapes include the central post and selected side bars up to Y=24/16=1.5 (`CrossCollisionBlock.java:36-81,95-97`). `SPRUCE_FENCE` is registered as `FenceBlock` and `SPRUCE_FENCE_GATE` as `FenceGateBlock` (`Blocks.java:1951-1954,1971-1974`); this establishes non-Oak representatives without relying on name-only inference. Gate collision shape is empty when OPEN, else orientation-selected 24/16-high Z/X shape (`FenceGateBlock.java:29-34,68-73`). `BlockBehaviour` caches large-shape classification by any axis min<0 or max>1 (`1.17.1:439-440, Cache:787-788`; 1.18 `:435-436, Cache:781-782`), so a closed over-height fence/gate passes a face cursor classification; full cubes and half slabs do not. A half slab is still considered when its block cell is type 0 and then subjected to the voxel intersection check.

Consumer boundary: 1.17.1 `Entity.collideBoundingBoxHeuristically` sends displacement with at least two nonzero axes through `level.getBlockCollisions(entity, aABB.expandTowards(vec3))` (`Entity.java:791-804`); this includes the ordinary horizontal X/Z case. A one-axis-only move instead reaches the separate `Shapes.collide(...LevelReader...)` direct state scan (`Entity.java:791-804, 840-872`, `Shapes.java:239-305`), which 1.18 no longer uses. 1.18's ordinary collision consumer calls `getBlockCollisions` with the expanded AABB from `Entity.collideBoundingBox` (`Entity.java:767-817`). I therefore accept equivalence only for the shared cursor/scanner path; I do not claim candidate-list/order equivalence or final movement equivalence for the 1.17.1 one-axis direct-scan route, whose downstream axis collision math was expressly outside this assignment.

**1.18 → 1.18.1 — no source difference in this bounded scan/provider claim.** The manifest-pinned `BlockCollisions.java`, `CollisionGetter.java`, `Cursor3D.java`, `Level.java`, `Entity.java`, and provider member files checked for this claim have the same bytes in these two ready trees; scanner, `FULL,false` chunk lookup, consumer AABB expansion and witness geometry are unchanged.

**1.18.1 → 1.18.2 — no candidate-output difference on the same bounded ordinary scanner path.** `BlockCollisions.java`, `CollisionGetter.java`, `Cursor3D.java`, `SlabBlock.java`, `CrossCollisionBlock.java`, `FenceBlock.java`, `FenceGateBlock.java`, and `Shapes.java` are byte-identical across these endpoints. The relevant `Level.getChunkForCollisions` body still requests `FULL,false` (`1.18.1 Level.java:571-573`; 1.18.2 `:570-572`). `Entity` and `BlockBehaviour` files have endpoint file-hash changes, but the checked collision-consumer calls retain `aABB.expandTowards(movement)` and the `getBlockCollisions` call (`1.18.1 Entity.java:767-817`; 1.18.2 `:777-817`), and the `hasLargeCollisionShape` predicate/cache metric and checked provider bodies retain the same behavior (`BlockBehaviour.java:435-438, Cache:781-782` in 1.18.1; `:437-440, Cache:783-784` in 1.18.2). No changed candidate was found for this seam scan.

## Boundaries and dependencies

This is a bounded source verdict, not pair freeze or runtime parity. It covers ordinary player collision's block-candidate scan for fixed block states in already-loaded FULL chunks at an ordinary chunk seam, away from world-border contact. Relevant dependency closure checked: `Entity` consumer → `CollisionGetter.getBlockCollisions` → cursor/scanner → `Level.getChunkForCollisions` → `BlockState` collision dispatch/cache → the listed shape providers. Excluded as assigned: entity collision admissions, world border, modern height limits, changing/unloaded chunks, and downstream axis math; the separate 1.17.1 one-axis `Shapes.collide(LevelReader,...)` route remains explicitly unclaimed.
