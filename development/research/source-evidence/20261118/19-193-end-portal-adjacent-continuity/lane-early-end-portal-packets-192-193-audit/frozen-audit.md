## Trace and bounded verdict

1. A server-side `EndPortalBlock.onEntityCollision` requires the entity not riding, no passengers, portal eligibility, non-client world, and shape intersection, then invokes virtual `entity.changeDimension(1)`. For a `ServerPlayerEntity`, dispatch reaches the override.
2. The player override sets `inTeleportationState = true`. In the Overworld (`dimension == 0`) to End (`dimension == 1`) branch it increments `ENTER_THE_END`, keeps the destination local `dimension` at 1, and calls `PlayerManager.changeDimension(this, 1)`.
3. The player-manager wrapper saves old dimension `i`, assigns `player.dimension = dimension` before calling its entity helper, chooses `serverWorld2` from the updated field, sends the respawn packet, removes/re-adds bookkeeping, and invokes `changeDimension(player, i, serverWorld, serverWorld2)`. Thus for the helper's ordinary Overworld-to-End route, the helper's `dimension` argument is 1 and `entity.dimension` is already 1; these are separate values with distinct roles.
4. In the helper, `d/e` begin as entity X/Z, the Overworld branch is selected from `entity.dimension == 0` only for other routes; because the wrapper has already updated the field to 1, the ordinary End route takes the final `else`. There, `dimension == 1` selects `toWorld.getSpawnPoint()` (the `else` selects `getForcedSpawnPoint()` for other destinations). It copies block X/Y/Z to the entity position values and applies yaw 90°, pitch 0°. The helper alternative `getForcedSpawnPoint()` delegates to the dimension forced-spawn getter, but is not selected for destination 1. The source contains an alive-gated `fromWorld.tickEntity(entity, false)` after positioning. After the `moving` section, the `if (dimension != 1)` placement block—including its second alive check, clamping, `PortalForcer.onDimensionChanged`, add-to-world and `toWorld.tickEntity`—is skipped for End destination. Then `entity.setWorld(toWorld)` runs.
5. The wrapper calls `player.networkHandler.teleport(player.x, player.y, player.z, player.yaw, player.pitch)` after helper return. The five-argument overload delegates with `Collections.emptySet()`, so the server writes an absolute `PlayerMoveS2CPacket` with empty relative flags and the current requested teleport ID after updating the server player's position/rotation. The End-entry route does not invoke `PortalForcer.onDimensionChanged`; that helper is gated behind `dimension != 1`. Separately, `ServerWorld.tick` invokes `portalForcer.tick(time)` as ordinary world maintenance; that is not this transfer helper path.
6. Release-local client handling is `ClientPlayNetworkHandler.handlePlayerMove(PlayerMoveS2CPacket)`. It reads coordinates and angles, adds current player values only for relative flags, zeroes velocity components for absolute X/Y/Z, applies `updatePositionAndAngles`, sends `AcceptTeleportC2SPacket(packet.getTeleportId())`, then sends a `PlayerMoveC2SPacket.PositionAndAngles` using `playerEntity.x`, `playerEntity.getShape().minY`, `playerEntity.z`, yaw and pitch, with `false` on-ground. `AcceptTeleportC2SPacket.write` serializes its ID as a VarInt. This identifies the code path only; no claim is made that a packet arrived or that any trajectory was observed.

Compared paired method bodies in this frozen roster for the route: the relevant End-trigger, player override, wrapper/helper logic, PortalForcer gate/body, server correction writer, and client handler/ack writer have no movement-operation difference between 1.9.2 and 1.9.3. The client network handler source hashes differ across release trees, but the inspected `handlePlayerMove` method body has the same operations and order. `ServerPlayerEntity.changeDimension` gains a release-local `@Nullable` annotation in 1.9.3; this does not alter the route. The reviewed bounded claim is therefore **no 1.9.2 → 1.9.3 movement difference found in ordinary Overworld → End entry / absolute correction / client ack path**. This does not close unrelated portal paths, generic dimension travel, the complete player tick, actual packet arrival, or full-pair discovery.
