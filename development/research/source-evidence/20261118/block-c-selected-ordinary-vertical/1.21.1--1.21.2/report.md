## Bounded coverage and call order

Scope is a locally controlled player in ordinary dry, nonvehicle, non-gliding, non-flying air movement. Assume no Slow Falling or Levitation, fluid, climbable, powder snow, block/contact effect, or collision. Jump causation, input/horizontal motion, and the boundary behavior of support/collision providers are not claimed.

`LivingEntity.travel` enters the ordinary-air branch for the stated dry conditions and only computes travel while `isControlledByLocalInstance()` is true (1.21.1 `LivingEntity.java:2091-2214`; 1.21.2 `LivingEntity.java:2178-2214`). In both releases `handleRelativeFrictionAndCalculateMovement` first moves by current delta movement; afterwards travel applies gravity and vertical drag to the returned vertical component. The unaltered call is in 1.21.1 `LivingEntity.java:2252-2265` and 1.21.2 `LivingEntity.java:2351-2364`.

- **Vertical integration: no difference under these assumptions.** 1.21.1 starts with `getGravity()`, only clamps it for Slow Falling when current `vY <= 0`, then in the air branch subtracts gravity (unless unloaded client chunk fallback applies) before applying drag (`LivingEntity.java:2092-2097,2192-2211`). 1.21.2 factors the same slow-fall condition into `getEffectiveGravity()` (`LivingEntity.java:2173-2176`), uses it after the same air movement and chunk gate, then applies the same vertical drag (`LivingEntity.java:2191-2213`). With excluded effects absent, it is the same gravity value and operation order. The friction-derived horizontal drag is factored as `ground ? blockFriction * 0.91F : 0.91F` in 1.21.1 and `ground ? blockFriction : 1.0F`, followed by `* 0.91F`, in 1.21.2; both are `float` expressions with equivalent results. Vertical drag remains `FlyingAnimal ? drag : 0.98F`; for a player it is `0.98F` in both. Chunk-unavailable fallback remains `-0.1` above the minimum build height and `0.0` at/below it (`getMinBuildHeight()` renamed to `getMinY()`).
- **Position integration: difference.** The shared path calls `Entity.move(MoverType.SELF, deltaMovement)` from the friction helper. At 1.21.1 `Entity.java:618-630`, the collision-resolved displacement is applied with `setPos` only when its squared length is strictly greater than `1.0E-7`. At 1.21.2 `Entity.java:640-652`, it applies `setPos` when resolved squared length is greater than `1.0E-7` **or** requested squared length minus resolved squared length is less than `1.0E-7`. For an unobstructed move, those squared lengths are equal, making the second condition true even when the displacement is tiny. This permits a nonzero subthreshold Y position update in 1.21.2 which 1.21.1 omits.
- **Fall state / reset: no difference for the local player.** `checkFallDamage` still accumulates negative resolved Y as `fallDistance -= (float)resolvedY`, and resets it on ground (`Entity.java:1163-1178` vs `1216-1233`); `resetFallDistance` still writes `0.0F` (`Entity.java:2392-2394` vs `2490-2492`). The 1.21.2 call is gated on server or local control (`Entity.java:670-672`), while 1.21.1 invokes it unconditionally (`Entity.java:645-649`); for this locally controlled client player both execute. Collision/ground determination and block callback changes are outside this bounded comparison.
- **Local-player wrapper:** `LocalPlayer.move` delegates to `super.move` in both releases (1.21.1 `LocalPlayer.java:881-886`; 1.21.2 `873-881`). The 1.21.2 walk-distance addition is horizontal and excluded from the vertical state claim.

## Causal numeric witness

Given a locally controlled player, no collision, and current ordinary airborne `deltaMovement.y = 0.0001` (with zero X/Z request), `Entity.move` receives requested and resolved squared lengths of `1.0E-8`. In 1.21.1, `1.0E-8 > 1.0E-7` is false, so it does not call `setPos`; in 1.21.2, `1.0E-8 - 1.0E-8 = 0.0 < 1.0E-7`, so it calls `setPos` and increases Y by `0.0001`. Fall-distance accumulation remains the same. This is a state-input witness for the movement operation, not a claim about the default jump impulse producing that exact velocity.

## Finding and closure

One independent source difference: `findings/vertical-subthreshold-position-write.md`. The accepted slice is only ordinary vertical position integration and its common fall-distance path. Gravity/drag, ordinary fall-distance accumulation/reset, and local-player delegation were paired. Exact collision/support and block-response dependencies, horizontal dynamics, jump generation, status/equipment, fluids, gliding/flying, nonlocal/remote paths, and unrelated `Entity.move` refactors remain excluded by assignment. No missing source or damaged method blocker.
