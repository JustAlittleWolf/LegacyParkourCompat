# Moved plain GLASS: EAST extension, positive-thickness phase

Source-only check of one exact state: vanilla `Blocks.GLASS`, moving piston direction EAST, extending, non-source, destination owner `(0,0,0)`, ordinary dry player, no piston nested movement path. Historical phase is `progress=1.0F,lastProgress=0.5F`; modern phase is `progress=1.0F,progressO=0.5F`.

## Result

The Glass candidate inherits full unit-block collision and outline geometry in 1.8.9 and 1.9. Its transparent rendering/solid-render flag does not reduce collision geometry. In 26.2, `Blocks.GLASS` is registered as `TransparentBlock`; its superclass chain inherits `BlockBehaviour.getShape` = `Shapes.block()` and collision shape delegates to that shape because Glass does not set `noCollision`. `TransparentBlock.getVisualShape` returning empty is a separate visual provider. Glass is piston-movable in all inspected versions: legacy `Material.GLASS` retains the default normal movement behavior (1.8.9 int default 0; 1.9 enum default NORMAL); 26.2 properties retain default `PushReaction.NORMAL`. No state-production difference blocks the witness: ordinary piston logic moves Glass into a non-source moving block entity carrying that exact moved state.

At the fixed phase, 1.8.9 samples `lastProgress=.5`, converts extension to `q=.5`, and trims the EAST-side maximum bound of unit Glass to X=.5, yielding owner-local `[0,.5] × [0,1] × [0,1]`. 1.9 unions current-progress `1` (offset 0, `[0,1]`) and previous `.5` (offset `-.5`, `[-.5,.5]`) shapes, yielding `[-.5,1] × [0,1] × [0,1]`. 26.2 collision reads current `progress=1`; extending offset is zero, so its moved Glass shape is `[0,1] × [0,1] × [0,1]`. Its no-clip early return is gated by `progress < 1`, false for this phase.

A positive-margin movement query using this same owner and phase: current player AABB `x=[1.1,1.7], y=[0.2,2.0], z=[0.2,0.8]`, request `dx=-0.5` with `dy=dz=0`. The swept query begins at x=.6. The historical plate ends at .5, so it is separated by .1 and is not appended by the strict collision intersection; 1.8.9 leaves `dx=-.5`. The 1.9 union and 26.2 unit cube both reach x=1; their gap to the player is .1 and the swept query overlaps them, so negative-X clipping yields `dx=-.1`. Thus the displacement difference has a 0.1 margin on both the old no-hit side and the modern clipping side; no touching-face inference is used. The local world is otherwise empty and cell `(0,0,0)` is loaded. The 1.8.9, 1.9 and 26.2 collision scans include this cell for the stated query.
