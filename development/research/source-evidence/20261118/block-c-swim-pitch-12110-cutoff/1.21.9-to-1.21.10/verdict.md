## Frozen trace

- `Player` extends `Avatar` (`Player.java:121`); `Avatar` extends `LivingEntity` (`Avatar.java:12`). `Avatar` declares no `travel` override in either release. `Player.travel(Vec3)` is the concrete player override at `Player.java:1295` in both.
- Passenger gate is first: passenger calls `super.travel` and skips the Player swim-pitch block. Non-passenger, swimming path samples `double lookY = this.getLookAngle().y` once; computes `double scale = lookY < -0.2 ? 0.085 : 0.06`; then short-circuit gate is `lookY <= 0.0 || jumping || !fluidState(BlockPos.containing(x, y + 1.0 - 0.1, z)).isEmpty()`. Only on true does it capture current delta movement and set it to `old.add(0.0, (lookY - old.y) * scale, 0.0)`. Thus the Y adjustment uses the pre-super travel velocity and the sampled lookY. This exact method body is hash-identical across the pair.
- Player then invokes `super.travel`. `LivingEntity.travel` (`LivingEntity.java:2275`) selects fluid when `(isInWater || isInLava) && isAffectedByFluids && !canStandOnFluid(fluidState(blockPosition()))`, else fall-flying, else air. For the ordinary swimming-in-water path, `travelInFluid` moves with `MoverType.SELF` then updates velocity. The player flying branch snapshots Y, calls `super.travel`, and overwrites Y as `snapshot * 0.6`; `Player.updateSwimming` disables swimming when abilities.flying. Both Player and LivingEntity source hashes are identical across versions.
- `Entity.getLookAngle()` (`Entity.java:2424`) calls `calculateViewVector(getXRot(), getYRot())`; raw `xRot` is a private `float` field (`Entity.java:207`), getter returns it directly (`:3772`) and setter stores `Math.clamp(value % 360.0F, -90.0F, 90.0F)` after finite check (`:3776`). `calculateViewVector` (`:1801`) performs float radians: `pitch * (float)(Math.PI / 180.0)`, yaw `-yaw * (float)(Math.PI / 180.0)`, then returns `new Vec3(sin(yawRad)*cos(pitchRad), -sin(pitchRad), cos(yawRad)*cos(pitchRad))`. Method bodies are equal across the pair.
- `Mth.SIN` is `float[65536]` (`Mth.java:32`), initialized for every `int` index `i` as `(float)Math.sin(i * Math.PI * 2.0 / 65536.0)`. `sin(float)` indexes `SIN[(int)(arg * 10430.378F) & 65535]`; `cos(float)` indexes `SIN[(int)(arg * 10430.378F + 16384.0F) & 65535]` (`:48-53`). Table width, initializer expression/order, float narrowing, cast-to-int and 16-bit mask are equal across the pair.
- The actual inherited `Entity.move(MoverType, Vec3)` is reached by the fluid travel helper with `MoverType.SELF` (`Entity.java:670` in 1.21.9; `:670` in 1.21.10). Its pair difference is only in the stuck-speed block: 1.21.9 multiplies by `stuckSpeedMultiplier` for every mover type; 1.21.10 skips that multiplication when type is `PISTON`, then resets the multiplier. Since this trace enters `move` as `SELF`, the changed predicate is false and the old and new operation is the same multiply then reset. It does not alter this swim-pitch Y path.
