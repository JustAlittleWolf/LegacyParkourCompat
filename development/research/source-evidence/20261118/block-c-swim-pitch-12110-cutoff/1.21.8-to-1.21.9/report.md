## Compared operation and result

**No source difference was found in the assigned swim-pitch Y path.** The line numbers below shift between releases, but the cited expressions, values, gates and order match.

- `net/minecraft/world/entity/player/Player.java`, `Player.travel(Vec3)`: 1.21.8 lines 1438–1459; 1.21.9 lines 1295–1316. Passenger players delegate immediately to `super.travel` and skip this local branch. Otherwise, when `isSwimming()`, the method samples `double lookY = this.getLookAngle().y` once, then selects `0.085` for `lookY < -0.2` or `0.06` otherwise. The acceleration gate is `lookY <= 0.0 || jumping || !fluidState(BlockPos.containing(x, y + 1.0 - 0.1, z)).isEmpty()`, in that short-circuit order. Only after that gate passes does it sample delta movement and set it to `delta.add(0.0, (lookY - delta.y) * coefficient, 0.0)`. The local vertical look sample is therefore the same value used for both coefficient choice and the gate and is not recalculated between them.
- The flight branch follows this swim adjustment in both versions: it snapshots the then-current vertical delta, calls `super.travel(input)`, then restores Y as the snapshot times `0.6`. Non-flight players call `super.travel(input)` once. This preserves the pre-super order of the swim-pitch addition.
- `net/minecraft/world/entity/Entity.java`, `getLookAngle()` and `calculateViewVector(float,float)`: 1.21.8 lines 1746–1754 and 2356–2358; 1.21.9 lines 1801–1809 and 2424–2426. `getLookAngle()` passes current `getXRot()` then current `getYRot()` (no partial-tick interpolation). `calculateViewVector` computes float pitch radians as `xRot * (float)(Math.PI / 180.0)`, then calls `Mth.cos(pitch)` and `Mth.sin(pitch)` in that order; the returned Y is `-sin(pitch)`. Thus the water adjustment's `lookY` is the negative pitch sine as produced by that exact float sequence.
- `net/minecraft/util/Mth.java`, fields and `sin(float)`: both versions lines 28–36 and 48–50. Each initializes `SIN` with `Util.make(new float[65536], ...)`, filling each slot `i` with `(float)Math.sin(i * Math.PI * 2.0 / 65536.0)`; the expression uses double math before the float cast. `sin` indexes `SIN[(int)(radians * 10430.378F) & 65535]`: float multiplication by the float literal, Java truncating float-to-int conversion, then a 16-bit mask. `cos` similarly uses the same table with `+ 16384.0F` before the cast and mask (both versions lines 52–54). No pitch conversion, LUT, index arithmetic or table initialization change was found.
- The vertical adjustment is made before `LivingEntity.travel`. The matching base method in `net/minecraft/world/entity/LivingEntity.java` dispatches fluid-affected water/lava movement to `travelInFluid(input)` (1.21.8 lines 2245–2253; 1.21.9 lines 2275–2283). On the water branch, `travelInFluid` calls `move(MoverType.SELF, this.getDeltaMovement())` (1.21.8 line 2323; 1.21.9 line 2353), directly consuming the adjusted velocity in the actual water move. These gates and the consuming move also match in the compared excerpts.

The textual evidence supports **no 1.21.8→1.21.9 behavior delta** for this operation. Because 1.21.8 lacks source provenance and local input pins, treat this result as a candidate no-difference coverage observation, not a provenance-complete accepted finding.
