## Compared slice and result

Compared Entity.yaw and Entity.lastYaw; declaration type and order with pitch and lastPitch; Entity.setRotation; the previous-yaw tick copy and wrap; and the first ordinary dry ground/air yaw-relative movement consumer, Entity.updateVelocity, reached from LivingEntity.moveRelative after the ground/air scale branch.

**No difference found in this bounded yaw slice.** Both releases declare yaw, pitch, lastYaw, lastPitch as float fields in that order. setRotation stores yaw as yaw % 360.0F and has no finite-value guard, retaining Java float remainder behavior for nonfinite inputs. The tick copy writes lastYaw = yaw. Living-entity interpolation wraps the previous value with loops at yaw - lastYaw < -180.0F and >= 180.0F, adjusting by 360 degrees; boundaries and operation order match. No yaw finiteness check appears in these examined paths.

Entity.updateVelocity reads current yaw, computes sin(yaw * (float)(PI / 180.0)) then cos with the same expression, and applies the same signs to sideways/forward input when adding X/Z velocity on both sides. It is invoked by LivingEntity.moveRelative in the ordinary non-water/non-lava branch.

Exact method-body SHA-256, identical on both sides in every pair: Entity.setRotation = 9914a6040906c2b1119c6382b21ee2e3a932dd0f16d2af08b8d6bb047bfa3930; Entity.updateVelocity = dc69b7e35a30fb51d2ac87bf546fa960e98a246c76731162ba5cd68b9cf98a4e. The wider LivingEntity.moveRelative body differs across some releases, so only the ordinary dry ground/air call path is noted here; other branches and acceleration dependencies are outside this finding slice.

This result is limited to yaw handling. Input-device construction, selected ground/air scale, input normalization, and broader acceleration/travel behavior are separate dependencies and were not adjudicated. No finding is warranted for this exact pair from this slice. This does not assert coverage of other movement areas or pair freeze.
