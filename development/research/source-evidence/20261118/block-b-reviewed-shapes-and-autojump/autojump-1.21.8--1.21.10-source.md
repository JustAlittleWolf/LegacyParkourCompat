- **1.21.9→1.21.10 — equivalent; no finding.** `LocalPlayer.java` file hash and the `updateAutoJump` method-body hash both match exactly. Local call and consumed input fallback therefore match exactly as well.

The shared method first gates on auto-jump enabled, timer `<=0`, on-ground, not staying on ground surface, not passenger, nonzero move vector, and block jump factor `>=1`. Its candidate route uses normalized actual displacement or the input/yaw fallback, rejects reverse facing below dot `-0.15F`, and requires empty collision shapes at the block containing `boundingBox.maxY` and the next block above. It builds the swept/inflated collision query, offsets both side rays by `0.51F`, iterates collision AABBs in returned stream order and stops at the first AABB intersecting either ray. It derives a candidate height from that AABB; the secondary query checks the block above the AABB center for loop index 1, can replace height with that shape's top, and returns if height exceeds `1.2F`. Because the loop index is `int` and the bound is `float 1.2F`, the body has no index-2 iteration; its nested `index > 1` headroom check is unreachable. The final timer write requires height strictly greater than `0.5F` and at most the jump limit (`1.2F`, increased by jump boost).

Shape controls within the requested static scope: full-cube candidate top is eligible when other gates/headroom pass; lower-half slab top (`0.5`) fails the strict lower bound, while upper-half slab top (`1.0`) passes. Dry stair candidates are subject to the same first-intersecting AABB and secondary center-column query; differing stair shape pieces affect which candidate is first and its `maxY`, but the AutoJump method itself is unchanged across all three versions. A clear route produces no candidate intersection and no timer write. No runtime trajectory was executed.
