# Contact slowdown comparison: 26.1.1 to 26.1.2 (revision 1)

Base draft preserved at `comparison.md`, SHA-256 `ee5594651788e111a6f0b680a3a76e673676e2dde68e833f8670b5dbe0c7388f`.

## Bounded verdict and player scope

No source difference was found in the assigned contracts for an ordinary local `Player` that is not riding, not using abilities flight, and not fall-flying. Compare with contact geometry, support world and all relevant query values held equal on both versions. This is bounded source equivalence, not whole-pair coverage or runtime parity.

## Contracts and ordering

- **Honey slide velocity and fall reset:** In each release, `HoneyBlock.entityInside` calls the same `isSlidingDown` checks before `doSlideMovement` (`net/minecraft/world/level/block/HoneyBlock.java:64-80, 89-105`). `doSlideMovement` scales horizontal X/Z only when `getOldDeltaY(entity.getDeltaMovement().y) < -0.13`; the factor is `-0.05 / getOldDeltaY(...)`. Otherwise X/Z are preserved. Both branches write the same Y value, `getNewDeltaY(-0.05)`, and then call `resetFallDistance()` (`:114-124`). These bodies match exactly.
- **Cobweb stuck speed:** `WebBlock.entityInside` chooses `(0.25, 0.05F, 0.25)`, or `(0.5, 0.25, 0.5)` when the entity is living and has WEAVING, then calls `makeStuckInBlock` (`net/minecraft/world/level/block/WebBlock.java:27-41`). The producer is identical.
- **Berry bush stuck speed:** For living entities other than foxes and bees, `SweetBerryBushBlock.entityInside` calls `makeStuckInBlock(state, new Vec3(0.8F, 0.75, 0.8))` before the separate server-side damage path (`net/minecraft/world/level/block/SweetBerryBushBlock.java:82-99`). The movement producer is identical; age, movement threshold and damage logic are excluded from this movement comparison.
- **Player override and consumption:** In both `Player.java` files, `Player.makeStuckInBlock` delegates to `super` only when `!this.abilities.flying`, then resets the current impulse context (`:1493-1500`). Therefore the stated non-flying player scope reaches the same `Entity.makeStuckInBlock`, which resets fall distance and stores `stuckSpeedMultiplier` (`Entity.java:2876-2879`). In both versions, `LivingEntity.aiStep` uses `travel(input)` on the non-riding branch and then calls `applyEffectsFromBlocks()` for the authoritative local instance (`LivingEntity.java:3059-3078`). Contact dispatch invokes block `entityInside` along recorded movement (`Entity.java:839-850, 885-897, 1195-1210, 1259-1277`). At the next ordinary `Entity.move`, a multiplier with squared length above `1.0E-7` scales requested delta except for piston movement, then is cleared and entity delta movement is zeroed (`Entity.java:704-730`). These producers, override, dispatch order and consumer are byte-identical across the pinned source trees.

With ordinary non-riding, non-flying player movement and equal geometry/support/query inputs, the assigned contact contracts have no 26.1.1-to-26.1.2 delta. This audit does not cover provider/shape implementation, other contact types, intermediate release boundaries, the full tick graph, or runtime parity.
