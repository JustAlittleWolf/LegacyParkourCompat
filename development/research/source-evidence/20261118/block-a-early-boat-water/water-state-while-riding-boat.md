# boat passenger skips player water collision update

1.8.9, ornithe-feather; feather-gen2-1.8.9+build.2-mergedv2.jar, feather-gen2-1.8.9+build.2.tiny: `1.8.9/ornithe-feather/net/minecraft/entity/Entity.java`, `public boolean checkWaterCollisions()`, lines 746-760.
1.9, ornithe-feather; feather-gen2-1.9+build.2-mergedv2.jar: `1.9/ornithe-feather/net/minecraft/entity/Entity.java`, `public boolean checkWaterCollisions()`, lines 845-860. The same method body is present at lines 845-860 in 1.9.1 and 1.9.2, and at lines 849-864 in 1.9.3 and 1.9.4. The 1.9/1.9.1/1.9.2 `Entity.java` source hashes match; 1.9.3/1.9.4 hashes match.

Difference: 1.8.9 always calls `World.applyLiquidDrag()` for the contracted entity box with `Material.WATER`. Starting in 1.9, `checkWaterCollisions()` first checks `this.getMount() instanceof BoatEntity`; for a boat passenger it sets the entity's `inWater` field to false and skips the water query. Otherwise the existing query and writes remain. The earliest checked release with the gate is 1.9.0; it persists through 1.9.4.

Movement meaning: `LocalClientPlayerEntity.tick()` calls `super.tick()` (1.8.9 lines 105-108; 1.9.4 lines 143-146). Through `PlayerEntity` and `LivingEntity`, this reaches `Entity.tick()`, which calls `checkWaterCollisions()` (1.8.9 line 300; 1.9.4 line 361), before the later `LivingEntity.tick()` jump and `moveRelative()` work. `LivingEntity.tick()` tests `isInWater()` to choose water jumping (1.8.9 lines 1430-1434; 1.9.4 lines 1690-1694) and calls `moveRelative()` (1.8.9 line 1450; 1.9.4 line 1711). `LivingEntity.moveRelative()` uses `isInWater()` to select its water or non-water movement branch (1.8.9 line 1119 onward; 1.9.4 line 1302 onward), and `PlayerEntity.moveRelative()` delegates to it (1.8.9 lines 1279-1292; 1.9.4 lines 1372-1391). Thus the gate changes the inherited local player's body water status consumed by its movement code while mounted. Once the player is no longer mounted, the next `Entity.tick()` runs the ordinary box-water query and refreshes the status; the boat-specific false value is not latched after that refresh. Since the branch also skips `World.applyLiquidDrag()`, it bypasses the passenger entity's water-current update as well; that is a separate consequence of skipping the player-body query, not a BoatEntity physics change.
