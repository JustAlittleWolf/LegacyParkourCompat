# Blind source freeze: Mojmap 1.20 → 1.20.1

## Scope and result

Independent source comparison of the ordinary local mouse callback path with captured mouse, active window, smooth camera off, and not scoping; `Entity.turn` and pitch setter/clamping; then the first active non-passenger flight move, including its controlling gates. Mouse-device callback setup and device plumbing are excluded. Result: no source delta in this scoped path. The exact consumed source files listed below have identical SHA-256 bodies across the pair, giving bounded body-level equivalence; the reviewed branches are described to make the scope and gates explicit. This is not whole-pair movement coverage or a statement about runtime parity.

## Compared reachable path

1. `MouseHandler.onMove` (`MouseHandler.java:175–210`) is reached for the window callback. After initial-position handling, captured-and-window-active input accumulates `x - xpos` and `y - ypos`; then `turnPlayer()` runs before `xpos/ypos` are advanced. The callback plumbing is outside scope; this establishes the relevant accumulator order and capture/active gate.
2. `MouseHandler.turnPlayer` (`:212–253`) first computes elapsed time from `Blaze3D.getTime()` and updates `lastMouseEventTime`; rotation math is gated by `isMouseGrabbed() && minecraft.isWindowActive()`. With smooth camera off and not scoping, both smoothing filters are reset and the regular branch produces `dx = accumulatedDX * (sensitivity * 0.6F + 0.2F)^3 * 8.0` and the analogous `dy`, in the source's staged double assignments (`s`, `s*s*s`, then `*8.0`). It then clears both accumulators, chooses Y sign from `invertYMouse`, calls tutorial `onMouse(dx, dy)`, and if player exists calls `player.turn(dx, dy * sign)`. No delta clamp or rounding was added in the newer source.
3. `Entity.turn` (`Entity.java:395–407`) computes pitch delta as `(float)dy * 0.15F` and yaw delta as `(float)dx * 0.15F`; it invokes `setXRot(getXRot() + pitchDelta)`, then `setYRot(getYRot() + yawDelta)`, then invokes `setXRot(Mth.clamp(getXRot(), -90.0F, 90.0F))`. Old pitch/yaw are incremented afterward from their old values by those deltas, and old pitch is clamped. The `setXRot` invocations are virtual. There is no override in `Player`, `LivingEntity`, or `LocalPlayer`; the inherited `Entity.setXRot` (`:3273–3279`) rejects non-finite input (logging via `Util.logAndPauseIfInIde`) and otherwise assigns `xRot`. The current pitch is therefore setter-validated both before and after clamp; old pitch is independently updated/clamped as written. This preserves float casts, addition and clamp order.
4. The first active creative/spectator flight movement path: `LocalPlayer.aiStep` (`LocalPlayer.java:648–802`) toggles/forces `abilities.flying` only under `abilities.mayfly` and its game-mode/input gates (or always-flying mode); when `abilities.flying && isControlledCamera()`, shift contributes `-1`, jump contributes `+1`, and a nonzero sum adds `(0, sum * getFlyingSpeed() * 3.0F, 0)` to delta movement. It then calls `super.aiStep`; ordinary grounded flight is disabled afterward unless the game mode is always-flying. At the player travel operation (`Player.travel`, `Player.java:1446–1471`), the active flying branch requires `abilities.flying && !isPassenger()`: save pre-travel Y velocity, call `super.travel(input)`, preserve resulting X/Z velocity but replace Y with saved-Y `* 0.6`, reset fall distance, and clear shared flag 7. Passenger flight reaches the ordinary `super.travel` branch. The swimming prelude and movement-statistics tail are also identical in the compared source. `LivingEntity.java` is byte-identical across the pair, so its delegated travel/movement body is within the equality witness.

## Freeze verdict and boundedness

The five source files containing the callback math, rotation virtual dispatch/setter, local flight controls, player active-flight travel, and delegated living travel are byte-identical between exact 1.20 Mojmap and exact 1.20.1 Mojmap sources, with each actual file hash matching its release's source inventory. The scoped ordinary path therefore has no 1.20 → 1.20.1 source delta. This audit does not establish other mouse states (smooth camera, scoping, no capture/inactive window), passenger movement, other input sources, other movement systems, intermediate patch boundaries, or whole-pair inventory closure.
