# Glide look-vector guard: near-vertical residual

## Scope

Source-only check of the existing `1.12.2--1.13.2/elytra-look-guard.md` claim, limited to finite negative pitches strictly greater than -90 degrees and to the pitch-derived horizontal-look length used by fall-flying `LivingEntity.moveRelative`. The previously accepted exact -90-degree yaw-0 denominator result is reused and not re-evaluated here. No product implementation, wiki material, gameplay, build, or runtime was consulted.

Canonical source families: Ornithe Feather, `feather-gen2-1.12.2+build.2-mergedv2.jar` / `feather-gen2-1.12.2+build.2.tiny`, and `feather-gen2-1.13.2+build.2-mergedv2.jar` / `feather-gen2-1.13.2+build.2.tiny`, as recorded in the immutable source finding. Exact 1.12, 1.12.1, 1.12.2 and 1.13, 1.13.1, 1.13.2 Feather methods and trig helpers were checked; the pitch/look formulas and guard distinction below are unchanged within each family.

## Finding: the 1.13 guard covers a reachable finite pitch band

1.12.2, Ornithe Feather: `decompiled_minecraft/1.12.2/ornithe-feather/net/minecraft/entity/living/LivingEntity.java`, `moveRelative`, lines 1434-1453; `decompiled_minecraft/1.12.2/ornithe-feather/net/minecraft/entity/Entity.java`, `getRotationVector(float pitch, float yaw)`, lines 1239-1245; `decompiled_minecraft/1.12.2/ornithe-feather/net/minecraft/util/math/MathHelper.java`, `sin`, `cos`, and sine-table initialization, lines 8-20 and 427-428.

1.13.2, Ornithe Feather: `decompiled_minecraft/1.13.2/ornithe-feather/net/minecraft/entity/living/LivingEntity.java`, `moveRelative`, lines 1493-1513; `decompiled_minecraft/1.13.2/ornithe-feather/net/minecraft/entity/Entity.java`, `getRotationVector(float pitch, float yaw)`, lines 1251-1259; `decompiled_minecraft/1.13.2/ornithe-feather/net/minecraft/util/math/MathHelper.java`, `sin`, `cos`, and sine-table initialization, lines 11-29.

Difference: both versions enter the pitch-up correction for negative `pitch * (float)(PI / 180)`. In 1.12, however, the horizontal vector is constructed with `h = -cos(-pitch * degrees)` and yaw trig multiplied by `h`; over the near-vertical pitches below, `h` is nonzero. The correction has no `j > 0` check before dividing by `j`. In 1.13, horizontal components are `sin(-yaw * degrees) * cos(pitch * degrees)` and `cos(-yaw * degrees) * cos(pitch * degrees)`. The same quantized cosine used for both components is exactly zero for a finite band, so `k = sqrt(x*x + z*z)` is zero at every yaw. The added `k > 0` condition then skips the complete pitch-up correction, including both divisions.

Exact float/table proof: the nearest representable float strictly inside the clamp at the lower end is pitch `-89.99999237060547F` (`0xC2B3FFFF`). With the source float constant `(float)(PI / 180.0)`, its 1.13 pitch angle rounds to `-1.5707961320877075F` (`0xBFC90FD9`). `MathHelper.cos` computes the sine-table index by float multiplication by `10430.378F`, float addition of `16384.0F`, truncation, and `& 65535`; this gives index 0, whose initialized table entry is exactly `0.0F`. Repeating the same binary32 operations for each representable pitch from offset 1 through offset 718 above -90 gives index 0. Thus 718 strictly interior float pitch values, from `-89.99999237060547F` through `-89.9945068359375F`, produce a zero horizontal look length in 1.13, regardless of finite yaw. At offset 719, pitch `-89.99451446533203F` (`0xC2B3FD31`) yields angle `-1.5707005262374878F`, table index 1, and cosine `0.0000958738019107841F`; this is the first nonzero value moving inward. This is a 718-value finite interior band, not only the excluded endpoint.

For the same nearest interior pitch, the 1.12 positive argument `-pitch * degrees` rounds to `1.5707961320877075F`; its cosine index is 32767 and its table value is `0.0000958738019107841F`. For the subsequent interior values through the band its index remains 32767, so the pitch-derived horizontal scale is nonzero. Following the source float operations through the yaw table at yaw `0F`, `37F`, `90F`, and `123.456F` gives positive horizontal lengths (approximately `9.58738e-5` in each case). The old correction reaches its divisions at these yaw values; the new guard fails at `k > 0` independently of yaw and suppresses the correction throughout the finite band.

Reachability: both versions clamp player camera pitch to `[-90.0F, 90.0F]` (`Entity.java` 1.12.2 lines 307-314; 1.13.2 lines 318-326), which admits these interior float values. The camera update computes a float pitch from a double cursor delta before clamping, so the lower-end adjacent float is representable by the update path. The fall-flying branch in `moveRelative` consumes `this.pitch` and `this.getLookVector()` when `isFallFlying()` is true. With nonzero horizontal player velocity, the old `o` term is nonzero for these negative pitches and changes vertical velocity and horizontal velocity; the 1.13 guard omits those operations.

Disposition: **known source-level near-vertical behavior difference**. It is an extension of the accepted guard finding: 1.13's denominator guard suppresses pitch-up correction for a quantized finite pitch band, not just the prior exact-endpoint case. This bounded result does not establish an exact intermediate release cutover.
