## Independent trace and limits

- `LivingEntity.onClimbable()` reads the feet `BlockState` and checks `BlockTags.CLIMBABLE` (then the trapdoor ladder case): `LivingEntity.java:1363-1373` in both trees. `LocalPlayer`'s jump initiation separately requires `!onClimbable()` (`LocalPlayer.java:725-730`); that gate prevents starting flight while climbing, but says nothing against an already-active glide continuing at later climbable contact. `Player.tryToStartFallFlying()` also requires `!isFallFlying()` and otherwise retains the same airborne, dry, non-levitating Elytra gates (`Player.java:1520-1528`).
- The active state reaches movement through `LivingEntity.aiStep`: after the input drag, `updateFallFlying()` is called immediately before `travel(new Vec3(...))` (`LivingEntity.java:2454-2460`). Its validator carries the shared flag locally while airborne, not a passenger, without levitation, and wearing an enabled chest Elytra; its shared-flag write-back is guarded by `!level.isClientSide` (`2478-2497`). `isFallFlying()` reads shared flag 7 (`2891-2893`). The climbable feet state is not a cancellation gate here.
- In `LivingEntity.travel`, fluid branches are tested first, then `else if (isFallFlying())`, before the generic friction branch (`1914-2022`). The glide branch takes its initial velocity snapshot as `vec36`; the exact **strict** pre-move condition is `vec36.y > -0.5`, and only then it writes `fallDistance = 1.0F` (`1980-1983`). Equality at `-0.5` does not write. The write precedes look-angle calculations, glide velocity adjustment/damping, `setDeltaMovement`, and `move(MoverType.SELF, ...)` (`1985-2008`). This glide branch bypasses generic `handleRelativeFrictionAndCalculateMovement` and `handleOnClimbable`, where feet-climbable cleanup otherwise writes `fallDistance = 0.0F` and clamps horizontal/downward velocity (`2062-2071`, `2089-2104`).
- The `1.0F` value is a pre-move write, not a guarantee of the tick's final fall distance. `Entity.move()` resolves collision and calls `checkFallDamage` immediately after (`Entity.java:485-518`). In both releases, landing passes the current fall distance to `block.fallOn(...)` and then sets it to zero; off-ground negative resolved movement adds `-d` to the field (`Entity.java:894-902`). Those immediate state writes limit the claim to branch and write order. Later damage/fall consequences are excluded and are not inferred here.
