## Ordered inventory and comparison

1. **Ordinary End Portal block contact / client-local pending state.** Compared 1.21.1 `world/entity/Entity.java:705,758-779,1001-1027` (entity movement calls `tryCheckInsideBlocks`; contact checks only integer block cells overlapped by the final player AABB) with 1.21.2 `world/entity/Entity.java:736-770,1038-1090` (for a nonremoved, physics-enabled entity, records/visits movement segments and tests the block's entity-inside collision shape against the swept player box); compared `world/level/block/EndPortalBlock.java:29-63` on both sides. In 1.21.1 the portal itself requires `canUsePortal(false)` and nonempty intersection of the player's local AABB and its half-height `SHAPE` before calling `setAsInsidePortal`. In 1.21.2 it supplies that same `SHAPE` via `getEntityInsideCollisionShape` (`EndPortalBlock.java:53-55`) and the shared movement-path caller performs the overlap gate before `entityInside`, whose local method retains `canUsePortal(false)` and `setAsInsidePortal`. **Finding:** the overlap/contact test moves from final-box overlap in the block callback to path-vs-portal-shape overlap in entity movement processing. A local player path that crosses the portal slab during a movement segment but ends with its AABB outside the slab can now enter the pending portal process. This can affect client-side portal local transition/visual state; actual dimension change remains server-gated. Draft: `1.21.1--1.21.2/end-portal-swept-contact.md`.
2. **End Gateway block contact / eligibility.** Compared 1.21.1 `world/entity/Entity.java:705,758-779,1001-1027` and 1.21.2 `world/entity/Entity.java:736-770,1038-1090`, plus `world/level/block/EndGatewayBlock.java:87-90` (1.21.1) and `:89-93` (1.21.2), and `world/level/block/state/BlockBehaviour.java:353-355` (1.21.2 default `getEntityInsideCollisionShape` returns `Shapes.block()`). The gateway callback's gates are otherwise the same: `canUsePortal(false)`, logical server, matching gateway block entity, and not cooling down; then it marks the portal process and triggers cooldown. Unlike End Portal, gateway has no special entity-inside shape override, so the new shared movement path uses its default full-block shape. **Finding:** a player path that crosses a gateway block's full collision shape during a movement segment but ends outside it can now reach the callback; older logic only invoked the callback for final-AABB occupied cells. Gateway contact and portal-process state are server-side due to the unchanged `!level.isClientSide` gate. Draft: `1.21.1--1.21.2/end-gateway-swept-contact.md`.
