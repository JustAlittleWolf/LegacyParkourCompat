## Checked source bounds and findings

All cited bounds are in `net/minecraft/...` under each release’s `mojmap` root. Because the enclosing source files have the same verified whole-file hashes, the examined bodies are byte-identical on both sides.

- Effect attachment/replacement/removal and attribute callbacks: `LivingEntity.java:978–1000` (`addEffect`), `1013–1022` (`forceAddEffect`), `1030–1042` (remove), `1044–1090` (callbacks). A new effect is stored before the add callback; normal replacement calls update only when `MobEffectInstance.update` succeeds; forced replacement stores then copies blend state and updates; removal leaves `activeEffects` before the callback. Attribute modifier attach/remove/refresh is gated to non-client-side callback execution. `MobEffect.java:135–170` shows ID-based remove then amplifier-materialized permanent re-add; its body is unchanged.
- Equipment modifier refresh: `LivingEntity.java:2626–2675`; changed old stacks stop location effects, then eligible changed new stacks enumerate slot modifiers, remove a matching destination modifier ID and add transiently. `ItemStack.java:964–974` enumerates item-component modifiers and enchantment modifiers. No Java-level glider-specific movement attribute path was found in this flow.
- Glider predicate: `LivingEntity.java:2893–2905` and `3678–3685`; requires not grounded, not passenger, no levitation, and an equipped stack with `GLIDER`, matching equippable slot, and no imminent break. The source is unchanged; conclusions about component defaults remain out of scope.
- Selected player consumers: `Player.java:579`, `792`, `1481–1484`; `LivingEntity.java:2132–2140`, `2192–2202`, `2235–2243`. The additional client-side direct consumers `LocalPlayer.java:633–638` (`SNEAKING_SPEED`) and `AbstractClientPlayer.java:66–75` (`MOVEMENT_SPEED`) also have identical, provenance-matched source files. Attribute operation order is unchanged in `AttributeInstance.java:119–133`, `141–168`, and `174–183`; definitions are unchanged in `Attributes.java`.

## Dependency limit

Each canonical source inventory contains 6,103 (`1.21.6`) / 6,104 (`1.21.7`) Java files and zero packaged non-Java data/resource files besides `.decompile-provenance.json`. Thus exact source provenance and Java behavior are verified, but movement-enchantment data, item/equipment attribute modifier component values, and other packaged defaults cannot be compared here. The no-difference verdict must not be read as proof that the full data-driven equipment/enchantment applicability surface was examined. No intermediate patch versions, runtime parity, or unrelated player-state writers were audited.
