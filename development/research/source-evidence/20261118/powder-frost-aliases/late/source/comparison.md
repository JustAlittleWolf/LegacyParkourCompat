# Powder snow frost source comparison

## Result

The `removeFrost` and `tryAddFrost` method bodies preserve their local gates, float calculation, and `ADD_VALUE` operation in all five examined sources. The modifier identity representation changes from a UUID to `minecraft:powder_snow` in 1.21, without a source-evidenced movement change by itself. A caller-level client/server change appears in 1.21.5: after travel, frost processing runs only on `ServerLevel`; movement-speed changes are then synchronized to clients as attribute metadata. This is an eligible direct player movement input difference. Comparing only the named frost methods would miss it.

## Compared behavior

In 1.20.5 (`LivingEntity.java`, `removeFrost` 533-540, `tryAddFrost` 542-556, freezing caller 2687-2700), 1.21 (490-516, 2682-2695), 1.21.2 (505-531, 2780-2796), and 1.21.4 (505-531, 2791-2804), `travel(...)` completes before the `freezing` section. The frozen-tick counter is changed only on the logical server and only while the entity is not dead or dying: powder snow plus `canFreeze()` increments up to the required maximum; otherwise it subtracts two down to zero. After that conditional, both `removeFrost()` and `tryAddFrost()` are called on both logical sides, before the later `push` phase.

Across those method bodies, removal requires a non-null movement-speed attribute and an existing frost modifier. Addition requires `!getBlockStateOnLegacy().isAir()`, then `getTicksFrozen() > 0`, then a non-null movement-speed attribute. It computes `float amount = -0.05F * getPercentFrozen()` and adds a transient `ADD_VALUE` modifier. In 1.20.5 the key is UUID `1eaf83ff-7207-4596-b37a-d7a07b3ec4ce`, and the modifier constructor also carries the display name `Powder snow slow`. From 1.21 onward the key is the namespaced `ResourceLocation` `minecraft:powder_snow`; the display name is absent. The amount, operation, and gates are unchanged in the examined sources. The identifier representation change is not independently shown to change movement.

In 1.21.5 (`LivingEntity.java`, freezing caller 2779-2791), the post-travel `freezing` section is inside `if (level() instanceof ServerLevel)`. The dead-or-dying guard is absent. Its counter gate is written as `!isInPowderSnow || !canFreeze()`, in which case it subtracts two down to zero; otherwise it leaves the current value unchanged. `removeFrost()` and `tryAddFrost()` follow inside the same server-only branch. Their method bodies retain the same non-air, positive-frozen-ticks, non-null-attribute, float amount, transient modifier, and `ADD_VALUE` gates as 1.21.4. Thus the client no longer locally executes either frost modifier method after its travel.

The client-side movement input remains reachable through source-defined attribute synchronization. `Attributes.java:63-65` marks `MOVEMENT_SPEED` client-syncable. `ServerEntity.java:345-359` sends dirty syncable attributes as `ClientboundUpdateAttributesPacket`; its `broadcastAndSend` also sends the packet to the owning `ServerPlayer` connection. `ClientboundUpdateAttributesPacket.java:30-36,71-80` snapshots the attribute base and modifiers, including modifier ID, amount, and operation. `ClientPacketListener.java:2179-2198` sets the received base, removes local modifiers, and reapplies each received modifier transiently. `Player.java:1470-1472` (1.21.5) reads `getSpeed()` from `getAttributeValue(Attributes.MOVEMENT_SPEED)`, so the next player speed read uses the received movement-speed attribute once that update has arrived. These sources establish the data path, not a particular network arrival tick or trajectory delta.

## Finding and limits

The new source delta is the change from local client frost-modifier recomputation in 1.21.4 to server-only frost recomputation plus synced attribute receipt in 1.21.5. Do not infer an exact patch introduction before 1.21.5 or beyond the inspected releases. No block-state production, rendering, damage result, or runtime parity claim is part of this comparison. Exact inspected endpoints only: 1.20.5, 1.21, 1.21.2, 1.21.4, and 1.21.5.
