# Independent verdict: glide denominator witness

## Verdict

The frozen numerical witness is source-confirmed for the scoped, ordinary local, dry, already-fall-flying player state, but the guard delta is **not independent of trigonometry**. At the ordinary camera-clamped pitch `-90.0F`, 1.12.2 produces a tiny nonzero horizontal look denominator and enters the negative-pitch correction; 1.13 produces an exactly zero horizontal look magnitude and its added `> 0.0` guard skips that correction. The difference depends on the two releases' exact float expressions feeding the shared sine-table lookup.

For the 1.12.2 correction that actually divides by the horizontal magnitude, no exact-zero denominator occurs anywhere on the camera-clamped negative-pitch interval. A zero horizontal magnitude can occur at the other ordinary endpoint, `+90.0F`, but the 1.12.2 correction gates are closed there, so no division by that zero occurs. This does not support describing the pair as a reachable old divide-by-zero fix.

## Source references and independent checks

All paths below are relative to the respective `decompiled_minecraft/<version>/ornithe-feather/` tree.

- 1.12.2 `net/minecraft/entity/living/LivingEntity.java:1425-1458`: `moveRelative` caller gate, fluid gates, `isFallFlying`, look vector, `i` pitch conversion, `j` horizontal look magnitude, and both corrections. In particular, the negative-pitch block is gated only by `i < 0.0F` before computing `vec3d.x * o / j` and `vec3d.z * o / j` at lines 1449-1453.
- 1.13 `net/minecraft/entity/living/LivingEntity.java:1459-1498`: same outer local/side, water/lava and fall-flying gates; the negative-pitch block at lines 1489-1494 additionally requires `k > 0.0` before either division.
- 1.12.2 `net/minecraft/entity/Entity.java:307-313` clamps local camera pitch to `[-90.0F, 90.0F]`; `1239-1245` computes the rotation vector; `1690-1692` exposes it as the look vector. `net/minecraft/util/math/MathHelper.java:15-20,426-429` gives the lookup index calculation and sine-table initialization.
- 1.13 `net/minecraft/entity/Entity.java:318-326` clamps local camera pitch to the same interval; `1250-1258` computes the rotation vector; `1690-1692` exposes it as the look vector. `net/minecraft/util/math/MathHelper.java:24-29,11-15` gives the same lookup index calculation and table initialization.

For pitch `-90.0F`, 1.12.2 evaluates the horizontal look multiplier as `-MathHelper.cos(-pitch * (float)(Math.PI / 180.0))`. The float radian product passed to `cos` is positive `1.5707964F`; `cos` computes the float expression `x * 10430.378F + 16384.0F`, casts it to `int` (truncation), and masks with `65535`, selecting index `32768`. That table entry is `(float)Math.sin(32768 * Math.PI * 2.0 / 65536.0)`, approximately `1.2246469e-16F`, not zero. The vector's horizontal component products occur as `float` before being widened into `Vec3d`'s `double` fields; `j` then squares and sums those widened doubles and uses `Math.sqrt(double)`. At yaw `0.0F`, `j` is approximately `1.2246468525851679e-16`, hence strictly positive. The fly-pitch value `i = pitch * (float)(PI / 180.0)` is negative, so the old unguarded negative-pitch correction is entered.

For the same pitch in 1.13, `getRotationVector` first computes `f = pitch * (float)(PI / 180.0)` and multiplies the horizontal vector by `MathHelper.cos(f)`. The float argument is negative `1.5707964F`; the lookup arithmetic selects index `0`, whose initialized sine value is exactly `0.0F`. Thus the returned horizontal `Vec3d` components and `k = sqrt(x*x + z*z)` are exactly zero. The 1.13 negative-pitch condition is `j < 0.0F && k > 0.0`; its second operand is false. The earlier vertical-speed correction is likewise gated by `velocityY < 0.0 && k > 0.0`, and the later alignment block also checks `k > 0.0`.

At 1.12.2 pitch `+90.0F`, the old lookup instead selects table index `0`, making the horizontal magnitude zero; however `i < 0.0F` is false, and the other blocks that could divide by the horizontal magnitude require `j > 0.0`. Therefore an exact zero exists as a value of the old horizontal denominator at an ordinary finite camera-clamped angle, but no corresponding old division is reachable there. Throughout camera-clamped negative pitch (`-90.0F` through but excluding `0.0F`), the old cosine lookup's index is in the `16384..32768` range and its entries are nonzero; in particular, at `-90.0F` it is the nonzero `sin(pi)` float residual above.
