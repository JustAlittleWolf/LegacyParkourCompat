# Independent audit: 26.2 death status and direction delivery

## Verdict

**COMPLETED.** The ordinary `ServerPlayer.die` path sends entity event byte 3 to the dying player's controlling connection. Its own packet order is combat-kill first, byte 3 second. Health and entity-motion synchronization are independent sends, so the source does not establish a universal total order between either and those death packets. A finite movement-only match is supported for an unblocked lethal direct-attacker hit with the victim at yaw 0 and the attacker exactly one block along +X: both versions use direction 0, and 26.2 delivers that direction to the local player before the death packets. This does not establish a match for arbitrary death causes or all directions and is not server-side historical physics.

## Delivery and order

In `26.2/unobfuscated/net/minecraft/server/level/ServerPlayer.java`, `ServerPlayer.die` sends `ClientboundPlayerCombatKillPacket` to `this.connection` (lines 884-915), then invokes `broadcastEntityEvent(this, (byte)3)` after the intervening death bookkeeping (line 934). `ServerLevel.broadcastEntityEvent` builds `ClientboundEntityEventPacket`; `ChunkMap.TrackedEntity.sendToTrackingPlayersAndSelf` sends it to tracking clients and explicitly to `player.connection` for a `ServerPlayer` event. The event therefore reaches the controlling client after the combat-kill packet was enqueued.

The accepted bound client audit and the canonical client sources show the event route calls `handleEntityEvent`; `LocalPlayer` and `Player` delegate event 3 to `LivingEntity`, whose event-3 branch plays its optional sound but guards health-zero and `die` with `!(this instanceof Player)`. Thus on 26.2 the event reaches the local player without invoking its death path or writing movement there.

The two death sends have no unconditional ordering against health or motion synchronization. `ServerPlayer.doTick` sends changed health after `super.tick()` returns; if death occurs inside that call, the death sends precede that health update, but a previous health update can precede the fatal hit, and a later-tick fatal hit has a later health send. `ServerEntity.sendChanges` sends entity motion on its tracking tick when `hurtMarked` is set, independently of `ServerPlayer.die`; it has no universal order relative to byte 3.

## Direction and finite witness

In 1.14.4 / Ornithe Feather, `LivingEntity.takeDamage` stores `damagedSwingDir` from the attacking entity's horizontal offset using `MathHelper.fastAtan2(i, h) * 180.0F / PI - yaw` (lines 917-974). Event 3 reaches `LivingEntity.handleEntityEvent`, which sets health to zero and calls virtual `die`; `PlayerEntity.die` then writes X/Z velocity as `-cos(damagedSwingDir + yaw) * 0.1F` and `-sin(...) * 0.1F`, with Y `0.1F` (lines 581-596).

In 26.2, the direct-attacker case obtains the damage source position in `DamageSource.getSourcePosition`; `LivingEntity.dealDefaultKnockback` derives `xd`/`zd` from that position and calls `indicateDamage` on an unblocked hit (lines 1290-1305). `ServerPlayer.indicateDamage` calculates `hurtDir = atan2(zd, xd) * 180.0F / PI - getYRot()` and sends `ClientboundHurtAnimationPacket`. `ClientPacketListener.handleHurtAnimation` calls `entity.animateHurt(packet.yaw())`, and `Player.animateHurt` stores that float as `hurtDir`. In `hurtServer`, `dealDefaultKnockback` runs before the lethal `die(source)` branch (lines 1248-1259), so the hurt-animation packet is enqueued before the combat-kill and byte-3 packets for this ordinary unblocked-hit witness.

Concrete witness: victim position is the origin with yaw 0 and is not a spectator; the direct living attacker is at `(1, 0, 0)`; the non-blocked melee hit is lethal and its damage source has that attacker position. The old attacker delta is `(h=1, i=0)`, so `fastAtan2(0, 1)` yields exactly 0 and `damagedSwingDir` is 0. On 26.2 the damage-source position yields `(xd=1, zd=0)`, `Mth.atan2(0, 1)` yields exactly 0, and the received `hurtDir` is 0. With the same yaw and non-spectator state, both death-response expressions use angle 0; both lookup-table trig functions give cosine 1 and sine 0 there, producing `(-0.1F, 0.1F, -0.0F)`. This is a finite source-supported direction/state witness for a movement-only response keyed to the received byte 3 and its preceding hurt animation.

This witness does not generalize to arbitrary sources. The old path uses `DamageSource.getAttacker`; 26.2 uses a damage-source position or projectile knockback direction, and may not send a direction for blocked or `NO_KNOCKBACK` damage. Non-cardinal angles also involve different atan implementations and float rounding. Event 3 alone therefore does not determine the exact old angle for every death. No server emulation is supported.
