## Source trace and numeric behavior

`MouseHandler.onMove` (`MouseHandler.java:207–221`) accepts callback coordinates as doubles, seeds the prior coordinates on the first move, then adds `newX - priorX` and `newY - priorY` to the double accumulators while the window is active. No finite/range validation occurs in this method. `handleAccumulatedMovement` calls `turnPlayer` only while the mouse is grabbed and a player exists, then clears both accumulators (`MouseHandler.java:225–253`).

`turnPlayer` reads `Options.sensitivity()` as `OptionInstance<Double>` (`Options.java:101–107, 705`). The option is validated to `[0.0, 1.0]` by `OptionInstance.UnitDouble.validateValue` (`OptionInstance.java:417–422`). It computes `sensitivity * 0.6F + 0.2F` in a `double`: the `Double` option value makes Java widen the float literals to `double` operands, preserving the values represented by the float constants. It then computes the cube and multiplies by `8.0` (`MouseHandler.java:255–259`). Smooth-camera mode sends scaled deltas through the two `SmoothDouble` filters; first-person scoping uses the cube without the factor of eight; the ordinary branch uses the factor of eight. Inversion multiplies the pitch delta by integer `+1` or `-1`; the resulting arguments remain doubles when passed to `player.turn` (`MouseHandler.java:261–285`).

`Entity.turn(double, double)` casts the pitch delta to `float` and multiplies by `0.15F`, then does the same for yaw. It calls `setXRot(currentPitch + pitchDelta)`, calls `setYRot`, clamps the current pitch to `[-90.0F, 90.0F]`, adds both deltas to old pitch/yaw, and clamps old pitch (`Entity.java:401–412`). `setXRot` rejects non-finite floats and leaves the stored field untouched; otherwise it writes the field (`Entity.java:3359–3369`). `Mth.clamp(float, float, float)` returns the lower bound when below it, otherwise `Math.min(value, upper)` (`Mth.java:101–103`). The getter returns the stored current pitch directly (`Entity.java:3359–3361`).

Two finite-large witnesses have different outcomes. With default sensitivity `0.5`, the exact double turn scale from the float literals is approximately `1.00000008940697`. A finite accumulated `DY` of approximately `2453.33311398825` therefore reaches `Entity.turn` as approximately `2453.33333333333`; its float cast multiplied by `0.15F` is finite `368.0F`. Starting from current pitch `0.0F`, `setXRot` stores `368.0F` before the later clamp stores `90.0F`. This demonstrates a finite post-cast value above the clamp range, with no prior pitch clamp. Separately, at default sensitivity, an accumulated finite pitch delta of `1.0e39` remains finite through double scaling and reaches `Entity.turn` above `Float.MAX_VALUE`; the cast becomes infinity. `setXRot` rejects that non-finite sum, so current pitch remains its prior value and the following clamp re-reads that unchanged value. The old-pitch accumulator is separately updated and then clamped. The source path imposes no finite/range check on cursor coordinates before accumulation; these are exact finite-double callback paths and do not establish what coordinates a particular physical device can produce.

The live active-Elytra path is present in the frozen sources. `Player.tryToStartFallFlying` requires the player to be airborne, not already fall-flying, out of water, free of levitation, and wearing an enabled Elytra in the chest slot; it calls `startFallFlying`, which sets shared flag 7 (`Player.java:1529–1543`). `LivingEntity.updateFallFlying` runs during the travel tick, verifies that flag and the active Elytra again, then preserves or clears the fall-flying flag (`LivingEntity.java:2665–2679, 2716–2740`). The normal `LocalPlayer` inheritance chain is `LocalPlayer extends AbstractClientPlayer extends Player extends LivingEntity` (`LocalPlayer.java:92`, `AbstractClientPlayer.java:18`, `Player.java:114`). `LocalPlayer.isEffectiveAi()` returns true (`LocalPlayer.java:485–487`), so in this non-ridden local-player case `Entity.isControlledByLocalInstance()` returns true (`Entity.java:2915–2917, 2995–3001`), allowing the `LivingEntity.travel(Vec3)` branch to execute. In that branch, when fall-flying is active, it obtains `getLookAngle()` and explicitly computes `$$15 = getXRot() * (float)(Math.PI / 180.0)` before using cosine and sine of that pitch in the velocity calculation (`LivingEntity.java:2091–2094, 2151–2177`). This is a live player movement consumer, not a rendering-only read. The exact cited files are byte-identical across the pair.
