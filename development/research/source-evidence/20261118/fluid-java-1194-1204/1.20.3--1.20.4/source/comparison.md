## Ordered caller path and bounded slices

`LocalPlayer.tick()` calls `super.tick()` when its chunk is present (`LocalPlayer.java:188-207`); `LivingEntity.tick()` reaches `baseTick()` and then `aiStep()` (`LivingEntity.java:2269-2309`); `Entity.baseTick()` updates body fluid state/pushing, then eye-fluid state, then swimming, in that order (`Entity.java:403-439`). `LivingEntity.aiStep()` dispatches ordinary movement through `this.travel($$9)` when there is no controlling passenger (`LivingEntity.java:2592-2603`). `Player.travel()` delegates to `super.travel()` unless its non-passenger flight ability branch is active; `LocalPlayer` has no `travel` override (`Player.java:1451-1473`; `rg` of its source has no `travel` method).

1. **Body water/lava admission and height.** `Entity.updateInWaterStateAndDoFluidPushing()` clears `fluidHeight`, runs water state/current work first, then samples lava with strength `0.007` in ultra-warm dimensions or `0.0023333333333333335` otherwise, and returns `isInWater() || lavaPresent` (`Entity.java:1187-1193`). The non-riding water path calls `updateFluidHeightAndDoFluidPushing(WATER, 0.014)`; on admission it conditionally emits the transition splash, resets fall distance, sets `wasTouchingWater`, and clears fire; otherwise it clears `wasTouchingWater` (`Entity.java:1195-1209`). `isInWater()` reads that flag. Lava is reported only when `!firstTick` and stored lava height is positive (`Entity.java:1144-1145, 1291-1292`). Both versions have the same gates and write order.

2. **Current push and normalization.** `updateFluidHeightAndDoFluidPushing` first returns `false` for an entity touching an unloaded chunk, without storing a new height. Otherwise it deflates the box by `0.001`, scans floor-to-ceil integer bounds, admits matching fluid cells whose surface is at/above the deflated box minimum Y, and stores the maximum intersecting depth. If fluid pushes are enabled, each flow is scaled by the current maximum depth when that depth is below `0.4`, then accumulated and counted. A nonempty sum is averaged by count; it is normalized only for non-`Player` entities, scaled by the supplied strength, conditionally raised to minimum magnitude `0.0045000000000000005` when horizontal velocity is below `0.003` and the push is also below that minimum, and added to delta movement. Height storage and the returned any-fluid flag follow (`Entity.java:3037-3101`). A local player is a `Player`, so the deliberate no-normalization branch applies in both versions.

3. **Eye-fluid write order.** `updateFluidOnEyes()` writes `wasEyeInWater` from the *previously stored* `fluidOnEyes` set before clearing the set. It samples at `getEyeY() - 0.11111111F`; unless an out-of-water boat spans that Y, it looks up the containing block, computes block Y plus fluid height, and adds the sampled state's tags only if that surface is strictly greater than the sample Y (`Entity.java:1211-1222`). Both versions preserve the stale-read-before-clear order and float literal.

4. **First ordinary water/lava move and drag/gravity gates.** `LivingEntity.travel(Vec3)` first requires `isControlledByLocalInstance()`, initializes gravity to `0.08`, and changes it to `0.01` only for non-rising movement with Slow Falling. It gets the fluid at the block position. Water takes precedence when `isInWater() && isAffectedByFluids() && !canStandOnFluid(state)`; otherwise lava runs under the corresponding `isInLava()` condition (`LivingEntity.java:2035-2089`). Water uses sprint slowdown `0.9F` or `getWaterSlowDown()`, base acceleration `0.02F`, Depth Strider capped at `3.0F` and halved off-ground, the depth-strider interpolation, and Dolphin's Grace slowdown `0.96F`; it applies relative input and movement before multiplying X/Z by the water slowdown and Y by `0.8F`, then applies fluid-fall adjustment. Horizontal collision plus climbability changes the sampled Y velocity to `0.2`; a final horizontal-collision/free-space gate can replace Y with `0.3F`. Lava applies relative input at `0.02F`, moves, then uses `(0.5, 0.8F, 0.5)` and fluid-fall adjustment when lava height is at/below the eye-height-dependent jump threshold, or `scale(0.5)` above it. It subtracts one quarter gravity only when `!isNoGravity()`, then has a separate horizontal-collision/free-space `0.3F` lift gate. Every listed condition, operation order, literal, and write is byte-identical in the pair.

## Verdict and residuals

No positive difference was found in this bounded comparison; no canonical finding is warranted. Effective water/lava tag membership and world/fluid queries are held equal by scope, rather than investigated as changed inputs. Relevant applicability gates retained in the comparison are the loaded-chunk check; `firstTick` for lava; local-instance control; non-rising Slow Falling; current fluid state and `canStandOnFluid`; fluid-affecting eligibility; water-before-lava branch order; sprint, Depth Strider, ground state, Dolphin's Grace, climbability, horizontal collision/free-space checks, lava height versus jump threshold, and no-gravity. `Player.travel` adds a swimming upward-motion prelude when swimming and non-riding; its flying branch is excluded here. Riding, creative flight, Elytra, external callbacks, tag/resource changes, intermediate patch releases, full-pair tick coverage, runtime behavior and packaged resources remain outside this assignment.
