## Paired source conclusion: no 1.16.4→1.16.5 delta found

The entire relevant source files are byte-identical, so there is no changed admission gate, clipping order, score, reclip, support bookkeeping, or edge-probe rule in this pair.

- `Entity.move` (`Entity.java:485–535`): after no-physics and piston special cases, applies stuck multiplier if its squared length exceeds `1.0E-7`, then calls `maybeBackOffFromEdge`, then `collide`. It moves the bounding box only for a result whose squared length exceeds `1.0E-7`. Horizontal-collision flags compare the edge-adjusted request and clipped result using `Mth.equal`; vertical collision uses exact `!=`. `onGround` is set to `verticalCollision && vec3.y < 0.0`. It obtains `getOnPos()`/state and calls fall bookkeeping. A vertical clipped component invokes `updateEntityAfterFallOn`; `stepOn` runs only when grounded and not stepping carefully.
- `Entity.collide` (`Entity.java:668–710`): constructs an entity collision context and world-border shape, combines entity collisions with the border for initial clipping, and obtains the direct clipped vector. Step-up is admitted only when `maxUpStep > 0`, the entity was already grounded or downward motion was clipped, and at least one horizontal component collided. It compares horizontal squared distances. Candidate A clips `(x,maxUpStep,z)` from the current box. Candidate B first clips a vertical `maxUpStep` against the box expanded horizontally, then clips `(x,0,z)` from that raised box and adds the actual rise. B replaces A only on strictly greater horizontal distance. A step candidate is accepted only when its horizontal squared distance is strictly greater than direct clipping; after acceptance it reclips vertically by `-stepY + requestedY` from the moved candidate box and adds that result. This ordering and strict tie behavior are unchanged.
- `collideBoundingBoxHeuristically` (`Entity.java:713–727`) dispatches to legacy axis clipping when at least two requested axes are nonzero; that branch appends block collisions queried from the swept expanded box and clips Y first, then the smaller-magnitude horizontal axis first (Z first on equal magnitudes), then X, then remaining Z as applicable. Otherwise it uses the LevelReader-aware `Shapes.collide` route. `collideBoundingBoxLegacy` and the LevelReader-aware counterpart have the same axis order. The heuristic's extra block-collision stream is the same in both versions.
- Ground/fall support (`Entity.java:508–535, 894–905`): grounded is a result of downward requested motion being vertically clipped, not a standalone support-shape query. When grounded with positive accumulated fall distance, `checkFallDamage` calls the current underfoot block's `fallOn`, then clears fall distance; if not grounded and actual clipped Y is negative, it adds `-actualY` to the float fall distance. `getOnPos` uses floor(x), floor(y - 0.2F), floor(z), with only the air/fence-wall-fence-gate fallback. This is unchanged.
- Sneak edge backoff (`Player.java:287, 1010–1064`): only when not flying, movement type is SELF or PLAYER, shift-ground behavior is active, and `isAboveGround()` passes. It probes X, then Z, then the combined X/Z offset, each at `-maxUpStep`, using `noCollision`; while unsupported it reduces that component in increments of `0.05`, zeroing values in the inclusive interval `[-0.05,0.05]`. Y request is preserved. `isAboveGround` is true if grounded, or if `fallDistance < maxUpStep` and the box moved down by `fallDistance-maxUpStep` collides. This is unchanged. `isSteppingCarefully` is shift state (`Entity.java:1813`), so a crouching grounded player skips `stepOn` too.
- World shape dispatch (`CollisionGetter.java`, `CollisionSpliterator.java`, `BlockState.java`, `BlockBehaviour.java`): collision enumeration scans candidate block coordinates, loads the relevant collision chunk, applies the spliterator filters, and calls `BlockState.getCollisionShape(world, pos, context)`. That delegates to the block's collision-shape provider; the default `BlockBehaviour` provider returns empty for `!hasCollision`, otherwise delegates to the state's shape. The spliterator moves non-unit shapes into world coordinates and tests overlap; the full-cube sentinel uses a box-intersection shortcut. Sneak support probes use `noCollision`, which checks the resulting block and entity collision streams for any nonempty shape. Dispatch and generic shape math are byte-identical.

## Limits

This closes the generic caller and provider-dispatch slice only. It does not census each block family or prove every world-provided shape result. An unchanged caller plus unchanged dispatch establishes that equal state, position, collision context, loaded collision chunks, and provider implementation feed the same generic path; it does not establish equal output for unexamined/different provider code, a different world/chunk/state input, or external modifications. No source difference or separate implementation finding is warranted in this bounded slice. No test/build/game launch was performed.
