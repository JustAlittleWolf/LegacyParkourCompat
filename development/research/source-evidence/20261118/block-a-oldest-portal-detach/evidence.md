# Older-profile portal-dismount-placement applicability gate

## Scope and verdict

Read-only trace of ordinary client inbound vehicle detach in exact Ornithe Feather sources for 1.8.9, 1.9, and 1.12.2. This closes only the older-profile applicability gate for portal-dismount-placement.

**Verdict:** The checked client detach receiver routes in 1.8.9, 1.9, and 1.12.2 do not directly write local-player XYZ or AABB. 1.8.9 has a base `Entity.startRiding(null)` method that positions an entity at the old vehicle, but that code is not reached for the actual local-player detach: virtual dispatch selects `LivingEntity.startRiding(null)`, whose client path clears mount links and returns without calling the base method. Its only `dismountRider` call is gated to non-client worlds. In 1.9 and 1.12.2, empty passenger lists detach through `yeetPassengers -> stopRiding -> removePassenger`, which only clears mount/passenger references and boarding cooldown.

No portal check/predicate occurs in the examined local receive/detach paths. The 1.8.9 server-only `LivingEntity.dismountRider` performs its own placement search, but is excluded here by `!world.isClient`. An independently supplied player correction can write position; it is a separate packet route and is not caused by detach inputs.

## Exact source trace

- **1.8.9 receiver:** `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java:735-762`, `handleAttachEntity`. For `packet.getType() == 0`, it substitutes `minecraft.player` when packet entity ID matches the local player's network ID, returns only if that entity is absent, then invokes `entity.startRiding(entity2)`. `entity2` is resolved from attached ID. The local player inheritance chain is `LocalClientPlayerEntity -> ClientPlayerEntity -> PlayerEntity -> LivingEntity` (`LocalClientPlayerEntity.java:53`, `ClientPlayerEntity.java:20`, `PlayerEntity.java:79`). Therefore the call dispatches to `LivingEntity.startRiding`.
- **1.8.9 packet fields:** `net/minecraft/network/packet/s2c/play/AttachEntityS2CPacket.java:9-52`. Constructor and serialization carry type, entity ID and attached entity ID only; the constructor represents a null attached entity as `-1`. No position/AABB is supplied.
- **1.8.9 actual client detach:** `net/minecraft/entity/living/LivingEntity.java:1483-1495`, `startRiding`. With an existing vehicle and null target it calls `dismountRider` only if `!world.isClient`; then clears the prior vehicle's rider reference and `this.vehicle`, and returns. There is no `super.startRiding` call in this branch. If there is no prior vehicle, it delegates to `Entity.startRiding(null)`, whose null branch has no vehicle and performs no placement.
- **1.8.9 non-reachable base placement:** `net/minecraft/entity/Entity.java:1343-1368`, `startRiding`, contains `setPositionAndAngles(vehicle.x, vehicle.getShape().minY + vehicle.height, vehicle.z, yaw, pitch)` for a null target with a current vehicle. This is the tempting direct writer, but virtual dispatch above proves it is not reached for the packet's local-player detach. If called, `setPositionAndAngles` at `Entity.java:899-906` writes current/previous XYZ then calls `setPosition`; `setPosition` at `:226-234` writes XYZ and rebuilds the entity shape/AABB.
- **1.9 receiver:** `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java:787-810`, `handleEntityPassengers`. For a known mount entity it calls `entity.yeetPassengers()` and remounts only IDs present in the packet. An empty passenger list detaches. The separate `handleAttachEntity` at `:813-824` only handles leash attachment for mobs.
- **1.9 detach callees:** `net/minecraft/entity/Entity.java:1477-1510`, `yeetPassengers`, `stopRiding`, and `removePassenger`. These update mount/passenger links and cooldown; no position, box or movement method is called in this chain.
- **1.12.2 receiver:** `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java:833-856`, `handleEntityPassengers`; empty list follows the same clear-then-remount flow. `handleAttachEntity` at `:857-868` handles mob leash only.
- **1.12.2 detach callees:** `net/minecraft/entity/Entity.java:1642-1675`, `yeetPassengers`, `stopRiding`, and `removePassenger`; same bounded exclusion of direct position/AABB writes.

### Separate correction and placement paths

In 1.8.9, `PlayerMoveS2CPacket` carries XYZ, yaw, pitch and relative flags (`net/minecraft/network/packet/s2c/play/PlayerMoveS2CPacket.java:10-52`). Its separate receiver `ClientPlayNetworkHandler.handlePlayerMove` (`:517-552`) resolves relative coordinates against current player state and calls `playerEntity.updatePositionAndAngles`. That is an independently supplied authoritative correction. It does not establish a direct detach write: the `AttachEntityS2CPacket` payload has no coordinates and its client detach override does not reach the base placement method. Ride-tick vehicle placement (`Entity.updateRiderPositon`, `net/minecraft/entity/Entity.java:1330-1334`) is another separate call site and is not the detach receiver path. Local input and connection lifecycle were not used to reach the finding.
