# Frozen source coverage: fluid-tag gate at `isInWater`

Status: terminal bounded source comparison, no source difference found in the assigned predicate path. Frozen 2026-11-18. Scope is exactly 1.15.1 → 1.15.2 Mojmap, the shipped `water`/`lava` fluid tag resources, and the `Entity.isInWater` dependency consumed by `Player.tryToStartFallFlying`.

## Claim and disposition

Both exact clients ship byte-identical `data/minecraft/tags/fluids/water.json` and `lava.json`. The water-tag membership dependency is live and unchanged in this path: `Entity.isInWater()` returns the `wasInWater` flag; the normal entity base tick refresh calls `updateWaterState()` → `updateInWaterState()` → `checkAndHandleWater(FluidTags.WATER)`. The scan tests intersecting `FluidState`s against the current tag, then `updateInWaterState` assigns the flag. `Player.tryToStartFallFlying()` uses `!this.isInWater()` as an outer eligibility condition before its Elytra check. All compared bodies on this path match between endpoints. Therefore identical default bytes do **not** remove the data dependency; they leave an unchanged, live dependency on water tag membership at the glide-start predicate.

For the shipped default alone, water membership is exactly `minecraft:water` and `minecraft:flowing_water`. Neither shipped list contains `#` tag references, so their default closure is those direct entries. This is not a claim about a particular loaded data-pack stack or remote server: `TagCollection.prepare` reads resource-manager entries, `Tag.Builder.addFromJson` clears accumulated entries only when an entry has `replace: true`, and the client applies received fluid tags for non-memory connections. Actual datapack or received memberships are consequently conditional and were not available as runtime inputs.

The shipped lava resource is likewise byte-identical and contains direct `minecraft:lava` and `minecraft:flowing_lava` values. LAVA has no membership role in this bounded predicate: the refresh call specifically passes `FluidTags.WATER`, and the predicate reads the resulting `wasInWater`. No LAVA membership was used to classify `isInWater` here.
