# Eye-fluid tag membership
1.18.1, Mojmap: `decompiled_minecraft/1.18.1/mojmap/net/minecraft/world/entity/Entity.java`, `updateFluidOnEyes` (1061-1080) stores the first matching member of `FluidTags.getStaticTags()` in one `Tag<Fluid>` field; `isEyeInFluid` (1140-1142) compares the stored tag by identity. At each base tick it snapshots previous water membership before clearing and resampling.
1.18.2, Mojmap: `decompiled_minecraft/1.18.2/mojmap/net/minecraft/world/entity/Entity.java`, `updateFluidOnEyes` (1071-1083) clears a set, checks the same eye position and surface-height gate, then stores every tag supplied by the sampled `FluidState`; `isEyeInFluid` (1143-1145) checks set membership. Previous-water sampling still precedes clearing/resampling. `FluidState` tag membership therefore comes from runtime tag data.
Difference: current eye state changes from first-match static-tag selection to membership in all tags attached to the fluid state. For vanilla water/lava membership, this source change alone establishes no different player result. If external custom/dynamic fluid data places one state in multiple relevant tags, current water/lava queries can now report those tags even when the older static-tag loop would have retained a different first match; the previous-water snapshot follows that changed current query on the next tick.
Movement meaning: player predicates that consume eye-water state, including underwater/swimming decisions, may differ only under the external overlapping-tag condition. Runtime tag declarations were not included in the decompiled source review; do not treat this as unconditional vanilla movement difference.
