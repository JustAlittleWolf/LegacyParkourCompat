The preceding push therefore does not move the player.

The WEST branch at `MovingBlock.java` 175–179 computes `minX = 0 - (-1 * 1) = 1`, leaving `maxX = 1`: the Stone candidate is `[1,1]` on X. The negative-X swept query crosses X=1. `World.java` 891–922 uses `floor(shape.minX)` as its lower X bound and an exclusive `o < floor(shape.maxX + 1.0)` upper bound; because the swept minimum is below 1 and its maximum is above 1, it visits cell X=0 (and the stated Z/Y extent visits cell `(0,0,0)`). `Block.java` 339–344 adds a candidate on `shape.intersects(candidate)` without a nonzero-width test; `Box.java` 153–158 accepts this plane strictly inside the swept positive-volume box.

For `Box.intersectY` 113–130 the strict horizontal overlap test fails at `player.minX == candidate.maxX == 1`, so the airborne negative `dy` is unchanged. `Entity.move`'s step gate at 447/460 is false (`onGround == false` and requested `dy` was not clipped). `Box.intersectX` 93–108 then takes its negative-limit branch (`box.minX >= this.maxX`, `1 >= 1`) and replaces negative `dx` with the zero gap.
