# Mixed full-cube / top-slab AutoJump candidate ordering

## Verdict and boundary

For the bounded 1.14 → 1.14.1 AutoJump query, the accepted ordering/timing claim extends to a mixed dry full-cube stone plus dry top stone slab provider set. In 1.14, an intersecting partial slab is yielded before the query's aggregate full-cube shape. In 1.14.1, each intersecting block shape is yielded in block-cell iteration order, so a lower-coordinate stone can win first. AutoJump breaks after the first intersecting candidate, and its subsequent one-block headroom/rise checks can change whether it arms the next-auto-jump counter.

This is source-path evidence only. No game/TAS launch or runtime parity was checked. The generic 1.13.1/.2 WorldView partial-before-full route is checked separately below; this is not a claim about original 1.13 slab/frame aggregation. It does not generalize to other partial shapes, liquids, or border/entity collisions.

## Source trace

- 1.14 `LocalClientPlayerEntity.autoJump`, lines 858–951, gates on AutoJump enabled, cooldown `<= 0`, on-ground, not sneaking/riding, nonzero movement input, a nontrivial movement vector (with input-derived fallback), and facing dot product not below `-0.15`. It checks collision-shape emptiness in the player's current head cell and the cell above before querying candidates. The candidate query is `getCollisions(this, box, Collections.emptySet()).flatMap(shape -> shape.getBoundingBoxes().stream())` (912–916). It tests the two lateral probe segments and breaks at the first intersecting box (918–945). For the candidate center it checks `t = 1; t < o` with base `o = 1.2`; a nonempty shape there replaces `s` with that shape's top, and returns if rise exceeds `o` (925–937). Finally it arms `ticksToNextAutojump = 1` only for rise `> 0.5` and `<= o` (949–951).
- 1.14 `WorldView.getCollisions`, lines 127–194, visits block cells and maps full-block collision shapes into a shared `VoxelSet`; non-full shapes are returned at their cell position (176–190). The returned stream concatenates the encountered per-cell shapes before a generated `IntVoxelShape` for the full-cube aggregate (194). The player's flattening step therefore sees the intersecting top slab before the aggregate stone boxes, regardless of the full stone cell's earlier coordinates.
- 1.14 `SlabBlock`, lines 28 and 46–53, returns `TOP_SHAPE = Block.block(0, 8, 0, 16, 16, 16)` for a top slab. `Block.getCollisionShape` delegates to the state's shape (365–366), so dry top stone slab is a non-full, individually yielded collision shape. Ordinary stone inherits the full-block shape (`Block.getShape`, line 360; collision delegation at 365–366), which is accumulated by the query.
- 1.14.1 `ClientPlayerEntity.method_3148` (AutoJump), lines 847–940, retains the relevant gates, probe checks, first-intersection `break`, the one-cell headroom/rise check and final `> 0.5F && <= 1.2F` arming condition. The corresponding collision call is `getCollisionShapes(this, box, Collections.emptySet())` (901–904).
- 1.14.1 `ViewableWorld.getCollisionShapes(Entity, BoundingBox, Set)`, lines 129–193, uses `CuboidBlockIterator` and emits each qualifying block's offset collision shape immediately when it overlaps the query (172–186); there is no full-block aggregation in this block-cell stream. `CuboidBlockIterator.step`, lines 24–53, increments X first, then resets X and increments Y, then resets X/Y and increments Z. ## Fixed historical eligibility and floor-clipped entry

In both exact target sources, the local player calls the base `Entity.move` and then passes the actual X/Z position differences, cast to `float`, into AutoJump: 1.14 `LocalClientPlayerEntity.move` lines 847–851 and 1.14.1 `ClientPlayerEntity.move` lines 835–839. Base `Entity.move` first resolves collision-clipped motion, then sets `onGround` iff vertical motion was clipped and the requested Y component was negative (1.14 lines 433–463; 1.14.1 lines 432–462). The motion resolver clips Y against collision shapes before X/Z (1.14 `m_73670363`, lines 689–696; 1.14.1 `method_17833`, lines 688–695). Thus from feet Y=8.1 a requested dy=-0.2 clips at the support-stone top Y=8 to approximately -0.1, making `onGround` true; with a collision-free requested dx=0.1, the actual horizontal difference remains approximately 0.1 and AutoJump receives its float cast. This is a grounded first move, not an assumed preexisting `onGround` flag.
