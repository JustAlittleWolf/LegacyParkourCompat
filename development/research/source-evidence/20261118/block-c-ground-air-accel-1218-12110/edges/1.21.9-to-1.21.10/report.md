## Reachable path and source comparison

- **Input to the local player:** `KeyboardInput.tick()` forms forward/side impulses and calls `new Vec2(side, forward).normalized()` (both releases: `client/player/KeyboardInput.java:23–36`; `world/phys/Vec2.java:48–51`). `Vec2.normalized()` computes a float square root and returns zero below `1.0E-4F`. `LocalPlayer.applyInput()`'s controlled-camera branch assigns `xxa` and `zza` from `modifyInput(input.getMoveVector())` (`client/player/LocalPlayer.java:612–625`). `modifyInput` returns a zero vector unchanged; otherwise it scales by `0.98F`, then by `0.2F` while using an item and not a passenger, then by the sneaking-speed attribute when moving slowly. The square-movement step normalizes the vector, computes `sqrt(1 + ratio²)` from absolute components, caps the adjusted length with `Math.min(length * distance, 1.0F)`, and rescales (`LocalPlayer.java:627–662`). All these files have identical hashes across the pair.
- **Local-player tick to travel:** `LivingEntity.tick()` applies input before constructing `new Vec3(xxa, yya, zza)` and dispatches `travel` when `canSimulateMovement() && isEffectiveAi()` (`world/entity/LivingEntity.java:2542` and `2845–2849`). `Player` returns true for both predicates on the logical client only for its local player (`world/entity/player/Player.java:1186–1193`). For the assigned non-passenger, dry, non-swimming, non-flying case, `Player.travel()` reaches `super.travel(input)` without a swimming vertical adjustment or ability-flying vertical-velocity replacement (`Player.java:1295–1320`). `LivingEntity.travel()` chooses `travelInAir` when neither affected by water/lava nor fall-flying (`LivingEntity.java:2275–2282`). These files are byte-for-byte identical across the pair.
- **Ground and air acceleration/friction:** `travelInAir` chooses block friction `μ` on ground and `1.0F` in air; horizontal post-move friction is `μ * 0.91F` (`LivingEntity.java:2306–2328`). `handleRelativeFrictionAndCalculateMovement` calls `moveRelative(getFrictionInfluencedSpeed(μ), input)`, handles climbing, moves, and returns the resulting movement (`2476–2486`). The acceleration input is `getSpeed() * (0.21600002F / (μ * μ * μ))` on ground and `getFlyingSpeed()` in air (`2520–2525`). For a non-flying, non-passenger `Player`, the override returns `0.02F`, or `0.025999999F` when the existing sprint state is true (`Player.java:1867–1873`); on-ground `getSpeed()` is the movement-speed attribute (`Player.java:1339–1341`). The per-tick sprint lifecycle is outside this assignment. The `LivingEntity` and `Player` source files are identical across releases.
- **Ground-friction block lookup/value:** The position helper returns `getOnPos(0.500001F)` in both releases (`world/entity/Entity.java:935–937` in 1.21.9; `938–940` in 1.21.10); the helper body is identical. `Block.getFriction()` returns the stored friction (`world/level/block/Block.java:457–459`), and `Blocks.java` is byte-for-byte identical, so the vanilla block friction assignments are unchanged. Although `BlockBehaviour.java` differs as a whole, the default `.6F`, constructor assignment, property-copy assignment, and `friction(float)` setter are unchanged (`BlockBehaviour.java:95, 111, 965, 1030, 1076` in both sources).
- **Yaw-to-velocity dependency:** `Entity.moveRelative()` obtains a vector from `getInputVector(input, speed, getYRot())` and adds it to delta movement (`world/entity/Entity.java:1585–1600` in 1.21.9; `1590–1605` in 1.21.10). Both method bodies match: squared input length below `1.0E-7` returns zero; length above `1.0` normalizes before scaling; then float `Mth.sin`/`Mth.cos` of yaw in degrees rotate the horizontal components as `x*cos - z*sin` and `z*cos + x*sin`. `Mth.java`, `Vec2.java`, and `Vec3.java` have identical hashes across the pair. The input/yaw transform is therefore an unchanged direct dependency of the local player's resulting horizontal velocity.
