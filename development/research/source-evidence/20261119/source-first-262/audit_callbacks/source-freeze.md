## Frozen verdicts

1. **Sweet berry bush. No bounded direct-response difference.** The living-entity contact condition still excludes bees and foxes. Contact writes `new Vec3(0.8F, 0.75, 0.8F)`, and the player flying gate, fall-distance reset, multiplier assignment and impulse-context reset are unchanged. The movement consumer retains its `lengthSqr() > 1.0E-7` gate, skips multiplier application for pistons, then clears the multiplier and velocity. The block callback's server-only damage and bonemeal eligibility do not establish a direct player movement difference. Evidence: `SweetBerryBushBlock.java:82–100` both, `Player.java:1494–1500 → 1515–1521`, `Entity.java:712–728, 2876–2879 → 719–735, 2943–2946`, `Blocks.java:5582–5593 → 4612–4623`.
2. **Honey block. No bounded slide or honey-specific landing difference.** The shape, speed and jump factors, off-ground and side-overlap gates, `0.98F` conversion and `-0.08`/ `-0.13` thresholds, horizontal reduction, new Y and fall-distance reset match. Landing dispatch into `fallOn` still calls the honey sound/event/damage path. The achievement cast-to-pattern rewrite is server-only. Central collision velocity treatment changed. In 26.1.2 the inherited `Block.updateEntityMovementAfterFallOn` multiplies Y by zero, while 26.2 runs collision restitution with honey's default zero block restitution and can differ in signed zero and in combinations with entity restitution or the new collision gate. The honey-only verdict applies to honey's own contact and registered inputs. Evidence: `HoneyBlock.java:25–124` both, `Blocks.java:5928–5932 → 4963–4967`, `Entity.java:772–790, 1469–1485 → 780–790, 802–849, 1556–1572`, `Block.java:498–500 → 494–496` and 26.2 `BlockBehaviour.java:96–113,995`.
3. **Bubble columns. No bounded direct-response difference.** Identical block callback, precision gate and above-state test (including the original position supplied to the above state's collision shape), direction property, player flying gate, surface and submerged clamp math, and submerged fall reset. The two response branches preserve X/Z. Shared swept callback dispatch and per-contact precision selection matched in the inspected ranges. Evidence: `BubbleColumnBlock.java:53–71` both, `Player.java:309–321 → 310–322`, `Entity.java:839–919, 1195–1293, 2782–2829 → 903–983, 1278–1376, 2849–2896`. This does not decide every neighboring block shape or fluid state.
4. **Piston push. No bounded piston-specific response difference.** Same ticker class retention, progressing collision displacement, slime velocity axis update for the local player, retract correction, honey carry, thread-local collision exclusion and immediate swept effects after `MoverType.PISTON`. Same per-axis, per-game-time cap `[-0.51, 0.51]`, tiny-magnitude thresholds and local move delegation. General collision solver/restitution results can differ independently. Evidence: `MovingPistonBlock.java:69–71 → 70–72`, `PistonMovingBlockEntity.java:120–273, 310–341` both, `LocalPlayer.java:986–993` both, `Entity.java:704–801, 839–919, 1037–1068 → 711–798, 903–983, 1101–1132`.
5. **Shulker box lid. No bounded lid-specific push difference.** Same ticker path, opening-only displacement, push-reaction gate, extent plus `0.01`, and `MoverType.SHULKER_BOX`. The old `BlockPos.getBottomCenter` calls the same `Vec3.atBottomCenterOf` helper directly called in 26.2. The shared progress-slice AABB construction is unchanged. If “shulker lid” also refers to the mob lid, the same peek push math, explicit player query and client dispatch are present, and the collision shape still uses the shulker's `makeBoundingBox` override. 26.2 refreshes mob dimensions immediately before the query. Its position-fudge gate requires a logical server, so this is not a separately confirmed direct client player push change. Excludes server position and downstream shared collision results. Evidence: `ShulkerBoxBlock.java:69–71 → 71–73`, `ShulkerBoxBlockEntity.java:62–132` both, 26.1.2 `BlockPos.java:131–133`, `Vec3.java:57–59` both, `Shulker.java:173–183, 202–209, 228–265 → 173–183, 202–221, 239–277`, `Entity.java:3320–3336 → 3393–3409`.
6. **Fluid jump selection and direct input response. No reachable bounded difference.** The inner lava decision changes from cached `!(fluidHeight > threshold)` to a re-read through `isInShallowFluid` with `<=`. On the local-player branch lava is already selected when needed, the tracked finite lava height and eye-height-derived threshold remain stable across these reads, and the signed input action remains `+0.04F` for a liquid jump or `-0.04F` when descending in water. NaN would distinguish the comparison in isolation. It is absent from the vanilla finite inputs in the audited path. Ground jump action and subsequent travel enter other bounded operations, including generic collision results. Evidence: `LivingEntity.java:2366–2372, 3031–3056 → 2403–2409, 2545–2547, 3098–3123`, `LocalPlayer.java:859–861` both, `Player.java:875–877` both, `Entity.java:3610–3616 → 3683–3689`, `EntityFluidInteraction.java:57–72, 139–146` both, `FluidState.java:49–50` and `FlowingFluid.java:471–472` both.

Shared context inspected: movement/contact order from the player tick to the block sweep and explicit mover callbacks, the direct movement writes or delegated pushes, and the relevant vanilla inputs for these claims. The generic collision restitution rewrite is a dependency of composition, not part of these callback identity verdicts. This review does not certify full-pair coverage, runtime parity, intermediate patches, every vanilla fluid or shape path, or historical implementation.
