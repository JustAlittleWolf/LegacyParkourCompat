# Independent paired collision-provider audit

I reached the following per-provider conclusions from the canonical exact 26.1.2 and 26.2 unobfuscated decompiled sources before opening any lane report. The SHA-256 source manifests match their ready markers: 26.1.2 54ae320660ca911a6d20514c965c33eb414fbedd1ad6727bbaa95fe906aa23c0 and 26.2 a7ad74fc712567eb87136afc1eafcfd602b4088e9869f3596331fd34faefe894. Provider, Blocks, Entity, Player, contexts and BlockCollisions file hashes checked against these manifests.

Both endpoints retain the ordinary entity path from Entity.collide, including candidate step-height collection, through CollisionGetter.getBlockCollisions, CollisionContext.of(entity), BlockCollisions, and BlockStateBase.getCollisionShape(level,pos,context). Context values use entity bottom, descending, main hand, fluid handling and exact isAbove epsilon (float 1.0E-5F). EntityCollisionContext and BlockCollisions are byte-identical. The 26.2 explicit-context overload is reached for particle movement, and position contexts also go to PotentSulfurBlockEntity. Those scopes do not replace the player's context. CollisionGetter.withPosition(as used by its old-position overload) retains its existing placement flag and position in both endpoints. Collision solver, world-border wrapper, callback or map-state production changes are separate from provider output.

- Scaffolding: no provider delta. The complete ScaffoldingBlock is byte-identical. Placement returns empty, above the unit cube and not descending returns SHAPE_STABLE, otherwise nonzero DISTANCE plus BOTTOM and above SHAPE_BELOW_BLOCK returns SHAPE_UNSTABLE_BOTTOM, else empty. Registration retains dynamicShape and noCollision; the override still supplies geometry. Held scaffolding is a getShape outline branch rather than a movement-collision condition.
- Pointed dripstone: no provider geometry delta. 26.2 PointedDripstoneBlock inherits the old shape table from SpeleothemBlock: TIP_MERGE 6×16, TIP 6 pixels wide 0–11 upward and 5–16 downward, FRUSTUM 8×16, MIDDLE 10×16 and BASE 12×16. Shape translates by state.getOffset(pos); both full-block overrides return false and horizontal max offset is the base minimum X. Both have XZ offsets and dynamic shape. BlockStateProperties uses the same serialized thickness values despite the enum family rename. New speleothem siblings and world-level generation/placement are separate scope.
- Powder snow: no provider delta. Placement or absent entity gives empty. Living player fallDistance > 2.5 gives the reduced falling shape prior to boots evaluation. Otherwise player needs powder-snow walkability, above full block, and not descending to get the full default shape, with leather boots preserved. Non-player falling blocks have a separate gate. Dynamic registration and entity-inside shape's empty-to-full fallback are unchanged. Player collision can differ because of a caller's inputs after another movement delta, which does not change the provider conditional.
- Turtle egg: no provider delta. Same EGGS=1/multiple geometry and registration. The class's type-registry rewrite is in hatch spawning, separate from shape.
- Chest: no provider geometry delta. ChestBlock's default collision delegates to its 14×14 single footprint with height 14, or connected half selected by TYPE and FACING. Trapped and weathering/waxed copper variants inherit this implementation. Ender chest has its own fixed geometry. The copper registration collection retains all weathering and waxed variants. Copper placement mapping may construct a different vanilla block ID, distinct from collision per received state.
- Hopper: no provider geometry delta. Registered HopperBlock retains the directional collision shape table and inherited default collision. Interaction shape is separate. Item-transfer callbacks and block-entity registry are separate scope.
