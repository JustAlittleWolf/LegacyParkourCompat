**Verdict:** No independent player bubble-column callback difference. The direct dispatch, flight gate, vertical velocity formula, write order and fall-distance behavior match.

- `client/player/LocalPlayer.java` 378–380 and 914 in both passes through `AbstractClientPlayer.java` 76–79 and `world/entity/player/Player.java` 442–453 to `LivingEntity.aiStep`. The intervening `Avatar` inherits from `LivingEntity`. Client authority is through `Entity.java` 3516–3522 / 3589–3595 and `Player.java` 1260–1262 / 1281–1283. `LivingEntity.java` 3070–3078 / 3137–3145 applies block effects after travel and gates the client path on local authority.
- `Entity.java` 839–850 and 885–897 / 903–914 and 949–961 gathers actual movement segments and calls the inside scan after grounded step-on. The scan 1195–1282 / 1278–1365 checks each encountered block, requires block overlap and an unvisited position, and computes precision as a long segment or target box overlap. `world/level/block/state/BlockBehaviour.java` 774–778 / 780–784 delegates to the block; its default full inside shape (337–339 / 331–333) is separate from ordinary collision. Bubble column registration has no ordinary collision in `world/level/block/Blocks.java` 5359–5370 / 4377–4388. The block provides water fluid state at `BubbleColumnBlock.java` 78–80 in both.
- `world/level/block/BubbleColumnBlock.java` 53–69 is byte-identical and only dispatches when precise. It reads the state at `pos.above()`; the contextless collision shape query passes the column's own `pos`. Both the queried collision shape and the above state's fluid must be empty for `onAboveBubbleColumn`; otherwise the callback is `onInsideBubbleColumn`. The two-argument shape wrapper uses a cached shape when present and otherwise an empty collision context in `BlockBehaviour.java` 680–686 / 686–692. Both callbacks receive the column state's `DRAG_DOWN`.
- `Player.java` 309–320 / 310–321 forwards both callbacks only while abilities flight is off. `Entity.java` 2782–2797 / 2849–2864 sets Y to `Math.max(-0.9, y - 0.03)` for downward drag and `Math.min(1.8, y + 0.1)` for upward thrust, retaining X and Z. The particle helper only runs for server level, with no client velocity consequence. `Entity.java` 2814–2829 / 2881–2896 handles inside with `Math.max(-0.3, y - 0.03)` or `Math.min(0.7, y + 0.06)` and resets fall distance after the write.
- An unobstructed column mouth intersected by a non-flying local player reaches the surface path in both releases. A solid ceiling immediately above or a fluid state above routes the precise contact to the inside formula. Neither callback gates on the player's grounded or vertical-collision state.

**Floor and ceiling dependency:** The retained formulas operate on the velocity they receive after travel. In 26.1.2 `Entity.move` chooses the legacy effect block near/below the player and calls its `updateEntityMovementAfterFallOn` for either vertical collision direction when simulating movement (767–785). The default scales Y by zero (`world/level/block/Block.java` 498–500), with the old slime override inspecting negative velocity (`SlimeBlock.java` 33–47). In 26.2 restitution instead uses effective entity bounciness (from the living attribute at `LivingEntity.java` 2201–2204, subject to bounce suppression), with the effect block's restitution, minimum speed and suppressing block tag applied only for a floor hit (`Entity.java` 775–786, 802–851). Thus collision and travel changes can alter the input Y or contact path before the callback. Collision restitution and arbitrary ceiling shape changes belong to their own slices. This review covers the direct callback and its reachability, with no runtime check.
