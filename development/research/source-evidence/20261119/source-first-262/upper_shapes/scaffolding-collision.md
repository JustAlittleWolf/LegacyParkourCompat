# Player collision shape selection for scaffolding, 26.1.2 to 26.2

## Bounded source verdict

Continuity for ordinary player collision shape selection when both versions receive the same vanilla scaffolding state, local player position and shift input. Direct selection, swept movement, step-up, support, ledge safety, pose probes, suffocation and auto-jump shape contexts were checked. No independent historical scaffolding collision-shape finding for this pair. Full player trajectories depend on surrounding movement operations.

## Ordered selection and movement path

1. At the trigger, `LocalPlayer.move` delegates to its superclass, with auto-jump updated after the move in both versions (`client/player/LocalPlayer.java:986–994`). Ordinary ground/air travel reaches the move via `world/entity/LivingEntity.java:2623–2636 / 2676–2689`. `Entity.move` handles no-physics, piston adjustment and stuck-speed inputs, applies edge safety, then calls `collide` (`world/entity/Entity.java:704–749 / 711–756`). Swept AABB queries use the player as the entity argument, and the optional step retry still uses that same entity even when the retry AABB has moved vertically (`Entity.java:1077–1159 / 1141–1230`). Thus shape selection samples current entity Y, independent of any shift to the query AABB.

2. Both movement sweep collectors use `level.getBlockCollisions(source, boundingBox)` after entity and conditional world-border shapes. In 26.2 the entity collector has an “IgnoringWorldBorder” name but retains the world-border code. `world/level/CollisionGetter.java:84–106` creates `CollisionContext.of(source)` for a non-null player; it retains the same `new BlockCollisions(... false, ...)` after the helper becomes a default method in 26.2. `world/level/BlockCollisions.java:31–109` is byte-identical. It first pads the query by `1.0E-7` before flooring with an extra one-block margin, skips outer corners and missing chunks, applies the suffocating-only filter if requested, permits outer faces only with a large collision shape and outer edges only for moving pistons, then requests the shape and checks its translated intersection. `ClientLevel` inherits the relevant collision enumeration, using `Level.getChunkForCollisions(FULL, false)` (`world/level/Level.java:764–765 / 769–770`, `client/multiplayer/ClientChunkCache.java:69–82`, `world/level/chunk/LevelChunk.java:208–240`). Shape clipping keeps Y first and selects Z versus X by strict `abs(x) < abs(z)` (`world/entity/Entity.java:1161–1177 / 1244–1260`, `core/Direction.java:378–380`). The step candidate gate, float relative heights, ascending sort and required horizontal improvement also match (`Entity.java:1077–1129 / 1141–1193`).

3. Player `CollisionContext.of` selects a non-placement `EntityCollisionContext` on both sides (`world/phys/shapes/CollisionContext.java:24–35` both). The context snapshots `entity.getY()` and `entity.isDescending()`. `isDescending` returns the local player's virtual `isShiftKeyDown`, which reads `input.keyPresses.shift()`; the pose-based `isCrouching` is a separate getter (`world/phys/shapes/EntityCollisionContext.java:38–48,67–89` both, `world/entity/Entity.java:2638–2640,3704–3706 / 2705–2707,3777–3779`, `client/player/LocalPlayer.java:677–685,777–786` both). Entity context `isAbove` uses the strict double comparison `entityBottom > pos.getY() + shape.max(Direction.Axis.Y) - 1.0E-5F`. The float literal is promoted as written, and the contextual fallback value is ignored in this implementation. The `Empty` context instead returns the supplied default and is non-descending (`EntityCollisionContext.java:91–102` both).

4. In both versions the registration uses `ScaffoldingBlock::new`, `noCollision()` and `dynamicShape()`. Only the registration key expression changes from a string to the same key through `BlockItemIds.SCAFFOLDING` (`world/level/block/Blocks.java:5439–5450 / 4469–4480`, `references/BlockItemIds.java:551` in 26.2). No dynamic-state shape cache is installed, and the state reports a potentially large shape. Its contextual accessor directly delegates to the owning block override so the base `hasCollision` guard does not mask the result (`world/level/block/state/BlockBehaviour.java:487–518,575–577,680–686,1086–1091 / 489–520,577–579,686–692,1094–1099`). The scaffolding source is byte-identical. Its ordered selection (`world/level/block/ScaffoldingBlock.java:29–43,140–150` in both) is:

   1. Placement context gives an empty collision shape.
   2. Otherwise, above the full unit block and not descending gives the stable shape, composed of a full-width slab from `14/16` to `1` plus rotated `2/16` square corner posts.
   3. Otherwise, test nonzero `DISTANCE`, then `BOTTOM`, then above a unit block shifted down by one (maximum local Y `0`). These gates give the full-width `0` to `2/16` bottom slab.
   4. Otherwise return empty. The `SHAPE_UNSTABLE` outline shape, outline main-hand-item condition and interaction shape are separate from the collision method (same file, lines 60–72). Collision shape reads neither the held item nor `WATERLOGGED`. The waterlogged state has a dedicated fluid accessor (lines 152–155).

5. The state predicates use vanilla values. The bounded producers agree in both versions (`ScaffoldingBlock.java:45–57,76–87,90–132,157–182`, `world/level/block/state/properties/BlockStateProperties.java:13,123`). Start distance at seven, inherit a scaffolding block below's distance, or immediately return zero on a sturdy upward face below. Otherwise minimize against each horizontal scaffolding neighbor's distance plus one, breaking at one. The bottom flag is distance greater than zero with no scaffolding below. Later on the scheduled server tick the block updates or falls/breaks under the same gates. Shape selection itself reads its state without rerunning this neighbor computation. Both vanilla tag providers include scaffolding in the climbable tag (`data/tags/VanillaBlockTagsProvider.java:289–302 / 252–258`).

Concrete continuity example from the source gates. At an ordinary loaded column over non-bottom scaffolding, center the horizontal player box over the block, put the player's feet exactly at block Y + 1, and request downward movement. The strict top check with the tolerance passes. With shift released, the swept player box therefore sees the stable slab and clips against its top. With shift held, the top gate fails and the bottom gate fails for non-bottom scaffolding, permitting the player to begin entering the block when no other collider obstructs that delta. A supported overhang with nonzero distance and bottom set can still yield the bottom slab while shift is held, when its lower threshold passes. These are predicted outcomes of the selector and collision code.

## Context addition and remaining dependencies

- In 26.2, `CollisionContext.positionContext(double)` uses the supplied Y with the same strict above threshold and a false descending flag (`CollisionContext.java:37–39`, `world/phys/shapes/PositionCollisionContext.java:10–43`). The 26.1.2 particle call passes null to the nullable-entity sweep, hence uses the empty context whose above predicate returns the caller-supplied default. The 26.2 particle uses the new position-only overload (`client/particle/Particle.java:140–158 / 140–160`, `Entity.java:1131–1159 / 1202–1207,1232–1242`). That reaches different scaffolding geometry for particles below the top and affects particle movement.
- Searches for `positionContext(`, `collideBoundingBox(`, and `getBlockCollisionsFromContext(` across both source roots found the other position-only callers in 26.2 `world/level/block/entity/PotentSulfurBlockEntity.java:189–242`. Geyser obstruction can influence player launch within that modern feature (`PotentSulfurBlockEntity.java:115–135`). The potent-sulfur block entity class and position-context factory are absent from the older source inventory. This is a modern-only feature dependency. No new player sweep, step-up, edge, support, auto-jump or pose caller uses that overload.
- General post-collision movement response changed from component zeroing and `updateEntityMovementAfterFallOn` to `restituteMovementAfterCollisions` (`Entity.java:770–800 / 778–860`). It can operate on a movement clipped by scaffolding, independently of the selected shape. Its whole player-state effect, other block states supplying support, full travel/input/inside-block processing, and third-party tags or custom states are outside this bounded verdict. Independent coverage audit and runtime parity remain open.
