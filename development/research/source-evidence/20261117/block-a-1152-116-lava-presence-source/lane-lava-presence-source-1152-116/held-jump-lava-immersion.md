# Held jump in lava uses fluid immersion threshold
1.15.2 Mojmap: `decompiled_minecraft/1.15.2/mojmap/net/minecraft/world/entity/LivingEntity.java`, jump section in `aiStep`, lines 2264–2279; `jumpInLiquid`, lines 1823–1825.
1.16 Mojmap: `decompiled_minecraft/1.16/mojmap/net/minecraft/world/entity/LivingEntity.java`, jump section in `aiStep`, lines 2423–2449; `jumpInLiquid`, lines 1900–1902; `net/minecraft/world/entity/Entity.java`, `getFluidJumpThreshold`, lines 2704–2706.
Difference: In 1.15.2, the jump section runs whenever `jumping` is true. It first gates on `waterHeight > 0.0` and (when grounded) `waterHeight > 0.4`; on the other side of that branch, any `isInLava()` calls `jumpInLiquid(LAVA)` without checking lava height, while the remaining ground/low-water case calls `jumpFromGround()` only when `noJumpDelay == 0` and sets the delay to 10. In 1.16 the entire fluid-jump section additionally requires `isAffectedByFluids()`. It selects `k` from lava height when `isInLava()` and otherwise water height, computes `bl = isInWater() && k > 0.0` and threshold `m = getFluidJumpThreshold()`, then branches using strict `k > m` tests and `onGround`: eligible lava movement calls `jumpInLiquid(LAVA)`; eligible water movement calls `jumpInLiquid(WATER)`; the ground/low-water case jumps from ground only with zero delay. `jumpInLiquid` itself remains `deltaMovement.add(0.0, 0.04F, 0.0)`.
Movement meaning: Held jump while touching lava no longer unconditionally takes the lava impulse branch. The branch distinguishes lava height relative to the eye-height threshold (0.0 for eye height below 0.4, otherwise 0.4), grounded state, water state and the existing jump delay; it can instead take the grounded jump path. This changes player vertical response in the source branches; no trajectory was simulated.
