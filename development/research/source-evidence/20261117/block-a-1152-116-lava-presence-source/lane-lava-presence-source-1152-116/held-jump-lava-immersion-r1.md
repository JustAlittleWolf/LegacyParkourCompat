# Held jump in lava uses fluid immersion threshold
1.15.2 Mojmap: `decompiled_minecraft/1.15.2/mojmap/net/minecraft/world/entity/LivingEntity.java`, jump section in `aiStep`, lines 2264–2279; `jumpInLiquid`, lines 1823–1825; `net/minecraft/client/player/LocalPlayer.java`, `isEffectiveAi`, lines 490–492, `serverAiStep`, lines 607–618, and `aiStep` delegation, line 778; `net/minecraft/world/entity/player/Player.java`, `aiStep` delegation, lines 497–515.
1.16 Mojmap: `decompiled_minecraft/1.16/mojmap/net/minecraft/world/entity/LivingEntity.java`, jump section in `aiStep`, lines 2423–2449; `jumpInLiquid`, lines 1900–1902; `net/minecraft/world/entity/Entity.java`, `getFluidJumpThreshold`, lines 2704–2706; `net/minecraft/client/player/LocalPlayer.java`, `isEffectiveAi`, lines 519–521, `serverAiStep`, lines 634–645, and `aiStep` delegation, line 813; `net/minecraft/world/entity/player/Player.java`, `aiStep` delegation, lines 483–500 and `isAffectedByFluids`, lines 1005–1007.
Difference: In 1.15.2, the jump section runs whenever `jumping` is true. It first gates on `waterHeight > 0.0` and (when grounded) `waterHeight > 0.4`; on the other side of that branch, any `isInLava()` calls `jumpInLiquid(LAVA)` without testing lava height, while the remaining ground/low-water case calls `jumpFromGround()` only when `noJumpDelay == 0` and sets delay to 10. In 1.16 the whole jump section additionally requires `isAffectedByFluids()`. It selects `k` from lava height when `isInLava()` and otherwise water height, computes `bl = isInWater() && k > 0.0` and threshold `m = getFluidJumpThreshold()`, then branches with strict `k > m` tests and ground state: eligible lava movement calls `jumpInLiquid(LAVA)`, eligible water movement calls `jumpInLiquid(WATER)`, and the ground/low-water case jumps from ground only with zero delay. `jumpInLiquid` itself remains `deltaMovement.add(0.0, 0.04F, 0.0)`.
Reachable LocalPlayer input and timing: `LocalPlayer.serverAiStep`, not `aiStep`, copies `input.jumping` to `jumping` under `isControlledCamera`. The local player's `isEffectiveAi()` returns true, so LivingEntity.aiStep enters its effective-AI branch and invokes virtual `serverAiStep`. The LocalPlayer aiStep override delegates to Player.aiStep, which delegates to LivingEntity.aiStep; thus controlled-camera input reaches this jump consumer. In each aiStep, jump handling occurs before `travel` and its Entity.move callback. The lava-touching flag is produced after that decision in a processed move and can be read on a later consumer pass if no intervening processed move changes it. In 1.16 the `fluidHeight` map is separately refreshed in Entity.baseTick before aiStep, not by the lava callback. Flying Player input is excluded from the 1.16 fluid-jump section because `Player.isAffectedByFluids()` returns false while flying.
Movement meaning: Held jump in lava no longer unconditionally takes the lava impulse branch. The 1.16 branch distinguishes selected fluid height relative to the eye-height threshold (0.0 below eye height 0.4, otherwise 0.4), grounded state, water state, jump delay and fluid-effect eligibility; it can instead take the grounded jump path. This is a source difference, not a measured trajectory.
