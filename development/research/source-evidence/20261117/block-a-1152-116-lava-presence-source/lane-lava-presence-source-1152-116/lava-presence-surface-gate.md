1.16 Mojmap: `decompiled_minecraft/1.16/mojmap/net/minecraft/world/level/block/LiquidBlock.java`, `entityInside`, lines 177–186; `net/minecraft/world/entity/Entity.java`, `move`, lines 551–558 and `setInLava`/`isInLava`, lines 1065–1071.
Difference: In 1.15.2, the lava-tagged block callback unconditionally calls `entity.setInLava()`. Entity movement resets the cached lava flag immediately before `checkInsideBlocks()`, whose callbacks repopulate it. In 1.16, the same reset/callback order remains, but `LiquidBlock.entityInside` computes `float f = blockPos.getY() + blockState.getFluidState().getHeight(level, blockPos)`, reads the full entity AABB, and calls `setInLava()` only when `aABB.minY < f || f > aABB.maxY`. For a valid AABB where minY ≤ maxY, the second disjunct is subsumed by the first; preserve the literal comparison and its float/double operands. Thus the new producer can leave `isInLava()` false for callback cases where the entity's lower box bound is at or above the fluid surface.
Movement meaning: LocalPlayer inherits this Entity cache; a changed cache value can change whether LivingEntity's lava travel and jump paths are admitted later in the movement tick. LocalPlayer's controlled-camera `aiStep` copies input jumping to `jumping` and delegates to `super.aiStep` (1.15.2 LocalPlayer.java lines 608–618, 778; 1.16 LocalPlayer.java lines 635–645, 813). This is a source-path consequence, not a measured trajectory.
