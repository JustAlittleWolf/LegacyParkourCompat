# Lava presence surface gate

1.16 Mojmap: `decompiled_minecraft/1.16/mojmap/net/minecraft/world/level/block/LiquidBlock.java`, `entityInside`, lines 177–186; `net/minecraft/world/entity/Entity.java`, `move`, lines 551–558, and `setInLava`/`isInLava`, lines 1065–1071.
Difference: In 1.15.2, the lava-tagged block callback unconditionally calls `entity.setInLava()`. Entity movement resets the cached lava flag immediately before `checkInsideBlocks()`, whose covered block callbacks repopulate it. In 1.16, this reset/callback order remains, but `LiquidBlock.entityInside` computes `float f = blockPos.getY() + blockState.getFluidState().getHeight(level, blockPos)`, reads the full entity AABB, and calls the setter only when `aABB.minY < f || f > aABB.maxY`. For an ordered AABB where minY ≤ maxY, the second disjunct is subsumed by the first; preserve the literal comparison and float/double operands. The 1.16 callback can leave the flag false when the box lower bound is at or above the fluid surface.
Movement meaning and timing: LocalPlayer inherits this Entity cache. Its current LivingEntity.aiStep jump check precedes the travel call, and travel selects its branch before its `Entity.move` processes this callback. This callback therefore does not admit the jump or travel branch already chosen in that pass; its result can be consumed on a later pass if no intervening processed move changes it. In both versions, `noPhysics` moves take the direct box-update branch without the reset/callback, and a piston move limited to `Vec3.ZERO` returns before it. LocalPlayer's input copy occurs in `serverAiStep`; the reachable path is specified in `held-jump-lava-immersion-r1.md`. This is a source-path consequence, not a measured trajectory.
