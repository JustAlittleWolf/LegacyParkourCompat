# Lava travel admission and velocity
1.15.2 Mojmap: `decompiled_minecraft/1.15.2/mojmap/net/minecraft/world/entity/LivingEntity.java`, `travel`, lines 1831–1841 and 1913–1925.
1.16 Mojmap: `decompiled_minecraft/1.16/mojmap/net/minecraft/world/entity/LivingEntity.java`, `travel`, lines 1908–1913 and 1957–1976.
Difference: In 1.15.2, travel is inside `isEffectiveAi() || isControlledByLocalInstance()`. The lava path is reached through nested admission `!isInWater() || (this instanceof Player && flying)`, then `isInLava() && !(this instanceof Player && flying)`; its body does `moveRelative(0.02F, input)`, moves with the current delta, scales delta by `0.5`, adds `(0.0, -d / 4.0, 0.0)` when gravity applies, then on horizontal collision sets Y to `0.3` if the raised-position `isFree` check succeeds. There is no lava-height branch in that body. In 1.16, the independent lava branch is admitted by `isInLava() && isAffectedByFluids() && !canStandOnFluid(fluidState.getType())`, following the water branch. After the same input acceleration and move, `getFluidHeight(FluidTags.LAVA) <= getFluidJumpThreshold()` selects `multiply(0.5, 0.8F, 0.5)` followed by `getFluidFallingAdjustedMovement(d, bl, ...)`; otherwise it selects `scale(0.5)`. Gravity and the horizontal collision/free-space response follow. `getFluidJumpThreshold()` is `getEyeHeight() < 0.4 ? 0.0 : 0.4` (Entity.java lines 2704–2706).
Movement meaning: For an entity admitted to lava travel, the 1.16 result now depends on cached lava immersion relative to an eye-height threshold: shallow lava uses Y damping 0.8F and fluid falling adjustment; deeper lava uses uniform half scaling. The fluid-effect and can-stand-on-fluid gates also newly qualify the branch. No trajectory was simulated.
