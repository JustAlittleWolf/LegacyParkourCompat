**Bounded claim:** The berry contact trigger changes from testing only the player's resulting AABB in 1.21.1 to testing the local player's movement segment in 1.21.2. With unchanged vanilla berry state, a non-flying player segment can touch/leave a bush while ending with no AABB overlap; the later release can assign the berry slowdown for the next `Entity.move`, while the earlier release does not assign it from that segment.

This accepts only the source-confirmed adjacent stable-release operation boundary 1.21.1 → 1.21.2. It does not claim broad tick coverage, runtime parity, or any boundary after 1.21.2.

## Source proof and reachable player witness

- **1.21.1 final-box path:** `Entity.move` reaches `tryCheckInsideBlocks()` after resolving movement (`Entity.java:705`); `checkInsideBlocks()` constructs its block-coordinate range from the current bounding box only and calls `entityInside` only for those positions (`Entity.java:1001-1020`). The ordinary local-player movement therefore does not newly invoke the bush handler when the resulting AABB has cleared the bush.
- **1.21.2 segment path and caller:** after `LivingEntity` travels, its client gate permits `applyEffectsFromBlocks()` for the locally controlled instance (`LivingEntity.java:2771-2775`). The no-argument operation supplies `oldPosition()` and current position, appends that segment, runs the block scan, and clears the movement/state caches (`Entity.java:736-751`). The scan traverses each recorded segment with `BlockGetter.boxTraverseBlocks` (`Entity.java:1038-1061`; `BlockGetter.java:172-185`), deduplicates visited block positions during that scan, then clears the visited set (`Entity.java:1038-1073`). Berry uses the default inside-collision shape, `Shapes.block()` (`BlockBehaviour.java:353-354`), so the swept-block handler is not rejected by the non-full-shape collision test (`Entity.java:1049-1054`).
- **Vanilla state permits the path:** Sweet berry bush registration uses `.noCollission()` in both releases (`Blocks.java:6181-6189` in 1.21.1; `Blocks.java:5398-5407` in 1.21.2). Thus no block-state rewrite or custom collision is needed to reach and exit it.
- **Concrete geometry (qualified inference):** using the source's ordinary player width `0.6F`, put a berry at x `[0,1]`, and let the player's center x move from `1.29` to `1.39` during an otherwise unobstructed horizontal segment. Its x-min moves from `0.99` to `1.09`: the final box is clear, but the swept min-coordinate traverses the berry's x-cell. The segment length is only `0.1` block and the bush has no collision, so this is reachable by ordinary continuous movement from a position just overlapping the bush. This geometric/reachability witness is an inference from source dimensions and traversal math, not a runtime result.
- **Effect, multiplier, gates, and cache:** in both `SweetBerryBushBlock.entityInside` implementations, a living entity other than a fox or bee gets exactly `new Vec3(0.8F, 0.75, 0.8)` (`1.21.1 SweetBerryBushBlock.java:80-89`; `1.21.2 SweetBerryBushBlock.java:79-92`). AGE and movement threshold checks are inside the separate server damage branch; they do not gate the multiplier. `Player.makeStuckInBlock` suppresses the parent assignment while flying in both versions (`1.21.1 Player.java:1589-1594`; `1.21.2 Player.java:1582-1587`). The unchanged parent `Entity.makeStuckInBlock` resets fall distance and stores the multiplier (`1.21.1 Entity.java:2427-2430`; `1.21.2 Entity.java:2525-2528`); `Entity.move` consumes it by coordinate multiplication when its squared length exceeds `1.0E-7`, clears it, and zeros delta movement (`1.21.1 Entity.java:611-614`; `1.21.2 Entity.java:633-637`). For a local non-flying client player, the 1.21.2 segment callback therefore applies the same next-move slowdown even when the 1.21.1 final-box query would miss.

The age-dependent server damage branch is not accepted as a movement finding; no health or damage production is included here. No source uncertainty or unclosed dependency remains for this bounded claim.
