# Blind source audit: End Portal Frame eye and Cauldron collision shapes

Verdict: **ACCEPT** for the two bounded provider claims below. The 1.12.2-to-1.13 source comparison changes occupied collision volume for both providers. The inspected 1.13.2 providers retain the 1.13 geometry. This audits only these providers and their movement collision dispatch; it does not close the entire 1.12.2--1.13 pair or establish an exact intermediate patch boundary.

## Movement collision dispatch

- **1.12.2:** `Entity.move` obtains block collision boxes through `World.getCollisions` (`entity/Entity.java:567`, also its step checks at 525–547). `World.getCollisions` scans block states and calls `BlockState.addCollisions` (`world/World.java:964–1014`, especially 993–1002). The state implementation delegates to the concrete block's `addCollisions` (`block/state/StateDefinition.java:375–376`). Thus the providers' `addCollisions` methods, not just their outline getters, define movement collision geometry.
- **1.13:** `Entity.move` passes its swept player box and motion to `WorldView.getCollisions` (`entity/Entity.java:578–583`). The default collision query invokes block collision collection (`world/WorldView.java:191–216); that collector obtains each state's `getCollisionShape` and moves the returned shape to the block position (`world/WorldView.java:113–164`). `BlockState.getCollisionShape` dispatches to `Block.getCollisionShape` (`block/state/BlockState.java:205–210`), whose default returns the state's `getShape` when `hasCollision` is true (`block/Block.java:404–410`). Both blocks' registry properties use the collidable default (`Block.java:1910`, `Properties.noCollision` at 1952) and neither registration opts out (`Block.java:1235–1242`).
- **1.13.2 consistency:** `Entity.move` calls the same shape-based world collision path (`entity/Entity.java:578–587`); `WorldView` collision collection reads `getCollisionShape` (`world/WorldView.java:154–177`, 125–140). The block collision default remains state-shape dispatch (`block/Block.java:393–394`), with `hasCollision` defaulting true (`Block.java:1901`) and both registrations collidable (`Block.java:1216–1223`).

## Findings

### Filled End Portal Frame

- **1.12.2:** `block/EndPortalFrameBlock.java:30–31` defines the base and eye boxes. `getShape` returns only the base (`:44–47`), while the movement collision override adds the base and, when `world.getBlockState(pos).get(EYE)` is true, the eye box (`:50–55`). The eye box occupies x/z 5/16–11/16 and y 13/16–1.
- **1.13:** `block/EndPortalFrameBlock.java:26–28,36–39` builds the same base, an eye box at x/z 4/16–12/16 and y 13/16–1, unions them, and returns the union only when `state.get(EYE)` is true. `Block.block` divides shape coordinates by 16 (`block/Block.java:152–154`); the default collision getter dispatches to this state-dependent shape. The 1.13.2 provider is byte-identical to the 1.13 provider.
- **Movement meaning:** for a frame with an eye, the collision volume grows one sixteenth of a block outward on each horizontal side of the eye bump; its top and base-frame volume remain unchanged. For an eye-free frame, both sources provide only the same base-frame volume. This is an occupied collision-shape delta, not an outline-only inference.

### Cauldron

- **1.12.2:** `block/CauldronBlock.java:35–39` defines a full-width floor ending at y 5/16 and four 2/16-wide, full-height walls. `addCollisions` submits those five boxes (`:46–53`).
- **1.13:** `block/CauldronBlock.java:34–45` defines an inner box x/z 2/16–14/16, y 4/16–1 and uses `VoxelShapes.join(fullBlock, inside, ONLY_FIRST)` for the state shape. `Block.block` scales the sixteenth-unit arguments (`block/Block.java:152–154`); `VoxelShapes.block()` is the unit cube and `join` applies the supplied boolean operation (`block/shape/VoxelShapes.java:55–65,121–153`). The 1.13.2 provider has the same relevant shape declaration and getter at `:34–45` (the full class has unrelated differences).
- **Movement meaning:** the side-wall footprint is the same, but the 1.13 shape subtracts the interior starting at y 4/16, leaving an interior floor only to y 4/16. In 1.12.2 the five collision boxes leave that interior floor to y 5/16. The top of the central floor is therefore lower by 1/16 in the inspected 1.13 geometry; player movement/collision can enter correspondingly farther into the cauldron interior.
