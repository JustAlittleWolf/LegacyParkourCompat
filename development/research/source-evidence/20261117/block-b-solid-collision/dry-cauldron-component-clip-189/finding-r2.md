## Command-enabled lawful setup and immediate request

This setup is command-enabled and source-legal, but is not a naturally reachable locomotion path. Put a dry bottom slab at block `(1,0,0)` and let the player stand on its top at feet `y=0.5`, with AABB `x=[0.99999995,1.59999995]`, `y=[0.5,2.3]`, `z=[0.2,0.8]`. Then an authorized `/setblock 0 0 0 cauldron` places the cauldron while the player is already supported on the neighboring slab. The player is not riding or moving during setup. After the block update, request `+0.2` Z.

The command paths do not test player collision before setting the block. In 1.8.9, `SetBlockCommand.getRequiredPermissionLevel()` is 2 (lines 26-27), and `run` calls `world.setBlockState(blockPos, blockState, 2)` (line 89); `World.setBlockState` (line 238 onward) validates world/chunk bounds and installs the state with no entity-collision rejection. In 26.2, `SetBlockCommand` requires gamemaster permission and the default branch invokes `setBlock` with `Mode.REPLACE` (lines 23-41, 99 onward); `BlockInput.place` line 66 delegates to `level.setBlock` line 74. `Level.setBlock` line 222 onward validates world bounds/debug mode and writes the chunk state, with no entity-collision rejection. Therefore an authorized command can lawfully create the embedded geometry around a stationary player; the `keep` option is unnecessary.

At the next request, old cauldron collision list order is floor, West, North, East, South. The East wall overlaps player X by 5e-8 but Z already overlaps the wall's full `[0,1]` range, so `intersectZ` leaves +0.2 unchanged for that component; it does not erase/reorder the subsequent South-wall constraint. The South wall spans X `[0,1]`, Y `[0,1]`, Z `[0.875,1]`; player X/Y overlap it, and the positive-Z gap is `0.875 - 0.8 = 0.075`. Old resolution therefore returns `+0.075` Z. For the same occupied union in a VoxelShape, Z clipping uses X as an orthogonal axis; `minX + 1e-7 = 1.00000005`, so the x-index range is empty and the shape returns the full `+0.2` Z. The requested strict translation flag differs.

The command makes this state lawful only in a command-enabled setting with sufficient permission (or an equivalent authorized command-block setup). It does not show ordinary walking can create a sub-epsilon penetration; no such natural path has been established. Keep the applicability classification conditional on this explicit world-mutation setup. No game or command was run; this is a source-path and geometry calculation only. The modern actual cauldron still has a different shape; this is a component-clipping test using the assignment's equal historical union, not a claim about native 26.2 vanilla-cauldron movement.

## Disposition

The numerical distinction is now reachable from a command-enabled, supported, non-riding setup, with a source-proven block write that does not depenetrate the player. It remains unproven for command-free natural movement. Preserve this domain limit when transferring/reviewing the candidate; do not infer generic basin clipping divergence or runtime parity.
