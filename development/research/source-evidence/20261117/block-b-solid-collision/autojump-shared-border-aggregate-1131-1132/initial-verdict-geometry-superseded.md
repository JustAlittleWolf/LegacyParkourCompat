## 1.13.2 mechanics and independent derivation

`LocalClientPlayerEntity.move` captures old x/z, calls `super.move`, then invokes `autoJump((float)(newX-oldX), (float)(newZ-oldZ))` (source lines 871–875). AutoJump requires enabled, countdown `<= 0`, on-ground, not sneaking/riding, nonzero input, and a forward/look dot not below `-0.15` (lines 882–903). Its two initial clearance reads call `getBlockState(...).getCollisionShape(...).isEmpty()` directly; those reads are physical block states. The synthetic border collision is introduced only by the subsequent collision query.

For the requested east step, use actual post-move position approximately `(8.99,64,0.5)` and actual displacement `(0.10,0,0)`. The measured squared displacement is about `0.01`, above the `0.001` input fallback threshold, so the directional vector comes from actual displacement. `PlayerEntity` base movement speed is `0.1F`; Speed II has the `0.2F` operation-2 modifier scaled by amplifier+1, giving queried speed `f=0.14F`. Thus `p=max(f*7,1/l)≈max(0.98,0.10)=0.98`. The candidate endpoint is post-move x plus actual dx plus lookahead, about `8.99+0.10+0.98=10.07`.

With width `0.6` and height `1.8`, the query box before shape collection is approximately x `[8.39,10.67]`, y `[64,65.8]`, z `[-0.1,1.1]`. `WorldView.getBlockCollisions` pads the integer scan: x cells 7–11, y 63–66, z −2–2. For a stationary border with east edge x=10 and ordinary loaded chunks, x=10 is synthetic outside-border occupancy. The simultaneous-boundary admission predicate retains x=10 interior-z cells on y edge rows 63 and 66. The x=10,y=63 first contiguous interior z run is −1..1; the greedy `VoxelSet.forEachBox` sweep extends that run through y=66. The first intersecting aggregate border AABB is **[10,11] × [63,67] × [−1,2]** for this z=0.5 query. Its top remains y=67. The earlier C r2 witness at z=0 had z max 1; the changed z bound does not alter this first box's x/y maximum or its floored center `(10,65,0)`.

Both lateral rays, at z≈0.2 and z≈0.8 and y raised by `0.51`, intersect that box. `new BlockPos(box.center())` floors `(10.5,65,0.5)` to `(10,65,0)`; this center cell is not itself a clearance read. With Jump Boost III (amplifier 2), AutoJump cap is `o=1.2F+(2+1)*0.75F=3.45F`, so the integer loop tests t=1,2,3. The first box leaves `s=67`; with feet at 64, `u=3`, which is above 0.5 and no greater than the cap. If all listed physical blocks are AIR, this path writes `ticksToNextAutojump=1`.

For the requested x≈8.99,z=0.5 state, the exact direct AIR reads are: initial head cells `(8,65,0)` and `(8,66,0)`; the three cap samples `(10,66,0)`, `(10,67,0)`, `(10,68,0)`; and the extra `t>1` head-clearance reads `(8,67,0)` and `(8,68,0)`. In particular, the x=9 samples in the supplied r2 report belong to its separate x≈9.7 fixture and must not be copied into this witness. AIR is required at these six coordinates; the support can remain at `(9,63,0)`. The border AABB does not make these direct state reads non-AIR.

For comparison, without Jump Boost the cap stays `1.2F`; with Jump Boost II (amplifier 1) it is `2.7F`, both below `u=3`, so neither arms this particular aggregate first box. Jump Boost III's normal jump contribution is `0.42F+0.3F=0.72F`, but `jump()` is not called during the stated current supported nonjump move. In that current tick the effect changes AutoJump's vertical allowance only; neither status effect changes the candidate query's vertical bounds or performs a vertical physics update. Speed II affects horizontal movement speed/lookahead; the witness fixes the actual accepted displacement, and its extra lookahead remains horizontal.

## Border flag, temporal gates, and 1.13 patch boundary

With border maximum x=10, both the expanded (`outsideWorldBorder=false`) and eroded (`true`) strict center predicates admit x=8.89 and x=8.99 at z=0.5. `WorldView` computes `collidesWithBorder` from the old flag, then flips the stored flag only when old and computed booleans are equal. Starting false leaves false; starting true makes the computed value true and transitions the stored flag to false. In either case the computed border-collision boolean passed to `getBlockCollisions` is true. Therefore the fixture has a stable false flag after the call and the border shape collection does not depend on history of the incoming flag. An adaptation that gates the query directly on the incoming flag would diverge from this source.

The timer assignment occurs synchronously during `move`→`autoJump`, after the local tick's timer countdown. At the next local tick, source checks `ticksToNextAutojump>0`, decrements 1 to 0, and sets the one-tick `bl4`/`input.jumping` event for that tick. It is not a persistent countdown after that tick. A two-second command-applied Jump Boost III has duration 40; status-effect tick decrements duration once in the living tick, and the effect remains positive when a 40-tick instance is read later that tick. No expiry occurs inside the synchronous move/AutoJump call. This is a command-enabled map witness; ordinary survival potion availability alone does not establish amplifier 2.

Exact-version caveat: 1.13's `autoJump` iterates `world.getCollisions(...).getBoundingBoxes()` from an aggregate `VoxelShape`; 1.13.1 changes this to flatten `Stream<VoxelShape>` boxes, and its `WorldView.getBlockCollisions` also changes to the streamed per-position path plus synthetic aggregate shape. 1.13.2's `LocalClientPlayerEntity.java` and `WorldView.java` hashes equal 1.13.1's, but they differ from 1.13. The shared jump cap and timer logic appear unchanged in the compared excerpts; the collision collection/ordering call is not unchanged. This review therefore supports the bounded 1.13.2 claim and the 1.13.1/1.13.2 shared method path only, not automatic promotion over the 1.13→1.13.1 boundary.

## Reviewed claims and limits

- The corrected 1.13.2 aggregate border AABB reaches y=67 for the requested geometry; Jump Boost III's cap 3.45 admits rise 3, while Jump Boost II's 2.7 does not.
- Combined Speed II + command-supplied Jump Boost III can arm the timer in the stated bounded supported step if the six direct headroom cells are AIR and all movement gates hold.
