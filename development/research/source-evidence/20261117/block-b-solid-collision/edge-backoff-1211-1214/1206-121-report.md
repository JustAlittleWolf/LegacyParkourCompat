## Compared operation and verdict

**No source difference found** in the ordinary player edge probe for these endpoints. In `net/minecraft/world/entity/player/Player.java`, `maybeBackOffFromEdge`, `isAboveGround`, and `canFallAtLeast` have identical bodies: 1.20.6 lines 1067–1125; 1.21 lines 1070–1128. The complete `maybeBackOffFromEdge` slice through the next method compares equal. It gates on not flying, nonpositive Y displacement, `SELF` or `PLAYER` mover type, `isStayingOnGroundSurface()`, and `isAboveGround(maxUpStep)`. `Entity.move` invokes this hook after applying any stuck-speed multiplier and before `collide` (Entity.java 1.20.6 lines 608–617; 1.21 lines 609–618). It probes X alone first, Z alone second, then the remaining diagonal; each axis is reduced by signed `0.05` steps, with the `<= 0.05` case zeroed before the diagonal loop returns the adjusted X/Z and original Y.

`isAboveGround(step)` is `onGround() || (fallDistance < step && !canFallAtLeast(0, 0, step - fallDistance))`. `canFallAtLeast(dx,dz,step)` gets the current player AABB on each call and tests `noCollision(this, new AABB(minX+dx, minY-step-1.0E-5F, minZ+dz, maxX+dx, minY, maxZ+dz))`. Thus the probe is a horizontally translated copy of the current footprint, with its top exactly at the current box bottom and its bottom `step + 1.0E-5F` lower. The epsilon is the source **float** literal `1.0E-5F` (promoted during double arithmetic), not a double literal. The probe uses vanilla `noCollision` and the current player entity/context; it is not a support-position or post-collision query.

## Same-state support witness

Use a fixed local state with a single solid support block under the player, air on the horizontal sides, no other colliding entities, every block/chunk reached by the probe loaded, and the world border distant from the query. This makes the comparison finite and removes unloaded-region and border outcomes. For a player box resting at Y=1 on a full cube, the test volume runs down from `1` to `1 - step - epsilon` and overlaps the cube. For a dry `BOTTOM` slab with player-box bottom at Y=0.5, it runs from `0.5` down by the same amount and overlaps the slab's `[0, 0.5]` collision volume. In either case, `noCollision` is false while the horizontal probe still overlaps the support, so `canFallAtLeast` is false; once a candidate footprint clears the support, `noCollision` becomes true and the 0.05 backoff loop reduces it. The outer support gate is reachable in this context (`onGround`, or the corresponding fall-distance test), provided its other stated predicates hold. This is an applicability witness for the unchanged operation, not a release difference.

`CollisionGetter.noCollision` is identical at both sides (46–61): it rejects a nonempty block collision first, then entity collisions, and for an entity checks the world-border collision. `getBlockCollisions` (83–85) creates `BlockCollisions`; its iterator obtains each vanilla state and that state's `getCollisionShape`, then intersects its moved shape with the query. The body is identical across the pair. `AABB.intersects` uses strict interval overlap in both sources (1.20.6 lines 228–235; 1.21 lines 233–240); the half-slab path uses shape intersection in `BlockCollisions` (75–86), not a full-cube substitution.

## Shape/render condition kept separate

`SlabBlock.getShape` is identical (both lines 56–63): `DOUBLE` returns `Shapes.block()`, `TOP` returns `TOP_AABB`, and `BOTTOM` returns `BOTTOM_AABB`. The constants are full-width boxes from Y=0..0.5 and Y=0.5..1 respectively (both line 32). `BlockBehaviour.getCollisionShape` delegates to the state shape when collision is enabled (1.20.6 lines 305–310; 1.21 lines 304–309). This branch depends on slab `TYPE`; waterlogged/dry state is not consulted by this shape method. Rendering/model selection is outside this movement probe and does not enter `noCollision`; no visual/render difference is asserted here.
