# 1.12.2 to 1.13.2: stair start-overlap displacement witness

## Exact sources

Both releases use the exact `ornithe-feather` mapping family, Feather build.2, Vineflower 1.12.0, Java 25.0.3. Ready markers identify version metadata 1.12.2 and 1.13.2 respectively. Their source-manifest SHA-256 values are `b8a37ccfccd2aac5f40f5e34fec85873dbdfa93a266043c103e592e4a8c949da` and `2c8cfb646bf622fb26ac0ca0cb5e02a354fb512e29f8b1010f1aaacd509e1211`. For every source file listed below, the published file SHA-256 matches its entry in that release's `ornithe-feather.sources.sha256` manifest. Pair verification reported zero source-file differences and no raw-input differences; the sole artifact difference is a regenerated derived remap JAR, not a published source difference.

## Shared stair geometry

Place one bottom, straight, south-facing stair at block position `(0,0,0)` in otherwise empty space. In 1.12.2, `StairsBlock.getCollisionShapes` emits the bottom base plus the south upper half for a straight stair (`StairsBlock.java:66-101`): base `[0,0,0]..[1,0.5,1]`, step `[0,0.5,0.5]..[1,1,1]`. Its virtual-shape resolver leaves a straight stair straight when no adjacent stair affects it.

In 1.13.2, the same base is `SlabBlock.BOTTOM_SHAPE` `[0,0,0]..[1,0.5,1]`; the stair shape is built by OR-ing the selected half-cell shapes (`StairsBlock.java:37-81`). `Direction.SOUTH` has horizontal id 0 (`Direction.java:19,89`), so straight stair index 0 selects mask 12 (`StairsBlock.java:53,99-104`), joining the south-west and south-east upper boxes into `[0,0.5,0.5]..[1,1,1]`. `Block.getCollisionShape` returns the block state's shape (`Block.java:393-395`), so the collision VoxelShape is the union of the lower base and upper south step.

## Reachable exact contact state

The server teleport command reaches the player network handler with absolute coordinates when x/y/z are not relative (1.12.2 `TeleportCommand.java:77-95`; 1.13.2 `TeleportCommand.java:174-214,232-254`). The network handler updates the server-side position and sends a `PlayerMoveS2CPacket` (1.12.2 `ServerPlayNetworkHandler.java:538-558` and following send; 1.13.2 `:801-814`). The command then marks the server entity on-ground and zeros vertical velocity (1.12.2 `TeleportCommand.java:104-107`; 1.13.2 `:290-293`), but the client handler applies the packet coordinates through `updatePositionAndAngles` directly (1.12.2 `ClientPlayNetworkHandler.java:578-612`; 1.13.2 `:621-655`). That calls `setPosition` without collision resolution (Entity.java `:1093-1114` / `:1096-1117`) and does not transfer the server's `onGround` assignment, so an already-airborne local player can retain `onGround=false` while being placed in the lower stair box.

Player width is `0.6F` and height `1.8F` (1.12.2 `PlayerEntity.java:399`; 1.13.2 `:450`). `Entity.setPosition` computes `float halfWidth = width / 2.0F`, then adds/subtracts it from the double horizontal center coordinates (`Entity.java:298-305` / `:309-316`). Thus `halfWidth` is the exactly represented float value `0.300000011920928955078125`, promoted to double. Set the player's coordinates to `(x=0.5, y=0.25, z=0.199999988079071044921875)`: x and z are horizontal center coordinates, while y is the feet/bottom coordinate. Here `z = 0.5 - (double)halfWidth`. The resulting AABB is:

- X `[0.1999999880790710449, 0.8000000119209289551]`
- Y `[0.25, 2.0499999523162841797]`
- Z `[-0.1000000238418579102, 0.5]`

Its `maxZ` is exactly `0.5`, so it face-touches the stair's upper south step; it overlaps the lower base by positive volume. This exact coordinate avoids the earlier rounded-center mistake: using `z=0.2` would make `maxZ=0.500000011920929`, already penetrating the upper step.

## Actual next local-player movement call

On the next tick, hold forward at yaw 0, with no fluid, flight, climbing, or effects, and retain `onGround=false`. The client tick chain is `LocalClientPlayerEntity.tick` → `PlayerEntity.tick` → `LivingEntity.tick` (1.12.2 lines 165, 174/204, 1619-1620; 1.13.2 lines 181, 176/208, 1689-1690). The living tick invokes local `serverTickAi`, which copies input movement into `forwardSpeed` (`LocalClientPlayerEntity.java:631-639`), damps that by `0.98F`, then calls `moveRelative` (`LivingEntity.java:1844-1847` / `:1922-1926`). At yaw 0, `updateVelocity` adds `(float)(0.98F * 0.02F)` to Z velocity (`Entity.java:1049-1066` / `:1057-1074`), exactly the float value `0.0196000002324581146240234375`, promoted to the double movement delta. The call is `move(MoverType.SELF, 0, 0, 0.019600000232458115...)` (`LivingEntity.java:1514` / `:1575`), dynamically reaching `LocalClientPlayerEntity.move` (`:846-849` / `:871-874`) and then the inherited `Entity.move` collision query. Because `onGround=false`, local auto-jump does not add a separate movement.

## Paired collision result

In 1.12.2, `Entity.move` queries `getShape().expanded(x,y,z)` and collects each intersecting stair AABB (`Entity.java:567`; `Block.java:378-383`). The swept query extends beyond `z=0.5`, so it includes both stair boxes. The lower base overlaps the player's starting box and does not clip positive Z. The upper step is separated in Z by exactly zero; `Box.intersectZ` therefore changes the positive delta to zero (`Box.java:225-243`, called at `Entity.java:595`). Resulting Z displacement: `0`.

In 1.13.2, `Entity.move` requests the moving collision stream (`Entity.java:580,594`). `WorldView` passes the original player shape as `excludeBlock` (`WorldView.java:158-164`). During block collection, the stair VoxelShape overlaps the player's start box through the lower base, so the collector returns empty for the entire stair shape (`WorldView.java:136-142`), dropping the separate upper component too. In the stated otherwise-empty space there are no other collision candidates. `calculateMaxOffset` returns the requested distance when the stream is empty (`VoxelShapes.java:194-204`). Resulting Z displacement: `0.019600000232458115...`.

This is a reachable one-tick player displacement difference caused by per-AABB legacy candidates versus whole-block VoxelShape exclusion. It does not audit other providers or callbacks.
