## Source facts

### Caller and unchanged probe

Both LocalClientPlayerEntity versions capture the pre-move X/Z, call `super.move`, then call AutoJump with `(float)(this.x - oldX)` and `(float)(this.z - oldZ)` in that order (1.13.2: 871–876; 1.14: 846–852). The delta keeps its sign. Both AutoJump methods require enabled, timer `<= 0`, on-ground, not sneaking, not riding, and nonzero movement input. The normalized probe direction first comes from the float delta squared-distance cast; when `g <= 0.001F`, it falls back to the yaw-rotated input expression `h*k - i*j`, `i*k + h*j`. It uses `l=(float)MathHelper.fastInvSqrt(g)`, then `vec3d4=vec3d3.scale(l)`. Preserve the facing gate exactly as `if (!(m < -0.15F))` (including NaN behavior), the two early head-block collision-shape checks, `p=Math.max(f*7.0F,1.0F/l)`, `0.51F` vertical ray lift, left ray test before right ray test, and `box2` iterator order. At the first `box2` that intersects either ray, AutoJump assigns `s=(float)box2.maxY`, computes the box center and block position, runs the upward clearance sample, then breaks. Timer is assigned only after this first qualifying shape when `u=(float)(s-this.getShape().minY)` satisfies `!(u <= 0.5F) && !(u > o)`.

The relevant difference is how that collision stream can contain the world-border shape, and where it appears in the stream. The AutoJump directions, inside tests, first-hit break, numeric casts, and timer conditions above do not otherwise change in these slices. The 1.14 method also constructs `CollisionContext.of(this)` and uses contextual block collision-shape calls; that adjacent change is outside this border-only claim.

### 1.13.2: synthetic bounded border cells, aggregated after block stream

`WorldView.getCollisions(entity, shape, ...)` reads `isOutsideWorldBorder()` and calls `collidesWithBorder(entity)`; for the ordinary inside state (`false`), that test expands the X/Z border by one block and compares the entity's **position** (`entity.x`, `entity.z`) strictly against it. If old state and the computed result differ, no state write occurs; `checkWorldBorder` is the computed result (lines 170–178). Thus an inside entity in this one-block shell has `outsideWorldBorder=false` and `checkWorldBorder=true`.

`getBlockCollisions` derives integer scan limits from the AutoJump **query box** (floor minima minus one; ceil maxima plus one; lines 112–118), not from the entity's current position. If the scan is not wholly interior and a loaded scanned BlockPos lies outside the border, it substitutes `VoxelShapes.block()` for that cell (lines 120–145). These cells are consumed into a `BitSetVoxelSet`; their per-cell shapes emit empty. The stream emits ordinary block shapes first, then a single filtered `IntVoxelShape` over that finite scan volume (line 151). `VoxelSet.forEachBox` merges contiguous full outside-border cells along Y when their X/Z footprint is the same, and visits the resulting boxes in X, then Y, then Z scan order.

### 1.14: actual border complement, entity-shell gate, border stream first

`WorldBorder` makes a border shape as `VoxelShapes.join(full-infinite-shape, border-interior-box, ONLY_FIRST)`. Both dynamic and static extents use X/Z bounds `floor(minX/minZ)` through `ceil(maxX/maxZ)` and Y from negative to positive infinity (dynamic: lines 299–311; static: 406–417). The result is the unbounded-Y complement of the rectangular border interior, not a synthetic cell sweep bounded to the AutoJump query.

`WorldView.getCollisions(entity, queryBox, excludeEntities)` computes the border gate from the entity's current `getShape()`, not from `queryBox`: `bl = overlap(border, block(entityShape.contract(1.0E-7)), AND)` and `bl2 = overlap(border, block(entityShape.expand(1.0E-7)), AND)`. It prepends the border shape iff `!bl && bl2`, then entity collisions. Later it concatenates the block scan and its aggregate IntVoxelShape (lines 127–195). The final filter checks overlap against `block(queryBox)`; thus insertion is entity-shell-gated but the AutoJump query still has to overlap it. Entity move uses the same border shape and contracted-entity test (Entity.java lines 645–660), so a post-collision player whose AABB face rests on an integer border edge is a source-supported reachable setup for this gate.

`VoxelShape.getBoundingBoxes()` preserves `forEachBox` decomposition order. A border AABB that intersects an AutoJump horizontal ray has `maxY=+Infinity`, so the AutoJump cast makes `s=+Infinity`. `Box.center()` uses `MathHelper.m_23874002(0.5, min, max)`, implemented as `min + factor*(max-min)`. For the border AABB's Y endpoints `(-Infinity,+Infinity)`, this computes NaN. `BlockPos(Vec3d)` floors each component; `MathHelper.floor(double)` casts to int and tests `x < i`, so NaN casts to 0 and returns 0 for that coordinate. Therefore center-Y NaN becomes block Y=0; the loop samples the block at Y=1 (only `t=1`, because `t<1.2F`) before the first-hit break. A nonempty sampled block can replace `s` with its contextual collision height (and early-return if too high); in the empty sample case, `s` remains positive infinity. The final timer comparison rejects positive infinity because `u > 1.2F`.

## Safe endpoint case and movement meaning

Choose an ordinary inside, grounded player after its horizontal move is clipped with its AABB face exactly at an integer `minX` border plane, z away from either border corner, with the AutoJump probe extending outward across that face. Keep the scanned border-adjacent chunks available and the sampled block above the first border AABB center empty; leave the ray corridor otherwise without a qualifying block. This is a legal fixed-profile player state: 1.14 Entity movement itself computes collision against that border shape and clips the AABB, then LocalClientPlayerEntity calls AutoJump.

For this setup, 1.14's entity shape contraction does not overlap the outside complement, its 1e-7 expansion does, and the query/ray also overlaps the border shape. The prepended border AABB is first and yields `s=+Infinity`; the center's NaN Y floors to zero, and the empty Y=1 sample leaves `s` unchanged, so AutoJump does not set the timer. In 1.13.2, the same inside position keeps `outsideWorldBorder=false`, the center-position shell check enables border scanning, and the query catches loaded synthetic border cells. With no earlier qualifying block shape, their merged finite box extends to scan limit `ceil(queryBox.maxY)+1`, strictly above the query maximum. Since `queryBox.maxY = playerShape.minY + 0.51F + playerHeight`, its `u` is above `1.2F` for an ordinary player in normal build heights; the timer is also not set. This proves a change in first-hit obstruction height (finite scan cap vs infinity) without claiming a different timer outcome in this safe case.

This case does not establish that every border-adjacent situation has the same first hit: 1.13 ordinary block shapes precede its aggregated border shape, while 1.14's border shape precedes entity and block shapes. A separate qualifying obstruction can therefore win on 1.13 before the synthetic aggregate, while 1.14 can stop at its inserted border shape. That broader effect is only source-order conditional here; no trajectory or runtime claim is made.

## Gaps / bounded verdict

- This confirms only the exact endpoint pair 1.13.2 → 1.14. Neighbor material naming 1.14.4 is not evidence for 1.14.4; no 1.14.4 source was read. Do not state a patch-exact introduction point.
- No wiki material, product implementation, product Git history, runtime test, or broader tick-graph inventory was examined. This is not a full-pair freeze or whole-player movement coverage claim.
- The empty block above the border AABB center and absence of another qualifying obstruction are explicit safe-case assumptions. If either fails, the post-hit block-height overwrite or 1.13 earlier block shape can change the result; source itself does not assert world contents.
