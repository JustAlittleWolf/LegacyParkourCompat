## Claim verdicts

| Claim | Verdict | Evidence and qualification |
| --- | --- | --- |
| Through 1.21.1, Honey's `entityInside` callback is reached from the ordinary `Entity.move` path. `LocalPlayer.move` forwards through `super.move`. | **Accepted** | For example, 1.19.2 `Entity.move` calls `tryCheckInsideBlocks` at line 657 and `checkInsideBlocks` invokes `BlockState.entityInside` at lines 886-912; 1.21.1 does so at lines 705 and 1001-1028. `LocalPlayer.move`'s `super.move` call is present in the assigned source versions, including 1.21.1 at lines 881-885. HoneyBlock's callback body is `entityInside` (1.19.2 lines 56-64; 1.21.1 lines 62-70). The scan is inside the move operation, after the position update and before `Entity.move`'s later horizontal block-speed velocity multiplier. This is per move invocation, not a global promise that every tick has exactly one movement invocation. |
| The move-local invocation continues across 1.19.2-1.21.1, with an inset change at 1.19.3 and `BlockPos.containing` from 1.19.4. | **Accepted** | The assigned intermediate source files were checked. 1.19.2 uses the `0.001` inset and `hasChunksAt`; 1.19.3 uses `1.0E-7` with the same loaded-bounds gate; 1.19.4 through 1.21.1 retain `1.0E-7`, using `BlockPos.containing` from 1.19.4. The two early inset findings correctly separate reachability from cadence. |
| The first inspected move-local to post-travel migration is 1.21.1 → 1.21.2. | **Accepted** | In 1.21.2 `Entity.move` has no block-effect callback call (its body ends at line 701); `Entity.applyEffectsFromBlocks` is lines 736-767. `LivingEntity.tick` invokes it after `travel` returns at line 2775, after the locally controlled/server gate. The assigned exact releases show no earlier transition. This bounds the observed change to the 1.21.1/1.21.2 pair; it does not identify an unpublished commit or an uninspected release boundary. |
| For an ordinary dry, non-fall-flying local player, the 1.21.2 callback follows air travel's movement, gravity and drag writes. | **Accepted** | `LocalPlayer.tick` calls `super.tick` (1.21.2 lines 189-192); `LocalPlayer.move` calls `super.move` (872-880). `Player.travel` delegates to `super.travel` for a non-passenger (1445-1466). `LivingEntity.travel` selects `travelInAir` when not in the water/lava branch and not fall-flying (2178-2195); that method completes its gravity/friction velocity writes at 2197-2213. `LivingEntity.tick` calls `applyEffectsFromBlocks` only afterward. Fluid and fall-flying paths are separately selected and should not be described as ordinary air travel. |
| The older loaded-area and inset gates, and the new post-travel inset/path/dedup gates, are as stated. | **Accepted, with a scope note** | Through 1.21.1 `Entity.checkInsideBlocks` computes the inset bounds and guards the scan with `level.hasChunksAt(min,max)` (e.g. 1.19.2 lines 886-912; 1.21.1 lines 1001-1028). `LevelReader.hasChunksAt` checks vertical bounds and the covered chunks (1.19.2 lines 184-203). In 1.21.2 the callback scan is gated by `isAffectedByBlocks`, alive-state checks, non-air state, the per-batch visited-position set and collision-shape/movement checks (`Entity.java` lines 1038-1077); the working box is deflated by `1.0E-5F`, and `BlockGetter.boxTraverseBlocks` supplies the path positions (lines 172-189). There is no explicit whole-box `hasChunksAt(min,max)` guard in this new callback path. This verdict makes no claim about implicit behavior of `getBlockState` outside that explicit callback gate. |
| A visited position can produce at most one callback in the 1.21.2 batch, and callback/collector order is as described. | **Accepted** | `visitedBlocks.add` precedes `entityInside`; the set is cleared after traversal. For a non-air state that passes the shape/path condition, the order is `entityInside`, `onInsideBlock`, then add to the state collector (`Entity.java` lines 1038-1077). “At most once” is the correct bound; a position marked visited before a later shape skip does not imply a callback is guaranteed. |
| Cadence continuity holds across all supported groups. | **Rejected as a global continuity claim; accepted only within the move-local group** | Source confirms the same broad move-local placement through 1.21.1, despite the separate 1.19.2/1.19.3 inset boundary change. 1.21.2 instead applies effects after `LivingEntity.travel`, uses movement-path collection and per-batch dedup, and lacks the former explicit whole-box loaded-area check. These differences prevent treating callback timing or callback eligibility as continuous across 1.21.1 → 1.21.2. The source does not by itself establish a particular runtime trajectory or callback count for every profile. |

## Review boundary

Both immutable findings are source-supported. `honey-callback-cadence.md` correctly records the 1.21.1 → 1.21.2 timing transition and keeps the per-block range change separate. `honey-block-inset.md` correctly records the 1.19.2 → 1.19.3 inset difference and the later path-based model. The comments about HoneyBlock velocity formulas remain outside this review, as assigned.

This is a source-only verdict. It makes no runtime-parity claim.
