## Compared source slices and result

- 1.8.9 `net/minecraft/item/ItemStack.java`, `getAttributeModifiers()`, lines 667–687: when `AttributeModifiers` is a list, iterate its compounds, decode with `EntityAttributes.fromNbt`, and include valid modifiers whose UUID has both least and most significant bits nonzero. It keys by `AttributeName`. The method has no equipment-slot parameter and ignores any `Slot` field. When the list is absent, it returns `Item.getDefaultAttributeModifiers()`.
- 1.9 / 1.9.1 / 1.9.2 `ItemStack.java`, `getAttributeModifiers(EquipmentSlot)`, lines 696–717; 1.9.3 / 1.9.4, lines 700–721: same decode and UUID validity gates, but now a modifier is included only if `Slot` is absent or its string equals the queried slot's `getKey()`. No `Slot` remains a wildcard. If no `AttributeModifiers` list exists, defaults are requested with that slot. The 1.9–1.9.2 files have identical local `ItemStack.java` hashes; 1.9.3 and 1.9.4 also have identical hashes, so these five available source copies show no later change in this operation. Provenance gap above remains.
- 1.9.4 `ItemStack.java`, `addAttributeModifier`, lines 723–740: serializes the modifier plus `AttributeName`, and writes `Slot` only for a non-null slot. This supports slot-bearing/custom stack data; it does not establish that survival-generated stacks receive movement-speed modifiers.
- 1.8.9 `LivingEntity.java`, `writeCustomNbt`, lines 376–388, and equipment-change slice lines 1274–1289: temporarily remove equipped-stack modifiers while serializing entity attributes, then restore them; on changed equipment, remove old-stack modifiers and add new-stack modifiers. Both use the no-slot stack lookup. 1.9.4 `LivingEntity.java`, `writeCustomNbt`, lines 432–446, and equipment-change slice lines 1508–1535: same lifecycle, iterating each `EquipmentSlot` and passing that slot to both remove/add lookups. On a changed slot, the server sends the equipment packet and replaces the per-slot cached stack after applying the queried modifier set.
- Both endpoint `PlayerEntity.java` use a base movement-speed attribute of `0.1F` (1.8.9 line 134; 1.9.4 line 155). `getSpeed()` reads `(float)this.getAttribute(EntityAttributes.MOVEMENT_SPEED).get()` (1.8.9 lines 1298–1300; 1.9.4 lines 1393–1395). In 1.9.4 `LivingEntity.travel`, lines 1356–1374, on ordinary land movement the on-ground branch computes `t = 0.16277136F / (s*s*s)`, then `u = this.getSpeed() * t`, then calls `updateVelocity(sideways, forwards, u)` before moving. Thus an equipped modifier that changes the player's movement-speed attribute reaches a normal grounded acceleration input. This is a bounded source-path witness; no trajectory or numeric end-state is claimed.
- `rg` over each endpoint's entire `net/minecraft/item` source found no `generic.movementSpeed` or `MOVEMENT_SPEED` item-source references. Thus ordinary built-in item default modifiers do not contribute movement speed in these versions. In both ItemStack implementations, presence of an `AttributeModifiers` list selects that list instead of default item modifiers; externally supplied custom item NBT can therefore carry an arbitrary attribute name such as movement speed, subject to successful modifier decoding and UUID validation. In 1.8.9 such a valid modifier is accepted regardless of an attached `Slot`; from 1.9 onward, a present slot string must match the equipment slot. Slotless external modifiers continue to apply in any queried slot.

## Difference and movement meaning

The independently observed source change is equipment-slot selection for stack NBT attribute modifiers: 1.8.9 applies valid listed modifiers without checking `Slot`; 1.9.0 onward accepts only a missing `Slot` or exact slot-name match. For a custom NBT stack containing a valid movement-speed modifier tagged for a different equipment slot, the 1.8.9 equipment lifecycle adds that modifier at the slot where the stack is equipped, whereas 1.9+ filters it out at that slot. If the tag matches, or `Slot` is absent, the attribute remains eligible and the player's movement-speed read can affect ordinary on-ground acceleration as described above. Vanilla obtainable default item definitions provide no movement-speed modifier; the evidenced movement case is limited to custom/external stack NBT.

No finer patch boundary is claimed from this evidence. The available 1.9.x source copies contain the slot filter, but provenance is absent for 1.9–1.9.3; treat introduction as unknown within 1.8.9–1.9.4 until exact-run source identities for those versions are closed.
