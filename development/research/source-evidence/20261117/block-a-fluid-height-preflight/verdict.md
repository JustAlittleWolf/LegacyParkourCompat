1. **`comparison.corrected-r1.md` — ACCEPT.** `1.15.2 Entity.checkAndHandleWater` returns on the six-integer preflight before assigning primitive `waterHeight`; `updateInWaterState` clears `wasInWater` but not that primitive. `1.16.0` first adds `fluidHeight.clear()` before its water/lava sampler calls, and the clear remains in every inspected patch through `1.16.5`. The `LivingEntity.aiStep` jump branch reads positive `waterHeight` without requiring `isInWater`, and the local input path supplies `jumping` before that branch. The proposed lower-bound witness is physically reachable in a void/map setup with vanilla water at Y=0: a long fall can supply downward velocity below the roughly 2.8-block threshold; the water branch moves before applying drag; on the next base tick the integer gate can reject the wholly-below-zero scan, leaving the prior positive depth; a normal jump input then adds the water jump impulse. `LocalPlayer.tick` admits the player through `hasChunkAt(BlockPos(x,0,z))`, and `ClientLevel.hasChunk` returns true, so the out-of-height local tick continues. At 1.16 the per-tick clear leaves depth zero, so this stale-water branch is absent. The witness is conditional on the map's lower-bound water placement; it is not a claim about generated terrain.

2. **`fluid-sampler-build-height-guard.corrected-r1.md` — ACCEPT as an operation-level source change, with its no-finding disposition.** The six-integer sampler preflight persists through 1.16.5; in 1.17.0 the method first calls `touchingUnloadedChunk()`, which inflates the box and checks X/Z via the four-integer `LevelReader.hasChunksAt` overload. That overload checks section coordinates through `hasChunk`; all surveyed `ClientLevel.hasChunk` implementations return true. Thus the X/Z test cannot reject an ordinary local-client player. For the former Y-only rejection, the old sampler's Y iteration has no in-height cells; the new scan sees no fluid outside the same dimension height bounds, and the ordinary wrapper clears its fluid-height map before sampling. Its out-of-height scan writes zero. This is a predicate rewrite with no distinct ordinary-client movement result through the wrapper, so it should not be submitted as an independent movement finding.

3. **`water-height-stale-preflight.corrected-r1.md` — ACCEPT as a separate conditional movement difference.** The source order and numeric witness are supported, including the rounded bounds (`floor(deflated.minY)`, `ceil(deflated.maxY)`), strict preflight comparisons, Player's standing dimensions, fall update, move-before-drag order, local tick admission and the `+0.04F` liquid-jump impulse.
