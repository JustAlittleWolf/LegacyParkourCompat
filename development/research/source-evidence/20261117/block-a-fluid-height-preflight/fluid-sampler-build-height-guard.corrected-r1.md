# Loaded-box fluid preflight: corrected r1 disposition
1.16.5, Mojmap: `net/minecraft/world/entity/Entity.java`, `updateFluidHeightAndDoFluidPushing(Tag<Fluid>, double)`, lines 2641-2652; `net/minecraft/world/level/LevelReader.java`, six-int `hasChunksAt`, lines 168-186; `net/minecraft/client/multiplayer/ClientLevel.java`, `hasChunk`, lines 265-267.
1.17.0, Mojmap: `net/minecraft/world/entity/Entity.java`, `updateFluidHeightAndDoFluidPushing(Tag<Fluid>, double)` and `touchingUnloadedChunk()`, lines 2771-2783, 2838-2845; `net/minecraft/world/level/LevelReader.java`, four-int `hasChunksAt`, lines 190-205; `net/minecraft/client/multiplayer/ClientLevel.java`, `hasChunk`, lines 215-217.
Difference: 1.16.5 passes floor(min XYZ)/ceil(max XYZ) of the deflated box into the six-int `hasChunksAt`; its default checks `maxY >= 0 && minY < 256`, then checks XZ chunks. 1.17.0 replaces it with a 1-block inflated-box XZ-only check. This is the first assigned exact release with the four-int call; it remains in 1.17.1. The release-level boundary is 1.16.5 to 1.17.0.
Movement meaning: `ClientLevel.hasChunk` returns true in both releases, so neither old nor new XZ test rejects ordinary local-client entities. If the old Y guard fails, the scan would visit no in-height block Y. In 1.16+, the ordinary wrapper clears `fluidHeight` before sampling; the old rejection leaves zero, while the new scan receives empty states out of build height and writes zero. The Y change therefore has no distinct ordinary-client movement result through that caller. Treat this as a source-level predicate change, not an accepted independent movement finding.
