# Active-flying player bubble-column callbacks

1.21.1, Mojmap: `decompiled_minecraft/1.21.1/mojmap/net/minecraft/world/entity/player/Player.java` (full file inspected; no bubble callback override); `AbstractClientPlayer.java:18` and `LocalPlayer.java:92` establish that `LocalPlayer` inherits `Player`. `Entity.java:2357-2380` contains the inherited callbacks. `BubbleColumnBlock.java:49-76` dispatches to the above or inside callback according to whether the block above is air.

1.21.2, Mojmap: `decompiled_minecraft/1.21.2/mojmap/net/minecraft/world/entity/player/Player.java:355-366`; `AbstractClientPlayer.java:17` and `LocalPlayer.java:92`; inherited formulas in `Entity.java:2455-2478`; dispatch in `BubbleColumnBlock.java:50-77`.

Difference: 1.21.1 `Player` inherits both entity callbacks, so its above-column callback writes Y velocity (`max(-0.9, y - 0.03)` when dragging down, otherwise `min(1.8, y + 0.1)`), and its inside-column callback writes Y velocity (`max(-0.3, y - 0.03)` when dragging down, otherwise `min(0.7, y + 0.06)`) then resets fall distance. In 1.21.2, `Player.onAboveBubbleCol` and `Player.onInsideBubbleColumn` both call `super` only under `!this.getAbilities().flying`. For a local player whose active `abilities.flying` bit is true, both inherited velocity responses are skipped; the inside callback's fall-distance reset is skipped with its guarded `super` call. With the bit false, both continue to the inherited responses. The callback formulas and block's above-air dispatch condition are unchanged across this adjacent pair.

Reachability: 1.21.2 `LivingEntity.java:2774-2775` applies block effects on the logical server or for the locally controlled client instance. `Entity.java:1038-1061` traverses candidate blocks, gets the entity-inside collision shape, and calls `entityInside`. `BlockBehaviour.java:350-355` supplies `Shapes.block()` by default; the traversal permits that exact shape (`shape != Shapes.block() && ...` is the skip condition). `BubbleColumnBlock` inherits this default and therefore reaches its callback dispatch on the local client path.

The separate 1.21.1 and 1.21.2 `Player.isPushedByFluid()` predicate returns `!abilities.flying`, but the bubble block directly calls the bubble callbacks. Fluid-current eligibility is not the callback gate. This claim uses the active `flying` state; flight permission (`mayfly`) and flight-toggle/conversion behavior are outside this finding.
