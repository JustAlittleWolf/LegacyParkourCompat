## Shape transition and exact source citations

- **1.21.4:** `BlockBehaviour.getEntityInsideCollisionShape(BlockState, BlockGetter, BlockPos)` defaults to `Shapes.block()` (`BlockBehaviour.java` 353–355), and `BlockBehaviour.BlockStateBase.getEntityInsideCollisionShape(Level, BlockPos)` dispatches to the block (`BlockBehaviour.java` 744–745). `NetherPortalBlock` defines a thin outline shape for rendering/ordinary shape queries (`NetherPortalBlock.java` 47–69) but has no inside-contact override. `Entity.checkInsideBlocks` gathers non-air swept candidates, resolves the inside shape, then skips the narrow test only for the full-cell sentinel before calling `entityInside` (`Entity.java` 1050–1084); the portal callback is `NetherPortalBlock.entityInside` 104–108. Registration remains `.noCollission()` (`Blocks.java` 2024–2030).
- **1.21.5:** `NetherPortalBlock.getEntityInsideCollisionShape(BlockState, BlockGetter, BlockPos, Entity)` is added at 67–69 and returns the portal's outline. The outline is `Shapes.rotateHorizontalAxis(Block.column(4.0, 16.0, 0.0, 16.0))` (`NetherPortalBlock.java` 49, 61–69); `Block.column` divides the two horizontal dimensions by 2 and builds the 4/16-wide, full-height column (`Block.java` 168–175); `Shapes.rotateHorizontalAxis` rotates that narrow axis (`Shapes.java` 344–350). For an X-axis portal its narrow Z interval is [6/16, 10/16]; for a Z-axis portal its narrow X interval is [6/16, 10/16]. `Entity.checkInsideBlocks` gets the inside shape and requires either the full-cell sentinel or `collidedWithShapeMovingFrom` before callback (`Entity.java` 1079–1120, 1129–1133). `AABB.collidedAlongVector` inflates each target by source half-extents, accepts start/end center containment, otherwise clips the center segment (`AABB.java` 391–406). Portal registration is still `.noCollission()` (`Blocks.java` 2084–2090).
- **1.21.6 first removal:** `NetherPortalBlock` has no `getEntityInsideCollisionShape` override (verified absence in the exact file, SHA above). The block default accepts the entity parameter and returns `Shapes.block()` (`BlockBehaviour.java` 314–316); `BlockStateBase` dispatches it (`BlockBehaviour.java` 659–661). The collector-based entity scan keeps the full-cell bypass, then calls the portal's `entityInside` only after acceptance (`Entity.java` 1113–1162). `NetherPortalBlock.entityInside` remains gated by `canUsePortal(false)` and directly calls `setAsInsidePortal` (`NetherPortalBlock.java` 102–106). The same absent override and byte-identical `NetherPortalBlock`, `BlockBehaviour`, `Entity`, `Block`, and `Shapes` files persist in 1.21.7 and 1.21.8.

## Reachable local-player witness and dependency closure

The static geometry witness is a dry standing player of width 0.6, on supported ground with feet inside the portal cell, center 0.05 from the nonslab side of the cell, and sufficiently short/stationary movement. The AABB's 0.3 half-width reaches 0.35, outside the X-axis portal slab beginning at 0.375. The end-box deflation by `1.0E-5F` does not change overlap with the portal cell. `BlockGetter.boxTraverseBlocks` starts from `BlockPos.betweenClosed(endBox)` for movement length squared below `Mth.square(0.99999F)` (`BlockGetter.java` 172–176 in all releases). Player width comes from `Player.getDimensions` (`Player.java` 136–146 in .4, 137–147 in .5, 146–157 in .6–.8); `EntityDimensions.makeBoundingBox` uses half the float width (`EntityDimensions.java` 15–23 in .5). The Z-axis case rotates the same setup.

On .4–.5 the full-cell contact invokes the portal callback; on .5 the slab-only shape rejects this position; on .6+ the restored default full-cell sentinel accepts it. The block-scan caller runs after movement through `Entity.checkInsideBlocks` (`Entity.java` 752–762 in .4, 792–801 in .5, 824–834 in .6–.8); its `isAffectedByBlocks` gate excludes removed/no-physics entities (`Entity.java` 781–782, 817–818, 851–852 respectively). The local-player path is live: in .4 `Entity.isControlledByLocalInstance` delegates to `isEffectiveAi` (`Entity.java` 3173–3183) and `LocalPlayer.isEffectiveAi` returns true (`LocalPlayer.java` 483–485); in .5+ `Entity.isLocalInstanceAuthoritative` dispatches through `Player.isLocalClientAuthoritative` to `isLocalPlayer` (`Entity.java` 3162–3168; `Player.java` 1312–1318 in .5 and 1324–1330 in .6; `LocalPlayer.isLocalPlayer` returns true at 348 in .5 and 342 in .6–.8). The callback gate is `Entity.canUsePortal(false)` (alive and not a passenger) plus `LivingEntity.canUsePortal`'s not-sleeping condition (`Entity.java` 2786, `LivingEntity.java` 3375–3376 in .4; `Entity.java` 2965 and `LivingEntity.java` 3422–3423 in .6). A successful callback sets/updates `PortalProcessor` and marks contact for that tick (`Entity.java` 2242–2253 in .4, 2378–2389 in .6; `PortalProcessor.java` 15–38, 52–69).

For a concrete local consequence common to these versions, open the normal survival inventory while contact is pending and keep the physical jump key held through the next local input sample. The ordinary inventory key opens `InventoryScreen` (`Minecraft.java` 1840–1845 in .4, 1861–1866 in .5, 1872–1877 in .6–.8); `InventoryScreen` extends `AbstractRecipeBookScreen`, which extends `AbstractContainerScreen`; the latter returns `false` from `isPauseScreen` (1.21.4/.5 `AbstractContainerScreen.java` 666–668, .6–.8 668–670). `LocalPlayer` processes the prior portal flag and closes an eligible non-pausing screen before its next `input.tick()` (`LocalPlayer.java` 642–663 and 844–866 in .4; 682–703 and 870–892 in .5–.8). Inventory closure sends `ServerboundContainerClosePacket` then closes the screen locally (`LocalPlayer.java` 315–323 in .4, 311–319 in .5, 305–313 in .6–.8); the server handler delegates to `doCloseContainer` (`ServerGamePacketListenerImpl.handleContainerClose`, .4 1669–1672, .5 1750–1753, .6–.8 1764–1767), with no player position or velocity write in that handler. In `Minecraft.setScreen`, opening a screen releases mouse capture and key mappings; closing it grabs the mouse when the active window permits (`Minecraft.java` 1030–1068 in .4, 1052–1089 in .5, 1064–1101 in .6–.8). Since the inventory screen released capture, active-window `MouseHandler.grabMouse` invokes `KeyMapping.setAll` only when the mouse is currently ungrabbed and the OS is not macOS (1.21.4 359–364, .5–.8 398–403); `KeyMapping.setAll` repolls bound KEYSYM keys from the active window (`KeyMapping.java` 55–58). `KeyboardInput.tick` then samples the key mapping (`KeyboardInput.java` 22–31 in .4/.5, 23–32 in .6–.8). LocalPlayer copies the sampled jump state into `jumping` (`LocalPlayer.serverAiStep` 607–617 in .4; `LocalPlayer.applyInput` 608–621 in .5–.8); the ordinary grounded living jump gate calls `jumpFromGround` (`LivingEntity.aiStep` 2739–2753 in .4, 2725–2739 in .5, 2777–2791 in .6–.8), increasing Y velocity consumed by travel. This is a source-supported reachable local input/movement consequence; it predicts the local jump path and is not runtime validation or a claim about server acceptance under all correction timing.

- Generic scanner traversal is separately bounded: the .4 movement list carries old-to-current movement; .5 uses resolved individual-axis batches and fallback/remainder; .6–.8 record/replay aggregate movement with recomputed delta and queue coalescing at the 100-item boundary. The short-motion endpoint candidate geometry is retained; .6 adds visitor abort on entity death. These scanner differences were not exhaustively audited for independent high-speed, axis-recomposition, or queue-edge movement effects and remain outside these two shape findings.
- No full-pair tick inventory, independent blind coverage audit, implementation review, or runtime parity gate is closed by this checkpoint.
