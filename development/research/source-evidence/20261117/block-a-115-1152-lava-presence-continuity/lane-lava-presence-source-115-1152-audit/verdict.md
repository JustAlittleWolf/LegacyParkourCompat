## Claim checks

- **Latch production and bypass:** `Entity.move` bypasses the latch producer in the `noPhysics` branch; a piston move limited to `Vec3.ZERO` returns before the reset/callback. Otherwise the reset occurs immediately before `checkInsideBlocks` (`Entity.java:450–461, 533–541`). Thus `noPhysics` movement leaves the existing field untouched; a zero-limited piston move also returns without recomputing it. A normal move clears `isInLava`, then callback visits can set it again.
- **Bounds and loaded gate:** `checkInsideBlocks` uses the post-move AABB; each min coordinate is inset by `0.001`, each max coordinate is inset by `0.001`, then pooled block positions floor those coordinates. It requires `hasChunksAt(min,max)` and iterates inclusive x/y/z block coordinates, calling `BlockState.entityInside` and `onInsideBlock` (`Entity.java:791–824`; `BlockPos.java:411–413`; `Mth.java:50–53`). No fluid-height or block-shape intersection gate appears in this callback loop. An unloaded checked region skips the loop after the preceding reset, so the flag remains false for that ordinary move.
- **Block callback:** `BlockState.entityInside` forwards to its block (`BlockState.java:248–250`). `Blocks.LAVA` is a `LiquidBlock` using `Fluids.LAVA` and `noCollission()` (`Blocks.java:94–96`). `LiquidBlock.entityInside` only checks whether its configured fluid is tagged lava and calls `setInLava`; it does not test the passed state, position, AABB height, or fluid surface (`LiquidBlock.java:171–175`). The generated fluid tag includes source and flowing lava (`FluidTagsProvider.java:17–21`).
- **Surface witness:** the lava block's default level is zero and the constructor puts `getSource(false)` at fluid-state index zero (`LiquidBlock.java:36–48`); `Fluids.LAVA` is `LavaFluid.Source` (`Fluids.java:10`); its amount is 8 and it reports source (`LavaFluid.java:233–242`). With no same fluid above, `FlowingFluid.getHeight` returns own height, `amount / 9.0F` (`FlowingFluid.java:465–477`; `FluidState.java:30–47`). Thus the source cell at y=64 has surface `64 + 8/9`. For an AABB with `minY=64.90`, the inset lower coordinate still floors to 64 and the visited cell includes the lava source despite the feet being above that fluid surface. The callback is block-cell overlap, not submersion.
- **Local timing and jump:** `LocalPlayer.tick` is gated by the loaded x/z chunk, then calls `super.tick`; `LivingEntity.tick` calls `super.tick` before `aiStep`, and `Entity.baseTick` updates water state and consumes the prior movement's lava flag first (`LocalPlayer.java:179–196`; `LivingEntity.java:2024–2025, 2103`; `Entity.java:340–384`). Local `aiStep` updates input and may synthesize auto-jump before calling `Player.aiStep`; dynamic dispatch reaches `LivingEntity.aiStep`. The local player reports effective AI; when mobile, `LivingEntity.aiStep` invokes `serverAiStep`, and `LocalPlayer.serverAiStep` copies current input jump only when it controls the camera (`LocalPlayer.java:490–492, 607–622, 631–648, 778`; `Player.java:497–517`; `LivingEntity.java:2253–2264`). The held-jump section then consults `waterHeight` before `isInLava`; on the stated loaded source-lava witness with no water, `waterHeight=0`, so lava selects `jumpInLiquid`, which adds `0.04F` vertical movement (`LivingEntity.java:1823–1825, 2265–2277`). The jump check precedes this tick's travel move, so it reads the flag produced by a preceding move.
- **Travel:** for a non-swimming, non-flying player, `Player.travel` delegates to `LivingEntity.travel` (`Player.java:1455–1486`; 1.15.2 shifts this method to `1447–1478`). The lava branch is selected after the water branch and excludes flying players. It applies `moveRelative(0.02F, input)`, moves, halves delta, applies `-d/4` vertical gravity when gravity is enabled, and applies the conditional `0.3F` vertical collision lift (`LivingEntity.java:1840–1842, 1913–1925`). The move recomputes the latch after the current tick's jump/travel branch. The local player reaches travel through `isEffectiveAi()`; `isControlledByLocalInstance()` is an additional valid entry condition for controlled instances, but is not needed for the ordinary on-foot local-player witness.
- **Separate height state:** `updateWaterState` calls the separate water-contact routine. `checkAndHandleWater` iterates fluid states in a deflated AABB, measures height through `FluidState.getHeight`, and assigns `waterHeight` only after its own loaded-region check succeeds (`Entity.java:943–972, 2593–2655`). This distinguishes the water-depth arbitration in the jump path from the block-cell lava flag.

Across the 78 recorded numbered slices, the method text is identical across all three exact releases. The source-file hashes show some whole-file differences in 1.15.2, but the assigned operation slices remain identical. The bounded no-difference conclusion and its limits in the candidate comparison are accurate.
