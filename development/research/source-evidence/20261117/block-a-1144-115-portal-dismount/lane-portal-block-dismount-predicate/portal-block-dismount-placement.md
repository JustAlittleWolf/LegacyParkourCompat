# Portal-block dismount placement

1.14.4, Mojmap: `net/minecraft/world/entity/LivingEntity.java`, `findStandUpPosition(Entity)` lines 1664–1741 and `stopRiding()` lines 2324–2331; `net/minecraft/world/entity/player/Player.java`, `rideTick()` lines 455–459.
1.15, Mojmap: `net/minecraft/world/entity/LivingEntity.java`, `findStandUpPosition(Entity)` lines 1697–1792 and `stopRiding()` lines 2388–2395; `net/minecraft/world/entity/player/Player.java`, `rideTick()` lines 458–463.
Difference: 1.14.4 chooses dismount placement by vehicle type and nearby standable space without checking portal state. 1.15 first checks whether the block at the vehicle's current position belongs to `BlockTags.PORTALS`; when true it sets the dismounting living entity to the vehicle's x/z and `vehicle.getY(1.0) + 0.001`, regardless of portal origin. `LivingEntity.stopRiding()` invokes placement only after an actual detach and only when `!level.isClientSide`; ordinary server-side player sneaking/shift dismount reaches it. A packet-driven `LocalPlayer` detach does not run this placement because that same side gate prevents the local invocation from calling `findStandUpPosition`.
Movement meaning: server-side player dismount position can change when the vehicle occupies a portal-tagged block, even for a non-portal-origin detach. This is not local-client XYZ emulation or portal dimension transport. Exact checked boundary is 1.14.4 without the branch versus 1.15 with it; introduction is unknown within that interval.
