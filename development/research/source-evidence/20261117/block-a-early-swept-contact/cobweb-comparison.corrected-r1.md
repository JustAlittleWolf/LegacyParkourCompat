# Local player block-contact path: corrected revision 1

Scope: exact Mojmap sources, 1.21 through 1.21.4; steady ordinary client LocalPlayer movement with vanilla block contact. This report accepts one operation finding for 1.21.1 → 1.21.2. It is not full pair coverage or runtime evidence. No wiki, product implementation, or Git history was consulted.

## Callback timing and position source

In 1.21.1, `Entity.move` resolves collision and updates the position, then calls `tryCheckInsideBlocks()` at `Entity.java:705`; the current move's start-of-method stuck-multiplier consumption has already passed. After this scan, `move` applies `getBlockSpeedFactor()` to horizontal delta movement at lines 706–707. `checkInsideBlocks` scans only the current final bounding box, skips the whole scan unless `level.hasChunksAt(min,max)`, and iterates X outermost, Y next, Z innermost; each state receives `entityInside` followed by `onInsideBlock` (`Entity.java:1001–1031`). There is no swept path scan.

In 1.21.2, `Entity.move` no longer calls the callback scan. `LivingEntity.aiStep` calls `travel`, then calls `applyEffectsFromBlocks()` under `!level.isClientSide() || isControlledByLocalInstance()` (`LivingEntity.java:2755–2777`). LocalPlayer delegates to `super.aiStep()` (`LocalPlayer.java:795`), so the local-instance branch covers the ordinary local client player. `ClientLevel.tickNonPassenger` calls `setOldPosAndRot()` before `tick()` (`ClientLevel.java:269–274`); the no-argument `applyEffectsFromBlocks()` then uses `oldPosition()` to current `position` (`Entity.java:736–749, 1501–1503`). `oldPosition()` is `(xOld,yOld,zOld)`, and this is the pre-tick to post-travel segment.

A full vanilla source-tree search in 1.21.2–1.21.4 finds no client movement caller of `recordMovementThroughBlocks`; the two call sites are in server packet handling. Ordinary LocalPlayer therefore checks the single default old-position-to-current-position segment, which represents net displacement rather than recording each internal move. `applyEffectsFromBlocks` first invokes `stepOn` for the support block when grounded, then appends/checks the movement segment; it runs after travel returns. The next ordinary LocalPlayer travel move is on the following tick: the pre-travel `moveTowardsClosestSpace` calls change delta movement only (`LocalPlayer.java:401–427, 674–677`), and ordinary travel performs the move before the callback. The 1.21.1 callback also occurs after its current `move` displacement. A same-tick follow-up move could consume a multiplier set by the old in-move callback only for a caller that actually invokes `move` again that tick; this was not established for steady LocalPlayer. Do not claim same-tick consumption for the LocalPlayer witness.

## Swept candidates, strict threshold, and DDA cap

For 1.21.2 and 1.21.3, `BlockGetter.boxTraverseBlocks(from,to,box)` first computes `delta = to.subtract(from)` and falls back to final-box cells only when `delta.lengthSqr() < Mth.square(0.99999F)` (`BlockGetter.java:172–189`). `Mth.square(float)` performs a float multiply (`Mth.java:598–600`), giving binary32 threshold `0x3F7FFEB0` = `0.99997997283935546875`; equality enters swept traversal. The corresponding magnitude is about `0.99998998637`. Squared displacement above that value enables path candidates but alone does not prove a body can be outside a unit block at both endpoints.

The 1.21.2/1.21.3 swept path applies a normalized direction offset of `1.0E-7` at its min-corner endpoints, inserts swept candidates into `ObjectLinkedOpenHashSet` first, then appends immutable final-box cells from `BlockPos.betweenClosed` (`BlockGetter.java:179–189`). Candidate insertion order is retained and duplicate cells are suppressed. In the DDA, the coordinate for the next crossing is advanced, then `if (counter++ > 16) break` executes before cube clipping; at most 17 cells reach the clip and entity-extent enumeration. Each clipped/contact point is clamped inside its cube and entity extents are enumerated X outermost, Y next, Z innermost (`BlockGetter.java:192–245`). Final-box iteration from `BlockPos.betweenClosed` has X fastest-changing, then Y, then Z (`BlockPos.java:397–418`).

`Entity.checkInsideBlocks` processes movement records in list order, uses one final AABB deflated by `1.0E-5F` for 1.21.2/1.21.3, skips air, and de-duplicates by packed block position. For each admitted position it obtains the entity-inside collision shape. Exactly `Shapes.block()` bypasses the extra moved-shape test; other shapes must pass `collidedWithShapeMovingFrom`. It dispatches `entityInside`, then `onInsideBlock`, then adds the state to the `blocksInside` set (`Entity.java:1038–1084`). There is no explicit `hasChunksAt` guard in this new scan; behavior at an unloaded client boundary was not tested.

## Reachable intermediate-only COBWEB witness

Exact vanilla facts: `Blocks.COBWEB` is `.noCollission()` (`Blocks.java:701–711`); the default entity-inside collision shape is `Shapes.block()` (`BlockBehaviour.java:353–355`); `WebBlock.entityInside` sets stuck speed to `(0.25, 0.05F, 0.25)` or `(0.5, 0.25, 0.5)` with Weaving (`WebBlock.java:26–33`). Because the shape is exactly `Shapes.block()`, the 1.21.2 path callback does not require ordinary collision or a successful separate shape-intersection test. The 1.21.1 final-box scan misses the cell when both endpoint boxes are outside it.

A concrete reachable free-fall source witness: put a COBWEB at block position `(0,0,0)` and center the standing player at `x=z=0.5`. The standing player box is 0.6 by 1.8 blocks (`Player.java:136–140`). Assume an open shaft, initial vertical velocity zero, no horizontal input, no collision, no fluid, no levitation or slow falling, no flying/fall-flying, no no-gravity, and ordinary gravity/friction. The default gravity attribute is `0.08` (`Attributes.java:41–43`; `LivingEntity.java:2168–2175`). Air travel moves using the current vertical velocity, then subtracts gravity and multiplies by `0.98F` (`LivingEntity.java:2191–2213`), so from zero the recurrence after each prior tick is `v[n+1] = 0.98F * (v[n] - 0.08)`. After 72 updates, `v` is approximately `-3.00470152646`; the next movement segment is approximately `(0, -3.00470152646, 0)`. Start that segment with feet at `y=1.1` and head at `y=2.9`; it ends with feet at about `-1.90470152646` and head at about `-0.10470152646`. Both endpoint boxes lie outside the COBWEB cell, while the body crosses it. The squared displacement is well above the strict cutoff and the segment crosses far fewer than 17 DDA cells. This is reachable from a starting height about 133.1051 in an open shaft; this trajectory is source-derived and not runtime-tested.

At the start of a later `Entity.move`, a nonzero stuck multiplier scales that move request, is cleared, and delta movement is zeroed (`Entity.java:633–637` in 1.21.2). Since ordinary LocalPlayer has no client-side segment recorder and its callback runs after travel, the witness multiplier is available to the next travel move on the next tick. In 1.21.1, the same web callback would run inside each `move` only if the final box includes COBWEB; with both endpoint boxes outside, this path witness does not set the multiplier. For other callers, old in-move callback timing can feed a later same-tick move only if such a later call occurs; this remains a conditional, not a demonstrated generic trajectory.

## Adjacent-release checks and 1.21.4 caveat

- 1.21 → 1.21.1: relevant LocalPlayer, Entity, LivingEntity, BlockGetter, WebBlock, BlockBehaviour, and Blocks sources are byte-identical by the earlier lane's recorded SHA-256 values; no delta in this operation was found.
- 1.21.1 → 1.21.2: callback timing and path traversal change as above; exact introduction is bounded to these releases.
- 1.21.2 → 1.21.3: the relevant callback, movement segment, and traversal sources are byte-identical by SHA-256; no delta in this operation was found.
- 1.21.3 → 1.21.4: callback remains after travel and the strict threshold and 17-cell cap remain. Geometry changes in both `Entity` and `BlockGetter`: 1.21.2/1.21.3 use one current final AABB for all movement records and reconstruct the prior collision box; 1.21.4 constructs a per-segment destination AABB and tests from a box at that segment's start (`Entity.java:1038–1096` vs `1050–1096`). Also, 1.21.2/1.21.3 offset path endpoints by normalized direction times `1.0E-7`, while 1.21.4 uses the unoffset box min and box min minus delta (`BlockGetter.java:179–183` vs `179–182`). This can matter on boundary-sensitive paths; exact set equality is not claimed for those or multi-segment/pose-changing cases. The non-boundary single-segment COBWEB witness above remains admitted by 1.21.4 source because the path is swept and the default shape bypass remains.

`applyEffectsFromBlocks` consumes the live movement list and clears it after traversal in 1.21.2/1.21.3 (`Entity.java:740–752`); 1.21.4 snapshots it and clears the original before callbacks (`Entity.java:751–764`). This matters if a callback appends movement during processing, but ordinary LocalPlayer has no vanilla client caller that does so; it does not add a second local movement segment to this witness.
