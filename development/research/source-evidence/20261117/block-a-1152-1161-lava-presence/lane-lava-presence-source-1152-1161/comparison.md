## Lane 1: local lava-presence producer and fluid-volume cache

1.15.2 `Entity.isInLava` is a boolean field (`Entity.java:156`); `setInLava` sets it true (`Entity.java:1055-1057`) and the predicate returns it (`Entity.java:1059-1060`). Each `Entity.move` block-collision pass clears it immediately before `checkInsideBlocks` (`Entity.java:534-535`). `checkInsideBlocks` visits block coordinates covered by the current bounding box, inset 0.001 at each face, if those chunks are loaded (`Entity.java:795-826`). `LiquidBlock.entityInside` then sets lava presence for every lava fluid block callback without a height/AABB test (`LiquidBlock.java:171-174`). Thus the value is a collision-pass latch refreshed during movement, not a fluid-height cache.

1.16.1 retains that collision-pass latch with a renamed field `isTouchingLava` (`Entity.java:157`); `move` clears it immediately before `checkInsideBlocks` (`Entity.java:552-553`), and `isInLava` returns it (`Entity.java:1065-1071`). `LiquidBlock.entityInside` first checks lava, obtains `f = blockPos.getY() + blockState.getFluidState().getHeight(level, blockPos)`, then sets presence iff `aabb.minY < f || f > aabb.maxY` (`LiquidBlock.java:178-185`). For a non-inverted AABB the second disjunct implies the first, so the exact effective test is `aabb.minY < f`: the player’s bottom must be below the fluid surface in at least one lava block callback. Compared with 1.15.2, callback-level setting is now height-gated.

Separately, 1.16.1 adds/uses a per-tag `fluidHeight` map (`Entity.java:153-157`). At `baseTick`, `updateInWaterStateAndDoFluidPushing` clears it, refreshes water state/current first, returns early if in water, otherwise scans lava (`Entity.java:354-375, 947-959`). `updateFluidHeightAndDoFluidPushing` scans the 0.001-deflated bounding box after a `hasChunksAt` gate; for each fluid-tag cell it computes fluid surface `q + fluidState.getHeight(...)`, admits it when surface `>= aabb.minY`, and accumulates max `surface - aabb.minY` into the cached height (`Entity.java:2633-2702`). The lava call’s current argument is 0.007 in ultra-warm dimensions, otherwise `0.0023333333333333335` (`Entity.java:954-955`); this affects fluid pushing, not the `isInLava` latch. The lava scan does not set `isTouchingLava`; direct presence still comes from the collision callback.

Distinguishing bounded witness: after a movement collision pass, place the local player’s AABB across a lava block cell while its bottom is at or above that cell’s fluid surface (`aabb.minY >= surface`). The 1.15.2 callback sets `isInLava` unconditionally; the 1.16.1 callback leaves the collision-pass flag false for that cell. If another callback does not set it, `isInLava()` therefore differs for subsequent code before the next movement collision pass. This is a source-level distinguishing precondition, not a simulated trajectory claim.

## Lane 2: direct locomotion consumers and tick handoff

LocalPlayer’s `tick` is chunk-gated and delegates to `super.tick()` in both versions (`client/player/LocalPlayer.java:179-183`); `Player.tick` delegates to `super.tick()` after player bookkeeping in both (`world/entity/player/Player.java:210-237` / `207-234`). The entity base tick refreshes lava fluid height in 1.16.1 before the later LivingEntity AI step/travel; 1.15.2 has no lava-height cache. `LivingEntity.aiStep` applies jump before `travel` in both (1.15.2 `LivingEntity.java:2260-2284`; 1.16.1 `LivingEntity.java:2418-2450`). During a travel/movement pass, `Entity.move` clears and recomputes the collision latch, so that newly computed `isInLava` is handed to later movement/jump calls; the jump at the beginning of the same AI step reads the value latched by the preceding movement pass.

- 1.15.2 jump: whenever `jumping`, the water-height threshold branch is considered; if the branch selects the non-water case and `isInLava()` is true, `jumpInLiquid(LAVA)` adds `0.04` Y, otherwise eligible ground/water-edge jumping uses `jumpFromGround` (`LivingEntity.java:2267-2278`). There is no `isAffectedByFluids` gate on this jump block.
- 1.16.1 jump: entire jump operation requires `jumping && isAffectedByFluids()` (`LivingEntity.java:2425-2449`). It selects `k` from cached lava height when in lava, otherwise cached water height; uses `getFluidJumpThreshold()` (0 for eye height <0.4, else 0.4; `Entity.java:2704-2706`) and on-ground/depth gates before lava `+0.04` or ground jump. Player’s `isAffectedByFluids()` is `!abilities.flying` (`Player.java:1005-1007`).
- 1.15.2 travel: within effective-AI/local-control gate, normal/fall-flying movement is under `!isInLava() || player flying`; otherwise it takes a dedicated lava branch (`LivingEntity.java:1831-1838, 1900-1910`): add relative input at 0.02, move, scale all velocity by 0.5, apply `-d/4` gravity unless no-gravity, then use a horizontal-collision/free-space test to set Y to 0.3. Lava is not selected by a cached lava depth.
- 1.16.1 travel: the lava branch requires `isInLava() && isAffectedByFluids() && !canStandOnFluid(blockPosition fluid type)` after checking the water branch (`LivingEntity.java:1912-1914, 1957-1976`); default `canStandOnFluid` is false. It adds relative input at 0.02 and moves. If cached lava depth `<= getFluidJumpThreshold()`, it scales velocity `(0.5, 0.8, 0.5)` and applies falling-adjusted movement; otherwise scales the whole vector by 0.5. Then it applies `-d/4` gravity unless no-gravity and retains the horizontal-collision/free-space Y=0.3 escape. Player flight bypasses this via `isAffectedByFluids()==false`; Player.travel still invokes superclass travel then restores its flight Y behavior (`Player.java:1395-1415`).

The 1.16.1 source therefore carries two distinct inputs into locomotion: collision-latched `isInLava()` and base-tick cached fluid height. The latter changes vertical branch selection/attenuation at the 0.4-ish eye-height threshold. A bounded witness for the fluid-depth gate is a non-flying local player with `isInLava()==true` and lava surface depth on either side of `getFluidJumpThreshold()`: the 1.16.1 jump/travel branches change based on that cached depth, while the 1.15.2 lava path has no such depth split. This establishes branch reachability only; trajectory parity requires separate runtime verification.

## Disposition / coverage boundary

Candidate independent operations to reconcile: (a) `LiquidBlock.entityInside` -> collision-latched lava-presence predicate, and (b) `LivingEntity` lava jump/travel response using that predicate and (in 1.16.1) cached lava height. Source slices checked: Entity fields, base-tick update order, movement clear/collision callback handoff, LiquidBlock callback, lava fluid-height scan/cache, LivingEntity travel and jump, Player flying/fluids gates, and LocalPlayer chunk/tick delegation. No unrelated fluid, water locomotion, non-player behavior or other version pair was reviewed. This lane report supplies source findings only; peer audit and master reconciliation remain open.
