# Exact common registration and dispatch-owner crosswalk: 1.13.2 → 1.14.4

## Scope

Source-only exact-key inventory of built-in block registrations, old effective `getFaceShape` owners, target effective collision/shape dispatch, inherited state-property names and a product cardinality where the property domains are directly derivable from source declarations, and exact-key references in accepted bounded wall packets. It is not a geometry comparison and does not assert any wall-bit result outside those packets. Aliases/renames are not inferred: only exact common registry paths are joined.

The TSV records direct membership only; nested tag expansion is not inferred. Old tag membership is not available in this inventory.

## Exact denominator

The direct source registration scan found **598** 1.13.2 built-in keys (including `air` via the default registry key), **676** 1.14.4 built-in keys, and **596 exact common registry paths**. These common paths cover **155** old concrete classes and **147** target concrete classes. No duplicate key or unresolved registration class expression remained. String helper registrations use the default `minecraft` namespace, and the old default-key registration resolves to `minecraft:air`.

[`registered-key-dispatch-crosswalk.tsv`](registered-key-dispatch-crosswalk.tsv) has one row per exact common path. For target inherited base routes it records `Block.getCollisionShape`'s `hasCollision` gate then the nearest `getShape` owner. The `.noCollision()` column records only a literal registration expression marker; absence is not treated as proof of effective `hasCollision=true`, since subclass constructors can change properties.

State columns enumerate inherited `buildStateDefinition`/`appendProperties` builder fields and multiply directly resolved Boolean, integer-range, enum, and horizontal-direction domains. `?` indicates an unresolved property-domain cardinality; there are **91** exact common keys with at least one unknown property product. No property enumeration implies source-value or geometry parity.

## Existing bounded wall packet references

For each key the TSV lists exact-token references in `wall_*` packets. It marks a report as ledger-recognized only if the exact report path appears in the independently accepted [`wall_projection_coverage_ledger/coverage.md`](../wall_projection_coverage_ledger/coverage.md) SHA-256 `fd42e07a67e2b8d74d4b81342822301f4cb42e44b2bf4752f7d7d7ce3196e75abd`. A packet mention alone is not acceptance, and each packet's state/provider limits remain controlling. **45** keys have an exact-token mention in a wall report. By joining exact registered classes/keys to report-declared full-family scopes, **215** keys map to bounded accepted packet coverage, **20** keys map only to partial packet coverage, and **361** exact common keys remain unexamined for wall-bit projection. The TSV states the packet path, scope and evidence hash for each mapped key; it does not broaden the packet's own state/provider limits.

## Remaining gates

This closes the exact common-key registration denominator and the Java inheritance/dispatch owner roster for these endpoints only. Aliases and target-only/old-only keys remain separate. The table does not close complete state-domain values for every key (91 keys have unresolved products), dynamic/world/neighbor/context inputs, `WALLS`/`LEAVES` resources and fence/attachment exceptions as a per-key predicate, or shape values. Not every exact common key has an accepted wall-projection packet. Full tick/external/resource dependency closure, independent pair-wide behavior audit, and pair freeze remain open. This inventory asserts no overall wall predicate, movement difference, or trajectory.
