## Source comparison

- Old `SlabBlock` exposes `HALF` and `WATERLOGGED`; `SlabType` has `TOP`, `BOTTOM`, and `DOUBLE`. Its `getFaceShape` returns `SOLID` for `DOUBLE` on every face; for single slabs, only `TOP` on `UP` and `BOTTOM` on `DOWN` are solid. Thus for each horizontal face (`NORTH`, `EAST`, `SOUTH`, `WEST`), only `DOUBLE` returns `SOLID`. Waterlogging does not enter this method. Old `WallBlock.shouldConnectTo` accepts a solid face unless the block is one of its attachment exceptions; no residual slab class/key is among those exception classes/keys.
- Target `SlabBlock` registers the same two properties, and its collision `getShape` returns a full cube for `DOUBLE`, the upper half shape for `TOP`, and the lower half shape for `BOTTOM`; it does not branch on `WATERLOGGED`, world, position, or context. The state domain is therefore six combinations per key (`3 HALF × 2 WATERLOGGED`), correcting the crosswalk's undercounted `HALF:2` cardinality.
- Target `WallBlock` asks `Block.isFaceSolid` for the opposite horizontal face. `Block.isFaceSolid` rejects leaves and otherwise calls `isFaceFull` on the collision shape; `isFaceFull` extracts that face and checks whether it is a full block. For the three slab shapes, the four vertical faces are full for `DOUBLE`, and are only half-height for `TOP`/`BOTTOM`, so the target predicate is true exactly for `DOUBLE`. Target `WallBlock` separately accepts the `WALLS` tag or an eligible fence gate and rejects attachment-exception blocks. These slab keys are not in the target walls resource: the inspected `data/minecraft/tags/blocks/walls.json` payload (SHA-256 `f20174f51f66d27681fd9d469a77c86cae82012c0d9125e7d246c426b772391c`) lists wall block IDs and no slab; no slab is an attachment-exception class/key.
- Relevant source hashes: old `SlabBlock.java` `2e7ff3fcfa5faa83aa4af7ea9b68f07af8d8fe7047e08ee3a9d7d37b78c7128f`; target `SlabBlock.java` `91f2ebc592e5cb07d5ce8a6faa123ec0d4b7bf10aa6323d6aceb343bc0f73a53`; old `WallBlock.java` `aeb67adf292a3b750e72a7d2fdc13f7b42f8633c6183964d00dfe8d6960e07bf`; target `WallBlock.java` `033da2cef0973f5d380a81b53ee76e23324fffece72edc74e12fcee0d8764be7`; target `Block.java` `1f8ec3628f08e196c2793e91ca0b94feacea6bc3939e7fb770f0682a6e66f2c5`; both endpoint `SlabType.java` `20ef3591cf5f5cf83886d7ab5034fd8402418f68e517180cbba2fe0c7535f697`.

## Result and limits

Across all 15 keys, all six `HALF × WATERLOGGED` states, and four horizontal faces (360 state-face cases), the old `FaceShape`/wall exception predicate and target collision-full-face/attachment-tag predicate agree: `DOUBLE` connects; `TOP` and `BOTTOM` do not. Hence this residual exact-common slab slice has no wall-arm predicate delta. This does not cover state/world-dependent providers outside these `SlabBlock` registrations, non-slab keys, non-horizontal faces, other wall gates, or movement effects.
