## Provider and wall predicate comparison

- Old `Block.buildStateDefinition` is empty (`Block.java:713`), so each selected old generic registration has a singleton state. Old `Block.getFaceShape` returns `FaceShape.SOLID` unconditionally (`Block.java:383–385`); it does not inspect material, collision, world, position, or direction. Old `WallBlock.shouldConnectTo` accepts a non-exempt `SOLID` face (`WallBlock.java:51–54`). None of these 105 keys is an old attachment exception or old wall special case; the exception list at `WallBlock.java:57–66` names specialized/keyed alternatives outside this exact roster.
- Target `Block.getShape` returns `VoxelShapes.block()` (`Block.java:371–373`). `Block.getCollisionShape` returns the state shape when `hasCollision` is true and empty otherwise (`Block.java:376–378`); `Block.Properties.hasCollision` defaults to `true` (`Block.java:811`) and `.noCollision()` is the only property setter that flips it false (`Block.java:853–855`). Each selected target registry call is an exact `register("key", new Block(...))` call and contains no `.noCollision()`; all 105 calls were scanned as complete balanced registration expressions. Thus each target singleton has the full-cube collision shape and a full horizontal face.
- Target `Block.isFaceSolid` reduces to `isFaceFull(state.getCollisionShape(...), face)` for these non-leaf generic `Block` instances (`Block.java:402–408`). Target `WallBlock` accepts that result unless `isExceptionForAttachment` rejects the block (`WallBlock.java:48–51` and placement calls at `:67–70`). None of this roster is a `LeavesBlock`, barrier, pumpkin/melon exception, or `FenceGateBlock`. The accepted exact 1.14.4 `walls.json` resource has 14 wall IDs and no key in this roster: payload SHA-256 `f20174f51f66d27681fd9d469a77c86cae82012c0d9125e7d246c426b772391c`, extraction record SHA-256 `f26f84c7221f667cd84ff4e048d06b0fd3c3aec52779f3fbd0a8f4e2afe64fea`, independent resource verdict SHA-256 `6402c6af692b3f198c853d3558b91d4de7c215db793e8847e66e45f08f4d8898`.
