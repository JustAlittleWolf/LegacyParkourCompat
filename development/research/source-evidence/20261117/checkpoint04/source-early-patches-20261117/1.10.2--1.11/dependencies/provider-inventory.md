## Caller and dispatch boundary

1. `World.getCollisions(Entity, Box)` scans its expanded integer bounds; skips unloaded chunks under the existing edge-column rule; chooses actual state inside the border or the default `STONE` state for the entity's outside-border route; then invokes `BlockState.addCollisions(world, pos, query, output, entity)`. Entity-vs-entity AABBs are appended after block boxes. The compared method body has no pair difference (the exact pair coverage report already bounds its call loop).
2. `StateDefinition` is the dispatch adapter: `getCollisionShape` calls `block.getCollisionShape`, `addCollisions` calls `block.addCollisions`, `getShape` calls `block.getShape`, `isFullBlock` calls `block.isFullBlock`, and `resolveVirtualProperties` calls the block resolver. `Block.addCollisions` defaults to one state collision box. Its `addCollision` helper skips the `EMPTY_BLOCK_SHAPE` sentinel, translates a non-sentinel box by block position, and appends it only when it intersects the query. A subclass callback can instead append several boxes or filter on the entity argument.
3. Player-facing callers include `Entity.move` and `Entity.doesNotCollide` (via `World.getCollisions`), player pose resizing in `Entity`/`PlayerEntity`, and local-client auto-jump in `LocalClientPlayerEntity`. Auto-jump directly reads `BlockState.getCollisionShape`: null at the player-head block and the block above gates the attempt; it then scans the collision list, upward block collision shapes, and null/non-null shape predicates. The local-player method is still a special caller of this same state-provider API. `World.isFullCube` also reads a state's collision shape and accepts `box != EMPTY_BLOCK_SHAPE && box.getAverageSideLength() >= 1.0`; direct `BlockState.isFullBlock` callers use the separate provider below. These are movement-relevant query paths; visual outline boxes do not enter the `World.getCollisions` callback unless inherited `getCollisionShape` delegates to `getShape`.
4. Other world methods (`getBlockCollisions`, `getCollisions(Box)`, `World.isFullCube`, block ray tracing, and block placement/support predicates) reuse these providers but do not all have a local-player caller. Their provider observation is recorded without promoting non-player navigation or rendering consumers.

### Registered additions and exclusions

1.11 adds registered `ShulkerBoxBlock` instances (the colored registry rows in `Block.init()` / `Blocks` aliases). It is absent from 1.10.2 and is a 1.11-only mechanic for the 1.10.2 profile; its collision/push behavior is excluded from emulating the old release. `FlowerBlock` and the yellow/red flower registrations exist on both roots and are not new-only merely because the class has a marker. No other changed/additional class is promoted to an old-era provider without a 1.10.2 registry entry or inheritance route.

## Neighbor and callback gates

- `FenceBlock`, `PaneBlock`, `WallBlock`, `ChorusPlantBlock`, and `StairsBlock` resolve transient virtual connection/shape properties before producing collision boxes. Their resolver bodies are present at both endpoints and compare equal after signature normalization; connected-neighbor geometry therefore has no observed 1.11-only method change in these providers. The relevant property sets are directions (four horizontal directions for fence/pane/wall, six for chorus) and facing/half/shape for stairs.
- `World.getCollisions` passes the queried `Entity` all the way through the state adapter to each `addCollisions` callback. Among the inventoried common callbacks, `LilyPadBlock` excludes `BoatEntity` and otherwise appends its box; the other static callbacks listed above do not branch on `entity`, and the default callback also ignores it. Moving-block entity delegation receives it and is the unresolved exception in the changed provider chain. Entity collision boxes appended by `World` are separate from block-provider geometry.
- `getShape` is not always a collision shape: explicit-empty overrides win. Rails, banners, buttons, plants, signs, liquids, vines, tripwire, redstone wire, fire, portals and pressure plates can return visible/selection bounds while collision remains empty. The collision caller is `BlockState.getCollisionShape/addCollisions`, never an inferred render outline.

## Remaining exact source gate

The provider registry and dispatch path are enumerated, but full collision dependency closure is still blocked at the dynamic moving-block provider: `MovingBlock → MovingBlockEntity.getShape/addCollisions`, with a live block-entity payload, plus the `PistonHeadBlock.SHORT` state producer. The pair's existing coverage report separately leaves moving-state collision geometry and full resolver dependency open. This inventory does not close either dependency or infer a final clipped/player trajectory. Pair freeze still requires that open path and the other non-provider source gates in the coverage report to be independently resolved.
