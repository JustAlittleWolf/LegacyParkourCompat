# Independent source audit verdict: MovingBlock extension-head correction (1.10.2 → 1.11)

**ACCEPT**

Audited only the assigned correction, its specified prior report and audit, the exact 1.10.2/1.11 `ornithe-feather` source trees, and the accepted nested provider inventory within its stated scope. The correction's input hashes match the assigned identities: prior report `76ff1fdcc10e24312489cc0f76f2fcb3aa8f526ad37072a28e7b6898c227d37a`, prior audit `7d5ad1213a15b25d6aa49ffe12d92d494a2dc312c83394561ab768436caf20`.

`PistonBaseBlock.move` creates the extension-head payload from the same default-long `PISTON_HEAD` state with flags `(true, false)` in 1.10.2 (line 328) and `(true, true)` in 1.11 (line 317). The `MovingBlockEntity` constructor assigns `source`; neither version reads or writes it in NBT, so the stated difference is the constructed in-memory payload. In 1.10.2 the moving block's collision shape uses the captured moved state and its single flattened shape (MovingBlock.java:134–136; MovingBlockEntity.java:80–89), and this extension path does not consult `source`. In 1.11 `MovingBlock.addCollisions` forwards the query entity; `MovingBlockEntity.addCollisions` selects a synthesized piston-head state for `source=true`, sets `SHORT` from the cited progress expression, and calls that state's collision provider (lines 295–320). `PistonHeadBlock.addCollisions` emits an arm box selected by `SHORT`. Thus the flag change is a distinct conditional collision-provider candidate; the correction properly limits the consequence to candidate collision boxes and does not infer a trajectory or net displacement.

The correction also preserves the relevant gates: a normal player `Entity.move` query passes the player entity through the 1.11 dispatch, while the moving entity's own push scopes `NOCLIP_DIR` around its call to `move`; the collision callback suppresses the moving shape only while progress is below 1 and that thread-local is true. The extension source branch does not trigger the separate retracting-base branch. NBT omission and the own-push no-clip condition do not justify excluding an ordinary player query. The accepted provider inventory is used only for nested provider behavior, as assigned.

No finding is made here about which worlds produce this payload, box intersection in a specific setup, trajectory, or full-pair coverage. The correction is accurate within its bounded scope.
