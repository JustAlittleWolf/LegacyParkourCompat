## Tick order and paired disposition

- **Local client entry and packet emission — no movement hunk.** `LocalClientPlayerEntity.tick()` (1.11.2 159–173; 1.12 164–178) checks the current chunk, invokes `super.tick()`, then sends rider angles/input or ordinary movement. The bodies pair identically apart from shifted line numbers. `serverTickAi()` (614–625; 630–641) calls its superclass, then for the camera player copies input sideways/forward/jump and eases pitch/yaw; the body is identical. `ClientPlayerEntity.java` is byte-identical in the parent screen. These facts close only the local-client wrapper and its direct input/network wrapper, not all callers.
- **Inherited order — same phase order, one already-bound axis signature change.** `PlayerEntity.tick()` (174–250 both) sets spectator no-clip/on-ground state, calls `LivingEntity.tick`, then updates player-side state and pose. The only relevant changed local-player tick bookkeeping observed here is removal of a `!isRiding()` reset of `minecartTravelStartPos`; the field feeds the minecart-distance statistic, not movement. `PlayerEntity.serverTickAi()` (410–414; 406–410) calls super, updates arm swing and sets `headYaw = yaw` in both versions. `updatePlayerPose()` (295–319; 291–315) has the same fall-flying/sleep/sneak dimensions and collision guard in both versions.
- `LivingEntity.tick()` calls `super.tick()`, then its tick body, then `mobTick()` (1.11.2 1581–1643; 1.12 1619–1681). In `mobTick()` (1737–1808; 1781–1852), after cooldown/interpolation/velocity cutoff and local `serverTickAi`, it applies jump input, then multiplies movement axes, performs `flyingTick()`, invokes player-overridden `moveRelative`, and finally pushes colliding entities. This preserves the ordering of the local input→jump→travel phases. Jump selection tests water, lava, then grounded/cooldown; `LivingEntity.jump()` (1361–1374; 1398–1411) retains the 0.42F base, jump-boost addition, sprint yaw impulse and dirty-velocity write. `getJumpStrength()` remains 0.42F. Player's jump override (1376–1384; 1375–1383) is the same, adding only jump statistics/fatigue.
- **Axis API change, bounded to the parent report.** `LivingEntity.moveRelative` and all three travel-mode calls change from `(sideways, forwards)` to `(forwards, sideways, upwards)` / four-axis `Entity.updateVelocity`; `mobTick` passes `verticalSpeed` as the new middle input. `PlayerEntity.moveRelative` changes its signature in parallel and otherwise retains the ability-flight handling, air speed, vertical velocity scaling and movement-stat call. The parent coverage report's exact source search found no `verticalSpeed` writer in the PlayerEntity hierarchy; the sole write is the sibling MobEntity. Therefore the new local-player axis is zero at this caller. The parent owns this signature/call-path candidate and its `Entity.updateVelocity` arithmetic; this note does not re-accept or broaden that claim.
- **Other changed LivingEntity tick code.** The `LivingEntity.tick()` post-travel body-yaw selection now considers wrapped player yaw while deriving body orientation from horizontal displacement (1.12 1692–1699 versus 1.11.2 1644–1655); this writes orientation/animation state after `mobTick`, not player position or velocity. Walk animation adds vertical displacement only for `FlyingAnimal` (1.12 1591–1598); PlayerEntity is not that class. These are not promoted to movement findings. `LivingEntity.dismountRider()` (1282–1350 vs 1321–1387) changes its candidate collision box construction and vertical offset; the parent report checked its only caller gate, `stopRiding`, as server-only (`!world.isClient`). Vehicle behavior is excluded, so this is not an eligible local-player route.
- **Same callers and consumers checked:** `baseTick()` (215–316; 218–319) keeps effect ticking and snapshot order; status-effect tick implementation lines 510 onward / 513 onward retains the same effect iteration/update logic. `setSprinting`, `setSneaking`, `getJumpStrength`, `jump`, and player pose gates have no movement-relevant paired body change. The LivingEntity equipment/attribute synchronization branch is gated by `!world.isClient`; client packet application is inventoried separately below. Base tick includes damage/breath/environment effects; damage calculations are out of scope.
