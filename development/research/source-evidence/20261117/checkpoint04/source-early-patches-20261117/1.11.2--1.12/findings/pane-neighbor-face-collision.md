# Pane neighbor-face collision connections
1.11.2, Ornithe Feather: `net/minecraft/block/PaneBlock.java`, `resolveVirtualProperties(...)` (109–114) and `shouldConnectTo(Block)` (136–144).
1.12, Ornithe Feather: `net/minecraft/block/PaneBlock.java`, `resolveVirtualProperties(...)` (109–114), `shouldConnectTo(WorldView, BlockState, BlockPos, Direction)` and its exception list (136–159); `net/minecraft/block/Block.java`, default `getFaceShape(...)` (362–365); `net/minecraft/block/AbstractLeavesBlock.java` inherits this default.
Difference: 1.11.2 connects to a neighbor when its default state is a cube, or when it is glass/a pane. The 1.12 predicate connects to a non-exception `SOLID` face or a `MIDDLE_POLE_THIN` face. `AbstractLeavesBlock` is newly excluded by the pane predicate, while its default `FaceShape` is `SOLID`; its 1.11.2 default state is a cube and the old predicate has no leaves exception. The pane's collision center and direction arms are emitted from the same shape table in both versions, but the virtual direction bit changes for a pane next to leaves.
Movement meaning: an existing pane adjoining leaves contributes the corresponding arm collision in 1.11.2 and omits it in 1.12. A local player moving through that neighboring arm can therefore receive different clipping through `World.getCollisions` and `Entity.move`. The exact pane face-query direction is passed from the adjacent pane position and should be retained when implementing the edge behavior.
