# Liquid flow face classification
1.11.2, Ornithe Feather: `net/minecraft/block/LiquidBlock.java`, `isFaceSolid(WorldView, BlockPos, Direction)` (83–92), `getFlow(...)` (131–169), and `applyMaterialDrag(...)` (175–177); `net/minecraft/world/World.java`, `applyLiquidDrag(...)` (1571–1610); `net/minecraft/entity/living/player/PlayerEntity.java`, `hasLiquidCollision()` (1736–1738).
1.12, Ornithe Feather: `net/minecraft/block/LiquidBlock.java`, `isFaceSolid(...)` (82–100), `getFlow(...)` (139–177), and `applyMaterialDrag(...)` (183–185); `net/minecraft/world/World.java`, `applyLiquidDrag(...)` (1579–1618); `net/minecraft/entity/living/player/PlayerEntity.java`, `hasLiquidCollision()` (1733–1735).
Difference: for a same-liquid neighbor, both return false; for an upward face, both return true; ice is false in both. On other side faces, 1.11.2 delegates to `Block.isFaceSolid`, which returns the neighboring material's `isSolid()` value. In 1.12, side faces return true only when the block is not an attachment exception or stair and the queried face is `FaceShape.SOLID`. A stair made of a solid material therefore counted as solid in 1.11.2 but is explicitly false in 1.12.
Movement meaning: in `getFlow`, for liquid state `LEVEL >= 8`, any qualifying neighboring solid face adds `(0,-6,0)` to the accumulated flow vector before normalization. A solid-material stair beside full/falling water triggered that branch in 1.11.2 but does not in 1.12. `World.applyLiquidDrag` normalizes the resulting vector and adds `0.014` times it to entity velocity when `entity.hasLiquidCollision()`; `PlayerEntity` returns true when not flying. The player's ordinary water collision check calls this world method, so this is a direct local-player velocity response, not merely flow rendering.
