## Binding method and limits

- Canonical source namespace is the decompiler guide's publication path `decompiled_minecraft/<exact-release>/ornithe-feather/`.
- Each mapping-local `.decompile-provenance.json` lists exact input URLs and SHA-256 values, tool/runtime identity, pipeline options, and a SHA-256 for every listed source file. I recomputed every listed source-file hash: all 1,819 entries per row match; no missing or mismatching entries.
- Mojang version JSON exists in the local pinned cache. Its actual SHA-256 matches both the cache pin and the provenance input hash; the metadata `id` is the exact row. The cached client JAR SHA-256 matches provenance and its SHA-1 matches the client SHA-1 declared by that version JSON.
- Feather metadata JSON exists locally; its actual SHA-256 matches its pin. It lists the exact row's stable `+build.2` artifact. The provenance records the corresponding Maven URL and artifact SHA-256.
- The raw Feather mapping JAR was not present in the checked local Maven Gradle artifact cache, so its recorded input SHA-256 was not independently recomputed from JAR bytes. The mapping artifact identity/hash below is therefore bound by the publication provenance plus the pinned Feather metadata coordinate, not a fresh raw-JAR byte check.
- No readiness marker or separate canonical identity registry was found in the four mapping-local publication directories. Per `buildSrc/README.md`, campaign preparation/readiness markers are a separate evidence decision and are not produced by decompilation. This packet does not claim campaign readiness or source acceptance.
