# Living entity knockback response changes its vertical gate
1.8.9, Ornithe Feather: `net/minecraft/entity/living/LivingEntity.java`, `takeDamage(DamageSource, float)` lines 616-694 and `applyKnockback(Entity, float, double, double)` lines 763-778.
1.9, Ornithe Feather: `net/minecraft/entity/living/LivingEntity.java`, `takeDamage(DamageSource, float)` lines 670-770 and `applyKnockback(Entity, float, double, double)` lines 863-879.
Difference: For a successful damage event with a non-null attacker, both versions call the victim's `applyKnockback`. In 1.8.9, the method ignores its `amount` argument, halves all three velocity components, subtracts a fixed 0.4F-scaled horizontal direction, and adds 0.4F vertical velocity (capped at 0.4F), without checking `onGround`. In 1.9, horizontal components are always halved and adjusted using the supplied amount; the vertical half-and-add/cap is performed only if `onGround`. The ordinary non-shield `takeDamage` path in 1.9 passes 0.4F, while the 1.8.9 call passes its damage amount to a method that ignores it. Knockback resistance remains an early random gate in both versions.
Movement meaning: An airborne player hit by an entity receives vertical knockback in 1.8.9 but not from this 1.9 response path. Grounded response retains the vertical half/add/cap procedure for the usual 0.4F call. Damage calculation and attacker eligibility are outside this finding; it isolates the direct player velocity response once the damage path calls knockback.
