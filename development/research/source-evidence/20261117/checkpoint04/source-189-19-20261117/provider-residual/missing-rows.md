## Player collision-query context

The source-only collision supplement records the fixed client path: `Entity.move` obtains candidate boxes through `World.getCollisions`, which dispatches to each block state's collision provider. In 1.8.9, `Block.addCollisions` calls the provider for world-space boxes and adds intersecting non-null results (`Block.java` 339–350); in 1.9, the provider yields a local box, and `Block.addCollision` translates it by the block position before the same intersection/add operation (`Block.java` 313–328). The conversion alone preserves box coordinates. These six providers were checked against that path; their geometry affects ordinary on-foot movement only when their collision boxes intersect the player's movement query.

## Disposition

`AbstractPressurePlateBlock`, `ButtonBlock`, `CauldronBlock`, and `FenceGateBlock` have no player collision delta in these bounded source methods. `DoorBlock` is equivalent for valid paired door state but retains the malformed companion-state dependency above. `FenceBlock` remains partial because both multipart clipping order and the `isCube` neighbor gate require closure. No panes, piston-head arms, or moving-piston response were read here. The remaining pair inventory and independent pair-wide audit are still required.
