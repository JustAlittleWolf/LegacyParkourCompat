## Current source disposition (r3)

### Local tick-gate/clamp candidate

The source comparison supports the bounded candidate in `findings/player-tick-world-limit-r2.md` (SHA-256 `B4B0ED48F380356ABCD47663C1B656A2EEFC39738EE5DE745B54102960456514`): when a local player is already outside the horizontal limit, 1.9.2's `LocalClientPlayerEntity.tick()` gate can return before `super.tick()`, while the 1.9.3 client-world path passes `allowEmpty=true`. `PlayerEntity.tick()` then runs inherited movement and clamps x/z to ±29,999,999 later in that tick. This source observation remains distinct from the conditional query observation below; the source does not establish how an ordinary session reaches the initial out-of-range local-player state.

### Conditional cached-state query observation

The bounded follow-up and its ACCEPT verdict establish only this source-level conditional: for an out-of-horizontal-range scan cell, 1.9.2 `World.isChunkLoaded` rejects before `World.getBlockState` or client-cache lookup. In 1.9.3, `World.isChunkLoaded` delegates to `ClientWorld.isChunkLoadedAt`; with the default `allowEmpty=true`, the scan proceeds. During `World.getCollisions`, an entity outside the world border takes the `!bl2` branch to `getBlockState`. A matching already-cached client chunk can supply its block state; a missing cache entry supplies `EmptyChunk`/air. If a returned state has a collision provider whose box intersects the query, the collision list can include that box.

`Entity.move()` calls `World.getCollisions` for support checks, ordinary movement, and step-up resolution. It also directly reads foot/below-foot states for landing and step callbacks, and `checkBlockCollisions()` reads states across the entity box after the movement collision resolution. These source call paths are inventoried as relevant readers, not proof that the required local-player state and query occur. Whether a non-spectator local player with `noClip=false` reaches an out-of-world-border `Entity.move()` query whose scan includes an out-of-range cell and satisfies `!bl2`, whether a matching out-of-range non-air chunk is populated in a normal session, and whether the conditional state changes a player trajectory remain open. The follow-up did not examine packet/loading paths or runtime behavior.
