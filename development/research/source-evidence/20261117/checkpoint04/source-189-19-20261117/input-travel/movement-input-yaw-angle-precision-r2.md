# Movement input yaw-angle precision (audit revision r2)
1.8.9, Ornithe Feather: `net/minecraft/entity/Entity.java`, `updateVelocity` lines 844–860.
1.9, Ornithe Feather: `net/minecraft/entity/Entity.java`, `updateVelocity` lines 943–959.
Difference: both methods first compute the incoming squared sideways/forward magnitude and enter the trigonometric movement update only when `!(magnitudeSquared < 1.0E-4F)`. They then take the square root, clamp the magnitude to at least `1.0F`, divide the requested scale by that magnitude, and scale both input axes. After this identical gate and normalization order, the yaw angle differs: 1.8.9 evaluates `yaw * (float) Math.PI / 180.0F`; 1.9 evaluates `yaw * (float) (Math.PI / 180.0)`. Sine/cosine then rotate the scaled inputs into X/Z velocity additions.
Movement meaning: for a qualifying incoming input, float angle rounding can change the lookup/returned sine and cosine and therefore the added X/Z velocity. The audit's static witness is yaw `258.75F` with nonzero airborne movement input; its trig table indices and resulting airborne velocity increments differ across the two expressions. Those velocity writes feed the same tick's `move` call. The input gate is evaluated before normalization; the witness is not a claim about any broader trajectory.
