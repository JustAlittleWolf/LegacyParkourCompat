# Sneaking flight input rescaling (audit revision r2)
1.8.9, Ornithe Feather: `net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java`, `mobTick` lines 535–604; `net/minecraft/client/entity/living/player/KeyboardInput.java`, `tick` lines 34–36.
1.9, Ornithe Feather: `net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java`, `mobTick` lines 641–720; `net/minecraft/client/entity/living/player/KeyboardInput.java`, `tick` lines 46–49.
Difference: both keyboard methods apply sneak normalization as `(float)(movement * 0.3)`, where `0.3` is a double literal. In `LocalClientPlayerEntity.mobTick`, 1.9 first multiplies both movement inputs by `0.2F` when the player is using an item and is not riding (lines 646–650). Later, only when flying, camera-controlled and sneaking, it divides each current input float by double `0.3` and casts back to float (lines 710–720). The 1.8.9 flight branch has no division (lines 596–604).
Movement meaning: with flight enabled, camera control and sneak held, 1.9 reverses the `0.3` sneak scaling on the current inputs before shared travel. If item-use slowdown ran first, the result retains that prior `0.2F` factor (approximately `0.2 / 0.3` of the unslowed axis); this branch does not restore unslowed input in that case. Without item-use slowdown, the input returns approximately to its unsneaked value. `serverTickAi` copies the resulting inputs to movement speeds and `LivingEntity.mobTick` passes them to `moveRelative`, whose player flight branch supplies horizontal acceleration before `Entity.move`.
