## Timing correction and witness

`Entity.baseTick` refreshes the cache and sets `firstTick = false` at its end (1.16.1: 372, 405; 1.16.2: 380, 413). `LocalPlayer.tick` calls `super.tick`; `LivingEntity.tick` calls `super.tick` and then `aiStep` (1.16.1: LocalPlayer 183–186, LivingEntity 2122–2123 and 2168; 1.16.2: LocalPlayer 184–187, LivingEntity 2124–2125 and 2170). Thus the new `firstTick` guard is already false by this local-player tick's held-jump/travel consumers. It suppresses lava reads earlier inside `baseTick` (including that method's lava handling); it does **not** suppress the later same-tick local-player travel/jump after a successful cache refresh. Avoid describing `firstTick` as a gate on those later consumers for this call path.

A source-level separating state exists for a loaded, lava-only box after a move: let the Lava-tagged fluid surface be `f` and the player's box bottom be `f - 0.0005`. The old callback sees `aabb.minY < f`, sets the old boolean, and that flag remains until the next move's reset. The new sampler sees a deflated bottom of `f + 0.0005`, records no positive lava depth, and after `baseTick` its predicate is false. With `firstTick` false, fluid effects enabled, no water contact, and a midair held jump, old code calls `jumpInLiquid(LAVA)` while new code does not select a fluid jump. This is a concrete source-level geometric witness; runtime reachability was not tested. It is conditional on the queried fluid satisfying `FluidTags.LAVA`; no intermediate-patch boundary is inferred.
