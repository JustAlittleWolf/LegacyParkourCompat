# Lava presence producer and cache
1.16.1, Mojmap: `net/minecraft/world/entity/Entity.java`, `baseTick` 354–405, `move` 469–559, `updateInWaterStateAndDoFluidPushing` 947–956, `setInLava`/`isInLava` 1065–1071, `updateFluidHeightAndDoFluidPushing` 2633–2697; `net/minecraft/world/level/block/LiquidBlock.java`, `entityInside` 178–185.
1.16.2, Mojmap: `net/minecraft/world/entity/Entity.java`, `baseTick` 362–413, `move` 485–570, `updateInWaterStateAndDoFluidPushing` 957–963, `isInLava` 1071–1073, `updateFluidHeightAndDoFluidPushing` 2641–2705; `net/minecraft/world/level/block/LiquidBlock.java` has no `entityInside`/`setInLava` call (checked exact file); `Entity.java` has no lava flag/setter.
Difference: In 1.16.1 `isTouchingLava` is a persistent boolean. `move` resets it immediately before `checkInsideBlocks`; a lava `LiquidBlock.entityInside` callback sets it when `f = blockY + fluidHeight` satisfies `aabb.minY < f || f > aabb.maxY`. `isInLava` returns that flag. Separately, `baseTick` clears `fluidHeight`, scans water first, and returns early when `isInWater()` before sampling lava; consequently lava height may be absent/zero while the lava flag is true. In 1.16.2 the lava flag/callback setter are removed. `baseTick` clears the cache, updates water, then always samples lava with dimension-dependent push strength (`0.007` ultra-warm, otherwise `0.0023333333333333335`). The sampler deflates the bounding box by `0.001`, requires `hasChunksAt`, visits `floor(min)` to `ceil(max)` with exclusive maxima, and accepts tagged fluid whose surface `q + getHeight(...)` is `>= aabb.minY`; it stores `e = max(surface - aabb.minY, 0)` when loaded. The new predicate is `!firstTick && cachedLavaHeight > 0.0`; exact surface contact can return sampler contact true while leaving cached depth zero, and an unloaded scan returns before the cache put (the preceding base-tick clear leaves no positive depth). The cache is refreshed in `baseTick` before player travel; `firstTick` becomes false at the end of that method. Fluid-tag membership was not independently verified from raw resources and remains an applicability dependency.
Movement meaning: A locally controlled player's lava-presence input now comes from positive sampled fluid depth at the base-tick refresh, rather than a per-move block callback flag. Contact/height, loaded-chunk and first-tick gates therefore affect whether later same-tick travel/jump sees lava. This finding covers only the producer/predicate and its update/reset path; downstream branch effects are documented separately.
