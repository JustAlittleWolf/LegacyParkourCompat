# Lava presence producer/cache
1.16.1, Mojmap: `net/minecraft/world/entity/Entity.java`, `baseTick` 372–405, `move` 551–553 and `checkInsideBlocks` 803–828, `updateInWaterStateAndDoFluidPushing` 947–956, `setInLava`/`isInLava` 1065–1071, `updateFluidHeightAndDoFluidPushing` 2633–2697; `net/minecraft/world/level/block/LiquidBlock.java`, `entityInside` 178–185; `net/minecraft/world/level/material/FlowingFluid.java`, `getHeight`/`getOwnHeight` 468–474.
1.16.2, Mojmap: `net/minecraft/world/entity/Entity.java`, `baseTick` 380–413, `updateInWaterStateAndDoFluidPushing` 957–963, `isInLava` 1071–1073, `updateFluidHeightAndDoFluidPushing` 2641–2705; `net/minecraft/world/level/block/LiquidBlock.java` has no `entityInside` override or lava setter call; `Entity.java` has no lava boolean/setter.
Difference: In 1.16.1 `move` clears `isTouchingLava` immediately before `checkInsideBlocks`, which scans the box with `+0.001`/`-0.001` block-position margins and calls block `entityInside`. A lava `LiquidBlock.entityInside` callback computes `f = blockY + fluidHeight` and sets the boolean when `aabb.minY < f || f > aabb.maxY`; for an ordered AABB the second disjunct is redundant, leaving the strict lower-surface test. `isInLava` reads this flag, which remains set until a later move reset. Separately, the base-tick cache update clears `fluidHeight`, updates water, then returns early if `isInWater()`, so the old lava-depth entry may be absent/zero even while the callback flag is true. In 1.16.2 the flag and callback setter are removed. Base tick clears the cache, updates water, and always samples lava using dimension-dependent push strength (`0.007` ultra-warm, otherwise `0.0023333333333333335`). The sampler deflates the bounding box by `0.001`, requires `hasChunksAt`, scans floor minima to exclusive ceil maxima, and accepts tagged fluid only when its surface `q + getHeight(...)` is `>=` the deflated box bottom. It stores the greatest nonnegative depth `e`; a failed chunk gate returns before the cache put. The new predicate is `!firstTick && cachedLavaHeight > 0.0`.
Timing: `Entity.baseTick` refreshes the cache and sets `firstTick = false` at its end. `LocalPlayer.tick` calls `super.tick`; `LivingEntity.tick` reaches `aiStep` after `super.tick` on this ordinary local-player path. Thus `firstTick` is still true for `isInLava` reads earlier inside the first base tick (including its lava handling), but is already false for that tick's later local-player held-jump/travel consumers. Do not describe this guard as suppressing those consumers after a successful cache refresh.
Movement meaning: A source-level separating witness exists conditionally for a loaded lava-only state: let a Lava-tagged fluid cell have nonintegral surface `f` and the player's box bottom be `f - 0.0005`, with that cell included in the old `checkInsideBlocks` scan. The old callback sees `aabb.minY < f`, sets the flag, and the flag survives until the next move. The new scan sees deflated bottom `f + 0.0005`, so the surface fails its `>= bottom` test and cached lava depth remains zero; after base tick the new predicate is false. This can reach the later held-jump/travel consumers. The witness is conditional on exact `FluidTags.LAVA` membership and the described loaded fluid state; raw tag-data resources are unavailable, so membership is not independently established. Runtime reachability was not tested. This finding covers producer/predicate and refresh/reset timing; consumer bodies and consequences are documented separately.
