## Accepted source claims

- **Old argument selects the forced accessor.** In both `PlayerManager.changeDimension(ServerPlayerEntity,int)` methods, `int i = player.dimension` is captured before `player.dimension = dimension`; the entity overload receives `i`. For dimension 0 → 1, the entity's new dimension is 1, so the dimension checks take the final branch, while the passed `dimension` remains 0. Thus `dimension == 1` is false and the helper selects `toWorld.getForcedSpawnPoint()`. It writes the selected block's integer X/Y/Z and yaw 90/pitch 0. The r1 notes correctly identify this in both releases.
- **Conditional and unguarded forced-spawn reads.** 1.8.9 `ServerPlayerEntity.changeDimension` checks the End forced-spawn result locally and sends the preliminary absolute teleport only when non-null; 1.9.4 has no such pre-respawn branch. The later entity helper in each release selects and dereferences its forced-spawn `blockPos` without a local null check. This confirms the source predicate and unguarded helper, without asserting a concrete world's value or invariant.
- **Final packet coordinates are current fields after the helper.** The entity helper writes the forced-spawn coordinates, then for a live entity calls `fromWorld.tickEntity(entity, false)` before `entity.setWorld(toWorld)`. The `setWorld` implementation only assigns the world reference. `onChangedDimension` updates chunk-map membership and requests the chunk at the player's current X/Z; it contains no direct X/Y/Z assignment. After that call, `PlayerManager` passes the then-current `player.x`, `player.y`, `player.z`, yaw and pitch to the final no-relative-args `networkHandler.teleport`. That network-handler method sends a `PlayerMoveS2CPacket` using the passed XYZ. Therefore the source proves what fields are read and when; it does **not** prove the final packet XYZ still equal the helper's forced-spawn write, because the live-entity old-world tick occurs between them.
- **Client claims.** The corrected client note and outcome consistently refer to the same forced-spawn helper write and later packet carrying post-helper current coordinates. Remaining respawn, absolute-axis velocity clearing, teleport-ID acknowledgement and client movement-response claims remain bound to the unchanged prior audit verdict and its frozen source identities.
