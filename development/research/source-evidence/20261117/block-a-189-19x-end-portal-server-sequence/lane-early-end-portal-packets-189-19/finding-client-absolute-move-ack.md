# Client absolute player move acknowledgment

1.8.9, Ornithe Feather: `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java`, `handlePlayerMove(PlayerMoveS2CPacket)`, lines 516-565; server packet construction in `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport(...)`, lines 364-397.
1.9, Ornithe Feather: `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java`, `handlePlayerMove(PlayerMoveS2CPacket)`, lines 545-594; server packet construction in `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport(...)`, lines 490-516.
Difference: Both client handlers add position components and angles only when their relative flags are set; otherwise they zero the corresponding player velocity component, then call `updatePositionAndAngles`. Both send `PlayerMoveC2SPacket.PositionAndAngles` with the player's X/Z, shape minimum Y, yaw and pitch, and `false`. In 1.9, the handler first sends `AcceptTeleportC2SPacket(packet.getTeleportId())`; the 1.8.9 handler has no corresponding acknowledgment. The 1.9 server teleport helper increments and attaches `requestedTeleportId`; the 1.8.9 helper sends no ID.
Movement meaning: An absolute End-arrival move resets X/Y/Z velocity and applies its packet position and angles in both releases. In 1.9 the client acknowledges that absolute move ID before sending its position/angle response; the source shows the additional protocol response without changing the described client position/velocity writes.
