1.9, Ornithe Feather: `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `changeDimension(int)`, lines 471-478; `net/minecraft/server/PlayerManager.java`, `changeDimension(ServerPlayerEntity,int)`, lines 488-513 and `changeDimension(Entity,int,ServerWorld,ServerWorld)`, lines 515-568; `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport(...)`, lines 490-516.
Difference: In both releases `PlayerManager.changeDimension` captures old dimension `i` before writing target dimension 1, then passes `i` to the helper. For an overworld-to-End transfer, the helper therefore receives 0 while `entity.dimension` is already 1. The helper falls through to its spawn-point branch and tests its old-dimension argument: `dimension == 1` is false, so both releases select `toWorld.getForcedSpawnPoint()`, then run the `dimension != 1` clamp/portal-forcer/add/tick path. In 1.8.9, `ServerPlayerEntity.changeDimension` also sends an optional absolute teleport before Respawn using `this.server.getWorld(1).getForcedSpawnPoint()` when non-null; this is the same configured forced-spawn source value as the helper's target. In 1.9 the preliminary move is removed. Both later send a final absolute move from the player fields after helper placement; the source does not guarantee those fields remain the raw block coordinates after clamp and portal-forcer processing. The respawn packet carries target dimension, old-world difficulty, old-world generator type and gamemode. The 1.9 teleport helper additionally attaches a requested teleport ID.
Movement meaning: With a non-null forced End spawn, 1.8.9 sends an extra absolute relocation at raw forced-spawn coordinates and zero angles before Respawn; transfer placement then selects that same configured forced-spawn point and may process the resulting position before the final move. In 1.9 the player receives only the post-respawn absolute move. Both absolute move packets clear client X/Y/Z velocity through the corresponding client handler.
