# End destination transfer position and packet order (r1)

Revision r1 corrects the final destination accessor identified by the independent source audit. It is bound to audit verdict SHA-256 `dd33df95417981163e157a257d972f8218c6ae16106ccbe9abbc609ba8f95c48`; original note remains unchanged.

1.8.9, Ornithe Feather: `net/minecraft/block/EndPortalBlock.java`, `onEntityCollision`, lines 61–64; `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `changeDimension`, lines 440–463; `net/minecraft/server/PlayerManager.java`, `changeDimension(ServerPlayerEntity, int)` and `changeDimension(Entity, int, ServerWorld, ServerWorld)`, lines 435–513; `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport`, lines 364–397.
1.9.4, Ornithe Feather: `net/minecraft/block/EndPortalBlock.java`, `onEntityCollision`, lines 63–70; `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `changeDimension`, lines 458–487; `net/minecraft/server/PlayerManager.java`, both `changeDimension` overloads, lines 489–569; `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport`, lines 490–516.

Difference: For a non-riding, passenger-free server player moving from dimension 0 to dimension 1, 1.8.9 first checks the target End world's forced spawn point. If non-null, `ServerPlayerEntity.changeDimension` calls `networkHandler.teleport(forcedX, forcedY, forcedZ, 0, 0)` before `PlayerManager.changeDimension`; the handler writes the server player's position/angles before sending its move packet. In both releases, the outer `PlayerManager.changeDimension` saves the old dimension as `i` before changing `player.dimension` to 1 and sending `PlayerRespawnS2CPacket`. It then calls the entity overload with `dimension == i == 0`. That helper tests the now-updated `entity.dimension` (1), reaches its final `else`, and selects `toWorld.getForcedSpawnPoint()` because the passed old-dimension argument is not 1. It writes the selected block's exact integer X/Y/Z with yaw 90 and pitch 0. For a live entity, the helper then invokes `fromWorld.tickEntity(entity, false)` before returning; after `onChangedDimension`, the manager sends a final absolute position packet using the player's then-current coordinates. 1.9.4 removes the preliminary forced-spawn lookup/teleport, but retains the same old-dimension argument and final forced-spawn accessor. It also calls `updatePermissions` after respawn and before entity removal/placement. The helper dereferences the selected block position without a local null guard; this comparison makes no claim about the world's invariant or a concrete forced-spawn value. These are source call/write orders, not observed packet arrival timing.

Movement meaning: In both versions, the helper's destination position write comes from `toWorld.getForcedSpawnPoint()`, not `toWorld.getSpawnPoint()`. The later final packet uses the player's current coordinates after the helper and `onChangedDimension`; this bounded comparison does not establish whether the intervening old-world entity tick changes those coordinates. 1.8.9 additionally emits an earlier absolute correction from the forced-spawn accessor when its pre-branch value is non-null, before the manager changes dimension and sends respawn. The second accessor call in the helper occurs after respawn in both versions. No claim is made that separate accessor reads return an identical value, nor that any concrete server supplies a non-null value. Portal entry is bounded to the server-side eligible path; this does not compare portal shape rules or other destinations.
