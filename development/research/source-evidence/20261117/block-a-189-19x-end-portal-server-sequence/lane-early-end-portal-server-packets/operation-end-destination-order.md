# End destination transfer position and packet order

1.8.9, Ornithe Feather: `net/minecraft/block/EndPortalBlock.java`, `onEntityCollision`, lines 61–64; `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `changeDimension`, lines 440–463; `net/minecraft/server/PlayerManager.java`, `changeDimension(ServerPlayerEntity, int)` and `changeDimension(Entity, int, ServerWorld, ServerWorld)`, lines 435–513; `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport`, lines 364–397.
1.9.4, Ornithe Feather: `net/minecraft/block/EndPortalBlock.java`, `onEntityCollision`, lines 63–70; `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `changeDimension`, lines 458–487; `net/minecraft/server/PlayerManager.java`, both `changeDimension` overloads, lines 489–569; `net/minecraft/server/network/handler/ServerPlayNetworkHandler.java`, `teleport`, lines 490–516.

Difference: For a non-riding, passenger-free server player moving from dimension 0 to dimension 1, 1.8.9 first checks the End world's forced spawn point. If non-null, `ServerPlayerEntity.changeDimension` calls `networkHandler.teleport(forcedX, forcedY, forcedZ, 0, 0)` before calling `PlayerManager.changeDimension`. The handler writes the server player's position/angles before sending its `PlayerMoveS2CPacket`. Then `PlayerManager` sets `player.dimension` to 1 and sends `PlayerRespawnS2CPacket`; only afterwards does its entity transfer branch choose `toWorld.getSpawnPoint()`, write that block's exact integer X/Y/Z with yaw 90 and pitch 0, and later send the final absolute position packet after `onChangedDimension`. If the forced spawn point is null, the pre-respawn teleport call is skipped. In 1.9.4 the pre-respawn forced-spawn lookup and teleport are absent: `PlayerManager` sets dimension 1 and sends respawn first, writes the destination spawn coordinates later, then sends the final absolute position packet. 1.9.4 also calls `updatePermissions` after the respawn send and before entity removal/placement. Both final destination writes use the End world's spawn block coordinates without centering. These are source call/write orders; they do not establish observed packet arrival timing.

Movement meaning: In 1.8.9, a non-null End forced spawn point produces an intermediate absolute position packet while the server player still has the old dimension, before the dimension/respawn packet; the final position is the End spawn block coordinate. In 1.9.4, the first position correction from this path is after respawn and is the End spawn position. The existence of the 1.8.9 intermediate packet is bounded by `getForcedSpawnPoint() != null`; source evidence here does not establish that input for any particular server. The portal entry is bounded to the server-side eligible path; this does not compare portal shape rules or other destinations.
