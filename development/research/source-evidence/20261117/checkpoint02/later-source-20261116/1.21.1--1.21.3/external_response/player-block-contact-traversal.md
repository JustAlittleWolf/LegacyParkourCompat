1.21.1, Mojmap: `decompiled_minecraft/1.21.1/mojmap/net/minecraft/world/entity/Entity.java`, `move` lines 598–715 and `checkInsideBlocks` lines 1001–1029; `decompiled_minecraft/1.21.1/mojmap/net/minecraft/world/level/block/piston/PistonMovingBlockEntity.java`, `moveEntityByPiston` lines 181–185.
1.21.3, Mojmap: `decompiled_minecraft/1.21.3/mojmap/net/minecraft/world/entity/Entity.java`, `move` lines 619–721, `applyEffectsFromBlocks` lines 736–760, `checkInsideBlocks` lines 1038–1074; `decompiled_minecraft/1.21.3/mojmap/net/minecraft/world/entity/LivingEntity.java`, post-travel `applyEffectsFromBlocks` call around line 2775; `decompiled_minecraft/1.21.3/mojmap/net/minecraft/world/level/BlockGetter.java`, `boxTraverseBlocks` lines 172–188; `decompiled_minecraft/1.21.3/mojmap/net/minecraft/world/level/block/piston/PistonMovingBlockEntity.java`, `moveEntityByPiston` lines 182–187.

Difference: In 1.21.1 `Entity.move` invokes `stepOn` when grounded and checks `entityInside` over blocks overlapping the current player bounding box after each move. In 1.21.3 the grounded `stepOn` and inside-block processing are grouped in `applyEffectsFromBlocks`; a locally controlled client `LivingEntity` calls it after travel, passing `oldPosition()` to the current position, and `boxTraverseBlocks` enumerates the swept bounding box path. The new inside-block scan filters non-air states and tests each state's entity-inside collision shape against that path. `PistonMovingBlockEntity.moveEntityByPiston` also now calls `applyEffectsFromBlocks()` after the piston move; the 1.21.1 helper only moves the entity.

Movement meaning: For a locally controlled player whose movement path intersects a block's entity-inside collision shape without the final bounding box overlapping it, 1.21.3 can run that block's direct player response during the tick where 1.21.1's final-box scan would not. The block callback set reached by a piston displacement likewise now receives an explicit post-push contact pass. This changes when and which vanilla block-contact responses can alter player velocity or movement state; block states are unchanged.
