# Independent review: Powder Snow stuck-piston boundary

## Verdict

**REJECT the proposed exact stable boundary 1.21.11 → 26.1.** The piston-specific exclusion is already present in the prepared, ready 1.21.10 Mojmap source, as well as 1.21.11 and 26.1. Thus 26.1 is not the first changed prepared stable source. The available ready sources bound the change to no later than 1.21.10; an exact preceding stable release boundary is not accepted because 1.21.9 has a source directory but no ready marker/source manifest, so its source identity is not established. Snapshot/development introduction remains unknown.

The original accepted 1.17.1 → 26.2 candidate supports the endpoint consumer difference only. Its recheck accepts the corrected threshold and zero-limited-piston early return, while explicitly leaving the introducing release unresolved. It does not support the new exact-cutover claim.

## Player reachability and order

On both 1.21.11 and 26.1, `LocalPlayer.tick` calls `super.tick` (1.21.11 `LocalPlayer.java:211–215`; 26.1 `:227–231`). `LivingEntity` performs travel and then applies block effects when the client instance is locally authoritative (1.21.11 `LivingEntity.java:2971–2979`; 26.1 `:3070–3078`). The Powder Snow provider calls `makeStuckInBlock` with `(0.9F, 1.5, 0.9)` (1.21.11 `PowderSnowBlock.java:62–65`; 26.1 `:62–71`). `Minecraft.tick` ticks entities before block entities (1.21.11 `Minecraft.java:1809–1813`; 26.1 `:1855–1859`). Piston block-entity ticking invokes collided/stuck entity movement, and `moveEntityByPiston` calls `entity.move(MoverType.PISTON, ...)` (1.21.11 `PistonMovingBlockEntity.java:320–328`, `:113–191`; 26.1 `:334–342`, `:120–199`). Thus the direct player response reaches the changed inherited `Entity.move` gate under the report's stated overlap, multiplier-threshold and nonzero-limited-vector conditions. The report's caller/order witness is supported; its cutover assertion is not.

For the earliest changed ready source itself, 1.21.10 has the same reachable order: `LocalPlayer.tick` calls `super.tick` (`LocalPlayer.java:195–201`); `LivingEntity` travels and then applies block effects when locally authoritative (`LivingEntity.java:2845–2853`); `Minecraft.tick` calls `tickEntities` before `tickBlockEntities` (`Minecraft.java:1779–1784`); piston ticking reaches `moveCollidedEntities` (`PistonMovingBlockEntity.java:320–328`), which calls `moveEntityByPiston`/`Entity.move(MoverType.PISTON, ...)` (`:113–191`). This supports the 1.21.10 exclusion as part of the same local-player response path.
