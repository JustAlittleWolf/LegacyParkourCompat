## Reachable path and terminal inventory

The inspected call path is `LocalClientPlayerEntity`/`ClientPlayerEntity` movement → inherited `Entity.move` and box updates → `World.getCollisions(Entity, Box)` / `World.containsLiquid` and entity/block intersection queries → per-block virtual shape callbacks. `Entity` then samples the resulting position/box, clips each axis, updates grounded/collision flags and dispatches `Block.onEntityCollision` for blocks intersecting its post-move box. Player/entity direct state predicates also read block/material state for ladder/climb, liquid, full-cube and solidity checks. These APIs make the following source families reachable under ordinary player movement:

- **Collision collection and math:** `entity/Entity.java` (`setSize`, `setPosition`, `move`, shape/box accessors, block contact dispatch, collision response); `world/World.java` (`getCollisions`, entity collision aggregation, `containsLiquid`, `isFullCube`/solid-blocking queries); `util/math/Box.java` (the mapped `Box` implementation, exact package path unresolved in this pass); `block/Block.java` (`getCollisionShape`, default solidity/cube predicates, `onEntityCollision`); `block/Blocks.java` registrations and singleton wiring.
- **Block shape overrides and inherited shape families found by source search:** `AbstractPressurePlateBlock`, `AbstractRailBlock`, `AirBlock`, `BannerBlock`, `ButtonBlock`, `CactusBlock`, `CakeBlock`, `CauldronBlock`, `CobwebBlock`, `DetectorRailBlock`, `DoorBlock`, `EndPortalBlock`, `FarmlandBlock`, `FenceGateBlock`, `FireBlock`, `LadderBlock`, `LeverBlock`, `LilyPadBlock`, `LiquidBlock`, `MovingBlock`, `PistonBaseBlock`, `PlantBlock`, `PortalBlock`, `RedstoneWireBlock`, `SignBlock`, `SkullBlock`, `SnowLayerBlock`, `SoulSandBlock`, `SugarCaneBlock`, `TorchBlock`, `TrapdoorBlock`, `TripwireBlock`, `TripwireHookBlock`, `VineBlock`, and `WallBlock`. Inherited/default shape behavior is supplied by `Block` and parent classes; therefore a virtual override list alone is not the full provider set.
- **Contact callbacks:** `Block.onEntityCollision` is dispatched by `Entity`; overrides found include `AbstractPressurePlateBlock`, `ButtonBlock`, `PortalBlock`, `SoulSandBlock`, `TntBlock`, and `TripwireBlock`. Callback reachability is box-overlap dependent. Pressure-plate/button/tripwire updates are state changes; portal handling can affect player state/position; soul sand is a direct movement response. The callback implementation and enclosing caller hashes are equal through 1.8.8, with no endpoint changed provider path in 1.8.8→1.8.9.
- **Fluid/material/current:** `World.containsLiquid`; `Entity` liquid-contact/current handling; `LiquidBlock`/`FlowingLiquidBlock` collision and flow/current derivation; `block/material/{Material,LiquidMaterial,AirMaterial,PlantMaterial,PortalMaterial}.java`; relevant block/material predicates. This includes neighboring liquid levels and adjacent fluid blocks as inputs to computed flow, and block material classification as input to collision/liquid predicates.
- **Pose/dimensions/box:** `Entity.setSize` and `setPosition` define entity width/height and bounding box; `PlayerEntity` sets normal size and changes size during sleep-related transitions; `LivingEntity` has pose-dependent size/state callers; `ClientPlayerEntity` and `LocalClientPlayerEntity` are the client movement readers/writers. `Entity` and `PlayerEntity` may trigger collision checks while repositioning after size changes. Player predicates read vanilla block solidity for movement decisions (for example local spawn/placement checks); these do not alter vanilla states.
- **Other direct movement predicates / neighbor reads:** `LadderBlock` checks supporting neighboring blocks; `VineBlock` and other connectable shapes inspect adjacent block states; stairs/fences/walls/panes/pistons and dynamic moving-block shapes derive shape from state and/or neighbors; `World.isFullCube`/`isSolidBlockingCube` sample block shape/material; `LocalClientPlayerEntity` includes a two-block `isSolid()` predicate. All are state-dependent, but the exact transitive neighbor predicate closure for every dynamically registered provider was not exhaustively followed in this supplement.
