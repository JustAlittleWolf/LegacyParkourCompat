# Fire, lava and cauldron callback closure

## Scope and result

This closes only the callback response/write-order contract for `BaseFireBlock`, `LavaFluid`, `LavaCauldronBlock` and `LayeredCauldronBlock` at 1.21.2/1.21.3 versus 26.2. The accepted sweep report establishes the old synchronous dispatch boundary: on each eligible old block visit, call `BlockState.entityInside`, then `onInsideBlock`, then add the state to the old `blocksInside` summary. Callback writes therefore happen before the next visit. The 26.2 calls below instead register typed operations in `StepBasedCollector`; those effects run after traversal, grouped by step and effect type. They cannot be made historical merely by keeping position order or by invoking the modern callback with a no-op/inline collector.

## Callback comparison

**Fire.** In both old releases, `BaseFireBlock.entityInside` first checks `!fireImmune`; for a negative fire timer it increments by one, otherwise a `ServerPlayer` gets a random increment of 1 or 2; if the resulting timer is nonnegative it calls `igniteForSeconds(8)`. It then calls `hurt(inFire, fireDamage)` regardless of fire immunity and invokes the superclass callback. These are immediate at each visited fire block (`BaseFireBlock.java:130–145`). In 26.2 the body registers `CLEAR_FREEZE`, `FIRE_IGNITE`, then one `runAfter(FIRE_IGNITE, hurt)` per callback (`BaseFireBlock.java:131–141`). The collector coalesces the `FIRE_IGNITE` type once per step but retains each after-consumer; both the ignition and every hurt happen at flush, ordered by type. Thus multiple old fire visits can each mutate the timer before the next block, while modern visits share one ignition per step and defer their damage. `Entity.clearFire` sets remaining fire ticks to zero in both endpoints; modern fire additionally schedules `clearFreeze`, which is not part of this old callback body.

**Lava fluid.** The old swept `Entity.checkInsideBlocks` loop calls block state callbacks only; it never calls `FluidState.entityInside`. Old `LavaFluid` has no `entityInside` override. This does not erase old base-tick fluid behavior: `Entity.baseTick` updates water/fluid exposure and pushing before travel, and if sampled `isInLava()` it calls `lavaHurt()` and halves fall distance. Those are separate base-tick operations, not historical swept-fluid callbacks. In 26.2, `LavaFluid.entityInside` registers `CLEAR_FREEZE`, `LAVA_IGNITE`, and a per-callback `runAfter(LAVA_IGNITE, Entity::lavaHurt)` (`LavaFluid.java:119–123`). The historical sweep contract must omit this new fluid callback entirely; it must not synthesize a legacy fluid visit or treat baseTick as one.

**Lava cauldron.** Old `LavaCauldronBlock.entityInside` first gates on `isEntityInsideContent(state,pos,entity)`, then synchronously calls `lavaHurt` (`LavaCauldronBlock.java:34–37`). That helper requires `entity.getY() < pos.y + getContentHeight(state)` and `entity.boundingBox.maxY > pos.y + 0.25` (`AbstractCauldronBlock.java:52–54`). 26.2's callback has no such content-height check: when dispatched, it registers the same three deferred operations as lava fluid (`LavaCauldronBlock.java:47–58`). The modern block supplies a `FILLED_SHAPE` for inside collision, but the source does not establish that this external eligibility predicate is equivalent to the old helper's exact two inequalities. Preserve the old content gate and synchronous `lavaHurt`; do not infer gate equivalence from callback occurrence.

**Layered cauldron.** Old `entityInside` requires `ServerLevel`, `entity.isOnFire()`, and the same cauldron-content helper. It calls `clearFire()` immediately once those pass, then checks `mayInteract`; only if that passes does it lower the cauldron (`LayeredCauldronBlock.java:63–78`). The lower operation immediately sets the block to the previous level (or empty cauldron at level zero) and emits `BLOCK_CHANGE` (`:80–85`). Snow-precipitation cauldrons convert the supplied state to a water cauldron before lowering. In 26.2 the callback registers a `runBefore(EXTINGUISH)` only on `ServerLevel`; its deferred consumer checks `isOnFire()` and `mayInteract()` and then lowers the captured state, but there is no `isEntityInsideContent` check. It also always registers `EXTINGUISH` (`LayeredCauldronBlock.java:84–118`). The consumer is run before the `EXTINGUISH` apply at the collector flush, after the scan; state update and `BLOCK_CHANGE` therefore occur late and cannot affect intervening scan callbacks. The old callback clears fire before `mayInteract` and before any world write; modern state-write eligibility checks fire and interaction together at flush. On non-server levels the modern callback still queues extinguishing, whereas the old callback does nothing. Modern `getEntityInsideCollisionShape` is level-specific, but its relation to the old content inequalities is not accepted here.

## Entity helpers and ordering boundary

The old `Entity.lavaHurt()` immediately skips fire-immune entities; otherwise it calls `igniteForSeconds(15)`, attempts 4 damage via `hurtServer` on a `ServerLevel`, and conditionally plays the generic burn sound. `igniteForSeconds` floors seconds times 20, `igniteForTicks` only raises the timer, and `clearFire` sets it to zero (`Entity.java:526–559`). The old block callback therefore observes the effects of prior lava/fire callbacks synchronously. 26.2 `LAVA_IGNITE` is a distinct deferred effect, followed by each retained `lavaHurt` consumer; `CLEAR_FREEZE` is also deferred. Collector enum order is `FREEZE`, `CLEAR_FREEZE`, `FIRE_IGNITE`, `LAVA_IGNITE`, `EXTINGUISH`; the collector does not execute registrations at the registration point. Old baseTick fire damage, lava damage and fall-distance handling remain their own earlier tick operations and must not be moved into this sweep.

The required minimal historical dispatch for these families is therefore: iterate only the accepted old block candidates; preserve old eligibility and family-specific gates; synchronously execute the corresponding historical block callback semantics (fire timer adjustment/ignite/hurt, cauldron `lavaHurt`, layered-cauldron clear-before-interaction and immediate state/event write); then call `onInsideBlock`; only after both calls return add the block state to `blocksInside`. Do not dispatch swept fluids, register typed effects, coalesce fire/lava effects by DDA stage, or delay cauldron writes. Keep the old post-sweep fire/lava summary and cleanup at its historical boundary. The source report's old callback-exception wrapping and alive/affected gates still apply.
