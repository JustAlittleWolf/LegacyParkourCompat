# Audit supplement: canonical helper identity requirement

## Decision

**Correction accepted, with a tighter metadata contract below.** The cached Vineflower source confirms that a flattened helper cannot pass the current member-name validation when the `InnerClasses` record identifies it as a member of `BlockElement`. The proposed first proof candidate must therefore use canonical `BlockElement$85922567` identity and consistently remap references/archive path before adding the missing nesting metadata. This establishes static feasibility for one allowlist entry only. It does not establish that all 59 diagnostics share the cause or that a decompile will produce zero ERRORs.

## Independent checks

- Cached `vineflower-1.12.0-sources.jar` SHA-256: `9AC4120C6AFDF83BF0E798F3A28C56040D5E05FD32462681704539A244398DA9`.
- `ClassesProcessor.java` lines 201–209 derive the enclosing class and, when `VALIDATE_INNER_CLASSES_NAMES` is on and the record is a member, skip it unless `innerName.equals(enclClassName + '$' + entry.simpleName)`. `IFernflowerPreferences.java` line 495 defaults `VALIDATE_INNER_CLASSES_NAMES` to `1`. The engine does not override this preference. Thus an entry with actual helper identity `BlockElement__85922567`, outer `BlockElement`, and simple name `85922567` fails the equality check. The correction's rejection of the flat-identity metadata-only proposal is verified.
- The pinned 1.8.1 Feather jar SHA-256 from the local artifact matches its `.pin.json`: `DAC40CBD25C4D76D99D4263FD9754AB0195EFD658756B6828FD06F0C4A8002F7`. Cached Tiny row 34231 is exactly `clv` → intermediary `C_85922567` → `net/minecraft/client/resource/model/BlockElement__85922567`.
- The 1.8.2 cached outer class carries an `InnerClasses` entry for `BlockElement$85922567` as a static member of `BlockElement`; the helper carries the corresponding entry and `EnclosingMethod: BlockElement` with no method. This is a useful exact comparator for both class-level records.

## Safe proof-candidate contract

1. Gate on exact Minecraft `1.8.1`, mapping label `ornithe-feather`, and the pinned Feather artifact SHA-256 above. Do not make the transformation depend on a regex or run it for other versions or mapping builds.
2. Add an in-memory mapping overlay for only the intermediary class `net/minecraft/unmapped/C_85922567`, changing its destination from `BlockElement__85922567` to `BlockElement$85922567`. Feed the overlay into the existing intermediary-to-named TinyRemapper pass. TinyRemapper must own the class identity remap so it rewrites the class entry and every symbolic class reference in the jar consistently. Do not patch only `this_class`, a zip entry, or an individual constant pool. Do not alter the pinned mapping artifact itself.
3. Before applying the overlay, fail closed unless the exact flat class exists, the canonical class does not, `BlockElement` exists, and the helper has the inspected synthetic enum-switch shape and no pre-existing/conflicting nesting metadata. Confirm the owner bytecode references the helper's expected synthetic `[I` field. If any check differs, stop without attempting a broader inference.
4. After remapping, add matching `InnerClasses` records for the canonical helper on **both** the helper and `BlockElement`, matching the 1.8.2 comparator (`inner=BlockElement$85922567`, `outer=BlockElement`, simple name `85922567`, static member; preserve the helper's synthetic status). Add `EnclosingMethod` only to the helper, with owner `BlockElement` and null method name/descriptor. Check the mapped jar for a single canonical helper and no lingering flat class identity or references.
5. Verify before/after structurally. The one expected archive entry moves from the flat path to the canonical path. For all class files, the only changed symbolic names may be old-helper→canonical-helper references, and the only added attributes are the intended nesting entries on the helper and owner plus `EnclosingMethod` on the helper. Compare all instruction opcodes, operand kinds/values after normalizing that one class-name mapping, exception handlers, frames, fields, methods, descriptors, and unrelated attributes. Assert no other entry changed. This allows the owner `GETSTATIC` operand's owner class name to change while proving its opcode and all unrelated method behavior remain intact. A raw byte-for-byte class hash is not an appropriate preservation criterion because the intentional class symbol and metadata changes alter classfile bytes.
6. Keep the current strict Vineflower ERROR counter/abort, failed-method-marker scan, required movement-source checks, provenance comparison, and publication flow untouched. An authorized exact-version preparation run must pass every gate before the output is accepted.

The proposal's use of TinyRemapper plus ASM is statically feasible in the existing pipeline: the engine already applies a second TinyRemapper pass from intermediary to named, and ASM core/tree are existing `buildSrc` dependencies. The overlay should be in-memory and limited to the one exact row. Whether that mapping provider is composed with `TinyRemapper` correctly, and whether Vineflower then clears the `BlockElement` diagnostic, must be established by a separately reviewed candidate patch and the designated owner's authorized generation; neither is proved by this review.

## Boundaries and remaining evidence

This verifies the name-validation correction and the exact single mapping/artifact identity. It does not broaden eligibility to the other helpers implicated by the 59-error count. Further entries require individual mapping rows, owner-reference evidence, bytecode-shape checks, canonical-name collision checks, and an exact comparator. No product or `buildSrc` file, cache artifact, mapping file, or original audit was changed; no build, test, decompile, download, or game operation was run. Zero-ERROR decompile proof remains open.
