## Concrete legal single-call witness

Use block coordinates with ordinary unit cells and an empty world border far away:

- Put a support wall block at `(−1,1,0)`. A Shulker anchored at `(0,1,0)` with attached face `WEST` has its required attachment on that side; the opposite cell `(1,1,0)` is empty, so the attached-position checks are met. Its closed box is `[0,1]×[1,2]×[0,1]`.
- Put one straight bottom stair at `(1,0,0)`, facing `EAST`, with no neighboring stairs. Its resolved straight-step collision shapes include the base `[1,2]×[0,0.5]×[0,1]` and upper step `[1.5,2]×[0.5,1]×[0,1]`. Put an ordinary support block at `(1,−1,0)` beneath it. The stair is a legal placed block and the support block top at `y=0` only face-touches the later `y=0` lower bound.
- Shulker opening is targeting amount `100` (`g=1`). At one tick, `prevOpenProgress=0.9F` and `openProgress` advances to `0.95F`; this follows the source's `+0.05F` step. The exact `MathHelper` sine-table sequence gives `e≈0.9755252898`, `d≈0.9938396811`, and `h=d-e≈+0.0183143914`. Thus the WEST expansion box after the update has X range `[0,1.9938396811]` and Y/Z ranges `[1,2]`/`[0,1]`.
- Local player dimensions are the ordinary `0.6F×1.8F`; put its feet at `y=1`, center `z=0.5`, and center X at `2.2838397` (equivalently set `minX = (1+d)-0.01`). Its box has minX about `1.9838397`, so it is outside the previous opening box by about `0.0083144`, then strictly intersects the newly grown Shulker box by `0.01` in X, with strict Y/Z overlap. The player is not inside the closed Shulker body. It overlaps the stair's upper support shape in X by about `0.0161603`, touches its top at `y=1`, and can be `onGround`; set sneaking true and `noClip=false`. This support state can be reached by a downward move clipped by that stair top; no prior trajectory is asserted.
- The query returns this player because its box strictly intersects the newly assigned opening shape. WEST selects positive X movement, so actual caller vector is `(k,l,m)=(h,0,0)` in 1.10.2 and `(i,j,k)=(h,0,0)` in 1.11.2. The source filter admits the player.

### Immediate source-resolved displacement

In 1.10.2, the untyped Shulker call enters the grounded+sneaking player edge loop. Its first probe uses the candidate box translated by `(+h,-1,0)`: minX becomes about `2.0021541`, strictly past the stair upper-step maxX `2.0` and the expanded Shulker's maxX `1.9938397`; its Y interval is `[0,1.8]`. The under-stair support block ends at `y=0`, so strict intersection is false; the stair is cleared in X; there are no other blocks/entities intersecting the probe. The probe is empty. As `0<h<0.05`, the loop sets dx and the saved X delta to zero. The subsequent collision solve applies zero X.

In 1.11.2, `MoverType.SHULKER` fails the new SELF/PLAYER condition, so no sneak-edge probe/reduction runs. The ordinary move query has `y` interval `[1,2.8]`: stair maxY is `1`, so it does not intersect the stair; the support block is below; there is no block collision. The opening Shulker entity shape is in the query and overlaps the player's initial box by `0.01` X, but the positive-X `Box.intersectX` branch clips only when the moving box's `maxX <= obstacle.minX`, which is false here; it does not reduce the requested `h`. The same query therefore accepts X=`h`. Immediate box minX becomes about `2.0021541`, minX exceeds both stair maxX and Shulker opening maxX, and the single move's accepted horizontal displacement differs by `h≈0.0183143914` (1.10.2 zero; 1.11.2 positive h). This is only the source-resolved outcome of this one Shulker opening push, not a multi-tick trajectory or runtime observation.
