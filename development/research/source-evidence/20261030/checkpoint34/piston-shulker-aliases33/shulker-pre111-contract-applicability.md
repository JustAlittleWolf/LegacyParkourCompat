## Call, predicate and float source contract

- In each listed `ShulkerEntity.tick`, the caller retains the `openProgress ± 0.05F` clamp update, float expressions for `d` and `e`, `h = d - e`, `h > 0.0`, WEST-directed `k = h`, expanded opening shape, entity query, Shulker/noClip filters, and the untyped `entity.move(k, l, m)` call. The targeted source is 1.9 `ShulkerEntity.java:223–281`, 1.9.3/1.9.4 `:225–283`, and 1.10/1.10.1/1.10.2 `:232–295` (the call is line 281, 283 and 295 respectively).
- The full `ShulkerEntity.tick()` method has one source hash across 1.9–1.9.4 and another across 1.10–1.10.2. The latter changes how position fields are assigned before shape calculation (and removes a redundant default switch label); the calculated position values, open delta operations, direction assignments, positive-delta gate, query/filter and untyped move block are unchanged. See the per-release method hashes in the matrix.
- `MathHelper.java` is byte-identical across all eight releases (SHA-256 `43b2a4e3931733dbc3538024b7182b024d874a5f22a269a6199c6b4ca8c59151`). The corrected `.9F → .95F` computation therefore selects the same table entries and produces the same positive `h` for all eight releases: `.9F` selects 45875, `.95F` selects 47514, yielding `h = 0.018321871757507324`.
- The old `Entity.move(double,double,double)` gate is present in all eight: `onGround && isSneaking() && this instanceof PlayerEntity`; there is no mover-type qualifier before 1.11. All releases probe positive X support at `getShape().moved(dx, -1.0, 0.0)` and reduce the candidate in `0.05` steps until support is found or the candidate becomes zero. The 1.9–1.9.4 source uses a local `double j = 0.05`; 1.10–1.10.2 spells the same double value as `0.05` at each comparison/subtraction. The condition order and reduction order are unchanged. `dy *= 0.05F` remains the distinct cobweb float scaling and does not enter this witness.
- `World.getEntities` (both the two-argument wrapper used by Shulker and its filtered overload) and `World.getCollisions` retain their query operations. At 1.9.3 the World signatures add nullable annotations; their method bodies match the preceding releases. The matrix records whole normalized method text, including those signature changes. `Box.intersectX` and strict `Box.intersects` hashes are byte-for-byte identical across all eight.

## Applicability result and limits

The old Shulker-call / no-mover-type edge-predicate / corrected-opening-float contract is source-applicable to exact profiles 1.9, 1.9.1, 1.9.2, 1.9.3, 1.9.4, 1.10, 1.10.1 and 1.10.2. The first inspected typed Shulker call and SELF/PLAYER-only edge gate remain the 1.11 boundary already accepted by the paired source audit. This report establishes neither the earliest possible patch introduction nor any full trajectory beyond the audited one-move witness; it does not extend the concrete stair geometry witness to earlier releases or freeze the 1.9–1.11 pair inventory.
