# Friction sampling and ground acceleration product reconciliation

## Disposition

No product code correction is needed for the retracted post-move slipperiness-resampling claim. The product has no hook or change that performs that resample. Its old support-position selection, grounded acceleration formula, and native fallback are separate operations and match the bounded source evidence examined here.

The independently audited grounded-acceleration formula difference is source-supported, but it is already represented by the existing `GroundSpeedHook` implementation for the 1.13.1/1.13.2 profile group. Profiles at 1.14 and later do not resolve that older hook and retain the native 26.2 formula, which matches the audited 1.14.4 formula. This reconciliation does not establish the exact historical patch cutover within 1.14, or runtime parity.

## Product operation trace

- `src/client/java/me/wolfii/legacyparkourcompat/mechanic/hook/travel/GroundSpeedHook.java` defines the independent `player.ground.speed` operation, receiving a `blockFriction` value and native result.
- `src/client/java/me/wolfii/legacyparkourcompat/mixin/LivingEntityMixin.java`, `legacyparkourcompat$groundAcceleration`, injects at the return of `getFrictionInfluencedSpeed(float)`. For a player, it dispatches `GroundSpeedHook`; otherwise or without a selected change it keeps the native result. It does not sample a block, query a support position, or change call timing.
- `src/client/java/me/wolfii/legacyparkourcompat/change/v1_13/GroundAcceleration.java` is annotated `V1_13_1`. When grounded it computes `friction = blockFriction * 0.91F`, then `0.16277137F / (friction * friction * friction)`, then `entity.getSpeed() * acceleration`; while not grounded it returns the native result. This preserves the 1.13.2 grounded formula and operation order.
- `ChangeResolver` resolves from the selected profile or later. Thus the `V1_13_1` acceleration change applies to 1.13.1/1.13.2 profiles but not to V1_14 or later. Those profiles retain the native 26.2 `getFrictionInfluencedSpeed` expression. The audited 1.14.4 expression is `getSpeed() * (0.21600002F / (slipperiness * slipperiness * slipperiness))`.
- `src/client/java/me/wolfii/legacyparkourcompat/mechanic/hook/entity/SupportingBlockPositionHook.java`, `src/client/java/me/wolfii/legacyparkourcompat/change/v1_14/GroundFrictionSupportCellChange.java`, and `src/client/java/me/wolfii/legacyparkourcompat/mixin/LivingEntityMixin.java`, `legacyparkourcompat$groundFrictionBlockPosition`, handle the support-position operation separately. For profiles before 1.15 the selected V1_14 change returns `(x, bounding-box minY - 1.0, z)`, the old source sample. It does not select a post-move position. The second old 1.13.2 friction read is before `move()` and uses the same entity coordinates and box minimum; no movement or support transition intervenes between the two reads in this ordinary branch.

The operation contract therefore remains: old profiles select the old grounded acceleration expression and old support sample; 1.14+ profiles use native acceleration; both use their resolved support-position operation. The old acceleration `0.6F` witness rounds to `0.9999998807907104F` versus `1.0F` for the 1.14.4 expression, which is a genuine float-level operation difference but does not imply a missing code change here.
