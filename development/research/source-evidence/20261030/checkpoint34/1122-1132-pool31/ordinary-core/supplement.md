## Tick order and fluid height

- 1.12.2 `Entity.tick()` calls `baseTick()` (Entity.java:320-326); base tick calls `tickSprintingEffect()` then `checkWaterCollisions()` (328-383). `checkWaterCollisions()` updates `inWater` from a vertically expanded entity box through `world.applyLiquidDrag`, clears fall distance on contact, and handles extinguishing (Entity.java:948-964). No stored water-submersion height is written by these routines. Water-eye predicate is separate and block-material based (`isSubmergedIn`, Entity.java:1027-1043).
- 1.13.2 `Entity.tick()` likewise calls `baseTick()` (332-338); base tick calls sprint particles then `m_03231680()` (340-395). This helper orders `checkWaterState()`, then `m_61708540()` to cache eye submersion, then `updateSwimming()` (Entity.java:947-981). `checkWaterState()` updates `inWater` by calling `m_69693160(FluidTags.WATER)` (Entity.java:961-977). That fluid scan iterates the contracted entity box's occupied cells, tests each FluidState's tag and surface height against box bottom, calculates maximum surface height above the entity box bottom in local `d`, adds averaged/scaled flow to velocity for entities with liquid collision, then writes `f_85121000 = d` and returns contact (Entity.java:2509-2575). Thus the precise producer for the jump-depth gate is the body of `checkWaterState`, called once in the entity base tick before living `mobTick()` movement.
- In the 1.13.2 PlayerEntity tick, `updateWaterSubmersion()` is called immediately before `super.tick()` (PlayerEntity.java:206-208), using eye-fluid predicate and a cached field (257-260). The inherited `Entity.baseTick()` then refreshes contact, fluid height and swimming before the living tick reaches local `mobTick()`/movement. `LocalClientPlayerEntity.updateWaterSubmersion()` adds enter/exit sound side effects around the superclass cache (LocalClientPlayerEntity.java:1003-1020). Player pose is updated at the end of PlayerEntity.tick after `super.tick()` (252-255), therefore after movement for the tick. This ordering means the early PlayerEntity eye-submersion cache invocation occurs before Entity fluid-state refresh; the separate `inWater`, height and swimming state refresh occurs during `super.tick()` before movement.

## Swimming movement, pose and dimensions

- 1.12.2 `PlayerEntity.moveRelative()` has only creative flying specialization before inherited `LivingEntity.moveRelative()`; no swim-orientation velocity pre-adjustment (PlayerEntity.java:1386-1404).
- 1.13.2, when `isSwimming() && !isRiding()`, adjusts vertical velocity toward look-vector Y before inherited movement. It uses `h=0.085` if look Y `< -0.2`, otherwise `0.06`; it applies only if looking non-upward (`g <= 0`), jump held, or the fluid state in the block at `(x, y + 0.9, z)` is nonempty (PlayerEntity.java:1442-1465). This is a distinct movement operation with a specific block-fluid query dependency and order before superclass travel. Report as confirmed candidate swimming-pitch propulsion operation; applicable to local player because the local `serverTickAi` supplies input and inherited living tick invokes virtual `moveRelative`.
- 1.13.2 `Entity.updateSwimming()` sets the swimming flag from sprinting plus in-water/submerged and not-riding gates (Entity.java:953-959); player override forces swimming off when creative flying (PlayerEntity.java:1471-1477), and `PlayerEntity.isSwimming()` additionally excludes flying and spectator (1819-1821). 1.12.2 has no equivalent swim flag/update path in the paired Entity source.
- Pose writer: 1.12.2 player chooses width/height by fall-flying, sleeping, sneaking, default; it probes `world.getCollisions(box)` and applies `setSize` only if empty (PlayerEntity.java:291-315). 1.13.2 adds `isSwimming() || isDoingSpinAttack()` before sneak, selecting 0.6F x 0.6F. It probes `world.hasNoCollisions(null, box)` and then `setSize` (PlayerEntity.java:334-360). The writer thus reuses the old dimensions gate and changes player box only if the candidate shape fits; its collision-query API changed and should be followed by the assigned shape/query lane for exact semantics. `setSize` rebuilds the shape at current coordinates (Entity.java:280-297 1.12.2; 291-307 1.13.2). This creates an independent pose/dimension movement difference and changes the box subsequently used by movement/fluid scans. The exact collision-query provider is not reviewed here.
