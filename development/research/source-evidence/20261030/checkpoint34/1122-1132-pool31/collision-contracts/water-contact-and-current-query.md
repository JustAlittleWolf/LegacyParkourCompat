Difference: 1.12.2 tests a box grown by `-0.4F` on Y against exact `Material.WATER` cells. A cell counts when its surface is no higher than `ceil(bounds.maxY)`; the block supplies a current through `applyMaterialDrag`. If accumulated current is nonzero and the player has liquid collision, the world normalizes the accumulated vector before adding `0.014` per axis to velocity. In 1.13.2 the check uses the player box contracted by `0.001`, reads tagged `FluidState`s, and counts states whose surface reaches the contracted box bottom. It tracks maximum immersion depth; for depth below `0.4`, each current vector is scaled by that depth. Currents are averaged by contributing fluid-state count, but the result is left unnormalized for `PlayerEntity` before the same `0.014` velocity increment. `FlowingFluid.getFlow` itself returns a normalized per-state direction, so the new shallow-depth scale is preserved by the player aggregation.

Movement meaning: on the local-player tick path, a non-flying player intersecting shallow flowing water with a nonzero current receives a smaller current impulse in 1.13.2 when measured immersion depth is below `0.4`: a single contributing state with depth `d` gives the new player query a vector of magnitude `d`, while the 1.12.2 world normalizes the nonzero accumulated direction to magnitude `1` before applying the impulse. The actual multi-cell result also depends on neighboring fluid states and their flow directions. This draft establishes the query/provider arithmetic, not a complete tick-by-tick trajectory or the patch where the difference first appeared.
