3. For the same ordered movement batch and with no callback mutation affecting inputs, callback dispatch order is structurally `movement record order -> BlockGetter.boxTraverseBlocks position order -> entityInside -> virtual onInsideBlock -> add BlockState to blocksInside`. The callback gate skips dead entities, air, duplicate positions, and partial inside-shapes not crossed; exceptions abort as a wrapped crash (`Entity.java:1038-1078` in 1.21.2/1.21.3; `:1050-1090` in 1.21.4). This is a conditional equal-input statement, not proof that the releases enumerate identical blocks for ordinary movement.
