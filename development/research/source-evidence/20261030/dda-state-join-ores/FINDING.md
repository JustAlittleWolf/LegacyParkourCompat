For IDs 14, 15, 16, 20, 21, 49, 56, 79, 80, 82, 87, 88 and 89, 1.8.9 `Block.deserialize` extracts the nibble and invokes the registered block's `getStateFromMetadata`; the inherited `Block.getStateFromMetadata` returns that registered block's default state. Their current palette rows serialize the matching final registry name with absent/empty properties, and the actual registered 26.2 block default is `{}`. ID 80's source alias is `minecraft:snow`; ordered rename processing results in `minecraft:snow_block`.

The redstone IDs are deliberately separate. Legacy ID 73 is the registered `minecraft:redstone_ore` block and old ID 74 is the distinct registered `minecraft:lit_redstone_ore` block. Neither old block encodes a `lit` property. In 26.2 both inputs become the *same registered* `minecraft:redstone_ore` block, with ID 73 selecting `lit=false` and ID 74 selecting `lit=true`. Do not collapse these two historical block IDs or infer that historical and current interaction/tick behavior is equivalent.

## Current registry and codec qualification

The final names are actual 26.2 registry entries in `world/level/block/Blocks.java`: gold/iron/coal ore `359–388`, glass `648–659`, lapis ore `661–670`, obsidian `1215–1223`, diamond ore `1282–1290`, redstone ore `1929–1947`, ice/snow/clay `1970–2011`, and netherrack/soul sand/glowstone `2032–2111`. The ordinary targets use the base block registration with no state properties; the redstone target uses `RedStoneOreBlock`, whose `StateDefinition` includes `LIT` and whose constructor registers default `lit=false` (`RedStoneOreBlock.java:23–25, 102–104`). `BlockState.CODEC` resolves the named registry block, while `StateHolder.codec` uses its default state when `Properties` is absent and otherwise decodes the supplied property map (`BlockState.java:8–10; StateHolder.java:145–157`). The current codec state column therefore states the full target tuple, not only the serialized name.

## Full tuple, name-only and context boundaries

- **Full tuple established:** all 240 selected pairs have a resolved old state tuple, DataFixer `Name` and `Properties` tuple, current registry key, current default/property tuple and closed row-local later-fix list. The rows have no flagged neighbor/shape pass in the selected projection.
- **Name-only projection is insufficient:** the same-name rows resolve to empty properties only after the default-state and codec chain is checked. Redstone specifically needs its property to distinguish the two old registered IDs; name-only `minecraft:redstone_ore` would conflate them.
- **Context-open portion of the conversion:** this assignment covers the ordinary chunk-section palette lookup, not block entities, entities, structure templates or flat-generator data. It does not prove any collision shape, collision-provider behavior, player response, or runtime movement parity. Redstone is a serialized state-identity mapping only; historical lit/unlit behavior remains separate from current behavior.
