# Chest and trapped-chest current-state projection

Pair: Minecraft **1.8.9** (`ornithe-feather`, Feather Gen2 build 2) to **26.2** (`unobfuscated`). This closes only the serialized-state and contextual shape inputs for old block IDs 54 and 146. It does not establish cross-version collision-box parity for all modern chest arrangements.

## Historical decoder and provider

1.8.9 `net/minecraft/block/Block.java:942,1142` registers ID 54 as one `ChestBlock(0)` under `chest` and ID 146 as a distinct `ChestBlock(1)` under `trapped_chest`. `ChestBlock.java:30-37,434-451` defines only `FACING`; metadata reads `Direction.byId(metadata)` and maps vertical output to NORTH. `Direction.java:168-170` applies absolute remainder modulo six. For stored nibble 0..15 the decoded values are 0,1,2,6,7,8,12,13,14 → NORTH; 3,9,15 → SOUTH; 4,10 → WEST; 5,11 → EAST. This is the decoder's result, not a claim that every nibble is a normal placement value.

The geometry updater is independent of facing. `ChestBlock.updateShape(world,pos)` scans NORTH, SOUTH, WEST, EAST in that first-match order and compares neighboring block object identity to `this` (`ChestBlock.java:56-68`). Therefore ID 54 recognizes only ID 54 neighbors and ID 146 only ID 146 neighbors. It writes the side-specific local bounds to the mutable singleton; absent a match it writes the single-chest bounds. This is a per-query historical context rule: kind plus the ordered same-kind neighborhood at the queried position. Do not cache modern `TYPE` as a substitute when the legacy neighbor arrangement can be inspected.

## Current registration, state and shape contract

`references/BlockItemIds.java` provides the resource keys; `Blocks.java:1274-1278,2883-2887` registers `minecraft:chest` and `minecraft:trapped_chest` as different current block objects with colliding wood properties. `TrappedChestBlock` extends `ChestBlock` with its own block entity and inherits the shape provider. `ChestBlock.java:72-77,137-147` defines FACING, TYPE and WATERLOGGED, with default NORTH/SINGLE/false. `BlockStateProperties.CHEST_TYPE` uses enum values `single`, `left`, `right`; WATERLOGGED is a boolean. `BlockState.CODEC` resolves a block key and defaults to `Block::defaultBlockState`; `StateHolder.codec` decodes optional `Properties` through the registered state-definition property codec and uses that default when absent (`BlockState.java:9`; `StateHolder.java:145-156`). The chest `MapCodec` is construction configuration (sounds/properties), not per-position shape state. Current chest placement also gates pairing by FACING: `getChestType` checks the same-kind single neighbor at facing-clockwise first, then facing-counterclockwise (`ChestBlock.java:224-244`), assigning LEFT/RIGHT; `getConnectedDirection` maps LEFT clockwise and RIGHT counterclockwise (`:196-203`). This orientation-relative selection is not the legacy north/south/west/east first-match scan.

The collision-shape provider reads only TYPE and FACING (`ChestBlock.java:192-203`): SINGLE returns the centered chest shape; LEFT/RIGHT choose a rotated half-shape from `getConnectedDirection`, which uses facing clockwise for LEFT and counter-clockwise for RIGHT. WATERLOGGED does not select collision geometry. Neighbor update (`:158-185`) connects only same-block horizontal neighbors when the current state is SINGLE, neighbor has a non-SINGLE type, both facings agree, and the neighbor's connected direction points back; it disconnects when the changed direction equals this state's connected direction. This is narrower than the historical four-way same-instance scan and its N>S>W>E precedence. A valid current `TYPE` is therefore a context gate, not an unconditional translation of old neighbor identity/precedence. Where a historical response needs arbitrary old topology, preserve all current vanilla states and compute the historical provider result from the queried state's kind plus current neighboring kinds in old order.

## Projection verdict

- **Exact tuple subset:** old decoded facing agrees with flattened `type=single` rows for metadata 0–8 and 12–14, for each of IDs 54/146; 9, 10, 11 and 15 differ.
- **Name-only coverage:** all 16 flattened rows per ID retain `minecraft:chest` or `minecraft:trapped_chest` after the complete ordered rename sequence; this does not prove old tuple equality.
- **Context gate:** paired-box choice depends on old same-kind neighbor identity in N/S/W/E priority, independently of facing. Current `TYPE`/FACING pair updates encode only the modern compatible-pair condition and cannot be blindly equated with the legacy rule.
- **Vanilla-state preservation:** do not rewrite FACING, TYPE, WATERLOGGED, registry identity or neighbor states to synthesize legacy geometry. The historical shape response is a read-time projection.

Evidence is bounded to the exact endpoints and source rows listed here. No intermediate boundary is claimed. See `source-hashes.sha256` for decompiled source and prior projection identities.
