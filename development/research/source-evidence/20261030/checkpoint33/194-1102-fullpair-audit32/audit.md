## Reconstructed ordered tick graph and terminal dependencies

1. `Minecraft.tick` advances the client world/player in the same relative order in both endpoints. `ClientWorld` ticks the local player; the local `mobTick` consumes the pending synthetic-jump timer before superclass jump/travel work. `KeyboardInput` is byte-identical. `Input.getMovement` and option registration/cache are new in the later endpoint as dependencies of auto-jump.
2. Ordinary jump, sprint/flight gates, movement-speed reads, jump boost, relative movement, pose dimensions, gravity/fluid branches and their position/velocity/box writers were paired. Player jump/flight arithmetic and pose-fit checks are equivalent. The water multiplier helper still supplies `0.8F` for players; its only override is polar-bear-specific. New no-gravity behavior belongs to a feature absent from the older player profile and is excluded.
3. Local movement reaches `Entity.move`: swept collision acquisition, sneaking edge support, Y→X→Z clipping, step-up candidates and squared-distance choice, final collision flags and state writes are equivalent. `World.getCollisions`/block iteration, movement `Box` operations, default `BlockState` shape delegation, translated collision boxes, and era-existing collision providers were paired. Farmland is the one accepted geometry delta: 1.9.4 and 1.10 retain full-block collision while their visual/provider shape is 15/16 high; from 1.10.1 the collision override is absent and the inherited 15/16 shape is used. Exact 1.10 and 1.10.1 embedded provenance hashes and complete per-file source maps were verified; the first stable source-present release is 1.10.1.
4. Post-move support/fall/step dispatch and `checkBlockCollisions` footprint traversal were independently retraced. The chosen support block, `onGround` gate, footprint floor/epsilon bounds, loaded-region gate, callback order and exception behavior match. Existing contact callback bodies, climbing checks, liquid presence predicates, loaded-area bounds, flow scans and velocity accumulation match. The `0.014` local-to-literal edit preserves the same double operation. New Magma behavior is damage-only on a block absent from the older release.
5. The later local-player move override adds the auto-jump queue/detect/consume route. Its option cache is copied from game options inside the `isCamera()` branch of `sendMovementToServer`. It calls `super.move` before detecting; it queues one tick only under its grounded/input/sneak/riding/facing/collision gates, and consumes the press on the next `mobTick`. The `bl4` guard prevents that synthetic press toggling flight. Its height threshold is `>0.5F` and at most a ceiling initialized to `1.2F`, raised by `(jump-boost amplifier + 1) * 0.75F` when jump boost is active. The geometry scan depends on the collision/provider closure above. Source presence begins at inspected release 1.10; the 1.9.4 absence does not prove an intermediate patch boundary. This is a source fact for a modern-only feature, excluded from historical older-profile emulation under the project invariant.
6. Direct client response routes were retraced: player position correction; entity relative movement/teleport when targeted at the local-player id; entity velocity; explosion impulse; entity spawn velocity; passengers/start-riding; vehicle correction; abilities; attributes/effects; entity synced data; sleep/wake; and respawn/reinitialization. Gates and relevant final position/velocity/shape state match. Two source scheduling changes—`trySleep`'s zero assignments and `Entity.updatePositionAndAngles`'s current/last coordinate assignments—have no intervening reads/calls and preserve final state. The changed synced-data branch only plays Elytra sound.
7. Block/world input receipt was checked as the world-state terminal feeding collision reads. `handleBlocksUpdate`, `handleBlockUpdate`, `handleWorldChunk`, `handleBlockEvent`, and `ClientWorld.setBlockStateFromPacket` keep their gates, order and calls. `WorldChunk.setBlockState` changes only when an empty section is stored relative to setting a local boolean; the same section/state is stored before subsequent callbacks and the returned/final state logic is otherwise identical. Piston `doEvent` dispatch is identical; the changed resolver's start-block branch is logically equivalent (`DESTROY` adds the start position and returns true, otherwise returns false). This closes the previously noted piston/client block-event edge without comparing server world evolution as a player-physics input.
8. The changed chorus-fruit caller adds `stopRiding()` before teleport attempts only inside `if (!world.isClient)`. It is a server-authoritative item-use producer and is out of historical client player-movement scope. `LivingEntity.tryTeleport`'s collision/shape validation is equivalent across endpoints; the direct position response consumer is already paired above. This candidate is rejected for this movement inventory, not left as an open player consumer.

## Resource and registration closure

The decompiled manifests contain Java paths only. These versions register blocks and state properties in Java; player collision and auto-jump geometry call Java `BlockState`/block shape methods. The inspected movement graph has no model, texture, blockstate-resource, or tag lookup dependency. Resource reload references are on presentation paths. Thus no external resource/tag input feeds the frozen movement terminals. The exact raw client archives were unavailable, so archive payload enumeration was not performed; that does not leave a movement dependency open in this Java source graph.
