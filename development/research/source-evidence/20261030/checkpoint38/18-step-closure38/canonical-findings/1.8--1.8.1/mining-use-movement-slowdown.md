# Mining-gated item use and local movement state: 1.8 → 1.8.1

## Finding

The 1.8 client permits `Minecraft.doUse()` while ordinary survival mining is active. In 1.8.1 the entire method body is guarded by `!interactionManager.isMiningBlock()`. The attack click is processed before the use click in the same client tick, so targeting a non-instant-mined stone block sets the mining flag before the bow-use attempt.

With a bow and arrow selected, stone's block-use hook returns false and bow `useOn` falls through, so 1.8 calls `useItem`; `BowItem.startUsing` locally stores item-in-use state. The 1.8.1 guard skips that transition. On the following non-riding local-player movement tick, the unchanged consumer multiplies both movement input axes by `0.2F` and clears double-tap sprint timing while `hasItemInUse()`; both sprint-start paths also require `!hasItemInUse()`. Thus this reachable input sequence changes local movement input and sprint eligibility in 1.8 versus 1.8.1. The same mining guard is present in 1.8.2, so the audited boundary remains absent there.
