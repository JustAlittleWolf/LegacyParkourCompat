# Pair audit erratum: client entity-push route

The prior `pair-source-inventory.md` and draft `findings/entity-push-impulse-precision.md` used a RemotePlayer as the source of the player impulse. That route is invalid: exact RemotePlayer constructors set `noPhysics = true`, so the shared `Entity.push(Entity)` guard returns; furthermore the client `EntitySelector.pushableBy` rejects remote-player candidates when the LocalPlayer is the query source. Preserve those prior files unchanged, but do not use that stated witness.

The corrected source route is a nearby ordinary non-player Mob as the query source. `Mob.tick()` calls `super.tick()` on the client; `LivingEntity.tick()` invokes virtual `aiStep()`; `Mob.aiStep()` invokes `super.aiStep()`; the inherited LivingEntity path calls `pushEntities()` after travel. As the `entity` argument to `EntitySelector.pushableBy(mob)`, the Mob's client-side entity list admits a `Player` candidate only when it is `isLocalPlayer()`. `doPush(localPlayer)` calls `localPlayer.push(mob)`. With a non-spectator local player not on climbable support, an awake/pushable Mob not marked `noPhysics`, no common vehicle, no vehicle passengers, default zero `pushthrough`, and `absMax(dx,dz) >= 0.01F`, the changed precision is consumed by the local player velocity writer. For conditional `localPlayer.x - mob.x = +0.03, z difference = 0`, the local player's new negative X impulse is `-0.008660254166892228` vs old `-0.008660254322328477`; no normal input trajectory is claimed.

The independent audit of this route remains open until its erratum is delivered. No pair freeze is implied.
