## Prioritized reconciliation

### P1 — Add the missing 1.15.2 eye-water producer behavior

**Disposition: actionable product gap.** The accepted endpoint comparison has a reachable local movement consequence: 1.15.2 computes `Player.wasUnderwater` from a direct current-tick eye-position query before `super.tick`; 1.16.0 and later read the cached `isEyeInFluid(WATER)` result before `Entity.baseTick` refreshes it. In 1.15.2 the threshold is the strict comparison `eyeY < blockY + (fluidHeight + 0.11111111F)`, with the epsilon added to float height before the block-Y addition. The audited `8/9F` source-fluid witness demonstrates that this numeric ordering can also change the result. Local-player underwater sprint qualification and the later water-travel friction branch consume the cached `wasUnderwater` value.

The product has the right dispatch point: `PlayerMixin#legacyparkourcompat$queryCachedEyeWater` redirects `Player.updateIsUnderwater` through `PlayerEyeWaterQueryHook`. Implementations currently exist at V1_12 (native), V1_13_1, and V1_14_2. `ChangeResolver` excludes changes older than the selected version, so a V1_15_2 selection resolves no query hook. `NativeEyeFluidSample` at V1_15_2 belongs to the separate `PlayerEyeFluidSampleHook`; it restores the modern fluid-tracker scan coordinate, but it does not replace `updateIsUnderwater`'s cached read with the historical current-tick query. As a result, selected 1.15.2 falls through to the modern cached producer.

**Minimal operation/alias queue:** add one `PlayerEyeWaterQueryHook` implementation anchored at V1_15_2 for `Player.updateIsUnderwater`: point-sample WATER at the current eye position, preserve the 1.15.2 loaded-chunk and boat gates, use contextual fluid height, and preserve the strict float operation order above. The exact old query is `Entity.isUnderLiquid(WATER, true)` (1.15.2 Mojmap). The already-present V1_14_2 implementation remains the closer match for profiles through that boundary; V1_15_2 supplies the direct producer for the verified 1.15.2 profile. Before allowing closest-later resolution to apply that anchor to the broader V1_15 profile, verify that 1.15.0/1.15.1 have the same producer or provide an appropriate version fence. At V1_16.0, source changes to the cached eye-fluid query; the no-hook/native path is appropriate for that newer operation. Keep `PlayerEyeFluidSampleHook` separate because it selects the sample coordinate inside the newer tracker refresh, not the value assigned to `wasUnderwater` at tick entry.

This is a source-supported movement operation, not a runtime parity result. No broader effect-reader or jump-boost work is proposed; the independent effect receiver remains out of scope here.
