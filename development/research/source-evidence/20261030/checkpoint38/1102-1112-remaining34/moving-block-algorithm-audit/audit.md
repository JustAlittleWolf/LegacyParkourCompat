# Independent audit: moving-block algorithm closure, 1.10.2 → 1.11.2

## Verdict

**Accept the two remaining dependencies as open response-trace gates.** The stair, corrected piston-head, and World/moved-fence closures do not execute either disputed operation. Exact source confirms that the 1.11.2 retraction helper is reachable from a successful primary PISTON response, and that the 1.10.2 terminal response call runs after the local-player entity phase while the 1.11.2 block entity is removed without that call. Neither source reachability nor the existing witnesses establish the required paired post-player AABB/response trace, so the two gates must remain open at that level.

The open status must not be described as source unreachability. There is a concrete local-client caller for both operation paths. Also, each typed 1.11.2 PISTON move dispatches through `LocalClientPlayerEntity.move`, which conditionally runs local auto-jump after `Entity.move`; the closure’s call-chain summary should include that secondary response route when a local-player movement is being evaluated.

## Route audit

### Retraction follow-up pull

- Both endpoint `PistonBaseBlock` retraction branches install a `MovingBlockEntity` at the base with `extending=false, source=true` (`1.10.2` `net/minecraft/block/PistonBaseBlock.java:168–182`; `1.11.2` `:172–186`). This is the exact state selecting the newer follow-up branch.
- In 1.11.2 `MovingBlockEntity.moveEntities(float)` computes `d = progress - this.progress`, collects the source head’s collision shapes, builds the directional swept query, skips only entities whose piston behavior is `IGNORE`, and calls `entity.move(MoverType.PISTON, ...)` only for `e > 0` (`net/minecraft/block/entity/MovingBlockEntity.java:116–164`). For a retracting source, the immediately following `moveEntity(entity, direction, d)` is entered only after that primary call (`:156–164`). The helper then independently requires the post-primary entity box to intersect the source-cell full cube and `abs(d-e) < 0.01` before issuing the opposite-direction PISTON move (`:231–244`). The condition sequence is explicit; none of the prior closure witnesses checks it.
- The local player is eligible at the source level: base `Entity.getPistonMoveBehavior()` returns `NORMAL` in both versions (`1.10.2` `net/minecraft/entity/Entity.java:2306–2308`; `1.11.2` `:2412–2414`), and the source reports/audits confirm no player override to `IGNORE`. The local client player tick calls its superclass on a loaded-chunk path (`LocalClientPlayerEntity.java:152–154` old; `:159–161` new), and world entity ticks precede block-entity ticks (`World.java:1270–1325` old; `:1271–1325` new). The block-entity tick has no client-side exclusion. Thus a local player can participate in the primary move and is a valid target for the subsequent helper if its post-primary box and clearance satisfy the helper gates.
- **Additional caller effect:** 1.11.2’s typed call dynamically dispatches through `LocalClientPlayerEntity.move(MoverType,...)`, which calls `super.move` and then `autoJump(dx,dz)` (`net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java:823–829`). `autoJump` has its own input, grounded, cooldown, and direction gates (`:835–868+`). The old path calls untyped `Entity.move(double,...)` and has no matching local-player `move` override. Therefore a qualifying new primary or follow-up local-player movement can also enter a conditional client auto-jump response. This is a call-route fact, not a claim that auto-jump fires in every retracting layout.
- **Status:** the helper is a reachable algorithm path, but its paired response gate remains open because no accepted evidence follows one local-player AABB through primary displacement, source-cell overlap, the clearance equality test, and the resulting paired old/new response. The source-retraction/SHORT audit establishes that the ordinary terminal SHORT arm is contained by the separately collected base; it does not run or close this second movement call. The stair witness is extending and does not enter `!extending && source`. The World/fence witness is a pose query/provider route and makes no paired retraction trajectory claim.

### Old-only terminal progress-1 response

- The old tick copies progress into `lastProgress`; when it is already at least 1, it runs `moveEntities()` before removing the moving block (`1.10.2` `net/minecraft/block/entity/MovingBlockEntity.java:166–184`, especially `:168–175`). New tick has the same terminal progress test but removes/completes directly, with no `moveEntities` call (`1.11.2` `:272–290`, especially `:274–281`).
- The client local-player/entity phase precedes block-entity ticking in both `World.tickEntities` bodies (`1.10.2` `net/minecraft/world/World.java:1270–1325`; `1.11.2` `:1271–1325`). Accordingly, if a local player remains in the old terminal response query after its own tick, the old endpoint can move it after that tick; the new endpoint removes the moving entity without that final response. This ordering verifies an exposed phase difference, not the needed spatial condition.
- **Status:** genuinely open as a paired terminal response trace. None of the prior geometry closures places and retains an eligible player in this final `moveEntities` query after the preceding player phase. The corrected progress-1 piston-head witness proves a collision-list clipping case before removal; it does not prove overlap with the old direct-response query after the player tick. The extending-stair direct-response witness is the prior half-step and does not analyze the extra old-only call. The fence closure concerns a standing-pose boolean query and expressly lacks an end-to-end retraction trajectory.

## Closure cross-check and limits

The two open claims are properly bounded to missing paired response traces, not to missing source calls. No false closure was found among the cited stair, source-head, or World/fence closures: each exercises a different state, provider, consumer, or tick phase. Conversely, the route audit does identify a reachable local-player caller for the 1.11.2 helper and an old terminal call opportunity; neither should be dismissed as unreachable simply because no paired displacement witness is yet accepted.
