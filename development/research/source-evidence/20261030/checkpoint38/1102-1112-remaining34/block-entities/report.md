## Piston-head path and paired geometry witness

The caller is **1.11.2 `MovingBlockEntity.addCollisions`** (`:318–345`): for a source moving block entity while retracting, it first collects the extended piston base, then creates a facing `PistonHeadBlock` state and sets `SHORT` with `extending != 1.0F - progress < 0.25F` (`:318–340`). For `extending=false`, `source=true`, and progress `0.8F`, this evaluates to `SHORT=true`. The generated head's `FACING` is the piston direction. `getAmountExtended(0.8F)` is `0.2F` for retraction (`:91–93`), and the head collision boxes are translated by that amount (`:331–345`). The condition allowing the head collision collector is satisfied for the ordinary player query (`NOCLIP_DIR` is unset; `:328–330`).

A reachable example uses an east-facing source piston retracting at progress `0.8F`. The paired extended-base box starts at local X `0.0` (`PistonBaseBlock.java:29–33, 52–69` in both endpoints). The old full east arm spans X `[-0.25, 0.75]` (`PistonHeadBlock.java:35–38` old), so after the `+0.2` retraction offset its collision begins at `-0.05`. The new short east arm spans `[0.0, 0.75]` (`PistonHeadBlock.java:41` new), so after the same offset it begins at `0.2`; the base remains the nearest new collision, starting at `0.0`. A local player's box overlapping the arm's Y/Z cross-section and approaching from the west can therefore move up to `0.05` less far toward the piston in the old collision solve: e.g. choose its current `maxX=-0.08` and request `+0.10 X`. The old head clips the attempted box at `maxX=-0.05`; the new head is absent from that gap and the base clips at `maxX=0.0`. This is a collision-solve response, not a claim about the full piston tick trajectory.

The client player route is ordinary `World.getCollisions(entity, box)` collection of the moving block entity's boxes, followed by the player's `Entity.move` axis solver. The permitted prior piston-response closure establishes the client moving-block entity tick/caller route; the permitted solver report establishes the ordinary player collision-list consumer. This witness is distinct from the already paired extending-stair case: it requires `!extending && source`, while the stair witness uses extension and an ordinary moved stair. Do not merge them into one geometric witness or create a second piston operation.
