# Bounded correction: early piston stair player response

1.8.9 uses a distinct, client-reachable response caller for the fixed extending bottom, north-facing straight cobblestone-stair witness. `MovingBlockEntity.tick()` advances the block entity by `0.5F` and passes `progress - lastProgress + 0.0625F`; at the second half-step this is `0.5625F`. Its moving-block collision query uses the stair’s full straight-stair AABB and reaches the player, then directly requests `Entity.move(+0.5625, 0, 0)`. In the stated clear route, that request is not clipped: the ordinary moving-block collision shape at the same instant is only extended to X `0.5`, behind the player, and the slab support at Y `0.5` merely face-touches the player box.

For 1.9, 1.9.1, 1.9.2, 1.9.3 and 1.9.4, the moved straight stair keeps the inherited full-cube `getShape`; `MovingBlockEntity` unions its current and previous half-step shapes. On the second step the east face is X `1`; the caller computes `1 - 0.65 + 0.01 = +0.36 X` and invokes ordinary `Entity.move`. The moving-block collision union already overlaps the player, so positive-X clipping does not reduce it. The accepted 1.10.2 source baseline has the same bounded amount.

The 1.8.9 amount difference is a separate closed source finding/version delta inside the same piston-induced player movement response. It is not evidence for a separate hook on its own. Exact applicability is limited to the versions and layout above.
