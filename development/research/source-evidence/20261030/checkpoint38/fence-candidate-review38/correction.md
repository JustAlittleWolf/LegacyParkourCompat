# Correction to the independent fence candidate review

This correction supplements the immutable review `review.md` (SHA-256 `3A7517F0318C5EFFF234F116CD8D58B3030AC5007166E1DEF4C5C1331C357689`). The original report remains unchanged. The correction follows re-reading the product resolver and checking the corrected candidate commit.

## Corrected review conclusions

1. **Withdraw the requested 1.12 stair implementation.** `ChangeResolver.resolve` filters registrations with `change.emulates().newerThanOrEqual(selected)` and chooses the lowest eligible ordinal. The candidate’s v1.11.2 registration is therefore not selected for a v1.12 or later profile. For v1.11.2 and earlier, mapping the stair to disconnected is the accepted old behavior. No new v1.12 candidate delta is required for this bounded change; later profiles retain vanilla behavior.
2. **Withdraw the full-neighbor-domain request for the assigned witness.** The accepted fixture has one historical straight stone stair south of the fence and air north/east/west. Those four inputs are all handled by the candidate’s gate. It computes all four bits and clears the south bit, producing the center-only collision geometry for the 1.11.2 profile. An unrecognized neighbor makes the hook return empty for the entire operation, preserving native geometry rather than mixing a partial historical mask with stored modern bits. That is a valid native fallback outside this deliberately bounded witness; it does not claim a complete fence predicate implementation.
3. **Withdraw the lower-boundary request.** The v1.10.1 no-op registration is a resolver barrier preserving the candidate’s pre-existing native fallback below the assigned v1.11.2 profile. It makes no historical correctness claim for releases earlier than 1.10.2. The earlier report treated the barrier as asserting such a claim; that was too strong.
4. **Product hook order is compatible for the accepted fixture.** The CrossCollisionBlock hook supplies the v1.11.2 center-only shape, then `BlockStateCollisionShapeMixin` receives it at return. The selected `FenceLegacySolidConnections` shape hook returns empty when the restored-neighbor mask is zero; the selected `NativeFenceGlassCollision` also returns empty. The selected fence/wall neighbor hook does not restore a bit for a stair or air. Therefore these later hooks do not replace the fixture’s candidate geometry. This only establishes composition for the accepted stair-plus-three-air case, not general fence equivalence.

## Corrected candidate commit review

Reviewed correction commit: `76c75df9638a4885b6b1a412b3d12b21e2438610` (`Map legacy stone stairs to cobblestone stairs`). It replaces the erroneous `minecraft:stone_stairs` candidate key with `minecraft:cobblestone_stairs` and cites the exact supporting sources. In 1.11.2 Ornithe Feather, `Blocks.STONE_STAIRS` is the stair crafted from `Blocks.COBBLESTONE` (`block/Blocks.java`, `crafting/CraftingManager.java`). In current 26.2, `BlockStateData` distinguishes the legacy straight stone-stair state mapping to `minecraft:cobblestone_stairs` from modern `minecraft:stone_stairs`, and the native block registry has both blocks. The corrected key admits the accepted straight-stair witness and leaves modern stone stairs outside this legacy whitelist. The correction is source-consistent.

**Disposition for the corrected candidate:** ACCEPT for the assigned bounded v1.11.2 stair-arm witness, subject to the parent integration review and with runtime parity still unverified. The original b7e6cff commit remains defective because it used the modern `stone_stairs` key; this acceptance is specifically for its correction commit.
