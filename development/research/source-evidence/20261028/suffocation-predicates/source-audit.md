# Independent blind source audit: 1.16.1 → 1.16.2

Inputs: exact Mojmap 1.16.1 and 1.16.2 source trees under `D:/Javastuff/LegacyParkourCompat/decompiled_minecraft/`; identity and selected-file hashes are in `source-identity.md`. This audit did not consult other frontier lanes, wiki inventories, product implementations or history. Line references below are in those exact source trees.

## Movement differences confirmed

### Sneak edge back-off gate

1.16.1 `net/minecraft/world/entity/player/Player.java:1010-1059`; 1.16.2 same file `:1010-1065`. `Entity.move` calls `maybeBackOffFromEdge` before collision resolution (`Entity.java:488-489` in 1.16.1; `:504-505` in 1.16.2). The 1.16.1 gate is `(SELF || PLAYER) && onGround && isStayingOnGroundSurface()`. In 1.16.2 it is `!abilities.flying && (SELF || PLAYER) && isStayingOnGroundSurface() && isAboveGround()`. The 0.05 decrement loops and their X, Z, then diagonal order are unchanged.

Concrete changed path: a non-flying player holding the stay-on-ground input can now have horizontal displacement reduced while `onGround` is false when `fallDistance < maxUpStep` and the bounding box moved down by `fallDistance - maxUpStep` would collide. The old gate skipped the back-off in that state. Conversely, the explicit new flight gate suppresses it while flying. This is a player movement operation, distinct from its gate predicate.

### Soul Speed support lookup

1.16.1 `net/minecraft/world/entity/LivingEntity.java:424-430,446-450`; 1.16.2 same file `:425-431,447-451`. The 1.16.1 hook tests `getBlockStateOn()`, which delegates to `getOnPos()` (`Entity.java:579-592,1032-1033`); that position floors `position.y - 0.2F` and has a fence/wall/gate fallback. The 1.16.2 hook reads the block at `getBlockPosBelowThatAffectsMyMovement()` (`Entity.java:627-628`), which floors `position.y - bbox.minY offset - 0.5000001` through `BlockPos` construction. Player's existing flying gate remains in `Player.java:918-920` on both sides.

`onSoulSpeedBlock()` feeds both the Soul Speed block-speed-factor lookup and attribute application, so the selected block can affect movement friction and the Soul Speed movement modifier. A reachable vertical interval exists where the two floored positions differ (for example, a player descending with feet between the `y - 0.5` and `y - 0.2` boundaries); the new lookup can then see the block below while `getBlockStateOn()` still names the air block above. This is a lookup operation change; the player gate and enchantment rules are unchanged.

Registration and shape dependencies were checked. `BlockTags.SOUL_SPEED_BLOCKS` remains bound to `soul_speed_blocks` (`BlockTags.java:77`), and `BlockTagsProvider.java:515` adds soul sand and soul soil in both versions. `SoulSandBlock.java` is byte-identical; its collision shape remains `Block.box(0,0,0,16,14,16)` (`:18`). `Blocks.SOUL_SAND` retains speed factor `0.4F`. No Soul Speed registration, tag-member or soul-sand-shape delta was found. A separate block-state predicate delta is recorded under the LocalPlayer suffocation response below.

### Local-player suffocation escape response

1.16.1 `net/minecraft/client/player/LocalPlayer.java:413-470,681-685`; 1.16.2 same file `:414-449,656-660`. Both versions call the response at four horizontal samples when `!noPhysics`. In 1.16.1 `checkInBlock` floors each sampled `(x, y + 0.5, z)`, treats any `isSuffocating` state in the player's integer vertical span as blocked, checks WEST, EAST, NORTH, SOUTH in that order, and applies a fixed `0.1` velocity on the chosen horizontal axis. In 1.16.2 `moveTowardsClosestSpace` samples `(x,z)` using current player Y, tests a one-block X/Z AABB spanning the player's bounding-box Y and deflated by `1.0E-7`, and uses `CollisionGetter.noBlockCollision` with `blockState.isSuffocating` as the block predicate. It selects among a `Direction[]` in WEST, EAST, NORTH, SOUTH order, with `Double.MAX_VALUE` as the initial comparison bound; velocity is `0.1 * direction step` on the selected axis.

The block-state predicate dependency also changes. 1.16.1's default `BlockBehaviour.Properties.isSuffocating` requires a motion-blocking material and a full collision shape (`BlockBehaviour.java:786-788`); 1.16.2 keeps that default (`:806-808`) but `Blocks.java` now explicitly sets `isSuffocating(Blocks::always)` for farmland (`:493-504`), soul sand (`:730-741`) and grass path (`:1965-1971`). Their shapes remain 15/16 high for farmland and grass path and 14/16 for soul sand (`FarmBlock.java:27-29`, `GrassPathBlock.java:17-18`, `SoulSandBlock.java:18`). Thus, when the LocalPlayer AABB intersects the volume of one of these blocks and one horizontal neighbor has no suffocating collision, the old point/column predicate reports free while 1.16.2's suffocating-state-plus-shape query can choose an escape direction and inject horizontal velocity. Standing normally on their top faces does not meet this overlap condition because the new query deflates the AABB away from the shape. The source-level trigger is an already-overlapping player box, such as after a position or block-state update; ordinary walking into the block is prevented by collision. This is a direct player response with a reachable source precondition, while the exact external update path that first creates the overlap remains open. Collision filtering closes through the new `CollisionGetter.noBlockCollision` helper (`CollisionGetter.java:62-63` in 1.16.2), which filters block collision shapes and requires all to be empty.

### Block-break acknowledgement setback

1.16.1 `net/minecraft/client/multiplayer/MultiPlayerGameMode.java:429-443`; 1.16.2 same file `:428-443`. Both capture the player position when sending an action and correct the local block when a returned state disagrees. In 1.16.1 the pending value stores position plus pitch/yaw and any qualifying state mismatch restores both position and rotation. In 1.16.2 it stores only `Vec3` and restores position only if the player is on the same client level and `Entity.isColliding(blockPos, blockState)` succeeds. The new shape test is `Entity.java:214-218` and uses the returned block state's collision shape translated to world coordinates, intersected with the player's AABB.

Reachable precondition: a sent block action has a pending position, the server acknowledgement requires replacing the local state, and the replacement state's collision shape intersects the current player AABB. Under that condition 1.16.2 sets the player to the captured position without resetting rotation; otherwise it skips the position correction. The old qualifying mismatch always restores captured position and orientation. This is a direct network-triggered player movement response, separate from collision resolution during the ordinary tick.

### Lava current sampling call gate and lava-presence query

`net/minecraft/world/entity/Entity.java`: 1.16.1 `:947-956,1065-1070`, 1.16.2 `:957-963,1071-1072`. In 1.16.1 the method clears fluid heights, samples/pushes water, returns immediately if `isInWater()`, and otherwise samples/pushes lava. In 1.16.2 it always samples/pushes lava after water and returns `isInWater() || lavaSample`. Therefore the fluid scan itself has no math/range delta, but its lava invocation gate changes. With a player AABB overlapping flowing water and flowing lava whose surfaces meet the scan threshold, on loaded chunks and with fluid pushing enabled, 1.16.2 adds the lava current after the water current; 1.16.1 returns after the water sample. The independent current-sampling primitive `updateFluidHeightAndDoFluidPushing` (`Entity.java:2633-2705` / `:2641-2705`) has unchanged loops, `FluidState.getHeight/getFlow`, accumulation, scaling and `fluidHeight.put` behavior.

Separately, 1.16.1 `isInLava()` reads `isTouchingLava`, a boolean cleared immediately before `checkInsideBlocks` and set by `LiquidBlock.entityInside` (`Entity.java:551-553,1065-1070`; `LiquidBlock.java:178-184`). In 1.16.2 the callback/setter and boolean are gone; `isInLava()` reads `!firstTick && fluidHeight[LAVA] > 0`, populated by the AABB fluid scan. This changes the state/predicate source and update timing. Concrete moving callers include `LivingEntity.travel` lava branch (`LivingEntity.java:1957` / `:1959`) and lava-dependent vertical/fall handling (`:2427-2436` / `:2429-2438`); `Entity.baseTick` also halves fall distance while in lava (`Entity.java:392-395` / `:400-403`). The new query can report partial fluid-height overlap and is evaluated from the base-tick scan, while the old query depended on block-collision callbacks. Damage consequences are outside this movement finding.

## Changed predicate or context with no established vanilla player movement delta

- `Entity.updateFluidOnEyes` (`Entity.java:974-996` / `:981-1003`) changes the boat suppression test from `boat.getBoundingBox().contains(samplePoint)` to only `boat.maxY >= sampleY && boat.minY <= sampleY`. `BlockPos(Vec3)` is replaced by the coordinate constructor for the same `(x, sampleY, z)` point. The changed boat predicate is real, but `Boat.positionRider` centers a single passenger and offsets two-passenger seats by at most `0.6` (`Boat.java:646-664`); ordinary passenger centers remain inside the boat bounds. An off-center modded or otherwise exceptional passenger case was not established as a vanilla LocalPlayer movement path. The eye-fluid result feeds `isUnderWater` and local swimming controls, so this predicate merits a bounded recheck if the scope includes nonstandard passenger placement.
- `LivingEntity.isPushable` adds `!isSpectator()` (`LivingEntity.java:2647-2649` / `:2648-2650`). The player already sets `noPhysics = isSpectator()` in `Player.tick` and `EntitySelector.pushableBy` excludes spectators (`EntitySelector.java:28-39`), so this extra condition has no reachable vanilla player-push effect found here.
- `Entity.setPos` now delegates box construction to `EntityDimensions.makeBoundingBox` (`Entity.java:331-334`); the helper copies the same two float locals and the same AABB arithmetic as 1.16.1 (`EntityDimensions.java:14-24` in 1.16.2). No positional/box math delta.
- `Entity.canCollideWith/canBeCollidedWith` and removal of the old collide-box accessors lead to entity-query/picking eligibility (`EntityGetter.java:66-70`); no ordinary player movement caller was found in the searched source. Block-break correction is covered above through the separate `isColliding` helper.
- The `LocalPlayer.processDimensionDelay` call was renamed to `processPortalCooldown` alongside portal-state refactoring. Portal transfer/cooldown and leash-rope anchor changes are outside ordinary movement; the rope-anchor methods are new or changed only for rope/render placement.
