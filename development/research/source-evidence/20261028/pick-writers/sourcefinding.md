Difference: In 1.8.9 the client tick calls the camera entity's `rayTrace` before `world.tickEntities`. That call uses `World.rayTrace(from, to, false, false, true)`: it does not prefilter candidates by collision shape, and it permits a hit in the starting cell. The starting cell is queried first, then the DDA tests ray-crossed cells in order by choosing the smallest boundary fraction; its strict X-then-Y comparisons leave Z as the tie fallback. It stops on the first non-null block hit, otherwise continues to the endpoint or 201-iteration bound. For each visited block whose `canRayTrace` gate passes, `Block.rayTrace` first calls `updateShape` and only then tests the six box planes. Thus a missed shape intersection still writes that block singleton's bounds. Anvil/chest inherit the base `canRayTrace() == true`. The same tick's entity collision scan reads the current singleton min/max bounds through `Block.getCollisionShape` without refreshing them for the colliding position.

The base `Block` constructor starts with a full cube. `AnvilBlock` does not replace it in construction, so it keeps that full cube until an eligible ray query first calls `updateShape`; afterwards each eligible anvil query writes the queried anvil's facing axis even if the ray misses. One registered anvil block object serves all `DAMAGE` property states, and `updateShape` reads `FACING` only, so a query through one damage state also changes the box later read for another damage state. `ChestBlock` replaces the base full cube in its constructor with its single-chest inset. Normal chest and trapped chest are registered as two separate `new ChestBlock(...)` objects, so their shared bounds are independent per block type; within each type, a ray query's neighbor-priority result can be read later by movement collision at another position of that same type.

In 26.2 the client tick also calls `pick` before `level.tickEntities`. On the ordinary fallback path, `LocalPlayer.pick` calls `Entity.pick`, which clips an `OUTLINE` shape with `CollisionContext.of(cameraEntity)` and no fluid picking. `BlockGetter.traverseBlocks` first queries a start cell computed from endpoints expanded by 1e-7 along the ray, then chooses each next cell by boundary fraction (strict X-then-Y comparisons, Z as tie fallback); the clip callback queries each traversed block's state shape, invokes the interaction-shape query only after an outline hit, then asks the context for a fluid shape. `Fluid.NONE` returns an empty shape without calling `FluidState.getShape`. It returns the nearer hit and traversal stops at the first non-null result, otherwise making a miss. A miss still performs state outline-shape queries, but they return state-resolved `VoxelShape`s and do not write shared bounds. For ordinary movement collision queries, `CollisionGetter.getBlockCollisions` creates `BlockCollisions` with the entity's collision context, and `BlockCollisions.computeNext` calls the queried block state's `getCollisionShape`. Chest `getShape` selects the queried state's `TYPE`; anvil `getShape` selects its queried state's `FACING` axis. These outline and collision shapes resolve from state on each query.

Movement meaning: with a reachable pre-movement pick path through an anvil or chest that misses that block, 1.8.9 can leave its shape on the shared singleton and the same tick's player collision scan can consume it at a different same-type block position. For anvil the last eligible query can select a different axis and spans every damage state; for chests the last eligible query can select another neighbor-priority half, separately for normal and trapped chests. Before an anvil's first writer it retains the constructor full cube; before any chest writer each chest type retains its constructor single-chest inset. 26.2's pick traversal has no equivalent shared shape write. The observable movement difference remains conditional on the most recent writer, pick traversal order/early exit, and the player's swept box reaching the resulting shape; this endpoint comparison does not identify the intermediate patch where the change occurred.
