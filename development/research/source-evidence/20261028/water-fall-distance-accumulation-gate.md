# Water gate on fall-distance accumulation
1.21.4, Mojmap: `decompiled_minecraft/1.21.4/mojmap/net/minecraft/world/entity/Entity.java`, `checkFallDamage` lines 1237–1252.
1.21.5, Mojmap: `decompiled_minecraft/1.21.5/mojmap/net/minecraft/world/entity/Entity.java`, `checkFallDamage` lines 1274–1291.
Difference: In 1.21.4, a downward delta is accumulated only in the `else if ($$0 < 0.0)` branch after the on-ground reset branch. In 1.21.5, accumulation is a preceding independent condition, `!this.isInWater() && $$0 < 0.0`; the on-ground handling follows it. This adds a water gate and changes the ordering relative to on-ground handling. The delta remains explicitly cast to `float` in both versions.
Movement meaning: When the movement callback runs with a negative resolved Y displacement while the entity reports `isInWater()`, 1.21.5 leaves `fallDistance` unchanged; the 1.21.4 writer has no water predicate. The change is reachable for an authoritative local player in 1.21.5, whose ordinary movement calls `Entity.move` with `MoverType.SELF`. In 1.21.4 the local-player callback is skipped by `Entity.move`'s authority gate, so the source does not support claiming this water condition altered that ordinary local-player path in 1.21.4. This finding concerns movement state only, not fall-damage production.
