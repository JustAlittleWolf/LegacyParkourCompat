# Independent source audit: 1.8.3 → 1.8.4

## Verdict

No in-scope local-player movement difference was found. The ordinary local-player input/tick, jump and movement calculations, entity position/box/velocity writers, collision dispatch, fluid/effect predicates, and relevant player-facing block responses inspected below are source-identical across this pair. The only changed source with a possible indirect movement dependency is `VineBlock.tick`; it is guarded by `!world.isClient` and mutates world block states, which this project leaves vanilla. `VineBlock.getCollisionShape` and the client-side vine-climbing predicate are unchanged. The other movement-adjacent source delta is server-side packet validation, outside the assigned client-physics scope and explicitly not replayed by this mod.

This closes the assigned client movement source audit. It is not a pair-freeze decision by itself; global pair freeze still depends on the coordinator’s complete source/wiki inventories and dependency review.

### Adjacent source deltas

- 1.8.3 and 1.8.4 `block/VineBlock.java:198-299` differ in randomized growth/update logic, including neighbor/side selection and horizontal connection-property propagation. In the downward merge branch, 1.8.3 tests `random.nextBoolean() || !(Boolean)state.get(property)` and clears the lower vine property; 1.8.4 tests `random.nextBoolean() && (Boolean)state.get(property)` and sets it. The adjacent growth branch also changes which target/support positions and state are used. The method body is under `if (!world.isClient)` (`:199`) and writes block states; `getCollisionShape` at `:126-129` remains `null`, and `LivingEntity.isClimbing` (`:794-799`) remains the same block-type test. Classification: server/world block-state production; retained vanilla block states are a project invariant. It does not establish a client movement change.
- `server/network/handler/ServerPlayNetworkHandler.java`, `handlePlayerMove` (`:180-346`; changed gate/math `:282-292`) changes the server's “moved too quickly” formula from component-wise minimum displacement/velocity magnitudes to displacement squared minus velocity squared, plus local variable names. It can affect server acceptance/teleport correction, but is server packet validation; historical movement is client-only and server replay is excluded. The selected-profile server policy is handled by this project independently.
- `server/world/PortalForcer.java` changes server-side portal orientation offset handling; excluded server/world transport behavior.
- Other modified blocks only adjust dispenser/dropper item-stack depletion or mob-spawner data handling. Remaining modified sources are UI/presentation, rendering, metadata, persistence, unrelated non-player AI, server administration/limits or diagnostics; none writes or reads local player movement state through the client movement path.
