# 1.13 pose alias and application closure

**Assignment:** Exact Ornithe Feather decompiled sources for 1.13, 1.13.1, and 1.13.2 only. This closes the ordinary local-player `PlayerEntity.updatePlayerPose` reachability, pose ordering, resize/write, collision-fit query, and immediately relevant state-consumer slice. It makes no claim about any earlier release, full movement parity, runtime behavior, or a patch boundary outside these three releases.

## Verdict

**Closed for the assigned three-release slice.** All three releases use the same outer pose-selection and resize operation, and it is reachable through an ordinary local-client-player tick. A concrete source boundary occurs between 1.13 and 1.13.1 in the collision-query API and representation: 1.13 returns a combined `VoxelShape` and tests `isEmpty()`, while 1.13.1/1.13.2 return a `Stream<VoxelShape>` and test `allMatch(VoxelShape::isEmpty)`. The pose call remains `world.hasNoCollisions(null, candidateBox)` in all three. With its null entity argument, each cited implementation omits entity and world-border collision inputs and checks block collision shapes. This closes the alias/source boundary; it does not assert the old and new collision enumerations are behaviorally equivalent in every geometry case.

## Ordinary local-player reachability and pose operation

In all three releases, `LocalClientPlayerEntity` extends `ClientPlayerEntity` (1.13 line 87; 1.13.1 and 1.13.2 line 89), and `ClientPlayerEntity` extends `PlayerEntity` (line 22 in each release). `LocalClientPlayerEntity.tick` invokes `super.tick()` when its current chunk is loaded (1.13 lines 179–181; 1.13.1/1.13.2 lines 181–183). `ClientPlayerEntity` declares no tick override in these source files, so that call reaches `PlayerEntity.tick`, whose tail invokes `updatePlayerPose` (1.13 line 253; 1.13.1/1.13.2 line 254). This is an ordinary local-client-player route; the selector has no local-player-only gate.

The selected dimensions and their order are text-identical in the three `PlayerEntity.updatePlayerPose` bodies: fall-flying → `0.6F × 0.6F`; else sleeping → `0.2F × 0.2F`; else swimming or spin attack → `0.6F × 0.6F`; else sneaking → `0.6F × 1.65F`; else standing → `0.6F × 1.8F` (1.13 lines 333–351; 1.13.1/1.13.2 lines 334–352). Only a width/height difference proceeds. It takes the current `getShape()`, creates `new Box(old.minX, old.minY, old.minZ, old.minX + width, old.minY + height, old.minZ + width)`, asks `world.hasNoCollisions(null, candidate)`, and calls `setSize` only if that predicate succeeds (1.13 lines 353–359; 1.13.1/1.13.2 lines 354–360). There is no new pose object or independent tracker state in these bodies.

`Entity.setSize` has the same operation text in all three sources (1.13/1.13.1/1.13.2 lines 285–301): it first stores width and height; on width shrink it rebuilds a box centered around current x/z and returns; otherwise it starts from the existing shape's minimum corner and extends by the new width and height. A width expansion additionally calls `move(SELF, oldWidth - newWidth, 0, oldWidth - newWidth)` only when `!firstTick && !world.isClient`. The local client therefore takes the direct box-write path without that server-only move branch.

## Collision-fit boundary and state consumers

- **1.13:** `WorldView.hasNoCollisions(entity, box)` at 274–275 delegates to the `VoxelShape`-returning `getCollisions` overload. `WorldView.getCollisions` at 203–218 checks border state and merges entity collisions only when `entity != null`; its block-shape pass is `getBlockCollisions` at line 210. With the pose call's literal `null`, the fit predicate reduces to whether the returned block-collision shape is empty. `World.java` has no `getCollisions` override in this release; the `WorldView` default is the fit provider. The shape is represented as one joined `VoxelShape`, and the predicate ends in `.isEmpty()`.
- **1.13.1 and 1.13.2:** `WorldView.hasNoCollisions` at 201–206 uses `Stream<VoxelShape>` and `allMatch(VoxelShape::isEmpty)`. The default collision gatherer at 170–190 conditions border updates/shapes on a non-null entity. `World.getCollisions` at 1755–1757 gets the `WorldAccess` block stream and appends entity collisions only when the source is non-null. Thus the pose call's null source checks the block stream only. The 1.13.1 and 1.13.2 `WorldView` and `Entity` source files are identical by SHA-256; `PlayerEntity` is not identical as a whole, but its selector body and operation are text-identical.

The successful resize changes the entity's stored dimensions and shape consumed by normal movement: `Entity.move` reads/mutates `getShape()` and fetches collision shapes for that box (1.13 lines 589–612; 1.13.1/1.13.2 lines 589–612). Player eye height also reads these pose/dimension flags: `PlayerEntity.getEyeHeight` returns sleeping/swimming/fall-flying/height/sneaking-dependent values (1.13 lines 1853–1864; 1.13.1/1.13.2 lines 1859–1869); `Entity.isSubmergedIn` samples fluid at `y + getEyeHeight()` (1.13 lines 1041–1049; 1.13.1/1.13.2 lines 1042–1050). These are direct state-consumer links, not predicted trajectory results.
