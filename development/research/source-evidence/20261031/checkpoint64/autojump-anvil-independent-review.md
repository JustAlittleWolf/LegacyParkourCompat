## Bounded closures verified against primary source

### Input and local tick edge

The endpoint `Input.java` and `KeyboardInput.java` files are byte-identical. Keyboard axes, key reads, and sneak scaling are therefore closed for those two providers only. `LocalClientPlayerEntity.serverTickAi` copies lateral/forward/jump input into the living control fields in both endpoints (1.12.2 `LocalClientPlayerEntity.java:631-642`; 1.13.2 `:634-645`). This does not close local sprint state: `LocalClientPlayerEntity.mobTick` has water-sensitive changes in direct sprint initiation and stopping (1.12.2 `:719-745`; 1.13.2 `:723-758`). The wet-but-not-submerged branch alters an existing sprint path; submerged double-tap initiation is tied to new swimming. Treat these separately.

The local player's `mobTick` reaches `input.tick()` before `super.mobTick()` (1.12.2 `LocalClientPlayerEntity.java:698,812`; 1.13.2 `:702,837`). The audited ordinary airborne path then clamps each `LivingEntity` velocity component below `0.003` before calling `moveRelative` and `Entity.move` (1.12.2 `LivingEntity.java:1781-1847`; 1.13.2 `:1852-1926`). Therefore the collision-query audit's `x=5e-8` solver arithmetic is correct conditionally but is **not** a constructed ordinary local-player witness: that residual is removed before the call, and keyboard axes plus quantized sine lookup do not establish the needed nonzero delta. Specialized callers remain unexamined, so the general reachability question stays open rather than being declared impossible.
