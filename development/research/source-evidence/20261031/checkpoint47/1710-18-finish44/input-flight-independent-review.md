# Independent source review: 1.7.10–1.8 input and flight claims

Reviewed the three source-only drafts in `input-flight/` against the exact read-only Ornithe Feather 1.7.10 and 1.8 sources. Both source trees are identified by provenance-manifest SHA-256 `11bada441ebe07661402d1c40e1c490b78b279ecaa084f9a4dc3ae2dd54caf6f` and `52c8312c34a1a491d4a200c84e90f5d8d95c7e5caa9571f864d8e70f9737db05`.

**ACCEPT — `flying-vertical-input-speed.md`.** In the old local-player `mobTick`, jump/sneak input adds or subtracts double literal `0.15` while flying. In 1.8 the active camera local player instead adds/subtracts `getFlySpeed() * 3.0F`; the configured speed is a float, with default `0.05F`. The camera gate admits the ordinary local camera player. This establishes the expression/type delta for a reachable input; accumulated position divergence remains predicted.

**ACCEPT — `sprinting-flight-air-acceleration.md`.** The paired player `moveRelative` methods temporarily set `speedInAir` to fly speed for an unmounted flying player in 1.7.10 and to fly speed multiplied by two when sprinting in 1.8. The same method restores the previous value after superclass travel. The paired `LivingEntity.moveRelative` uses `speedInAir` when airborne and applies it through `updateVelocity`; ordinary local control reaches this path. The stated flying, airborne, unmounted, sprinting, directional-input witness is reachable.

**ACCEPT — `sneak-held-sprint-double-tap.md`.** Both local input ticks snapshot prior forward-threshold state and then sample keyboard input. In 1.8 only, grounded double-tap arming also requires the saved prior `input.sneaking` to be false. Keyboard input scales a forward-only sneak sample by `0.3F` on both sides. A reachable sequence is: hold forward+sneak, release sneak while keeping forward, release forward, then press forward again with sneak released. In 1.7.10 the first release arms the seven-tick window and the second forward edge starts sprint; in 1.8 prior sneak prevents the first window, so the second edge only arms its window. The changed sprint state is set before that tick's travel. Normal hunger/ability, grounded and non-collision gates are assumed; later path divergence is predicted.

No additional acceptance was inferred from these three claims. Pair-wide inventory closure, implementation correctness and runtime parity are not evaluated here.
