Difference: both registries bind carpet at numeric id 171. The 1.7.10 constructor stores bounds `[0,0,0]..[1,1/16,1]`, but its collision override returns `[x,x+1] × [y,y] × [z,z+1]` (`byte var5 = 0`, multiplied by `0.0625F`). In 1.8 the constructor retains the 1/16 bounds and has no collision override, so the inherited base provider returns `[x,x+1] × [y,y+1/16] × [z,z+1]`. In each release `addCollisions` appends a non-null provider box when the swept query intersects it. `Box.intersects` uses strict separation checks: a zero-height carpet box **is collected** when its Y plane lies strictly inside the query's Y interval and X/Z overlap; the degenerate box is rejected only when the query is wholly to one side or merely touches the plane at an endpoint. `World.getCollisions` scans X, then Z, then Y (starting at `floor(query.minY)-1`) and feeds carpet through that same provider/intersection gate. `Entity.move` collects collisions from the expanded movement box, clips Y before X then Z. For a descending player whose query crosses the plane, `Box.intersectY` treats that zero-height box as a floor: with a negative limit and player bottom at/above the plane, it clips to `plane - playerBottom`.

The player is falling with the same `move(0,-0.2,0)` request in each profile. The expanded query spans `y=0.925..top`, so it intersects the support and crosses carpet's plane at `y=1`.
