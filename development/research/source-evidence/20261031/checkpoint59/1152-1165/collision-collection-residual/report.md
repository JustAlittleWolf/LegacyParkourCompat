## Local movement route

Both `LocalPlayer.move(MoverType, Vec3)` overrides delegate to `super.move`, so non-`noPhysics` local movement enters the same `Entity.move` → `Entity.collide` route (1.15.2 `Entity.java:450–470, 641–650`; 1.16.5 `:485–505, 668–677`). The `CollisionGetter`/`CollisionSpliterator` block collector is reached from `collideBoundingBoxHeuristically` in the multi-axis branch: 1.15.2 `Entity.java:686–699`, 1.16.5 `:713–726`. The one-axis fallback uses `Shapes.collide` direct block scanning rather than this collector; that method body is otherwise the same in the pair, with only `getBlock() == Blocks.MOVING_PISTON` replaced by `BlockState.is(Blocks.MOVING_PISTON)`, which delegates to `Block.is(Block)` identity comparison. The top-level border stream is yielded before the block cursor in both versions; its geometric gate is not re-audited here (see the separately hashed world-border report).

## Block collector and shape predicate

The old inline `CollisionGetter.getBlockCollisions` and new `CollisionSpliterator` use the same expanded integer bounds (`floor(min - 1e-7) - 1` through `floor(max + 1e-7) + 1`), `Cursor3D` coordinate visitation (X fastest, then Y, then Z), and boundary-type counts. The `Cursor3D` implementation changed representation, but the index-derived local coordinates and old incremental coordinates visit the same coordinate tuple in the same order for these finite local-player query bounds. Both skip type 3; apply the same large-collision-shape and moving-piston-only boundary gates; fetch the same collision chunk and block state; create one `CollisionContext` for the query; request the same translated block collision shape; and yield the first shape having positive-volume intersection with the query box.

The added `BiPredicate<BlockState, BlockPos>` is only a candidate gate: the ordinary `CollisionGetter.getBlockCollisions(entity, aabb)` overload constructs `CollisionSpliterator` with an always-true predicate. `Entity.move` uses this overload in the swept block query, so predicate composition cannot remove an ordinary movement block candidate. The explicit-predicate overload is used by the already bounded LocalPlayer closest-space/suffocation route; its state predicate and geometry witness are outside this collector-order closure and are not reopened.

For the one optimized predicate, `voxelShape == Shapes.block()`, the new `queryAabb.intersects(block unit bounds)` uses strict raw-AABB overlap, but it is not unconditionally equivalent to the old `Shapes.joinIsNotEmpty(Shapes.create(queryAabb), movedBlock, AND)`: `Shapes.create(AABB)` first uses `findBits` and, when all three endpoint pairs fit its accepted grid, rounds each endpoint to a 1/2/4/8 subdivision before the join. It uses an exact `ArrayVoxelShape` only when any axis fails that grid/range test. Thus ordinary exact face/edge/corner tangencies are false in both, and boxes outside the local `[approximately 0,1]` coordinate range or failing any `findBits` axis are geometrically equivalent; however, a raw positive overlap smaller than a grid snap can be erased by the old construction and accepted by the new fast path.

A sufficient query-space witness is `AABB[(0.375,0.25,0.25) .. (1+δ,0.875,0.875)]`, where `0 < δ < 1.25E-8`, against a state at `(1,0,0)` whose collision provider returns the canonical `Shapes.block()` shape. For every axis the old `findBits` succeeds at resolution 1/8; `Math.round(8*(1+δ))` is 8, so the old query shape ends at x=1 and only touches that block, yielding no collision shape. The new raw AABB test sees positive x overlap δ and yields it. This query is realizable on the LocalPlayer movement route with the vanilla swimming dimensions in both endpoints: a swimming box of 0.6×0.6×0.6 at x=[0.375,0.975], y=[0.25,0.85], z=[0.25,0.85] swept by `(0.025+δ, 0.025, 0.025)`; the paired `Player.java` hashes pin the `Pose.SWIMMING` dimensions. In a multi-axis collision call, the yielded cube can then constrain the x clip to 0.025 where the old collector omitted it; the `Entity.move` component comparison can consequently observe a changed requested/clipped x component. This is a narrow, source-established candidate movement delta; this report does not assert a particular world-generation/setup frequency. For every noncanonical collision shape, the 1.16.5 collector still uses the old `Shapes.joinIsNotEmpty` predicate. Candidate bounds still receive the same `1e-7` query inflation.

## Entity candidate filtering

`Entity.move` changes its entity-collision call from an empty exclusion set to `entity -> true` (old `Entity.java:648`, new `:675`). The consequential filter migration is in `EntityGetter.getEntityCollisions`: old code used the source's same-vehicle check, the other entity's legacy `getCollideBox`, and the source's optional `getCollideAgainstBox`; new code passes a predicate into `getEntities`, requiring candidate bounding-box intersection and `source.canCollideWith(candidate)`, then maps candidate bounding boxes to shapes.

For a LocalPlayer source, `getCollideAgainstBox` is inherited from `Entity` and returns null. A source-tree scan of the exact pair found only two legacy target `getCollideBox` overrides: `Boat` returns its bounding box; `Shulker` returns its bounding box iff alive. Their newer candidate predicates match: `Boat.canBeCollidedWith()` is true; `Shulker.canBeCollidedWith()` is `isAlive()`. Other candidates inherit both the old null collision-box result and the new false `Entity.canBeCollidedWith()`. The new base `canCollideWith` preserves the old source-to-candidate same-vehicle exclusion. For the LocalPlayer route, the formerly default `NO_SPECTATORS` list predicate does not add candidates: players inherit `canBeCollidedWith() == false`. Old and new candidate query AABBs both use the same `1e-7` inflation; `AABB.getSize() < 1e-7` guard, strict bounding-box intersection, Level chunk range, and LevelChunk self/bounds filtering are retained. Therefore the migration preserves the colliding candidate shapes for the vanilla LocalPlayer source, including exact tangency behavior. This does not claim equivalence for other source-entity subclasses (for example vehicle-specific `canCollideWith` overrides) or modded entities.

## Disposition

**Partial:** block cursor order and default predicate, plus LocalPlayer entity-candidate filtering, are closed with no independent delta. The full-block fast path leaves the exact grid-snap condition above open as a reachable multi-axis LocalPlayer movement candidate: the old query shape can round a sub-`1.25E-8` overlap back to tangency while the new raw AABB fast path accepts it. Whether this rare coordinate/pose/vector setup is accepted as an implementation finding is for the integration owner; the source dependency itself is not closed. This does not re-open the separately reported closest-space/suffocation or border epsilon witnesses, nor general block-provider/state/tag changes, arbitrary non-LocalPlayer source entities, modded entity overrides, or extreme malformed sweep bounds. No product code or canonical sources were changed; no build, test, decompile, game, or runtime was used.
