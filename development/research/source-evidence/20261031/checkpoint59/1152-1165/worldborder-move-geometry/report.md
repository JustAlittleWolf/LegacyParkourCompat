## Ordinary movement route and result

`Entity.move` reaches its private `collide(Vec3)` on the non-`noPhysics` path in both releases (1.15.2 `Entity.java:450–470`; 1.16.5 `Entity.java:485–505`). Given the same current AABB and border state, that method obtains `WorldBorder.getCollisionShape()`, applies the same `Shapes.joinIsNotEmpty(border, Shapes.create(box.deflate(1.0E-7)), AND)` gate, and adds either no border shape or that shape to its collision stream (1.15.2 `Entity.java:641–650`; 1.16.5 `Entity.java:668–677`). The border stream is composed ahead of the ordinary coordinate clipping call in the same order. The direct gate, constant, cast/types and branch are textually identical.

The border shape is also constructed identically for moving and static extents: the outside of the rectangle from `floor(minX/minZ)` to `ceil(maxX/maxZ)`, with infinite Y, formed by `Shapes.join(Shapes.INFINITY, Shapes.box(...), ONLY_FIRST)` (moving extent: 1.15.2 `WorldBorder.java:330–343`, 1.16.5 `:324–337`; static cache: 1.15.2 `:404–421`, 1.16.5 `:495–512`). Static extent min/max calculation order is unchanged. `Shapes.joinIsNotEmpty` / its private merged-index body are unchanged (`Shapes.java:161–219` both sides); `AABB.deflate` delegates to the same `inflate(-d)`, the six strict AABB intersection comparisons are unchanged (1.15.2 `AABB.java:204–205, 246–248`; 1.16.5 `:208–209, 250–252`), and the axis clip iterates the supplied stream with the same `1.0E-7` near-zero exit and same `VoxelShape.collide` call (`Shapes.java:222–234` both sides). `VoxelShape.collide` retains the same directional coordinate probes with `±1.0E-7` offsets (1.15.2 `VoxelShape.java:199–224`; 1.16.5 `:190–215`). These strict intersection / epsilon gates therefore give the same answers at exact tangency and on either side of the `1.0E-7` deflation threshold for the same box and border shape.

The secondary block-query path does contain the already reported change: in the multi-axis heuristic (`Entity.java:686–699` old; `:713–726` new), `getBlockCollisions` can be appended. Its old inline border check uses the deflated/inflated tests (`CollisionGetter.java:78–90`), while the new spliterator adds the strict integer-bound early return (`CollisionSpliterator.java:102–131`). This difference does not remove or replace the ordinary movement border collider: `Entity.collide` has already inserted that same border shape into the rewindable stream before the heuristic appends block collisions. If the direct gate suppresses the shape because the deflated box intersects the outside shape, the spliterator's matching `isOutsideBorder` test also suppresses its copy; if the direct gate inserts it, an old/new difference in the secondary query can only omit or repeat that already present border shape. Duplicate copies do not alter the per-axis clipping result: `Shapes.collide` walks the stream in order and the same `VoxelShape.collide(axis, sameAABB, currentDistance)` operation applied twice is idempotent. Thus the strict-interior epsilon witness in `closest-space-geometry/border-interior-epsilon.md` remains a pose-fit/no-collision-query delta, not ordinary `Entity.move` clipping.

**Disposition:** no ordinary player movement clipping delta from this border-query gate is established for equal raw AABB, border state, and movement vector. This closes the assigned Entity.move border/tangency residual narrowly; it does not close general collision traversal or any other `Entity.move` change.
