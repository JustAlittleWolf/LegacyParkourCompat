# Relative entity movement preserves raw zero-delta coordinates

1.16.1, Mojmap: `net/minecraft/client/multiplayer/ClientPacketListener.java`, `handleMoveEntity`, lines 638–658; `net/minecraft/world/entity/Entity.java`, `xp/yp/zp` long packet accumulators and `setPacketCoordinates(double,double,double)`; `net/minecraft/network/protocol/game/ClientboundMoveEntityPacket.java`, `packetToEntity(long,long,long)`.

1.16.2, Mojmap: `net/minecraft/client/multiplayer/ClientPacketListener.java`, `handleMoveEntity`, lines 628–648; `net/minecraft/world/entity/Entity.java`, `setPacketCoordinates(Vec3)`/`getPacketCoordinates()`; `net/minecraft/network/protocol/game/ClientboundMoveEntityPacket.java`, `updateEntityPosition(Vec3)`.

Difference: for a position-bearing relative-move packet, 1.16.1 adds each short packet delta to the entity's `long` 1/4096-unit accumulators, converts all three accumulators to a `Vec3`, then calls `lerpTo`. 1.16.2 updates each axis separately: a zero short delta returns that axis's prior double unchanged; a nonzero delta floors the coordinate to a long packet value, adds the short delta, and divides by 4096.0. The newer entity setter stores the resulting `Vec3` without quantization. The receiver branch is reachable for a registered LocalPlayer in ClientLevel because `isControlledByLocalInstance()` is false there.

LocalPlayer dispatches `lerpTo` to `LivingEntity.lerpTo` in both endpoints, which queues target fields and sets `lerpSteps=3` rather than immediately writing current position: 1.16.1 `LivingEntity.java:2583–2590`; 1.16.2 `LivingEntity.java:2585–2592`. On a later `LivingEntity.aiStep` while `lerpSteps > 0`, the entity steps toward the queued target and calls `setPos` (1.16.1 `LivingEntity.java:2376–2385`; 1.16.2 `LivingEntity.java:2378–2387`).

Movement meaning: conditional on the local player's packet-coordinate state containing a finite fractional coordinate off the 1/4096 grid and a relative-move packet with zero delta on that axis, 1.16.2 preserves that raw coordinate in its queued interpolation target while 1.16.1 snaps it through the long accumulator. The receiver state is source-reachable after a fractional absolute teleport packet in 1.16.2; this claim does not assert that server packet production emits such a sequence in an ordinary live session. An eventual position consequence depends on the later interpolation step being processed; packet/tick ordering and runtime parity are not claimed. When the prior coordinate is already on the 1/4096 grid, the zero-axis target difference collapses.

Boundary support: exact version ID 1.16 and version 1.16.1 retain the long-accumulator route; version 1.16.2 adds the per-axis update route. `updateEntityPosition(Vec3)` is absent in 1.16 and 1.16.1 and present in 1.16.2. The `1.16` Mojmap ready metadata and source manifest identify that release under its exact ID (not `1.16.0`); `.1` and `.2` have their own ready/source manifests. This pins the observed source boundary to 1.16.1→1.16.2.
