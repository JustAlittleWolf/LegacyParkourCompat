## Wall state production boundary

The four wall fields are the only additions with a direct movement-facing block consumer. Their fixed-state collision interpretation is closed above. `WallBlock` also produces those states from neighbors and the block above: placement/update paths call `connectsTo`, `updateSides`, and `makeWallState` (`WallBlock.java:130-257`). This producer path is not equivalent to the fixed-state query. In particular, 1.16.5 adds `IronBarsBlock` as a connection in `connectsTo` (`:130-134`), which can supply a connected side and thus a different collision volume. The existing wall-to-bars movement lead and independent audit already carry that producer-side witness; this report does not duplicate it. The broader update-order and dynamic `WALLS`/`WALL_POST_OVERRIDE` tag dependencies remain open in the existing wall provider report. The vanilla default tag membership/sync closure remains as previously recorded; it does not close arbitrary datapack/server tag overlays.

This is the fixed-state scope boundary: with equivalent raw logical wall direction masks and the same tag/neighborhood inputs, the new descriptors alone do not change the collision volumes. A movement change caused by producing a different wall state belongs to the wall neighbor/state-producer route and must be reconciled with its existing finding, not inferred from the new constants.
