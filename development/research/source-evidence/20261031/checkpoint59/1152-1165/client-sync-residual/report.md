# Client synchronization residual: 1.15.2 → 1.16.5 (Mojmap)

## Scope and result

This closes the assigned remaining movement-positive synchronization rows under the stated comparison: equal raw logical packet fields, fixed block/fluid states, and equal effective tag membership. It compares client-side receiver/consumer operations that can directly write LocalPlayer movement state or supply its movement predicates. Server packet production and send timing are kept separate. I reused the exact source-closure artifacts named below; no canonical sources were generated or edited.

**Disposition:** one already established conditional movement delta remains: ordinary death respawn can recreate a LocalPlayer with sprint data retained but without copying the sprint-speed attribute modifier. The following movement tick can read the lower `MOVEMENT_SPEED` value through `Player.getSpeed`/ground travel while sprint remains true. This is a bounded state/timing candidate, not a general respawn finding; the exact default-attribute dirty/sync timing relative to that next movement read remains open. No new delta is established for block update, multi-block update, tag application/binding, or tag lookup when the compared block/fluid states and effective memberships are equal. Full-chunk application has a separate already closed conditional client-cache movement route (duplicate tracked-entity entries causing repeated push impulses on an overlapping LocalPlayer); see the existing chunk-cache report. Packet scheduling/production is not needed for that receiver-side conditional.

For the respawn row, the remaining exact gate is only whether a default-attribute sync/update normalizes the newly constructed local attribute map before the first eligible local movement read. For tag and block-state delivery, the source-visible receiver applies state/tag data on the client thread; the next local tick is the consumer point, but equal states/membership make no delta to the predicate values. No ordering claim is made about when a server chooses to send those updates.
