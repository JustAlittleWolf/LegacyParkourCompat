## Equal-input query results

- **World access:** `Level.getBlockState` checks `isOutsideBuildHeight`, returns void air if outside, otherwise fetches the horizontal chunk and delegates to `LevelChunk.getBlockState` (1.17.1 `Level.java:377–383`; 1.18.2 `:369–375`). `Level.getFluidState` has the corresponding empty-fluid fallback and delegates to the chunk (1.17.1 `:387–394`; 1.18.2 `:379–386`). The gates, calls and order are the same. `Level.getChunkForCollisions` still requests `FULL,false` from `getChunk` (1.17.1 `:572–574`; 1.18.2 `:570–572`), consistent with the already-audited client cache provider.
- **Height and section coordinates:** `LevelHeightAccessor.isOutsideBuildHeight` remains `y < minBuildHeight || y >= maxBuildHeight`; `getMaxBuildHeight`, `getMinSection`, `getMaxSection`, `getSectionIndex`, and `getSectionIndexFromSectionY` retain the same arithmetic (1.17.1 `LevelHeightAccessor.java:11–40`; 1.18+ `:11–43`). `LevelChunk` and `ChunkAccess` resolve the same section index from the supplied height accessor. For equal min/height inputs, build-height and section-index query results are unchanged. This comparison does not equate version-specific dimension-height inputs.
- **Chunk state reads:** `LevelChunk.getBlockState` and `getFluidState` use the same section-index bounds, local-coordinate masks, debug-world special cases, air/empty fallback values and crash-report path (1.17.1 `LevelChunk.java:210–267`; 1.18+ `:173–230`). `LevelChunkSection.getBlockState` reads the palette state at `(x,y,z)` and `getFluidState` derives fluid from that state in all four versions (1.17.1 `LevelChunkSection.java:41–47`; 1.18+ `:46–52`). `EmptyLevelChunk` continues to return void air and empty fluid. Its changed biome-holder field/result is not movement-facing.
- **Section-empty fast path:** 1.17.1 checks `LevelChunkSection.isEmpty(section)`, which recognizes the `EMPTY_SECTION` sentinel and then checks `nonEmptyBlockCount == 0` (`LevelChunkSection.java:96–102`). 1.18+ checks `section.hasOnlyAir()` with the same zero test (`:101–103`). Count bookkeeping changed: 1.17.1's `recalcBlockCounts` adds both non-air blocks and non-empty fluid states to `nonEmptyBlockCount` (`:120–139`); 1.18+ adds non-air states to that counter and maintains the fluid ticking count separately (`:121–150` in 1.18.2). For valid vanilla block states, a non-empty fluid is represented by a non-air liquid or waterlogged block state, so the zero/nonzero gate returns the same result. The changed count magnitude does not change valid-state block/fluid lookup. A fluid-bearing air state or an inconsistent serialized count is outside the equal valid vanilla-state input.
- **Palette indexing and reads:** the 1.17.1 linear index is `y << 8 | z << 4 | x` (`PalettedContainer.java:58–60`). The 1.18+ `SECTION_STATES` strategy uses four bits (`PalettedContainer.java:300`) and computes the same index order (`Strategy.getIndex`, `:331–333`). For valid palette IDs, every read returns the value mapped at the same packed storage index. A conditional malformed-input behavior changed: 1.17.1 `PalettedContainer.get(int)` substitutes `defaultValue` when `Palette.valueFor` returns null (`:134–137`); 1.18+ returns `valueFor` directly (`:125–128`). New linear palettes throw `MissingPaletteEntryException` for an out-of-range ID but return the array slot directly for an in-range ID (`LinearPalette.java:72–78`); hash-map and global palettes throw when their ID has no entry (`HashMapPalette.java:61–67`, `GlobalPalette.java:31–37`). Their 1.17.1 counterparts return null for missing linear/hash-map entries or the global default for a missing registry ID. Thus corrupt/out-of-range or hole IDs can now throw or propagate null/default differently; valid decoded vanilla block-state palette IDs are unaffected. `LevelChunk.getBlockState` catches thrown errors and wraps them in a `ReportedException`; this is not a valid-state movement difference.
- **World query interfaces and ray traversal:** `BlockGetter.clip` retains block-state then fluid-state reads; block shape and interaction override; fluid shape; squared-distance comparison with the block hit winning ties (1.17.1 `BlockGetter.java:69–86`; 1.18+ `:65–82`). `traverseBlocks` keeps equal-endpoint short-circuit, the same `1.0E-7` endpoint interpolation, start-cell visit, sign/delta calculations, X/Y/Z tie order, inclusive `<= 1.0` loop, callback early return and miss fallback (1.17.1 `:117–174`; 1.18+ `:113–170`). `clipWithInteractionOverride` also preserves the nearer-interaction-face direction substitution (`:89–99`; 1.18+ `:85–95`). The differences in these methods are parameter/local names only.
- **Reader/client predicates:** `LevelReader`'s `getChunk` forwarding overloads, `hasChunkAt`, `isWaterAt` and `containsAnyLiquid` keep their coordinate conversions, loops and predicates (1.17.1 `LevelReader.java:114–157,170–177`; 1.18+ `:115–158,169–176`). `ClientLevel.hasChunk(x,z)` returns `true` in all four versions (1.17.1 `ClientLevel.java:215–217`; 1.18+ `:254–257`). These methods show no query delta under equal provider/state inputs.

This report compares their downstream section/palette reads and ray query interface. It does not compare chunk packet encoding/application, palette/state producers, cross-packet/tick ordering, dimension metadata production, block-shape providers, or the already-owned collision cursor/collection implementation.
