## Open edges

- No source-provenance manifest is present for 1.20.6 or 1.21.1. Their local bytes can be compared, but their decompile inputs/mapping artifacts are not independently attested here.
- The value and synchronization paths that install `SNEAKING_SPEED`, `WATER_MOVEMENT_EFFICIENCY`, and `MOVEMENT_EFFICIENCY` modifiers were not followed through every enchantment/effect and client attribute packet. In particular, the server-only `LivingEntity.onChangedBlock(ServerLevel, ...)` path and location-effect application need source closure before accepting the player-side Soul Speed/Depth Strider mapping.
- External player position/velocity writers and callbacks (network corrections, piston and block callbacks, explosions/attack sources, fluid pushing, pose changes) were not exhaustively enumerated in this core-member pass. `LivingEntity.knockback` is included because its direct player velocity write changed; the trigger graph remains open.
- This is a bounded core census only. It does not establish complete pair coverage, exact patch introduction inside the 1.20.6→1.21 interval, runtime parity, or implementation acceptance.

## Evidence caveat correction (append-only)

The earlier provenance caveat was too broad. Although neither endpoint has `.decompile-provenance.json` inside the `mojmap/` source directory, both version roots contain `mojmap.provenance.json`, `mojmap.ready.json`, and `mojmap.sources.sha256`. The ready marker identifies the exact version and `mojmap` namespace. For 1.20.6, SHA-256 of `mojmap.sources.sha256` is `56aae10684471d7abb1c366bd5dd431ab976112a87e6cc5c687a68f1eff06311`, matching `sourceManifestSha256` in `mojmap.ready.json`; for 1.21.1, the corresponding digest is `900f956e00f6fc1300bb3d689ea49df2b1a57bcaa54617344ef456d95d47cb48`, also matching its ready marker. The manifest entries for all four selected core files (`LocalPlayer.java`, `Player.java`, `LivingEntity.java`, `Entity.java`) match the local file SHA-256 values at each endpoint. Therefore these endpoints have source-manifest integrity and recorded decompile-run provenance; the earlier statement that their input/mapping provenance was unverified is superseded. This correction changes no method-diff, movement classification, or open-edge conclusions above.
