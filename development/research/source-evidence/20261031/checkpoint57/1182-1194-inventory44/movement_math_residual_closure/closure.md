## Movement-reachable changed members

- `Mth.clamp(float/double/int)`, 1.19.3→1.19.4: old forms branch `x < min ? min : x > max ? max : x`; new float/double forms are `x < min ? min : Math.min(x, max)`, and int form is `Math.min(Math.max(x, min), max)`. Direct ordinary movement callers include `LocalPlayer` sneak-speed bonus (`LocalPlayer.aiStep`, `0.3F + bonus`, bounds `[0,1]`), `Entity` pitch and piston displacement clamps (bounds `[-90,90]` and `[-0.51,0.51]`), and `LivingEntity` fluid-fall horizontal motion clamp (bounds `[-0.15F,0.15F]`). For these call domains, finite non-NaN values preserve the same result; the direct `[0,1]` float bound also preserves signed zero (`Math.min(-0.0F,1.0F)` yields `-0.0F`). Both forms return a NaN for NaN input, but this review does not claim preservation of NaN payload bits. No ordinary route producing NaN clamp input is established, and no changed numeric movement result is established. The other changed float/double clamp consumers found in these classes are water-vision timers/render interpolation, health clamping, or position packet sanitization, not ordinary movement state.
- `BlockPos` double constructors / `Vec3i(double,double,double)` removal and replacement by `BlockPos.containing(...)`, 1.19.3→1.19.4: reachable `LocalPlayer` and `Entity` block-position reads migrate to `containing`. Old `Vec3i(double...)` calls `Mth.floor` independently on x/y/z; new `BlockPos.containing(double...)` explicitly performs the identical three `Mth.floor` calls before the int constructor. Operation and rounding are therefore preserved for finite, infinite, NaN, and out-of-int-range inputs under the same Java float-to-int semantics. This is an API/call-site migration, not a movement delta. Removed `Vec3i.offset(double...)` / `BlockPos.offset(double...)` have no direct ordinary `LocalPlayer`/`Entity` movement caller in the examined classes.
- Changed helper use that is not a candidate: `Mth.floor`, `sin`, `cos`, `lerp`, `Vec3` arithmetic/normalization, and existing `AABB` movement methods are unchanged across the edges where referenced by ordinary movement. `BlockPos.containing` is the sole changed utility API route that newly appears at 1.19.4; its exact old constructor operation is shown above.
