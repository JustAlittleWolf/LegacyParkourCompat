# Clientbound movement-state residual closure

Scope: source-only review of the 254 changed-path rows classified `network-protocol` across the five adjacent edges, focusing on clientbound packet fields and their `ClientPacketListener` consumers that can reach the local player's movement state. The frozen path list is `paths.txt` (149 unique paths); relevant source hashes are in `source-hashes.tsv`. The master audit verifies the six exact Mojmap manifests and every manifested Java file. This is a bounded packet-response closure, not a complete pair member freeze.

## Movement-adjacent receiver routes

- **Entity movement packets:** `ClientPacketListener.handleMoveEntity` and `handleTeleportEntity` are direct receive paths. Starting 1.19, relative position handling uses `VecDeltaCodec` and teleports call `syncPacketPositionCodec` rather than `setPacketCoordinates`; both handler paths retain `!entity.isControlledByLocalInstance()` around the packet position/rotation application. Thus the local controlled player is not updated through these remote-entity packets. Remote entity position/collision behavior is outside the assigned direct LocalPlayer state-writer lane and non-player physics scope. Packet class hashes are in the ledger.
- **Explosion response:** `ClientboundExplodePacket` changes coordinate wire precision from float to double at 1.19.3. Its three knockback fields remain floats, and `ClientPacketListener.handleExplosion` has identical method source on all six versions; the local player's velocity response continues to read those knockback fields. The center and affected-block list can affect explosion presentation and client block state, which are outside movement with fixed world state. No direct LocalPlayer velocity math change is found in this packet lane.
- **Attributes:** `ClientboundUpdateAttributesPacket` switches `Registry.ATTRIBUTE` lookups to `BuiltInRegistries.ATTRIBUTE` in 1.19.3. `ClientPacketListener.handleUpdateAttributes` retains the same operation order: find entity, obtain attribute map, set base, remove modifiers, and re-add incoming modifiers. No local movement arithmetic changed here; packet values are server/state input.
- **Status effects:** `ClientboundUpdateMobEffectPacket` evolves its effect lookup and carries FactorData; 1.19.4 changes codec ops only. The receive handler builds the effect instance from the same id/amplifier/duration/flags and applies it. The 1.19.3 removal of `setNoCounter(isSuperLongDuration())` only changes `MobEffectUtil.formatDuration` display (the only `isNoCounter` use), not effect ticking or movement. 1.19.4's `-1` infinite duration is a new state-production feature; no legacy producer is inferred. `ClientboundRemoveMobEffectPacket` handler is source-identical across all six versions.
- **Synchronized entity data:** `ClientboundSetEntityDataPacket`/`handleSetEntityData` change from legacy getters plus a null-list guard to accessors plus an always-present packed list, and registry serialization changes with the registry refactor. The handler still assigns the packet data values to the addressed entity; no changed player movement math is present. Its payload is synchronized state production. The narrower respawn-copy behavior is already covered by the accepted 1.19.2→1.19.3 respawn finding and is not repeated here.
- **Block acknowledgements:** the 1.18.2 block-break acknowledgement path is replaced by sequence-based block-change acknowledgement beginning in 1.19. This route is a direct LocalPlayer position writer, not only block-state delivery: when a mismatched authoritative block state overlaps the player, the old path conditionally restores the position captured at action send; the new prediction path restores the position captured when that block was first predicted. The action-result gate and position capture point differ. See `block_ack_position_restore_draft.md` for the bounded candidate. Server/state production remains excluded.
- **Position correction and respawn:** `ClientboundPlayerPositionPacket` correction and `ClientboundRespawnPacket` entity-data copy were explicitly closed in earlier bounded reviews and are not reopened.

Remaining changed clientbound packet paths are chat, command, recipe, sound, status, player-list, resource-pack, non-player spawn/movement, chunk/block/fluid state, animation, damage, and other metadata/state delivery. They either have no LocalPlayer movement consumer or deliver world/entity/server state outside this fixed-state/source-response slice. Serverbound packets are requests/producers and are outside this client-consumer scope.
