# Status-effect and attribute member closure

Scope: the 11 changed status-effect/attribute classes from the frozen 1.18.2→1.19→1.19.1→1.19.2→1.19.3→1.19.4 case-sensitive source roster. For each of the six versions, the recomputed source-manifest SHA matched the ready marker's `sourceManifestSha256`, and all 66 selected source-file hashes matched their manifest entries; no mismatch was found. Exact class hashes are in `source-hashes.tsv`.

## Changed members and result

The changed-path ledger contains 21 changed path/edge rows: 7 on 1.18.2→1.19, none on 1.19→1.19.1 or 1.19.1→1.19.2, 9 on 1.19.2→1.19.3, and 5 on 1.19.3→1.19.4. Those are the complete changed rows for the selected package paths.

- `MobEffect`, `MobEffects`, and `MobEffectInstance` (1.18.2→1.19): existing movement-effect attribute definitions and `applyEffectTick` control flow remain the same. 1.19 adds optional factor data only for the new Darkness effect (`MobEffects.DARKNESS`, padding 22), whose factor interpolation is camera/render state. Effect ID serialization widening and the `Math.max(amplifier, 0)` rewrite are storage/metadata or value-equivalent for finite existing amplifiers. The only new default factor-data updates are under the optional Darkness instance.
- `MobEffectUtil` (1.18.2→1.19): adds `addEffectToPlayersAround`, which selects players and applies effects on the server; this is state production. Existing `formatDuration`, `hasDigSpeed`, and `hasWaterBreathing` read/format paths do not change movement math.
- `AttributeModifier` (1.18.2→1.19): the no-UUID constructor changes its random source for UUID generation. The modifier amount and operation are unchanged. Player movement modifiers in vanilla (`MobEffects.MOVEMENT_SPEED`/`SLOWNESS`, sprint, Soul Speed, powder snow) use explicit stable UUIDs; this random identifier delta has no vanilla ordinary-player movement sink.
- `RangedAttribute` (1.18.2→1.19): `sanitizeValue` adds `Double.isNaN(value) ? minValue : ...`. For finite values, including ordinary vanilla movement/jump attributes and finite vanilla effect modifiers, clamping is unchanged. A NaN base/modifier can change resulting attribute values, but this requires an injected/corrupt/custom attribute value or other non-vanilla state producer, outside the assigned ordinary vanilla movement route. No vanilla ordinary player effect/provider here produces NaN.
- `DefaultAttributes` (1.18.2→1.19): added default providers are Allay/Frog/Tadpole/Warden or other new non-player entity types only. Player defaults are unchanged.
- `AttributeInstance`, `AttributeMap`, `Attributes`, `AttributeSupplier` (1.19.2→1.19.3): changed bodies are registry-reference relocation (`Registry.ATTRIBUTE` → `BuiltInRegistries.ATTRIBUTE`) and Holder overloads forwarding to existing `Attribute` methods. `AttributeInstance.calculateValue` remains operation-equivalent and uses the same addition → multiply-base → multiply-total order; movement getter/cache behavior is unchanged.
- `MobEffect`, `MobEffects`, `MobEffectInstance`, `MobEffectUtil` (1.19.2→1.19.3): registry references move to `BuiltInRegistries`; `noCounter` methods are removed (display flag only). Existing finite movement effects and modifier values do not change.
- `MobEffectInstance` (1.19.3→1.19.4): adds the `-1` infinite-duration sentinel and branches in duration stacking/tick/apply. This is a newly introduced effect feature; no ordinary finite legacy movement effect changes tick cadence. Infinite-duration effect production is outside the assigned fixed vanilla movement state scope. Darkness FactorData also changes its animation/timing implementation and remains a view/render effect.
- `MobEffects` (1.19.3→1.19.4): existing effect RGB colors change, including Speed/Slowness, while their movement modifiers remain exactly `+0.2F` and `-0.15F` `MULTIPLY_TOTAL`; Jump Boost, Slow Falling, Levitation, and other existing movement effect declarations preserve their movement-relevant values.
- `MobEffectUtil` (1.19.3→1.19.4): duration formatting becomes a `Component`; `addEffectToPlayersAround` changes its server-side refresh predicate from `< duration` to `endsWithin(duration - 1)`, equivalent for finite integer durations and different only for newly supported infinite effects. It is a server/state producer path, not a direct movement consumer.
- `DefaultAttributes` (1.19.3→1.19.4): default entries concern non-player entities; no LocalPlayer attribute supplier is changed.

## Movement route closure

The exact direct consumers remain the unchanged movement path: `LivingEntity.tickEffects` applies/removes effect modifier maps; `AttributeInstance.getValue` calculates and caches the same ordered modifier formula; `Player.aiStep` reads `Attributes.MOVEMENT_SPEED` to set speed; `LivingEntity.travel` reads current movement/effect predicates for jump, levitation, slow falling, and water movement. The previously audited Jump Boost consumer and respawn attribute synchronization are intentionally not repeated here. No new closed ordinary LocalPlayer movement candidate or eligible continuation route was found in the selected effect/attribute members.

This closes only the assigned effect/attribute member slice. It makes no whole-pair coverage or runtime-parity claim.
