A changed codec deserves explicit closure: `VecDeltaCodec` was added in 1.19 and changed in 1.19.3. In 1.19.2, `encodeX/Y/Z` floor scaled position-minus-base deltas and decode floors the scaled base before adding each delta (`VecDeltaCodec.java:10-39`). In 1.19.3/1.19.4, encoding rounds scaled position and base separately and decode rounds the scaled base before adding the delta (`VecDeltaCodec.java:11-49` in 1.19.4). This is the eligible relative-position quantization change on 1.19.2→1.19.3; 1.18.2→1.19 is a behavior-equivalent refactor of the prior packet helper.

**Reopened route correction:** the earlier conclusion below that the LocalPlayer is excluded was wrong for 1.18.2–1.19.3. `Entity.getControllingPassenger()` returns null in the base class; `LivingEntity`, `Player`, `AbstractClientPlayer`, and `LocalPlayer` do not override it. None of those classes overrides `Entity.isControlledByLocalInstance()`. `LocalPlayer` overrides only `isEffectiveAi()` in this relevant chain. In those five releases `Entity.isControlledByLocalInstance()` falls back directly to `!this.level.isClientSide`, which is false for a client-side LocalPlayer. Although LocalPlayer overrides `isEffectiveAi()` to return true in each release, that override is not called by the older predicate. A packet handler entity lookup that resolves the packet id to `minecraft.player` therefore enters the `if (!entity.isControlledByLocalInstance())` branch in both `handleMoveEntity` and `handleTeleportEntity`. The 1.19+ relative-move branch calls `getPositionCodec().decode`, updates the codec base, and calls `lerpTo`; teleport handling calls `syncPacketPositionCodec` before the same gate, then calls `lerpTo` and writes on-ground when the branch is entered. This establishes a reachable direct LocalPlayer response route through 1.19.3 without requiring proof that vanilla server code normally emits such packets. Exact comparison shows the 1.18.2→1.19 helper/class refactor preserves the old per-axis arithmetic, base initialization/update order and LocalPlayer gate result, so that row is a no-difference disposition. The later 1.19.2→1.19.3 floor-to-round change remains an eligible direct response difference.

In 1.19.4 the base predicate changes to use `this.isEffectiveAi()` when there is no controlling passenger, and `LocalPlayer.isEffectiveAi()` returns true. The negated receive branch is then filtered for LocalPlayer. This distinct 1.19.3→1.19.4 receiver-gate difference is documented in `arithmetic-equivalence.md` and drafted as `local-player-control-gate.md`; it is separate from VecDeltaCodec arithmetic. `handleTeleportEntity` still synchronizes the private packet codec before that gate; it does not apply the packet position, rotation, or on-ground flag to LocalPlayer through this branch. `route-audit.tsv` records all six exact releases, method anchors, and results. `source-hashes.tsv` records SHA-256 for the traced `Entity`, `LivingEntity`, `Player`, `AbstractClientPlayer`, `LocalPlayer`, `ClientPacketListener`, and `VecDeltaCodec` files.
