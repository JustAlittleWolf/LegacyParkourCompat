# Relative position reconstruction quantization
1.19.2, Mojmap: `net/minecraft/network/protocol/game/VecDeltaCodec.java`, `encode(double)`/`decode(long)` lines 10–26 and `encodeX/Y/Z` lines 29–39.
1.19.3, Mojmap: `net/minecraft/network/protocol/game/VecDeltaCodec.java`, `encode(double)`/`decode(long)` lines 11–28 and `encodeX/Y/Z` lines 31–41.
Difference: The 1.19.2 encoder floors scaled coordinates; the decoder reconstructs each nonzero axis as `decode(floor(base * 4096) + delta)`. The 1.19.3 encoder rounds scaled absolute position and base separately; the decoder reconstructs each nonzero axis as `decode(round(base * 4096) + delta)`. The per-axis zero-delta branch still preserves base. In both versions `ClientPacketListener.handleMoveEntity` decodes, updates the codec base, then passes the reconstructed coordinates to `lerpTo` (1.19.2 `ClientPacketListener.java:523–544`; 1.19.3 `:552–573`). When the packet id resolves to the current LocalPlayer, the client receiver enters this branch in both releases: `Entity.isControlledByLocalInstance` falls back to `!level.isClientSide` with no controlling passenger (`Entity.java:2713–2716` in 1.19.2; `2742–2745` in 1.19.3).
Movement meaning: For a relative movement response addressed to LocalPlayer, the coordinate reconstruction can differ for base/delta combinations where floor and round produce different grid values; the resulting vector is the position passed to LocalPlayer's interpolation response. This finding makes no claim about server packet production or a predicted trajectory.
