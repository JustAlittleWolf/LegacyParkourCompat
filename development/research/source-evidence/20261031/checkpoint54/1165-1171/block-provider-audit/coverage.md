# Bounded block/provider/callback audit

Scope: exact Mojmap sources 1.16.5, 1.17, and 1.17.1. This is an add-on to the frozen source roster in this directory, not a claim that the full pair or the complete player tick graph is frozen. The roster was captured before reading the prior source-only reports. Static source inspection only; no runtime trajectory claim.

## Provider and member closure

The frozen roster includes 148 candidate/registration/query paths. Target methods and static shape expressions were extracted into `method-fingerprints.tsv`, `changed-methods.tsv`, and `shape-expression-fingerprints.tsv`; `source-hashes.tsv` records 436 present source files with matching on-disk and publication hashes. The direct movement callbacks examined are Block, BedBlock, SlimeBlock, HoneyBlock, WebBlock, SweetBerryBushBlock, BubbleColumnBlock, and PistonMovingBlockEntity's response helper. Block's default `stepOn` and `updateEntityAfterFallOn` are empty/zero-delta. Bed and slime bounce/step movement, honey/web/berry stuck movement, bubble-column response, and piston response preserve their player movement gates, values, and operation order across all three sources. Bed remains eligible as a contact response, but its bounce multiplier path is identical.

The target-member diff found 17 changed bodies. Each has a non-movement or unchanged-player disposition: fall damage/API signature changes in Block, Bed, Hay, Slime, TurtleEgg, and Farm; server state/signal changes in BasePressurePlate, Farm, RedStoneOre, TurtleEgg and WitherRose; item-only Hopper behavior; Honey sound/event behavior; Magma damage; Stair's unchanged empty base callback; RedStoneWire outline-only geometry; and WitherRose server effect/damage. Slime's changed `stepOn` signature retains the same movement multiplier. Exact changed path/member anchors are listed in `changed-methods.tsv`.

The shape-expression scan found changed expressions only in EndPortalBlock, VineBlock, LecternBlock, CauldronBlock/AbstractCauldronBlock, EndRodBlock/RodBlock, WoolCarpetBlock/CarpetBlock, PistonMovingBlockEntity, and shared Shapes code. End portal and vine shapes are excluded from collision by `.noCollission()`; the EndPortalBlock player intersection is server-level gated. Lectern's changed boxes are outline-only while its collision-shape constants are unchanged. Cauldron and end-rod constants moved to parent classes without changed values or selection; carpet retains the same one-sixteenth collision height. Piston changes are helper-argument refactors. Shared shape engine behavior is separately covered by the prior collision39 selected review; its candidate claims are not reopened here.

## Support and neighbor-state extension

To close an omitted dependency class, searched all block source files in all three versions for `getBlockSupportShape` and `isFaceSturdy` declarations. Only LeavesBlock, SnowLayerBlock, and SoulSandBlock override `getBlockSupportShape`; there are no block subclass overrides of `isFaceSturdy`. The three support-shape methods match exactly in outcome and selection across versions: leaves return `Shapes.empty()`, snow layers return `SHAPE_BY_LAYER[LAYERS]`, and soul sand returns `Shapes.block()`. `BlockBehaviour.getBlockSupportShape` continues to delegate to the empty-context collision shape, while BlockState's `isFaceSturdy` delegates through the same cached-or-`SupportType.isSupporting` branch in 1.16.5, 1.17, and 1.17.1. The compared `SupportType` operations are unchanged. This extension therefore adds no local-player movement delta.

Stair shape selection, collision shape, and state/neighbor predicates; vine face support and climbability; fence/wall/gate/door/trapdoor/slab/stair/scaffolding/ladder state-derived collision forms; and block registration friction/speed factors and built-in climbable/soul-speed/fluid tags were checked. Existing 1.16.5-era values and predicates are unchanged. 1.17 adds modern cave-vine climbability tag members only. External datapack/resource tag overrides are not in the source publication and are outside this vanilla-source conclusion.

For 1.16.5 and 1.17.1 the path hashes match their adjacent `mojmap.sources.sha256` manifests and parent sidecars (`mojmap.provenance.json`, `mojmap.ready.json`, and `artifacts.sha256`). For 1.17 the same path hashes match the source map embedded in `mojmap/.decompile-provenance.json` (mapping build 4141). The files were read from the assigned read-only roots `D:\Javastuff\LegacyParkourCompat\decompiled_minecraft\{1.16.5,1.17,1.17.1}\mojmap`.

This closes the bounded old-block-provider and direct-block-response slice only.
