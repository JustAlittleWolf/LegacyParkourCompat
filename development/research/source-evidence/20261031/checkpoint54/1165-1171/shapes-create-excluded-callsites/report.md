## Dispositions

- **EndPortalBlock — exclude the shape-conversion call from client movement.** In all three releases, `EndPortalBlock.entityInside` converts the entity AABB and joins it with the portal shape only inside `level instanceof ServerLevel` (Mojmap `net/minecraft/world/level/block/EndPortalBlock.java:40-49`). The callback can be reached during entity block-contact processing, but that guard excludes the LocalPlayer's logical-client execution. The portal's ordinary `getShape` returns the block's static `SHAPE`; this AABB overlap decides the server-side dimension-transfer trigger, not collision clipping or a client position response. The transfer itself is server-side.
- **HopperBlockEntity — item-only exclusion.** In 1.16.5, `entityInside` first requires `entity instanceof ItemEntity` before the AABB/suck-shape intersection; in 1.17 and 1.17.1 the static callback retains the same `ItemEntity` gate (respective files, lines 401-414). The created shape controls item suction/insertion. A LocalPlayer cannot satisfy the gate, so this callsite does not enter player tick, collision, or position-response paths.
- **CollisionGetter.isUnobstructed(Entity) and EntityGetter.isUnobstructed(entity, shape) — no LocalPlayer movement caller found.** The CollisionGetter overload wraps `entity.getBoundingBox()` with `Shapes.create` and delegates to the entity-plus-shape overload. EntityGetter's implementation scans entities intersecting the supplied shape bounds and admits obstructions only for live, building-blocking entities outside the caller's vehicle (1.16.5 `EntityGetter.java:34-45`; later releases have the same operation). Exact-source callsite search across each `net/minecraft` tree found the entity overload used by mob/entity spawn or placement predicates (for example `Mob` and the animal/monster subclasses) and found no LocalPlayer/player tick, collision, or position-response caller. Block-placement checks call the block-state/position overload, not this entity-AABB overload. This excludes these methods as current LocalPlayer movement callsites; it does not claim their semantics are irrelevant to non-player spawn behavior.
- **Boat.getGroundFriction — vehicle-physics exclusion.** Each release derives the boat's shallow bottom-contact AABB, converts it to a shape, and uses it while evaluating boat status/land friction (`Boat.java:477-505` in 1.16.5; `489-517` in 1.17/1.17.1). It is consumed by boat/vehicle physics and is outside the stated movement scope. A passenger may follow vehicle motion, but this shape operation is not LocalPlayer's movement or collision response.
- **ServerGamePacketListenerImpl — server-only, with correction-policy caveat.** The listed AABB shape is constructed in the server network listener's player-movement collision-validation path (1.16.5 line 962, 1.17 line 943, 1.17.1 line 929). It does not run in LocalPlayer tick/collision code. A server validation decision can be externally visible if it triggers a correction packet; that is connection policy, not historical client physics. For an eligible profile connection, the project server policy must relax any conflicting check rather than replay the historical shape calculation.
- **Entity.refreshDimensions — non-player/server-gated.** 1.16.5 has no `Shapes.create(AABB)` allocation in `refreshDimensions` (it resizes the box and the expansion move is guarded by `!firstTick && !level.isClientSide`). In 1.17 and 1.17.1 the new shape allocation is within a guard requiring logical server, non-first tick, physics enabled, dimensions no greater than four, an increase in width or height, and `!(this instanceof Player)` (`Entity.java:2473-2494` in 1.17; `2475-2496` in 1.17.1). It is a non-player server reposition/free-space adjustment, so it cannot affect LocalPlayer dimensions or client position response through this operation.
- **JigsawPlacement — world-generation geometry.** Its AABB conversions are used to assemble/check structure-piece volumes (`JigsawPlacement.java`, census-listed locations); no LocalPlayer is an input and this code is not on player tick/collision/position-response paths.
- **LevelRenderer and GameEventListenerRenderer — rendering/debug only.** LevelRenderer's listed conversion feeds a rendered debug shape; GameEventListenerRenderer's conversions build overlay/debug boxes. They do not feed physics, player movement, or position response.
