## Additional independently retraced boundary member: WorldBorder collision

The frozen roster included `WorldBorder` but the bounded collision reports did not disposition its changed extent clamp. I retraced its collision consumer and paired extent shape construction. This is an additional conditional direct movement-response candidate, source-introduced in 1.17 and unchanged in 1.17.1:

- Set the same raw client-side border state in each compared release with `centerX = 60,000,000`, `centerZ = 0`, `size = 60,000,000`, and the default `absoluteMaxSize = 29,999,984`. `WorldBorder.setCenter` and `setSize` store these values without clamping them.
- In 1.16.5, `StaticBorderExtent.updateBox()` uses `minX = max(centerX - size/2, -absoluteMaxSize) = 30,000,000` and `maxX = min(centerX + size/2, absoluteMaxSize) = 29,999,984`. `Shapes.box` routes through the old `AABB` constructor, which sorts endpoints, so its inner horizontal rectangle includes X `[29,999,984, 30,000,000]`.
- In 1.17/1.17.1, the `Mth.clamp` calls clamp both ends to `29,999,984`; `Shapes.box` permits equal bounds and the six-coordinate `Shapes.create` returns empty for the zero-width X extent. The border's `INFINITY ONLY_FIRST innerBox` collision shape consequently differs from the old shape.
- `Entity.collide()` reads `level.getWorldBorder().getCollisionShape()`. Its overlap gate includes the border shape when the current player AABB is wholly inside the old inner rectangle, then passes that shape into collision resolution. A LocalPlayer at X `29,999,990`, Z `0`, with an open eastward SELF displacement collides with the old outer border shape at X `30,000,000`; in 1.17/1.17.1 the new full-space border shape overlaps the current AABB, so the overlap gate drops the border shape from the collision stream. This establishes a conditional difference in the collision displacement under equal border, player and requested-movement inputs.
- Boundary hashes: `WorldBorder.java` 1.16.5 `2925df8d985d0ec2d075d4f5c57538dcc628528b72a1d35e90af27fe4fbadb2a`, 1.17 and 1.17.1 `b848dd0dc6043d6c9012726844bea53cf4558c0135a08fa3be55960b0e557df9`; `Entity.java` 1.16.5 `f9a9a073fe3105a0aa53d0f21ec72e59084e8d21a14c1cd3be75703865ee2666`, 1.17 `81231ad8ac1b9a7a9f7ee186352c7e73c0c5211a3034c3a35c04badc6914c8ef`, 1.17.1 `ab28e1fba924771ec048140dfd293ee5a46a7dfe81f71a1a0b1aecc1927232de`; `AABB.java` and `Shapes.java` hashes are in the three-way inventory.

This is a static source witness for an unusual but constructible border state. Border-state production/replication is held equal and not analyzed; no server-state or runtime parity claim is made.
