### Pose and player dimensions

- `net/minecraft/world/entity/Entity.java`, `refreshDimensions()`: **1.16.5** lines 2306–2331 updates the box locally, using centered bounds when new width shrinks and min-corner-preserving width/height updates otherwise; its widening correction is gated to non-client, non-first-tick entities. **1.17 / 1.17.1** lines 2473–2500 assign the new dimensions, call `reapplyPosition()`, then run a free-position search only for eligible non-player server entities. That server search is outside player-client movement scope.
- Existing player pose dimensions match across the three versions: standing is 0.6 × 1.8; sleeping uses `LivingEntity.SLEEPING_DIMENSIONS` = fixed 0.2 × 0.2; fall-flying, swimming and spin-attack are 0.6 × 0.6; crouching is 0.6 × 1.5; dying is fixed 0.2 × 0.2. See `Player.java` `POSES` initializer at 1.16.5 lines 113–121, 1.17 lines 125–133, and 1.17.1 lines 125–133, and `LivingEntity.java` `SLEEPING_DIMENSIONS` at 1.16.5 line 126 / 1.17 and 1.17.1 line 152. `Player.getDimensions(Pose)` remains a map lookup with standing fallback (1.16.5 `Player.java:1990–1992`, 1.17 `:1975–1977`, 1.17.1 `:1966–1968`); standing-eye-height gates/values remain the same (1.16.5 `Player.java:1818–1828`, 1.17 `:1847–1857`, 1.17.1 `:1838–1848`).
- A player client transition from `SLEEPING` (width 0.2) to `STANDING` (width 0.6) exposes a real bounding-box difference in `refreshDimensions`: both versions dispatch `DATA_POSE` through `onSyncedDataUpdated` to this method (1.16.5 `Entity.java:2300–2304`; 1.17 / 1.17.1 `:2467–2471`). In 1.16.5's width-expansion branch, the new box preserves old `minX/minZ`, so at the same player position it is centered +0.2 on both horizontal axes; 1.17 and 1.17.1 call `reapplyPosition()` after assigning dimensions, rebuilding the 0.6-wide box around the same player position. This is a source-level candidate for a changed client player collision box after waking, potentially affecting later movement/collision. Bed-entry eligibility itself is excluded; whether the wake-pose box response is intended to remain in this slice needs explicit scope reconciliation. No trajectory or collision consequence was reproduced here.
- `Pose.java` adds `LONG_JUMPING` in 1.17; that is a 1.17-only pose/feature and has no prior-profile player dimension entry (the player map falls back to standing). No changed dimension or pose value for an existing movement pose was found. `EntityDimensions.java` is byte-identical across all three sources.
