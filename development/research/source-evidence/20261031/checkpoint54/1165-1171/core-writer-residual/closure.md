## Accepted changed LocalPlayer response: Shulker opening

`Shulker.tick()` is a client-reachable external writer. In 1.16.5 it updates `currentPeekAmount` unconditionally, then at lines 230–245 computes physical peek displacement in `double`, builds the full Shulker body AABB expanded toward the opening face, queries non-spectators, and invokes `entity.move(MoverType.SHULKER, Vec3(...))` for non-Shulkers with `noPhysics == false`. On 1.17 and 1.17.1, `tick()` still invokes the peek update and response on both logical sides (the client-only branch later in `tick` is unrelated). The response is extracted into `onPeekAmountChange()`; it uses a directional swept/front-face AABB, adds a same-vehicle exclusion, and computes `h` in `float` before widening the vector components. Anchors: 1.16.5 `Shulker.tick()` lines 163–247, displacement and query lines 230–245; 1.17/1.17.1 `tick()` lines 168–180, `getPhysicalPeek` lines 204–206, `updatePeekAmount` lines 208–222, `onPeekAmountChange` lines 224–241.

Concrete conditional source witness for the first opening step: same synchronized state in all versions, Shulker attached to the block at (0,0,0), opening toward +X, previous raw peek 0 and target raw peek 100. The tick advances peek to 0.05F. The exact Mth lookup-table operation in the two bodies yields old double `h = 0.00615283846855164`; the new float subtraction yields `h = 0.006152838` widened to the movement vector. For an ordinary on-foot LocalPlayer AABB overlapping the front face (e.g. centered at x=1.25, y=0, z=0.5, width 0.6), both query regions include the player and `!noPhysics` permits the call. The requested displacement therefore differs. This request clears Entity.move's squared-displacement `1e-7` no-op threshold and can be realized in open +X space. Independently, the 1.16.5 full-body query also includes on-foot non-spectator player boxes that the 1.17 directional front-face sweep excludes (e.g. body-centered x=0.5 against the same opening); this is a conditional source-state witness, not a claim about how commonly a player reaches that state. The old overload uses `EntityGetter.getEntities(entity, AABB)`, whose default predicate is `NO_SPECTATORS`; the 1.17 predicate retains that and additionally excludes passengers sharing the Shulker's root vehicle. Both exclusions admit an on-foot player.

Classification: eligible changed direct local movement response begins 1.16.5→1.17 and persists in 1.17.1. Within that pair the changed query membership and changed displacement arithmetic are separate source effects; the numeric witness establishes the latter without depending on a changed membership boundary. Source identities are the `Shulker.java`, `EntityGetter.java`, `EntitySelector.java`, `Level.java`, `AABB.java`, and `Mth.java` rows in `core-source-hashes.tsv`; the file hashes were independently recomputed from the exact roots and matched the ledger. The three Shulker SHA-256 values are mechanically stored there (1.16.5 `148223a61c38992efdb88f1537886efcbff4697ab4b46a18f335995a40739570`; 1.17 and 1.17.1 `102331800abe50283910e0fd94334c1ee4d4094bcd471bad3426ed9a2bcf3816`).

## Closed direct writer families

- **Trident Riptide** (`TridentItem.releaseUsing`): reachable from local use release through `Minecraft` → `MultiPlayerGameMode.releaseUsingItem()` → `Player.releaseUsingItem()` → item method. It calls `player.push`, `startAutoSpinAttack`, and conditionally self-moves upward when grounded. The method is client-reachable and eligible, but its relevant Riptide gates and impulse/vector order are source-equivalent across the three versions. The 1.16.5 direct rotation field reads become getter reads in 1.17; those getters return the same fields. `Mth.sqrt(float)` and the item-level reader remain value-equivalent. Close as paired no-difference under the equal release-event and equal item/state assumptions; platform key/device sampling is excluded.
- **Ravager roar / strong knockback**: replicated stun state can reach client `Ravager.aiStep()` and its nearby LivingEntity knockback. The applicable player target response and `LivingEntity.push(double,double,double)` helper are unchanged in the compared versions. Close as paired no-difference for that named path.
- **Dragon / golem / minecart and other external generic targets**: dragon knockback is gated to logical server; Iron Golem's damage-dependent hit knockback does not apply on client because client `hurt` returns false; minecart impulse is explicitly server-gated. Passenger positioning/movement writers are vehicle physics. Attacks, damage, item-entity/projectile writers and entity target-only writes do not write LocalPlayer movement. These are producer, non-player, vehicle, or excluded response paths, not direct client LocalPlayer writers.
- **Chorus fruit**: `randomTeleport` is under `!level.isClientSide`; client-side player position application is a received packet response covered in the separate packet lane.
- **Entity.load / recursive-load routes**: `EntityType.loadEntityRecursive` callers are world loading, spawner, bee-hive, summon, and PlayerList paths; none loads/sets the live LocalPlayer. The 1.17.1 Y clamp in `Entity.load` therefore is not a LocalPlayer route. Client LocalPlayer construction/position synchronization belongs to the packet lane.
- **Entity.move / Entity.push / ordinary tick writers**: these are closed in the sibling source-only Entity.move closure, received-response report, and tick graph. Their findings are reused; this report does not reopen or duplicate them.
