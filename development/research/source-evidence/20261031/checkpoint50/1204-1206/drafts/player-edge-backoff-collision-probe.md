# Player edge backoff collision probe

1.20.4, Mojmap: `net/minecraft/world/entity/player/Player.java`, `maybeBackOffFromEdge` lines 1048–1100 and `isAboveGround` lines 1102–1106; `net/minecraft/world/entity/Entity.java`, `move` lines 596–617 and `collideWithShapes` lines 915–950; `net/minecraft/client/player/LocalPlayer.java`, `move` lines 871–875.
1.20.5, Mojmap: `net/minecraft/world/entity/player/Player.java`, `maybeBackOffFromEdge` lines 1067–1125, including `isAboveGround` and `canFallAtLeast`; `net/minecraft/world/entity/Entity.java`, `move` lines 597–618 and `collideWithShapes` lines 916–951; `net/minecraft/client/player/LocalPlayer.java`, `move` lines 878–882. The same Player helper body is present in 1.20.6 at lines 1067–1125.

Difference: On non-flying, non-upward `SELF`/`PLAYER` movement while `isStayingOnGroundSurface()` (which returns `isShiftKeyDown()` in both releases) and `isAboveGround(...)` hold, 1.20.4 backs off each horizontal component in 0.05 increments while `level().noCollision(this, getBoundingBox().move(dx, -maxUpStep(), dz))` is true. The diagonal pass uses the same full player box probe. 1.20.5 captures `maxUpStep()` once and uses `canFallAtLeast(dx, dz, step)`: a translated horizontal footprint spanning only from `getBoundingBox().minY - step - 1.0E-5F` to the current `minY`. The new helper uses `Math.signum`-derived 0.05 increments, an absolute-value cutoff, and a `break` after zeroing an axis. `isAboveGround` likewise switches from a full-box downward `move` probe to `canFallAtLeast(0, 0, step - fallDistance)`.

Movement meaning: This override is reached from `Entity.move` during ordinary player movement. The old and new no-collision probes cover different vertical regions: the old probe can be blocked by a collision shape intersecting only the body-height portion of the lowered player box, while the new probe tests only the vertical strip from the requested drop depth up to the feet. `CollisionGetter.noCollision` applies block collisions, entity collisions, and the world-border test to either AABB; block shapes are obtained with `CollisionContext.of(player)`. The probes can therefore make different decisions about which 0.05 horizontal increments to remove near an edge, changing the displacement passed into collision resolution. `BlockCollisions.computeNext` uses the query AABB to intersect translated, context-dependent block collision shapes; `CollisionGetter.getBlockCollisions` supplies that iterator. `CollisionGetter.noCollision` is identical in both releases at lines 46–62; `getBlockCollisions` is lines 83–85. `BlockCollisions.computeNext` (lines 64–89) constructs context-dependent block shapes and intersects them with the probe AABB. These provider sources are byte-identical in 1.20.4, 1.20.5 and 1.20.6.
