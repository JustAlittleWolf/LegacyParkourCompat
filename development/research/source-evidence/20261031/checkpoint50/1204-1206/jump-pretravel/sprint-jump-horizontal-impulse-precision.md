Difference: `ClientPacketListener.handleLogin()` gives LocalPlayer `KeyboardInput` and makes it the camera; `KeyboardInput.tick()` reads the jump key. `LocalPlayer.tick()` reaches its `aiStep()`, which reaches `Player.aiStep()` and `LivingEntity.aiStep()`. LocalPlayer's `isEffectiveAi()` returns true, so the living AI stage calls virtual `serverAiStep()`; while it is the controlled camera, LocalPlayer copies `input.jumping` into the inherited jump field. `isAffectedByFluids()` returns true; on an ordinary dry grounded jump with `noJumpDelay == 0`, the unchanged `LivingEntity.aiStep()` gates reach virtual `Player.jumpFromGround()`, which delegates to `LivingEntity.jumpFromGround()`. LocalPlayer's sprint-start branch can set the sprint state read by that jump method. For equal yaw and sprint state, `Mth.sin` and `Mth.cos` return `float` in both versions. In 1.20.4 each float is multiplied by float literal `0.2F`, rounding each product to float before widening into `Vec3`'s doubles. In 1.20.5 each float is multiplied by double literal `0.2`, producing the component as a double. The subsequent accumulation is equivalent: both `setDeltaMovement(current.add(vector))` and `addDeltaMovement(vector)` use that same operation in `Entity`.
Movement meaning: For an ordinary grounded sprint jump with the same yaw and sprint state, and computed 1.20.5 jump power strictly greater than `1.0E-5F`, the changed product precision can slightly change horizontal velocity. This claim is limited to the horizontal impulse; it makes no claim that vertical jump power is unchanged. At or below the threshold, 1.20.5 suppresses the horizontal sprint-impulse write, so this isolated comparison does not apply.
