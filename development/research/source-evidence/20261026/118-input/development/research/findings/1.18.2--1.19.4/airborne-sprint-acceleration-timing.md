# Airborne sprint acceleration uses current state and a smaller coefficient

1.18.2, Mojmap: `1.18.2/mojmap/net/minecraft/client/player/LocalPlayer.java`, `aiStep`, lines 642–807, and `serverAiStep`, lines 606–619; `net/minecraft/world/entity/player/Player.java`, `aiStep`, lines 491–515, and `travel`, lines 1422–1453; `net/minecraft/world/entity/LivingEntity.java`, `aiStep`, lines 2507–2552, `travel`, lines 2009–2142, `handleRelativeFrictionAndCalculateMovement`, lines 2161–2171, and `getFrictionInfluencedSpeed`, lines 2206–2208; `net/minecraft/world/entity/Entity.java`, `moveRelative`/`getInputVector`, lines 1151–1167.

1.19.4, Mojmap: `1.19.4/mojmap/net/minecraft/client/player/LocalPlayer.java`, `aiStep`, lines 645–802, `serverAiStep`, lines 609–622, and sprint predicates, lines 1022–1043; `net/minecraft/world/entity/player/Player.java`, `aiStep`, lines 499–517, `travel`, lines 1440–1467, and `getFlyingSpeed`, lines 2112–2118; `net/minecraft/world/entity/LivingEntity.java`, `aiStep`, lines 2500–2550, `travel`, lines 1983–2112, `handleRelativeFrictionAndCalculateMovement`, lines 2152–2162, and `getFrictionInfluencedSpeed`, lines 2197–2199; `net/minecraft/world/entity/Entity.java`, `moveRelative`/`getInputVector`, lines 1181–1197.

Difference: In 1.18.2 `LocalPlayer.aiStep` decides sprint state before calling `Player.aiStep`, but `Player.aiStep` writes `flyingSpeed = 0.02F` and conditionally adds `0.006F` only after `super.aiStep()` has already travelled. Ordinary airborne movement therefore reads the coefficient retained from the previous tick. In 1.19.4 the cached field/update is removed: airborne `getFrictionInfluencedSpeed` calls `Player.getFlyingSpeed`, which reads current `isSprinting()` and returns `0.025999999F` or `0.02F` when ability flight is off. The sprinting constant is also one float ULP smaller: the old float addition produces bits `0x3cd4fdf4` (`0.026000000536441803`), while the new literal has bits `0x3cd4fdf3` (`0.025999998673796654`).

Movement meaning: Consider a live, mobile local player with the controlled camera, in a loaded chunk, unmounted and airborne, outside water/lava, not fall flying or ability flying, with no collision/climbable interaction. Keep forward input held, no item in use, no blindness, food above six, and let the preceding tick end with sprint off. Pressing the sprint key makes `LocalPlayer.aiStep` start sprint before `serverAiStep` copies the current input and `LivingEntity.aiStep` scales it by `0.98F` and travels. At yaw zero with forward-only input, old code adds `((double)0.98F) * ((double)0.02F)` to Z velocity; new code adds `((double)0.98F) * ((double)0.025999999F)` instead, approximately 0.00588 more before movement and drag. Thus the position changes on this same tick in unobstructed air. Conversely, stopping sprint while retaining nonzero directional input leaves the old sprint coefficient for one tick, while 1.19.4 immediately selects the non-sprint coefficient. Even with sprint stable across ticks, the new literal reduces the forward-only acceleration by `((double)0.98F) * 2^-29`, approximately 1.8254e-9 per tick before drag. Ground acceleration still uses `getSpeed()`; ability flight uses a separate current-state speed path in both endpoints.

Exact release boundary: inspected Mojmap `Player.aiStep` and `travel` in 1.19 (lines 516–522 and 1474–1482), 1.19.1/1.19.2 (lines 517–523 and 1479–1487), and 1.19.3 (lines 513–519 and 1463–1471). All retain the cached post-travel assignment and temporary ability-flight override. The first inspected release with the current-state getter is 1.19.4, establishing the 1.19.3 → 1.19.4 release cutover.
