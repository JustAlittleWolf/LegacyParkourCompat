## Residual behavior recheck

- **Climb predicate/helper:** `LivingEntity.isClimbing()` and `canClimbTrapdoor(...)` method-body hashes match at all four releases. The predicate floors player/entity `x`, `getShape().minY` and `z`, rejects spectator players, and accepts ladder/vine blocks directly; the trapdoor branch requires `OPEN`, a ladder below and matching `FACING`. `isClimbing()` remains consumed by the same living-entity travel/effect gates in the inspected endpoint/alias code. No climb/provider implementation change was found within these bounded methods. Ladder/trapdoor/vine implementation bodies were not audited; their cross-endpoint hash changes remain assigned dependency work.
- **Effect-map addition:** `LivingEntity.getEffects()` is present from 1.12 at `LivingEntity.java:614`; `EffectsPredicate` reads it at `EffectsPredicate.java:30,35` for advancement criteria. This is not evidence of a local-player movement consumer.
- **Water-state helper:** `Entity.checkWaterState()` is absent in 1.11.2 and present at 1.12 onward (`Entity.java:944-946`). Its only invocation in the checked sources is `FlyingWaterAvoidingWanderAroundGoal.getTarget()` (`FlyingWaterAvoidingWanderAroundGoal.java:23`); the goal is constructed with `PathFinderMobEntity`, so this call path is mob AI, not player movement. `Entity.checkWaterCollisions()`, `Entity.isSubmergedIn(Material)`, `Entity.isInLava()` and `World.applyLiquidDrag(...)` method bodies hash identically across the four releases. This does not close fluid-provider dependencies: `LiquidBlock.getHeightLoss`, `Block.applyMaterialDrag` and block/material/state registration behavior remain provider work.
- **Post-block collision callback:** In 1.12, `Entity.move`'s collision traversal invokes `Block.onEntityCollision(...)` and then `this.onBlockCollision(blockState)` (`Entity.java:825-826`); the base `onBlockCollision` is an empty method (`:843-844`). Search across the inspected entity/client/server source roots finds the only override in `ServerPlayerEntity.java:280-282`, which runs the enter-block criterion. `ClientPlayerEntity` has no override. This is not a local-client movement response. The callback/provider path is bounded here; collision candidate/shape-provider analysis remains unclosed.
- **Registry keys:** `Blocks.java` resolves the same selected keys in 1.11.2 and 1.12.2: `FLOWING_WATER`, `WATER`, `LADDER`, `ICE`, `SOUL_SAND`, `TRAPDOOR`, `VINE`, `PACKED_ICE` and `FROSTED_ICE` all use the same `getOrThrow("<key>")` expressions. Alias `Blocks.java` is byte-identical across 1.12/.1/.2. This verifies the selected registry expressions, not all provider registration behavior.
