# Independent source audit: 1.21.2 → 1.21.3 Salmon migration and local-player push

## Verdict

**Accept, bounded to the exact source claims and the limits below.** The 1.21.3 EntitySalmonSizeFix is registered in the data fixer chain and changes a saved small Salmon record to medium when that entity chunk is migrated from data version 4080. This is a server persistence producer path. For equal valid received Salmon variant state, the client-side size, sync receiver, player query, and push math are unchanged between the two releases. The source does not establish an in-scope client movement code delta; it establishes a conditional route by which a server-produced Salmon size/state difference can affect local-player delta movement.

The query helper limitation is real. The decompiled EntityTypeTest.forClass body contains a parameter name that shadows its captured Class<T> and prints an impossible generic B.isInstance(B) call. Its exact runtime cast/filter body cannot be accepted literally from this source. EntitySection visibly indexes through EntityTypeTest.getBaseClass() and then invokes tryCast; getBaseClass() returns the captured class, and the client-side EntitySelector independently filters candidates to local players, but I do not infer that these facts repair the malformed tryCast body. The identical malformed source hash is 6a85ac27f1427bd19f041ebc92b4e3a0002d7e01da4c276c0ca49f09a50001b6 on both sides.

## Independent trace

- DetectedVersion.java:33 and SharedConstants.java:15 set world/data versions 4080 in 1.21.2 and 4082 in 1.21.3. DataFixers.java:1368–1369 adds schema 4081 and registers EntitySalmonSizeFix. The fixer targets minecraft:salmon; at EntitySalmonSizeFix.java:12–16, it reads type with fallback medium, preserves only large, and writes medium for every other value.
- ServerLevel.java:233–236 constructs EntityStorage with DataFixTypes.ENTITY_CHUNK; EntityStorage itself takes a ServerLevel. Its load path calls SimpleRegionStorage.upgradeChunkTag before loading recursive entities. SimpleRegionStorage.java:35–37 extracts the stored version and calls updateToCurrentVersion. This binds the migration to saved server entity chunks; it does not show that every Salmon source (including bucket/custom item data) takes that path.
- Both Salmon.java files define the tracked type as MEDIUM, refresh dimensions when that tracked field changes, and compute dimensions by scaling superclass dimensions. SMALL is 0.5F, MEDIUM 1.0F, LARGE 1.5F. Variant.byName has a changed fallback (SMALL → MEDIUM); valid names map to the same sizes in both releases. The client receiver ClientPacketListener.handleSetEntityData calls SynchedEntityData.assignValues, which invokes the entity update callback. This receiver and the variant/size methods are equal apart from the described fallback. ServerEntity’s tracked-data writer is source context only; it is an external/server producer.
- The shared LivingEntity.tick calls pushEntities. In a non-ServerLevel level, LivingEntity.pushEntities queries entities against the Salmon’s bounding box and passes each result to doPush; doPush calls the candidate’s push(this). EntitySelector.pushableBy rejects a source-team NEVER rule, spectators and unpushable candidates; on a client level it additionally requires the candidate to be a Player and isLocalPlayer(), then applies the candidate team collision rules. Player.isLocalPlayer() is false in the base class and LocalPlayer.isLocalPlayer() returns true.
- The eligible local player must be alive, nonspectating and not on a climbable (LivingEntity.isPushable). One additional gate omitted from the author’s enumerated list is LivingEntity.push(Entity): it returns without delegating to Entity.push when the receiver is sleeping. Player, AbstractClientPlayer and LocalPlayer do not override this method in the checked sources, so that inherited gate applies to the local player. Entity.push(Entity) also skips same-vehicle and either-side noPhysics pairs, requires horizontal separation Mth.absMax(dx,dz) >= 0.01F, and adds the normalized horizontal impulse only when the receiving entity is not a vehicle and is pushable. Thus an awake, eligible local player can receive an impulse if the typed query selects it, a changed Salmon box newly overlaps it, and these same gates pass; exact query cast semantics remain unproven from the malformed helper.

## Applicability and unresolved boundaries

The 1.21.3 migration changes a server-side persistence input. For equal valid received state (small, medium, or large), both clients use the same scale, dimensions, tracking receiver and push code; the source-level server-to-client state producer may supply a different variant after loading old persisted data. That distinction does not yield a client movement implementation delta under equal received state.

The EntityTypeTest.forClass tryCast body is malformed by decompilation in both version trees: its B $$0 parameter shadows the captured Class<T> $$0 used correctly by getBaseClass(). The query caller requests Player.class, and the selector’s local-player gate is directly readable, but the precise class-cast filter is not proven from this decompiled helper. I do not infer its implementation.

The changed fallback for missing/unknown type strings is source-confirmed, but ordinary-client reachability from such values is not closed. Bucket/custom item input, malformed payload producers, effective external data and runtime trajectories remain unresolved. No pair freeze, client parity, or implementation readiness is claimed.
