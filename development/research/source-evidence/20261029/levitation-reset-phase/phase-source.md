# Levitation fall-distance reset changes the same-tick sneak edge gate

1.19.4, Mojmap: `1.19.4/mojmap/net/minecraft/world/entity/LivingEntity.java`, `travel` 2092–2096 and `handleRelativeFrictionAndCalculateMovement` 2152–2163; `1.19.4/mojmap/net/minecraft/world/entity/Entity.java`, `move` 550–570; `1.19.4/mojmap/net/minecraft/world/entity/player/Player.java`, `isStayingOnGroundSurface` 308–310, `maybeBackOffFromEdge` 1041–1092 and `isAboveGround` 1095–1099; `1.19.4/mojmap/net/minecraft/client/multiplayer/ClientPacketListener.java`, `handleUpdateMobEffect` 1483–1500.

1.20, Mojmap: `1.20/mojmap/net/minecraft/world/entity/LivingEntity.java`, `aiStep` 2559–2573 and movement helper 2172–2176; `1.20/mojmap/net/minecraft/world/entity/Entity.java`, `move` 593–614; `1.20/mojmap/net/minecraft/world/entity/player/Player.java`, `isStayingOnGroundSurface` 309–311, `maybeBackOffFromEdge` 1043–1094 and `isAboveGround` 1097–1101; `1.20/mojmap/net/minecraft/client/multiplayer/ClientPacketListener.java`, `handleUpdateMobEffect` 1497–1514.

Difference: In 1.19.4, Levitation resets `fallDistance` after `handleRelativeFrictionAndCalculateMovement` has called `move(SELF, ...)`. In 1.20, `LivingEntity.aiStep` resets it before travel when Levitation or Slow Falling is active. The movement and player gate otherwise read the live `fallDistance` at `Entity.move`'s pre-collision `maybeBackOffFromEdge` call. Both versions gate that response on `noPhysics == false` (the true branch bypasses edge back-off), non-flight, nonpositive Y movement, `SELF`/`PLAYER`, shift held, and `isAboveGround`; the latter reads `fallDistance < maxUpStep()` and a downward-shifted-box collision test.

Movement meaning: A clientbound effect update addressed to the local player installs Levitation without resetting that player's accumulated fall distance. That value can already be at least `maxUpStep` after downward movement when the effect is received. Under equivalent player/world state, for the same positive `maxUpStep`, if the player is airborne, the old fall-distance gate is false before movement; the new pre-travel reset can make the gate true when the lowered-box collision condition holds. With a nonpositive SELF Y displacement and a support layout that also makes the horizontal back-off checks succeed, 1.20 can reduce horizontal movement by 0.05 steps in that tick where 1.19.4 does not. This is a source-reachable movement difference; a concrete block-shape witness, network/tick schedule and trajectory remain unproven.
