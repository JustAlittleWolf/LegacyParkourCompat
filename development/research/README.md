Confirmed findings remain after implementation. They do not carry implementation or runtime status.

[backlog.json](backlog.json) is machine-managed storage, not a file agents need to read or edit wholesale. It associates findings with source acceptance, code and integrated commits, keeps concrete open evidence/applicability gaps, and tracks pair coverage/dependencies/audit separately from runtime parity. Suborchestrators, implementers and reviewers supply updates in chat; they do not create parallel status or handoff files. The product revision bounds inherited static correspondence; historical review paths identify Git evidence, not files that must be archived in the current tree.

Use the backlog tool's `summary` command for current finding counts, implementation correspondence and open evidence gaps; do not duplicate these changing totals here. `present` means static implementation correspondence, not independent acceptance or runtime parity. Coverage entries retain examined areas (including bounded no-difference checks), partial and unexamined slices, concrete dependencies, exact Git ledger references and next actions. Read the relevant entry for its current audit and gates; historical acceptance remains bound to its exact artifacts and requires checking the current publication identity before reuse. These inherited records do not themselves renew acceptance or establish runtime parity.
