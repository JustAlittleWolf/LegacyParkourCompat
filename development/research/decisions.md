# Scope and invalid movement witnesses

The root README and AGENTS define current scope: historical client player movement on vanilla block states. Historical server physics, vehicle/non-player motion, rendering/input-device plumbing, state production, damage, and bed-entry eligibility do not become movement tasks. Direct player responses and predicates reading vanilla state remain eligible.

- **1.21.4/1.21.5 F09 input damping:** the newer controlled-camera path also applies 0.98F. The revised forward-only 1ULP witness cancels after square correction; its diagonal residual belongs to the separate normalization/square-movement operation. Neither claim supports a damping implementation.
- **1.19.4/1.20.1 trapdoor/wire:** the closed bottom trapdoor already has a FULL upward face in the older support test. The movement witness was withdrawn; later ACCEPT covers withdrawal only. Redstone/block-state production is separately excluded, and the open-trapdoor replacement is unproved.
- **1.21.4/1.21.5 scale refresh:** the older appliedScale poll follows dirty-attribute dispatch at tick tail. Both endpoints refresh before next movement; the stale-next-tick witness was withdrawn.
- **1.8.9/1.9.4 WORLD27 server boundary:** the configured +/-30M witness overlooks the effective 29,999,984 cap. Do not restore that witness or replay historical server physics; the eligible client correction operation is separate.
- **1.14.4/1.15.2 Toggle Crouch:** optional toggle input production is a modern feature; default hold-state edge loops match. This does not reject the independent near-ground edge predicate operation.
- **1.19.2/1.19.3 correction clamp:** the accepted response is to finite out-of-range absolute corrections from an external/custom server. Vanilla teleport rejects those coordinates; a codec is not a vanilla producer proof.
- **Honey 1.19.2/1.19.3:** acceptance establishes first stable changed release 1.19.3 for the command/local-gravity witness. Exact 1.19, 1.19.1, 1.19.2 and 1.19.3 source review supports a separate V1_19_3 profile. Each operation retains its own endpoint; this representation change does not establish full honey-contact parity.
- **Auto-jump before introduction:** exact 1.9.4 lacks the feature and 1.10.2 contains it. Earlier profiles retain modern auto-jump. Disabling the feature is outside scope; historical normalization and collision ordering must fall back to native before V1_10. The 1.10.2 double inverse-square-root followed by a float cast remains distinct from the later float helper.
- **Swimming and crawling before introduction:** preserve native modern feature admission and SWIMMING dimensions on earlier profiles. Absence in old source does not justify forcing the swimming flag false, replacing crawl dimensions with standing dimensions, or preventing native crawl entry. Historical CROUCH dimensions remain an independent response. The whole 1.13 pose-resize replacement is deferred because it blocked modern crawl admission; exact old block-only collision queries and current-key pose timing do not by themselves establish a feature-preserving integration. Retaining native pose selection does not prove historical pose parity.
- **Chorus teleport and world minimum Y:** server teleport production and server-provided world dimensions are external inputs. Equal received state is required for movement comparison; replacing their production does not implement a client movement delta.
- **Mounted End Gateway target selection:** the block-entity tick chooses a server teleport target and propagates passenger positions. Preserve the received teleport state; selecting a different server-side root/player target is external teleport production, not a logical-client movement response.
- **Diode support removal in 1.20.2:** unsupported repeater/comparator removal changes the supplied vanilla block-state population. The collision shape of an extant diode is unchanged. Do not retain historical block states to manufacture the collision-world difference.
- **1.13.2 ground-drag support resample:** the second sample follows input acceleration but precedes climbable clamping and `move`. The claimed post-movement support-boundary witness was incorrect. Do not add a post-movement drag resample from this finding; the independent ground-acceleration arithmetic delta remains valid.
- **Vehicle dismount border checks:** the inspected canDismountTo consumer runs through server-only LivingEntity.stopRiding/dismountVehicle. The separately scoped client bed-wake response remains eligible.

- **Ender pearl dimension ownership and farmland conversion pushes:** pearl owner clearing during server dimension transfer and displacement produced by server farmland-to-dirt conversion supply authoritative teleport state. Preserve equivalent received player state rather than reproducing these server producers on the client. This does not exclude client responses to equivalent corrections.

- **1.21.8/1.21.10 entity-motion packet quantization:** both client handlers apply the decoded velocity directly. The changed codec produces an external velocity state; its original unquantized input cannot be recovered after decoding. Preserve equal received state rather than adding another quantization pass.
- **1.21.8/1.21.10 spectator sleep exit:** the changed `LivingEntity.tick` sleep check is inside the logical-server branch. Its resulting pose/position updates are authoritative external state. Do not replay this server wake producer on the client; this leaves separately sourced client bed-wake responses eligible.

These constrain current work; they are not a campaign ledger. Preserve input-state movement predicates such as the pending sprint-timer operation even when they depend on input representation.
