## Exact source-derived query

Use the registered `glass_pane` at `(0,64,0)`, with AIR in the four horizontal neighbor positions and no water. The A state resolves to four false connection flags; the B placement/default path yields the same flags and `WATERLOGGED=false`. Both providers contribute only the center pane voxel for this state.

Use a locally controlled airborne player positioned by `Entity.setPosition(0.13749,64.2,0.13750005)`. The exact resulting double box is X `[-0.16251001192092895,0.43749001192092896]`, Y `[64.2,65.99999995231629]`, Z `[-0.16249996192092894,0.43750006192092894]`, using the float `f` and `g` conversions and operation order cited above. No other collision shapes, entities, or world-border contact are present. Set horizontal input to zero and deliver the equivalent entity-velocity packet with X integer `25` and Y/Z integers `0`. The paired packet handler and `lerpVelocity` set `velocityX=25/8000.0=0.003125`. The local-player path skips remote-velocity damping, and `0.003125` is not below the strict `0.003` cutoff. Zero input adds no velocity. On the ordinary airborne, non-liquid, non-fall-flying path, the next `moveRelative` call therefore passes `(0.003125,0,0)` to `Entity.move` in both versions. This replaces the earlier snapshot's unsupported `1.0` argument with a value bound to a source-reachable player state.

In A, the movement-expanded collision query reaches maxX `0.43749001192092896 + 0.003125 = 0.44061501192092895`, so it strictly overlaps the pane center box beginning at X `0.4375`. Its Y overlap is `[64.2,65]`; its Z overlap is `0.00000006192092893986256`. The pane is collected by strict translated-box intersection. The subsequent positive-X clip uses the original player box and leaves `0.4375 - 0.43749001192092896 = 0.00000998807907104382`, so A applies X `0.00000998807907104382`.

In B, the expanded swept query also collects the pane shape; the effect is not a broadphase omission. The pane's X/Y/Z coordinates are arrays `[7/16,9/16]`, `[0,1]`, and `[7/16,9/16]` over the full-block one-cell voxel set. For the X-axis clip, `VoxelShape.calculateMaxDistance` gets the orthogonal Z lower and upper probes from `box.minZ + 1.0E-7` and `box.maxZ - 1.0E-7`. Both are below the array's first Z coordinate `7/16 = 0.4375`, so `getCoordIndex` returns `-1` for each: the lower loop index is clamped to `m = 0`, while the upper exclusive index is `n = min(1, -1 + 1) = 0`. The orthogonal loop range `[m,n)` is empty and does not visit the pane's single occupied voxel. B therefore applies the full requested X `0.003125`. This is the array-shape fallback path, not a sixteenth-block voxel grid.

The difference is confined to this exact query and state. Panes existed in both endpoint versions. The B waterlogging bit is false; all other collision candidates are excluded by the stated world conditions. This does not identify the first changed release in the interval or close the pair.
