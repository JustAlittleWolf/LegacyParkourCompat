# Pose-entry collision inset
1.15.2, Mojmap: `net/minecraft/world/entity/Entity.java`, `canEnterPose(Pose)` (1605–1607), `getBoundingBoxForPose(Pose)` (2320–2325); `net/minecraft/world/entity/player/Player.java`, `updatePlayerPose()` (357–384), `getDimensions(Pose)` (2047–2049), pose dimensions (111–120); `net/minecraft/world/level/CollisionGetter.java`, `noCollision` and block-shape intersection (55–56, 67–109).
1.16, Mojmap: `net/minecraft/world/entity/Entity.java`, `canEnterPose(Pose)` (1620–1622); `net/minecraft/world/entity/player/Player.java`, `updatePlayerPose()` (350–377). The same `canEnterPose` body is present in 1.16.1 (1620–1622) and 1.16.2 (1640–1642).
1.16.5, Mojmap: `net/minecraft/world/entity/Entity.java`, `canEnterPose(Pose)` (1640–1641), `getBoundingBoxForPose(Pose)` (2360–2365); `net/minecraft/world/entity/player/Player.java`, `updatePlayerPose()` (350–377), `getDimensions(Pose)` (1990–1992), pose dimensions (112–121); `net/minecraft/world/level/CollisionGetter.java`, `noCollision` (48–59); `net/minecraft/world/level/CollisionSpliterator.java`, block collision-shape intersection (70–85); `net/minecraft/world/phys/AABB.java`, `deflate(double)` (250–251), `inflate(double,double,double)` (151–158), strict intersection (208–210).
Difference: The player pose dimensions, candidate-box construction, and `updatePlayerPose()` gates and fallback order match. Both endpoint ticks call this method after the other player tick work. `canEnterPose` in 1.15.2 checks `level.noCollision(this, candidateBox)`; it checks the same query on `candidateBox.deflate(1.0E-7)` in 1.16, 1.16.1, 1.16.2, and 1.16.5, shrinking every face by 1.0E-7. The exact source boundary is between 1.15.2 and 1.16. The outer swimming-fit gate, requested-pose check, crouching fallback, and swimming fallback are unchanged. Thus a collision wholly inside the removed 1.0E-7 shell ceases to block each of those checks; the difference can also let the outer gate run and commit a pose where 1.15.2 leaves the current pose unchanged.
Movement meaning: This is conditional on the ordinary player candidate box intersecting a block or entity collision shape only within that shell, with no other collision. A concrete block-boundary witness is a full-cube shape at [0,1]×[1,2]×[0,1], with the player at y=1,z=0.5 and x=1.29999996. The 0.6F player width gives half-width 0.3F; Java float-to-double arithmetic makes the candidate minX 0.9999999480790711, so it overlaps the cube by about 5.19E-8. Deflating raises minX to 1.0000000480790712 and removes that intersection. For a crouched player releasing shift in this conditional position, 1.15.2's outer swimming-fit check fails and leaves the pose unchanged; 1.16.5's inset makes the swimming and standing checks pass and selects standing. This is a source-bounded collision witness, not a claim that a particular input trajectory reaches that coordinate.
