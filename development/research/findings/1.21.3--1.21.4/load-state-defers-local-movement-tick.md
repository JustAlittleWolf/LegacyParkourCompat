# Load-state defers local movement tick
1.21.3, Mojmap: `net/minecraft/client/player/LocalPlayer.java`, `tick()`, lines 189–212.
1.21.4, Mojmap: `net/minecraft/client/player/LocalPlayer.java`, `tick()`, lines 191–217; `net/minecraft/world/entity/player/Player.java`, `hasClientLoaded()` and `tickClientLoadTimeout()`, lines 2096–2109; `net/minecraft/client/multiplayer/ClientPacketListener.java`, readiness notification, lines 2460–2463.
Difference: 1.21.3 runs `dropSpamThrottler.tick()`, `super.tick()`, input and movement packet work, and ambient sound ticks on each `LocalPlayer.tick()`. 1.21.4 first decrements a 60-tick player load timeout, then runs that whole body only when `clientLoaded || clientLoadedTimeoutTimer <= 0`; the client marks it loaded once its level load status is ready.
Movement meaning: through the client entity-tick path (`Minecraft.tick()` → `ClientLevel.tickEntities()` → `tickNonPassenger()` → `LocalPlayer.tick()`), the newer gate can defer the local player’s `LivingEntity`/movement tick and movement/input packet updates until level readiness or timeout, while the older client ticks them immediately. This is client-only loading behavior; the handshake is sent to the server, which separately checks its player load state before handling movement packets.
