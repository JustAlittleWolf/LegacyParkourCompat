# Collision restitution and direct player response

26.1.2, unobfuscated: `decompiled_minecraft/26.1.2/unobfuscated/net/minecraft/world/entity/Entity.java`, `Entity.move`, lines 704-799; `decompiled_minecraft/26.1.2/unobfuscated/net/minecraft/world/level/block/Block.java`, `Block.updateEntityMovementAfterFallOn`, lines 498-500.
26.2, unobfuscated: `decompiled_minecraft/26.2/unobfuscated/net/minecraft/world/entity/Entity.java`, `Entity.move`, lines 711-800 and new `Entity.restituteMovementAfterCollisions`, lines 802-841; `Entity.getBlockBounciness`, lines 845-851; `Entity.getEntityBounciness`, lines 854-855; `Entity.isShiftKeyDown` / `isSuppressingBounce`, lines 2689-2699; `decompiled_minecraft/26.2/unobfuscated/net/minecraft/world/level/block/Block.java`, `Block.getBounceRestitution`, lines 494-496.

Difference: Both versions resolve movement, write position, derive horizontal/vertical collision flags, obtain the legacy on-block state, check fall damage for the local authoritative instance, then handle removal. In 26.1.2, the surviving path zeros each collided X/Z velocity component directly (`Entity.move`, 776-779). When movement simulation is allowed and Y was clipped, it dispatches to the block's `updateEntityMovementAfterFallOn` (`781-785`). In 26.2, those responses are replaced by one restitution call (`784-785`), gated by `canSimulateMovement()` and `(movedVertically && verticalCollision || horizontalCollision)`.

The new restitution method starts with zero when bounce is suppressed, otherwise entity bounciness. It reverses each collided X/Z component scaled by restitution. For a vertical collision below, block restitution applies only when downward speed is at least effective gravity, bounce is not suppressed, and the effect block is not tagged `SUPPRESSES_BOUNCE`; the coefficient is the maximum of entity and block restitution. This block-tag test is nested under `verticalCollisionBelow`, so it does not suppress horizontal or upward collision responses. When restitution is positive, Y uses `portionWithMovement = movement.y / currentMovement.y`, `gravityCompensation = portionWithMovement * getEffectiveGravity()`, `effectiveDrag = Mth.lerp(portionWithMovement, 1.0, getAirDrag())`, then `(gravityCompensation - currentMovement.y) * effectiveDrag * restitution`. Otherwise the collided Y velocity is set to zero. A positive bounce emits `GameEvent.BOUNCE` and sets `syncPosition`; `Entity.java:842` writes the computed vector with `setDeltaMovement`.

Player reachability and gates: `Player.canSimulateMovement()` is unchanged at `26.1.2 Player.java:1269-1271` and `26.2 Player.java:1290-1292`; local players simulate on the client, remote players do not. `LivingEntity.getEntityBounciness()` reads `Attributes.BOUNCINESS` (`26.2 LivingEntity.java:2202-2203`), and LivingEntity attributes include it (`LivingEntity.java:355`); `Attributes.BOUNCINESS` has default value 0.0 and range 0.0-1.0 (`26.2 Attributes.java:31`). Consequently the default local player still has zero restitution on horizontal collision, as in 26.1.2. If that player attribute is nonzero, 26.2 instead reverses collided X/Z velocity by `-currentMovement.component * bounciness` and can emit BOUNCE; 26.1.2 always zeroes those collided components. This branch is reachable through the 26.2 `/attribute <target> <attribute> base set <value>` command (`AttributeCommand.java:70-81`, setter at `301-303`), subject to its gamemaster permission gate. The horizontal response uses entity restitution and the suppression gate only; it does not consult the on-block restitution or `SUPPRESSES_BOUNCE` tag. `Entity.getBlockBounciness()` scales the block coefficient by `0.8F` only for entities that are not LivingEntity (`Entity.java:845-851`), so Player receives the full configured block value.

Holding shift suppresses restitution for LocalPlayer: `LocalPlayer.isShiftKeyDown()` returns `this.input.keyPresses.shift()` (`26.2 client/player/LocalPlayer.java:678-680`), and the inherited virtual `Entity.isSuppressingBounce()` calls `this.isShiftKeyDown()` (`Entity.java:2697-2699`). This makes the base coefficient zero and also blocks the downward block-restitution branch.

The built-in `SUPPRESSES_BOUNCE` provider adds only Honey Block (`26.2 VanillaBlockTagsProvider.java:1216`). Thus built-in Honey contact suppresses the block-derived downward rebound; the source gate is downward-only. Other data-driven tag contents are outside this vanilla built-in provider statement.

## Slime witness

26.1.2, unobfuscated: `decompiled_minecraft/26.1.2/unobfuscated/net/minecraft/world/level/block/SlimeBlock.java`, `updateEntityMovementAfterFallOn` and `bounceUp`, lines 33-49: unless bounce is suppressed, a downward collision sets Y to `-movement.y * factor`, where `factor` is 1.0 for `LivingEntity` (therefore for Player) and 0.8 otherwise.
26.2, unobfuscated: `decompiled_minecraft/26.2/unobfuscated/net/minecraft/world/level/block/SlimeBlock.java` removes that collision callback; `decompiled_minecraft/26.2/unobfuscated/net/minecraft/world/level/block/Blocks.java:2978-2980` gives the slime block restitution `1.0F`, read by the new Entity method through `Block.getBounceRestitution()`.
Movement meaning: a local player landing on slime used the direct full-speed LivingEntity rebound in 26.1.2; in 26.2 it enters the shared restitution calculation, whose gravity/drag procedure and minimum-impact/suppression/tag gates can change the resulting Y velocity or suppress the rebound.

## Bed witness

26.1.2, unobfuscated: `decompiled_minecraft/26.1.2/unobfuscated/net/minecraft/world/level/block/BedBlock.java`, `updateEntityMovementAfterFallOn` and `bounceUp`, lines 138-152: unless bounce is suppressed, a downward collision sets Y to `-movement.y * 0.66F * factor`; Player is a LivingEntity, so factor is 1.0.
26.2, unobfuscated: `decompiled_minecraft/26.2/unobfuscated/net/minecraft/world/level/block/Blocks.java:701-705` gives bed blocks restitution `0.75F`; the 26.2 Entity restitution method consumes this value instead of invoking the removed BedBlock movement callback.
Movement meaning: a local player landing on a bed changes from the direct `0.66F` LivingEntity rebound to the shared restitution calculation with gravity compensation, effective drag, and the same minimum-impact/suppression/tag gates.

Unchanged adjacent operation checked: slime `stepOn` still applies its low-vertical-speed horizontal scale in both versions (`SlimeBlock.java`, 26.1.2 lines 51-56 and 26.2 lines 25-30); this is separate from the collision restitution change.
