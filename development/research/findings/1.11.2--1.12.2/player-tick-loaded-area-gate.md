Difference: The shared `World.tickEntity(Entity, boolean)` operation requires a 32-block surrounding area for all entities in 1.11.2 when `requireLoaded` is true. In 1.12.2 it skips that area check for every `PlayerEntity`; `requireLoaded && entity.inChunk` still controls the entity tick. The source change is already present in exact 1.12 and 1.12.1, Ornithe Feather gen2 build 2, `World.java` lines 1412-1434. On `ServerWorld`, the area helper's chunk predicate delegates to the server chunk source's actual `isChunkLoaded`; this is a literal shared/server-side gate change. The regular entity loop separately excludes `ServerPlayerEntity`, so this observation alone does not establish a changed ordinary server-player tick.

Movement meaning: This does not establish a historical client-player movement difference. The actual client path in 1.11.2 is inherited `World.tickEntities` -> `tickEntity(entity)` -> `tickEntity(entity, true)` -> private `isAreaLoaded(..., true)` -> virtual `ClientWorld.isChunkLoadedAt(chunkX, chunkZ, true)`. The override returns `allowEmpty || !getChunkSource().getChunk(...).isEmpty()`, immediately true for this call. The helper's Y interval is fixed at 0..0 and passes its height gate. Therefore missing surrounding client chunks cannot suppress this tick. In 1.12.2 the player's area check is bypassed, with the same client result. Both local-player `tick` methods also call `World.isChunkLoaded(pos)` -> `isChunkLoaded(pos, true)` -> the same virtual override, so that current-chunk expression does not require a received/nonempty client chunk either. `entity.inChunk` is a separate retained condition; it does not make the missing-neighbor witness reachable.

The client call path uses concrete `ClientWorld` constructions in `ClientPlayNetworkHandler` (1.11.2 lines 276 and 901; 1.12.2 lines 289 and 910). Neither client source tree overrides `tickEntities`, either `tickEntity` overload, or either `isChunkLoaded` overload, and neither complete source tree declares a subclass of `ClientWorld`. The proposed witness with the current chunk present but a missing neighboring chunk is withdrawn.

Supporting older exact sources have the same outcome: 1.9.4 `ClientWorld.isChunkLoadedAt` lines 103-106 and 1.10.2 lines 104-107 use the same short-circuit override, while their `World.tickEntity` area calls pass true (lines 1397-1401 and 1407-1411). In 1.8.9, `World.tickEntity` lines 1330-1334 also passes true, inherited `World.isChunkLoadedAt` lines 226-228 uses `chunkSource.hasChunk && (allowEmpty || ...)`, and `ClientChunkCache.hasChunk` lines 30-33 always returns true. These are client gate checks, not evidence of parity for other movement operations.
