# Retracting moving piston uses separate base and head collision shapes

1.10.2, ornithe-feather, `feather-gen2-1.10.2+build.2-mergedv2.jar` and `feather-gen2-1.10.2+build.2.tiny`: `1.10.2/ornithe-feather/net/minecraft/block/MovingBlock.java`, `getCollisionShape`, lines 134–137; `net/minecraft/block/entity/MovingBlockEntity.java`, `getAmountExtended` and both `getShape` overloads, lines 76–89; `net/minecraft/block/Block.java`, `addCollisions`/`addCollision`, lines 342–355; `net/minecraft/block/state/StateDefinition.java`, collision dispatch, lines 364–370.

1.11, ornithe-feather, `feather-gen2-1.11+build.2-mergedv2.jar` and `feather-gen2-1.11+build.2.tiny`: `1.11/ornithe-feather/net/minecraft/block/MovingBlock.java`, `getCollisionShape`/`addCollisions`, lines 129–140; `net/minecraft/block/entity/MovingBlockEntity.java`, `getShape`/`getStateForShape`, lines 96–115, and `addCollisions`, lines 295–322; `net/minecraft/block/PistonHeadBlock.java`, shape constants and collision assembly, lines 25–93.

1.11.1 and 1.11.2, ornithe-feather, each exact release's `feather-gen2-<version>+build.2-mergedv2.jar` and `feather-gen2-<version>+build.2.tiny`: `<version>/ornithe-feather/net/minecraft/block/MovingBlock.java`, lines 129–140; `net/minecraft/block/entity/MovingBlockEntity.java`, `addCollisions`, lines 318–346; `net/minecraft/block/PistonHeadBlock.java`, lines 25–93. These two releases have byte-identical files for these three providers. The ordinary-query assembly already exists in 1.11; the 1.11.1 direction-specific piston-response suppression and added `forceShape` argument do not move this ordinary-query boundary.

Difference: In 1.10.2, `MovingBlock` inherits `Block.addCollisions`. Dynamic state dispatch asks `MovingBlock.getCollisionShape`, which returns the union enclosing the moved state's outline box translated at **current and last** progress. Translation is `(extending ? progress - 1 : 1 - progress) * facing`. This is an enclosing box union, not separate sampled boxes and not the moved block's multi-box collision provider.

For a normal or sticky retracting source, `movedState` is the unextended piston base with its facing. `PistonBaseBlock.doEvent`, type 1, creates the moving block entity with `extending=false, source=true`: 1.10.2 `net/minecraft/block/PistonBaseBlock.java`, lines 146–182; 1.11.2 same member, lines 150–186. The event's server-only power recheck precedes the shared type-1 branch; source state exists on the client. The queued type-1 event supplies only `direction.getId()` (1.10.2 line 120; 1.11/.1/.2 line 124), so its metadata has no extended bit. The default `EXTENDED=false` and metadata conversion are at 1.10.2 lines 40 and 348–349; the unextended base outline is the full cube (lines 48–66).

From exact 1.11, `MovingBlock.addCollisions` delegates to the moving entity instead of obtaining that union. For `!extending && source`, it first adds the **untranslated**, direction-specific extended base box by setting `PistonBaseBlock.EXTENDED=true` on the stored state. It then constructs a default piston-head state with the moving entity's facing and `SHORT = extending != (1.0F - progress < 0.25F)`, and adds the head plate and selected arm collision boxes translated at **current** progress only. It translates the query in the opposite direction before calling the state's collision provider, then translates only the newly appended boxes forward. For retraction the arm is short exactly when `progress > 0.75F`; at ordinary tick progress 0 and 0.5 it is long, and at 1 it is short. Plate constants, six long-arm constants, six short-arm constants, and the provider's direction dispatch are explicit in `PistonHeadBlock`, lines 25–93. `TYPE` is left at the default value by this collision assembly; sticky and default head types share these collision boxes.

The ordinary query has no active piston-response suppression: 1.11's thread local defaults false; 1.11.1/1.11.2 default null and suppress a matching piston direction only during a direct piston response. Base collision is added before that suppression. The separate `getShape`/`getCollisionShape` union still exists in 1.11 and later, and `getStateForShape` substitutes the head for a retracting source, but ordinary block collision assembly no longer calls it. In 1.11.1/1.11.2 world queries pass `forceShape=false`; `MovingBlock`'s override delegates regardless of that argument, and the moving entity asks the translated head provider with true.

Movement meaning: The local client's `LivingEntity.moveRelative` calls player movement with its velocity (1.10.2 lines 1332–1421; 1.11.2 lines 1388–1477). `LocalClientPlayerEntity.move` delegates to inherited movement (1.10.2 lines 812–815; 1.11.2 lines 824–827). `Entity.move` obtains `World.getCollisions` for the swept player box and clips motion against those boxes (1.10.2 lines 514–540; 1.11.2 lines 564–594). `World.getCollisions` visits loaded cells and invokes state collision dispatch (1.10.2 lines 903–937; 1.11.2 lines 960–1015). This path runs for the controlled client player; it is not evidence to replay server piston production or server movement.

A concrete static clipping witness uses an east-facing retracting source at (0,0,0), `progress=0.5F`, `lastProgress=0F`, with other relevant cells air, loaded chunks, no border substitution or entity obstacle, and ordinary movement outside a piston response. A nonsneaking airborne player's box has min=(2,0.1,0.2), with the ordinary player width `0.6F` and height `1.8F` (max approximately (2.6,1.9,0.8)), attempted motion=(-0.6,0,0), and `onGround=false`. The prior animation can leave that player there: its box only touches the outer source/head boundary at x=2, so it need not be intersected or pushed. In 1.10.2 the translated full cubes at x=[0.5,1.5] and [1,2] give the enclosing x=[0.5,2] obstacle. In 1.11/.1/.2 the fixed base has x=[0,0.75], translated head plate x=[1.25,1.5], and long arm x=[0.25,1.25] with y,z=[0.375,0.625]. `Box.intersectX` (1.10.2 lines 143–162; identical formula in 1.11.2) therefore clips old dx to 0 and new dx to -0.5. The source cell is visited because floor(swept minX)-1=0. There is no step candidate because the initial ground flag is false and dy is zero. This establishes a direct player displacement difference without relying on a predicted full trajectory or a runtime test.

Exact applicability: The swept moved-state union operation is present in the checked stable releases **1.9, 1.9.1, 1.9.2, 1.9.3, 1.9.4, 1.10, 1.10.1 and 1.10.2**; exact 1.11 introduces the separate ordinary collision assembly, retained through 1.11.2. Earlier checks use each release's ornithe-feather build.2 mappings: 1.9/.1/.2 `MovingBlockEntity.getShape` lines 79–88; 1.9.3/.4 same member at those lines; 1.10/.1 same member lines 80–89; their `MovingBlock.getCollisionShape` and absence of an `addCollisions` override were checked together with base creation and shape dependencies. **1.8.9 does not use this old operation**: its `MovingBlock.getCollisionShape` lines 118–130 and 171–208 trim one end of the stored state's collision box using last progress rather than translating and unioning current/last outline boxes. This finding does not authorize applying the 1.9–1.10.2 algorithm to 1.8.9 or uninspected earlier profiles.

The claim is bounded to normal/sticky retracting sources and direct client-player ordinary collision queries. Extending sources, nonsource moved blocks, direct piston response/suppression, stationary head arm changes, and modern-only moved states/features require their own applicability evidence. Their native state or event production must not be rewritten merely to obtain this historical query result.
