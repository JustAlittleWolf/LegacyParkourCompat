1.9.4, ornithe-feather: `1.9.4/ornithe-feather/net/minecraft/entity/Entity.java`, `public void updateVelocity(float sideways, float forwards, float scale)`, lines 947-963; `net/minecraft/util/math/MathHelper.java`, `sin(float)` / `cos(float)`, lines 15-21 and sine-table initialization, lines 422-425.

Difference: Both versions retain the same squared-input threshold (`1.0E-4F`), square-root and minimum-length gates, `scale / length` normalization, and sideways/forward scaling order. 1.8.9 computes each yaw angle as `yaw * (float) Math.PI / 180.0F`; 1.9.4 computes it as `yaw * (float) (Math.PI / 180.0)`. The latter moves division into the double constant before narrowing to float. Both then call the same 65,536-entry `MathHelper` sine table and apply the same X/Z additions.

Movement meaning: A concrete old-representable state demonstrates that the operation-order change can cross a sine-table index boundary. With `yaw = 0.0823974609375F`, `sideways = 0.0F`, `forwards = 0.98F`, `scale = 0.02F`, and zero initial X/Z velocity, binary32 evaluation gives angle `0.0014381071086972952F` in 1.8.9 and `0.0014381069922819734F` in 1.9.4. The `sin(float)` index expression selects entry 15 versus 14; the cosine index is 16399 in both. The airborne client path supplies this scale from the unchanged `speedInAir = 0.02F` field (1.8.9 `LivingEntity.java` line 87; 1.9.4 line 113). The normalized movement inputs are identical, while the X acceleration therefore reads a different sine-table entry. This is a source-derived arithmetic example only; it does not infer a later position trajectory.

The local-client input route copies keyboard floats in `LocalClientPlayerEntity.serverTickAi`, then inherited `LivingEntity.mobTick` multiplies sideways and forward speed by `0.98F` and calls `moveRelative` (1.8.9 lines 1424-1450; 1.9.4 lines 1684-1711). Its ordinary ground, water and lava branches pass the same inputs to `updateVelocity` in both releases. `KeyboardInput.tick` keeps the same key-to-float updates and sneak multiplication by `0.3` (1.8.9 lines 13-37; 1.9.4 lines 13-49). `LocalClientPlayerEntity.serverTickAi` copies those floats to the player fields (1.8.9 lines 470-475; 1.9.4 lines 586-591). 1.9.4 also has a fall-flying branch in `LivingEntity.moveRelative` before the ordinary travel branch (lines 1306-1354); it is a separate modern-feature path and does not change the ordinary yaw conversion described here.

The exact first stable 1.9 patch containing this angle expression is not established by the assigned 1.8.9/1.9.4 pair; only its presence by 1.9.4 is established. The intermediate-release boundary remains open.
