Difference: `getInputVector` retains its squared-length `< 1.0E-7` zero gate and `> 1.0` normalization gate, scale then yaw rotation, and float sine/cosine. The called normalization changes from a double local receiving `Mth.sqrt(x*x + y*y + z*z)` (which casts the square root to float first) to receiving `Math.sqrt(...)` directly. The divisor is compared with `1.0E-4` and each coordinate is divided by it in double on both sides. The first newer stable release is 1.17.
Movement meaning: an ordinary local player pressing forward and left, without crouching or using an item, supplies `(1.0F, 0.0F, 1.0F)` before the `0.98F` input damping. Each horizontal component then widens to `0.9800000190734863`, with squared magnitude `1.9208000747680671`, so normalization is reached. The old divisor is `1.3859293460845947`; the newer divisor is `1.3859293180996162`. At yaw zero, airborne without sprinting or flight, the `0.02F` movement scale produces horizontal acceleration components `0.014142135022068599` and `0.014142135307629587`, respectively. With zero initial horizontal velocity and unobstructed ordinary air, these accelerations are passed to `move(SELF, ...)` and produce different positions. From horizontal position `(0.5, 0.5)`, the old bounding-box translation and center recovery produce `(0.5141421350220686, 0.5141421350220686)`, while the newer position addition produces `(0.5141421353076295, 0.5141421353076295)`. This is a source-derived arithmetic witness; ground travel also calls the same normalization operation.
