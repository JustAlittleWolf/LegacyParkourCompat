# Jump boost addition precision

1.16.5, Mojmap: `net/minecraft/world/entity/LivingEntity.java`, `getJumpPower` and `jumpFromGround`, lines 1878–1895; `net/minecraft/world/entity/Entity.java`, `getBlockJumpFactor`, lines 611–615.
1.17, Mojmap: `net/minecraft/world/entity/LivingEntity.java`, `getJumpPower` and `jumpFromGround`, lines 1963–1980. The float addition is unchanged from 1.16.5.
1.17.1, Mojmap: `net/minecraft/world/entity/LivingEntity.java`, `getJumpPower`, `getJumpBoostPower` and `jumpFromGround`, lines 1967–1985; `net/minecraft/world/entity/Entity.java`, `getBlockJumpFactor`, lines 693–697.

Difference: In 1.16.5 and 1.17, `jumpFromGround` stores `getJumpPower()` in a `float`, adds `0.1F * (amplifier + 1)` to that float when Jump Boost is present, and writes the resulting float as the Y velocity. In 1.17.1, the effect contribution is extracted as `getJumpBoostPower()`, whose return type is `double`; `jumpFromGround` adds that double to the float base and writes the double result. `getJumpPower()` still returns `0.42F * getBlockJumpFactor()`. `Entity.getBlockJumpFactor()` still reads the current and movement-supporting block factors as floats and returns the current factor unless it equals 1.0F, in which case it returns the supporting factor. The local-player caller path is `LocalPlayer.serverAiStep` setting `jumping` from input (1.16.5 lines 612–615; 1.17 lines 618–621; 1.17.1 lines 616–619), then `LocalPlayer.aiStep` calling `super.aiStep` (1.16.5 lines 786–789; 1.17 lines 809–813; 1.17.1 lines 807–811). `LivingEntity.aiStep` reaches `jumpFromGround` when `jumping && isAffectedByFluids()`, the ground/fluid checks permit the ordinary jump branch, and `noJumpDelay == 0` (1.16.5 lines 2427–2441; 1.17 lines 2510–2524; 1.17.1 lines 2514–2528). The new helper also serves `AbstractHorse` in 1.17.1; that separate non-player consumer is outside this finding.

Movement meaning: With both block factors equal to 1.0F, Jump Boost amplifier 0, a grounded local player, no jump delay, and the ordinary non-fluid jump branch, the base is binary32 `0.41999998688697815` and the effect term is binary32 `0.10000000149011612`. The old path rounds their sum to binary32 `0.5199999809265137` before widening for the velocity write. The 1.17.1 path widens both float operands and sums in binary64, writing `0.5199999883770943`. Thus the first vertical velocity differs by `7.450580596923828e-9` for this finite reachable player input/state witness. The observed source boundary is after 1.17 and present in 1.17.1; no earlier patch within that interval was inspected.
