# Entity push square-root precision
1.16.5, Mojmap: `net/minecraft/world/entity/Entity.java`, `push(Entity)`, lines 1180–1208; `net/minecraft/util/Mth.java`, `sqrt(double)`, lines 37–39; `net/minecraft/world/entity/EntitySelector.java`, `pushableBy`, lines 28–54; `net/minecraft/world/entity/LivingEntity.java`, `pushEntities` and `doPush`, lines 2502–2550.
1.17.1, Mojmap: `net/minecraft/world/entity/Entity.java`, `push(Entity)`, lines 1278–1307; `net/minecraft/world/entity/EntitySelector.java`, `pushableBy`, lines 28–54; `net/minecraft/world/entity/LivingEntity.java`, `pushEntities` and `doPush`, lines 2614–2662. The same double-precision operation is present in the first stable 1.17 release (`Entity.java`, `push(Entity)`, lines 1276–1305).
Difference: With the same guards (entities are not passengers of the same vehicle, neither has `noPhysics`, `max(abs(dx), abs(dz)) >= 0.01F`, and the player receiver is not a vehicle), 1.16.5 assigns `Mth.sqrt(double)` to a double; the helper returns `(float)Math.sqrt(d)`, rounding the divisor to float before the following divisions and reciprocal. 1.17.1 assigns `Math.sqrt(double)` directly to a double. Both keep the normalization, reciprocal clamp, 0.05 scaling and gated velocity writes in that order. The patch boundary is between 1.16.5 and the first stable 1.17 release.
Movement meaning: On the logical client, `EntitySelector.pushableBy` admits a `Player` candidate only when it is the local player. When an awake nearby entity reaches that candidate, `LivingEntity.doPush` calls the player's `push(nonplayer)`. The player's `Entity.push` then writes the normalized horizontal delta to the player through its gated `this.push(-d, 0.0, -e)` call. That incoming player response is in scope even though a non-player entity triggers it; the non-player's own velocity write is separate. For some coordinate differences, the changed divisor precision changes the player's resulting delta.
