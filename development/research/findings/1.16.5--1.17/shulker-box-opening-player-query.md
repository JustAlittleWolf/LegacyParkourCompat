# Opening shulker box player query

Paths below are relative to `net/minecraft/` in each release's Mojmap sources.

**1.16.5.** In `world/level/block/entity/ShulkerBoxBlockEntity.java`, `triggerEvent` (163–174) sets OPENING on event 1 with count 1. `tick` and `updateAnimation` (53–75) save the previous float and add `0.1F`. Ordinary opening ticks call `moveCollidedEntities` after the animation update. On reaching `>= 1.0F`, the call instead occurs inside the update, before OPENED, the clamp to `1.0F` and the neighbor update. There is one query on that tick. The method reads the block at the position, checks for a shulker box and reads FACING (107–116).

`getBoundingBox`, `getTopBoundingBox` and `getProgress` (97–105, 271–273) start with the unit block bounds. On each axis they expand by `0.5F * getProgress(1.0F) * facingStep`, contract by the opposite direction's unit step, then translate to the block position. The float interpolation is `old + 1.0F * (current - old)` (`util/Mth.java`, 473–475). This selects the full protruding slab from the facing surface, across the unit width on the two perpendicular axes. From closed, the tenth increment reaches `1.0000001192092896` before the query.

**1.17.** In the same block entity, `triggerEvent` (133–144) selects OPENING on the same event. `tick` and `updateAnimation` (63–82) still save the previous float and add `0.1F`, but call `moveCollidedEntities` once inside OPENING. On the last tick the state becomes OPENED, progress is clamped and neighbors are updated before this call. With a shulker box as the supplied tick state, the method reads FACING and passes the two raw progress floats to `Shulker.getProgressDeltaAabb` (104–112). The separate half-progress block shape at 100–102 is not the entity query.

`world/entity/monster/Shulker.java`, `getProgressDeltaAabb` (248–254), takes the float maximum and minimum, widens each to double, expands the unit box by `facingStep * max` and contracts it by `-facingStep * (1.0 + min)` on each axis. The caller translates to the block position. Measured outward from the facing surface, the slab runs from the previous progress to the current progress. Its perpendicular spans remain the full block width.

**Local player.** Both queries pass a null excluded entity. The local player enters client entity storage on login (`client/multiplayer/ClientPacketListener.java`, 1.16.5 line 391 and 1.17 line 375). In `world/level/EntityGetter.java` the two-argument overload selects NO_SPECTATORS (1.16.5 lines 30–32, 1.17 lines 31–33). The loaded local player's current bounding box must strictly overlap on all three axes. See 1.16.5 `world/level/chunk/LevelChunk.java` 476–492 and `world/phys/AABB.java` 204–210, and 1.17 `world/level/entity/EntitySectionStorage.java` 111–117, `world/level/Level.java` 577–583 and `world/phys/AABB.java` 226–232. A non-spectator local player inherits the NORMAL piston reaction (`world/entity/Entity.java`, 1.16.5 lines 2579–2581, 1.17 lines 2709–2711), so admission reaches the shulker-box movement call.

For an east-facing box with clear space, place the player's nearest X face 0.95 blocks east of the block's east face, with Y and Z overlapping. During an uninterrupted opening from closed, 1.16.5 never selects that player. In 1.17 the tenth query reaches from about 0.90 to exactly 1.0 blocks beyond the east face and selects the player for the first time.
