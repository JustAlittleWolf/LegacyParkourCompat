# Autojump selects the first intersecting collision
1.12.2, Ornithe Feather: `net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java`, `autoJump`, lines 910–943; `net/minecraft/world/World.java`, `getCollisions`, lines 978–1002.
1.13.2, Ornithe Feather: `net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java`, `autoJump`, lines 935–965; `net/minecraft/world/WorldView.java`, `getBlockCollisions`, lines 123–150; `net/minecraft/util/math/BlockPos.java`, `iterateRegionMutable`, lines 212–238.
Difference: Autojump stops at the first box intersecting either forward side ray and uses that box’s top height to decide whether to set `ticksToNextAutojump`. The 1.12.2 world scan orders candidate blocks X-outer, then Z, then Y. The 1.13.2 region iterator advances X-innermost, then Y, then Z-outer; autojump flattens each returned voxel shape into bounding boxes and still stops at the first intersection. Thus a swept path intersecting obstacles at crossed X/Z positions can select a different obstacle height.
Movement meaning: With a taller obstacle at smaller X/later Z and a one-block obstacle at larger X/earlier Z, both intersecting the autojump rays, the old traversal can select the taller obstacle while the new traversal selects the one-block obstacle. Since the selected height feeds the `0.5F` and `1.2F` thresholds, the client can set `ticksToNextAutojump` in one version and leave it unchanged in the other.
