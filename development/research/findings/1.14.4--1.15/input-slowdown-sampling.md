# Local input slowdown sampling

1.14.4, Mojmap: `1.14.4/mojmap/net/minecraft/client/player/LocalPlayer.java`, `isTryingToSneak`, lines 588–590, `isVisuallySneaking`, lines 593–597, and `aiStep`, lines 625–634; `1.14.4/mojmap/net/minecraft/client/player/KeyboardInput.java`, `tick`, lines 13–26; `1.14.4/mojmap/net/minecraft/world/entity/Entity.java`, `canEnterPose`, lines 1641–1643, and `isVisuallyCrawling`, lines 1836–1842.

1.15, Mojmap: `1.15/mojmap/net/minecraft/client/player/LocalPlayer.java`, `isShiftKeyDown`, lines 591–593, `isCrouching`, lines 596–600, `isMovingSlowly`, lines 602–604, and `aiStep`, lines 632–640; `1.15/mojmap/net/minecraft/client/player/KeyboardInput.java`, `tick`, lines 13–26; `1.15/mojmap/net/minecraft/world/entity/Entity.java`, `canEnterPose`, lines 1605–1607, and `isVisuallyCrawling`, lines 1819–1825. Exact 1.15.1 and 1.15.2 retain these members and the same input sampling operation.

Difference: In 1.14.4 the local player evaluates its crouch-or-crawl predicate before polling input and passes that value plus spectator state to the keyboard. After polling current sneak input, keyboard slowdown requires no spectator and either current sneak input or the supplied pre-poll predicate. In 1.15 the keyboard instead slows only for the supplied pre-poll `isMovingSlowly` value: it neither combines the newly sampled shift input nor applies a separate spectator gate. `isMovingSlowly` is crouching or the unchanged crawl predicate, which requires swimming pose and no body water. The crouching branch requires no ability flight, no swimming state and collision-free crouch fit, followed by previous input shift intent or standing-fit failure. 1.15 additionally excludes sleeping from that standing-fit-failure branch, while previous shift intent remains an alternative. Neither crouching branch has a passenger guard. The keyboard scalar remains `(float)(axis * 0.3)` on both axes; item slowdown follows input polling.

Movement meaning: With an ordinary non-flying, non-swimming player in open space, forward held, no item use and previous sneak input false, pressing sneak during this tick produces `0.3F` forward input in 1.14.4 but `1.0F` in 1.15. With sneak still held, the next tick's previous input makes the newer predicate true and produces `0.3F`. On releasing sneak after it was held, the pre-poll predicate can keep input slowed for that release tick in both versions. Crouch-fit failure, forced crouching and dry swimming-pose crawling can independently determine the supplied predicate; actual pose production and collision shapes remain separate inputs. This changes an existing player input response, rather than introducing a new movement feature.
