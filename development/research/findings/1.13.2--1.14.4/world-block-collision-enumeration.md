Difference: 1.13.2 and 1.14 (`ViewableWorld.getCollisionShapes`) set each lower bound to `floor(min) - 1` and upper bound to `ceil(max) + 1`, then traverse through one less than the upper bound. They omit positions lying on two or more of those six outer faces. The 1.13.2 query checks loaded chunks, aggregates full-block shapes, and handles the border through a separate flag. The 1.14 query uses collision-status chunks and an entity collision context; it aggregates full-cube shapes and returns other intersecting shapes individually. Beginning in 1.14.1 and continuing through 1.14.4, the world-query bounds are `floor(min - 1.0E-7) - 1` and `floor(max + 1.0E-7) + 1`, and the block iterator visits both endpoints. Relative to the 1.14 query range, the candidate coordinate range extends one cell below an exactly integral minimum and one cell above an exactly integral maximum, independently on each axis; non-integral bounds have the same range. The later boundary filter still omits cells on all three outer axes. The 1.14.1–1.14.4 world query emits intersecting shapes individually. Thus this world-query formula changes at the 1.14→1.14.1 boundary; 1.14.3 separates block and entity collision streams, which 1.14.4 exposes as `getBlockCollisions` and `getEntityCollisions`.

The 1.14 entity movement clipping scan is a separate enumeration: its `VoxelShapes` helper already uses the epsilon-expanded bounds in 1.14 and traverses a direction-dependent interval on the movement axis, and continues doing so through the later inspected releases. In 1.14.1–1.14.2, entity movement reaches that helper through `VoxelShapes.method_17945` / `method_17944`; in 1.14.3–1.14.4, the world block-query method also feeds multi-axis clipping while the helper handles tangential clipping.

The 1.14 world-query enumerator also probes the queried entity's own bounding box (`entity.getBoundingBox()` in 1.14–1.14.3; `entity.getShape()` in 1.14.4), separately from the candidate AABB supplied for block enumeration. It tests the entity box contracted and expanded by `1.0E-7` against the world-border collision shape, which is the exterior of the floored/ceiled border interior (`WorldBorder.Area.method_17906` in 1.14–1.14.3; `WorldBorder.Extent.m_09880556` in 1.14.4); it emits that exterior shape when the contracted entity box does not overlap it but the expanded box does.

Movement meaning: In 1.13.2 and 1.14, local-player auto-jump scans the old world query; in 1.14.1 and later it scans the changed query. The 1.14 movement clipping path already uses the epsilon-expanded per-axis helper, so the world-query boundary alone does not establish a change to that path at 1.14.1. From 1.14.3, the changed world query also feeds multi-axis clipping. An additional enumerated cell can affect a result only when its block shape intersects the candidate AABB and survives the boundary, chunk, block-state, and collision-context filters. No trajectory difference follows from the enumeration formulas alone.
