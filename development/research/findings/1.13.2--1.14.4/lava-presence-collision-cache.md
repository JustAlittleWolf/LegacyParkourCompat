# Lava presence uses the last entity collision pass

1.13.2, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `isInLava`, lines 1053–1055; `net/minecraft/entity/living/LivingEntity.java`, `moveRelative`, lines 1478–1488.
1.14.4, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `move`, lines 540–543, `m_43101496`/`isInLava`, lines 1054–1059; `net/minecraft/block/LiquidBlock.java`, `onEntityCollision`, lines 167–172; `net/minecraft/entity/living/LivingEntity.java`, `moveRelative`, lines 1786–1796.
Difference: 1.13.2 computes lava presence on each query from the entity shape contracted by `(0.1, 0.4, 0.1)` and asks whether that box contains a lava-material block. In 1.14.4, `isInLava` returns a cached flag. `Entity.move` clears it immediately before `checkBlockCollisions`; a colliding `LiquidBlock` sets it when its fluid is lava. Thus detection is tied to the full entity-box collision scan and the last such scan, rather than the contracted box at query time.
Movement meaning: `LivingEntity.moveRelative` consults `isInLava` to select its land/fall-flying movement branch, and `mobTick` consults it for held jump input. A player whose box only grazes a lava block outside the old contracted core can be treated as in lava in 1.14.4 and dry in 1.13.2. Position or shape writes between collision scans can also leave the 1.14.4 flag stale until the next scan.
