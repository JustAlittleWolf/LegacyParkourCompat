# World-border collision hysteresis after contraction

1.13.2, Ornithe Feather Gen2 build 2: `WorldView.getCollisions` updates the entity's `outsideWorldBorder` state from a center-point test with one-block hysteresis (`world/WorldView.java:170–199`); that result controls whether `getBlockCollisions` treats outside-border block positions as full cubes (`WorldView.java:112–151`). `LocalClientPlayerEntity.move` delegates to `super.move` (`client/entity/living/player/LocalClientPlayerEntity.java:871–876`), reaching this query through `Entity.move` (`entity/Entity.java:473–590`).

1.14.4, Ornithe Feather Gen2 build 2: `Entity.m_72373519` adds the world border's exterior voxel shape when the contracted current entity box does not already overlap that exterior shape (`entity/Entity.java:656–665`). The static border shape is the complement of its floored/ceiled interior rectangle (`world/border/WorldBorder.java:46–48, 299–311, 406–417`); `WorldView.getBlockCollisions` enumerates block shapes without the older entity-state border mode (`world/WorldView.java:133–156`). `LocalClientPlayerEntity.move` delegates to `super.move` (`client/entity/living/player/LocalClientPlayerEntity.java:846–850`), reaching this mover through `Entity.move` (`entity/Entity.java:444–465`).

Difference: after a client `SET_SIZE` world-border update (1.13.2 `client/network/handler/ClientPlayNetworkHandler.java:1450–1452`; 1.14.4 `client/network/handler/ClientPlayNetworkHandler.java:1510–1512`; both apply `network/packet/s2c/play/WorldBorderS2CPacket.java:107–132`), a player at X `11.2` can be left outside a newly contracted border centered at `(0,0)` with size `20` and maximum X `10`. In 1.13.2, an initially false `outsideWorldBorder` flag becomes true on the first inward move because the player center exceeds `maxX + 1`; border block obstacles are then disabled. After inward movement to X `9.5`, the flag remains true because that center is still outside the shrunken `maxX - 1` threshold of `9`. In 1.14.4, a standing player has dimensions `0.6 x 1.8` (1.13.2 `entity/living/player/PlayerEntity.java:333–359`; 1.14.4 `entity/living/player/PlayerEntity.java:109–111, 1964–1965`), so at X `9.5` its box spans `[9.2,9.8]` and is wholly inside the border.

Movement meaning: for otherwise empty terrain and a positive X request of `0.4`, 1.13.2 has no border obstacle and allows the full move, taking the player's box across the border; 1.14.4 includes the exterior shape and clips the move at X `10`, advancing the center only `0.2`. This finding applies only after the stated contraction and state sequence. It does not claim that ordinary movement crosses an unchanged border.

## Inspected release boundary

In Minecraft 1.14.0 (Ornithe Feather Gen2 build.2), ordinary entity movement routes through the border collision check in `Entity` and conditionally includes the world-border exterior voxel shape according to whether it overlaps the current entity box contracted by `1.0E-7`. `WorldBorder` constructs that exterior from the unbounded shape minus the floored/ceiled interior (`Entity.java:452–454,645–652`; `WorldBorder.java:299–310,403–417`).

The same conditional inclusion persists in the inspected patch releases: 1.14.1 (Yarn `1.14.1+build.10`; `Entity.java:451–452,644–651`; `WorldBorder.java:49–51,404–420`), 1.14.2 (Yarn `1.14.2+build.7`; `Entity.java:453–454,646–652`; same `WorldBorder` members), and 1.14.3 (Yarn `1.14.3+build.13`; `Entity.java:460–461,653–660`; same `WorldBorder` members). No reversal appears in those inspected patches.

The earliest inspected stable release with the replacement behavior is 1.14.0, and the behavior persists through the inspected 1.14.1–1.14.3 sources. The 1.14.0 evidence uses Feather mappings; the patch-release evidence uses Yarn mappings. This bounded boundary supplement does not extend the accepted contraction-only witness beyond its stated endpoints, claim behavior outside the inspected releases, or close implementation/runtime status.
