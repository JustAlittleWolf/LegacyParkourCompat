# Eye submersion depends on neighboring fluid and chunk availability

1.13.2, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `isSubmergedIn`, lines 1042–1051, and water-state refresh, lines 947–980; `net/minecraft/fluid/FlowingFluid.java`, `getHeight`, lines 447–450.
1.14.4, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `m_69330161`, lines 1035–1052, and water-state refresh, lines 942–975; `net/minecraft/fluid/FlowingFluid.java`, `getHeight`, lines 442–454.
Difference: Both versions reject boat passengers and sample fluid at `y + getEyeHeight()`, then compare that height against the sampled block's fluid height plus `0.11111111F`. In 1.13.2, flowing-fluid height is `state.getLevel() / 9.0F`. In 1.14.4, the world-aware height is `1.0F` when the block above contains the same fluid, otherwise it uses the same level-derived value. The 1.14.4 helper also has a `checkLoaded` branch; the entity and player tick refreshes pass `true`, returning false when the eye block's chunk is unloaded. The public `isSubmergedIn` route passes `false`.
Movement meaning: With the eye near the top of a non-source flowing-fluid block that has the same fluid above, the 1.14.4 height can make the player submerged where 1.13.2 does not. The base tick feeds this predicate into `updateSwimming`, so sprinting can enter swimming in the changed case. During an unloaded eye-chunk tick, the cached state is forced false in 1.14.4; the unguarded 1.13.2 path reads the world fluid state.
