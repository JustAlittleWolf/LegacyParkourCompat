# Eye submersion reads contextual fluid height

1.13.2, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `isSubmergedIn`, lines 1042–1051, and water-state refresh, lines 947–980; `net/minecraft/fluid/FlowingFluid.java`, `getHeight`, lines 447–450.
1.14.4, Ornithe Feather Gen2 build 2: `net/minecraft/entity/Entity.java`, `m_69330161`, lines 1035–1052, and water-state refresh, lines 942–975; `net/minecraft/fluid/FlowingFluid.java`, `getHeight`, lines 442–454.
1.14, Yarn: `net/minecraft/entity/Entity.java`, `isInFluid`, lines 986–998; `net/minecraft/fluid/BaseFluid.java`, `getHeight`, lines 430–436. The contextual rule is present in this first stable 1.14 release and persists through 1.14.4. Yarn 1.14.1–1.14.2 use `isInFluid`; 1.14.3 uses `isSubmergedIn` for the helper.

Difference: Both sides reject boat passengers and sample fluid at `y + getEyeHeight()`, then compare that double eye height against the sampled block's fluid height plus `0.11111111F`, with the addition performed in float. In 1.13.2, flowing-fluid height is `state.getLevel() / 9.0F`. In 1.14–1.14.4, the world-aware height is `1.0F` when the block above contains the same fluid, otherwise it uses the same level-derived value. The helper also has a `checkLoaded` branch and the tick refreshes pass `true`, but the client world's virtual `isChunkLoaded(int,int)` override always returns true (1.14 Yarn `ClientWorld.java:212–214`; 1.14.4 Feather `ClientWorld.java:222–224`). Thus this branch does not establish a client chunk-residency difference.

Movement meaning: With the eye near the top of a non-source flowing-fluid block that has the same fluid above, contextual height can make the player submerged where the old state-only height does not. The tick feeds the eye-fluid state into `updateSwimming`, so sprinting can enter swimming under the changed condition. An absent adjacent chunk does not reject the point query through this inherited client-world check.
