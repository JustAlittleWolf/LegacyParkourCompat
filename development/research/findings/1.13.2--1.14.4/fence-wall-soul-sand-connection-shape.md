# Fence and wall connection shapes beside Soul Sand

1.13.2, Ornithe Feather: `net/minecraft/block/Block.java`, `getFaceShape` (383-385) defaults to `FaceShape.SOLID`; `isExceptionForPlacement` / `isExceptionForAttachment` (241-257) do not exclude Soul Sand. `net/minecraft/block/SoulSandBlock.java`, `SHAPE` and `getCollisionShape` (14, 21-23), returns a 16×14×16 collision box. `net/minecraft/block/FenceBlock.java`, constructor (22-26) passes `(2, 2, 16, 16, 24)` to `PaneBlock`; `shouldConnectTo` (46-61) accepts a non-exempt `SOLID` neighbor face; `getPlacementState` and `updateShape` (76-108) set the corresponding four direction properties from adjacent faces at placement and horizontal neighbor recomputation. `net/minecraft/block/PaneBlock.java`, constructor / `makeShapes` / `getCollisionShape` / state index (32-35, 38-84, 90-108), builds the collision array from direction properties. `net/minecraft/block/WallBlock.java`, collision arrays / selector (22-39), connection predicate (51-66), and placement/update (68-118), uses the same `SOLID`-face test and adds its post according to `UP`.

1.14.4, Mojmap: `net/minecraft/world/level/block/Block.java`, `isFaceSturdy` / `isFaceFull` (403-410), derives sturdiness from a full face of the collision shape. `net/minecraft/world/level/block/SoulsandBlock.java`, `SHAPE` / `getCollisionShape` (15-24), still returns a 16×14×16 box. `net/minecraft/world/level/block/FenceBlock.java`, constructor (25-32) passes `(2, 2, 16, 16, 24)` to `CrossCollisionBlock`; `connectsTo` (45-50), `getStateForPlacement` (63-81), and `updateShape` (83-97) use the sturdy-face predicate when deriving direction bits during placement and horizontal neighbor recomputation. Its inherited `CrossCollisionBlock.makeShapes` / `getCollisionShape` / direction index (35-76, 89-118) builds and selects the collision array from those properties. `net/minecraft/world/level/block/WallBlock.java`, collision arrays / selector (25-53), connection predicate (60-64), and placement/update (67-123), uses the same sturdy-face gate; `UP` still selects the post shape. The connection exception lists are `Block.java#isExceptionForConnection` (259-266); neither lists Soul Sand.

Difference: In 1.13.2, Soul Sand inherits the block-level `SOLID` face label despite its 14/16-high collision box. Fence and wall connection predicates therefore set the adjacent direction bit beside Soul Sand. In 1.14.4, `isFaceSturdy` tests the actual collision face; a horizontal face of that 14/16-high box is not full, so the direction bit stays clear. The placement and horizontal-neighbor recomputation callers write the bit that the collision-shape array reads; the index mapping is explicit in `CrossCollisionBlock.java:98-118`. For either block, the 1.13.2 selected collision shape includes the arm on that side (the fence's constructor supplies height 24; the wall's collision arrays use height 24); the 1.14.4 endpoint omits that arm. This establishes a local collision-shape difference for the default built-in Soul Sand/fence or Soul Sand/wall arrangement, not a later trajectory.

Built-in tag membership boundary: 1.13.2 `net/minecraft/tag/BlockTags.java` has no `FENCES` or `WALLS` constants, and the pinned 1.13.2 jar contains no corresponding `fences.json` or `walls.json` entries. In 1.14.4, `net/minecraft/tags/BlockTags.java:20,36,43` binds `WOODEN_FENCES`, `WALLS`, and `FENCES`; `net/minecraft/data/tags/BlockTagsProvider.java:69-70,270-286,363` defines their built-in memberships. Pinned 1.14.4 jar entries: `data/minecraft/tags/blocks/walls.json`, SHA-256 `f20174f51f66d27681fd9d469a77c86cae82012c0d9125e7d246c426b772391c`; `fences.json`, `8c4ebabbf6d088340c70c29091eadfd94d11cd551b193af52ea06cc073bc7483`; and `wooden_fences.json`, `6c7f827ceb45ad6b6b7df14e8871908b2a17f904ec3c03cb3551ef48acdf188f`. The walls list enumerates wall blocks, while fences references wooden fences plus nether-brick fence. These source defaults and pinned built-in datapack memberships do not include Soul Sand in either tag. Runtime/custom datapack changes to tag membership are outside this witness and could affect tag-based connection branches; no universal claim is made for such modified data.

Boundaries: This is limited to placement and horizontal neighbor recomputation of fence/wall direction properties, resulting collision-shape selection, and the pinned built-in datapack membership described above. It is a source-confirmed adjacent-state witness, not an inventory of every non-full face that received the old default `SOLID` label. Serialized/current neighbor-connection bits and the movement-loop collision consumer were not audited here; no tick writers were inspected.
