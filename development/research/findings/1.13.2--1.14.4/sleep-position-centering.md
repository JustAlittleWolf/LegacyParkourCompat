# Successful sleep centers the player from 1.14

1.13.2, Ornithe Feather Gen2 build 2: `net/minecraft/entity/living/player/PlayerEntity.java`, `trySleep`, lines 1228–1288; the loaded-bed branch and position writes are lines 1269–1278.
1.14, Ornithe Feather Gen2 build 2: `PlayerEntity.trySleep` lines 1192–1243 calls `LivingEntity.startSleeping` at line 1230; `net/minecraft/entity/living/LivingEntity.java`, `startSleeping`, lines 2710–2730, sets position at line 2728.
1.14.1–1.14.3, Yarn builds 10/7/13 respectively: `net/minecraft/entity/player/PlayerEntity.java`, `trySleep` lines 1191–1244, calls `sleep`; `net/minecraft/entity/LivingEntity.java`, `sleep` and `setPositionInBed`, respectively lines 2692–2711, 2698–2717, and 2706–2725. Each helper sets x/z to block coordinates plus `0.5` without a chunk-loaded branch.
1.14.4, Ornithe Feather Gen2 build 2: `PlayerEntity.trySleep` lines 1211–1262 calls `LivingEntity.startSleeping`; `net/minecraft/entity/living/LivingEntity.java`, `startSleeping`, lines 2717–2737, sets position at line 2735.

Difference: On the successful sleep response, 1.13.2 sets size to `0.2F × 0.2F`; with the bed chunk loaded it reads the bed facing and computes x/z with float offsets `0.5F + facingOffset × 0.4F`, then adds those float values to the integer bed coordinates. Without the chunk loaded it uses centered x/z. From 1.14, the sleep helper always sets x/z to bed coordinates plus the double literal `0.5`; there is no loaded-chunk or facing offset branch. Both paths use the same `y + 0.6875F` sleep position. The 1.14 helper also enters sleeping pose and zeros velocity. This finding covers the direct player response after a successful sleep call, not bed-entry eligibility.

Movement meaning: For a loaded bed, 1.13.2 positions the player `0.4` block toward the facing direction (subject to its float arithmetic); 1.14 centers the player. For an unloaded bed, both versions center x/z.

Applicability evidence: Representative earlier exact sources show the same loaded/unloaded split: 1.8.9 `PlayerEntity.trySleep` lines 1109–1136 and 1.9.4 lines 1197–1224 read bed facing inside `isChunkLoaded`, use switch-selected `0.1F`/`0.9F` positions, and center in the else branch; 1.10.2 lines 1214–1243 follows the same pattern. In 1.11.2 lines 1229–1241, 1.12.2 lines 1223–1237, and 1.13.2 lines 1269–1283, the loaded branch expresses the same facing offset as `0.5F + direction.getOffsetX/Z() * 0.4F`, while the unloaded branch remains centered. These versions fetch facing before the chunk-loaded branch, but use it for position only in the loaded branch. The reviewed 1.14, 1.14.1, 1.14.2, 1.14.3, and 1.14.4 sleep helpers all use unconditional centered x/z. Their `trySleep` methods still read facing for bed checks, but the successful position response does not use facing or chunk-loaded state. No changed dependency was found in the successful direct position response.
