Difference: 1.13.2 scales horizontal input by `0.3` when the newly sampled sneak key is down. In 1.14.4, the local tick computes a visual-sneaking value before polling input and passes it into `KeyboardInput.tick`; for nonspectators, input is scaled when either the newly sampled sneak key or the prior visual-sneaking state is true. For ordinary non-swimming, non-flying crouching, that prior value is true when sneaking fits and either shift was already held or standing does not fit. The local player polls input inside its superclass tick, and the player updates pose after that superclass tick, so input scaling uses the pre-poll visual state while pose selection and dimension changes use the newly sampled key. The 1.14 Feather call order and input expression have the same shape. The separate `isVisuallyCrawling()` input route remains outside this ordinary-crouch comparison.

The prior visual-sneaking gate performs entity-aware pose-fit queries: `canEnterPose` passes the player and pose-specific bounding box to `noCollision`. The 1.13.2 physical resize instead builds a requested box from the current box's minimum corner and passes `null` to `hasNoCollisions`; the world collision provider appends entity collisions only for a non-null entity. Thus the old resize query checks block collisions without the player's collision context or entity-collision query, while the newer pre-poll movement gate checks pose fit through the player-aware provider.

Movement meaning: Pressing crouch scales input in both versions. On release with enough room to stand, 1.13.2 immediately restores full input, while 1.14.4 keeps crouch-scaled input for that release tick. With headroom of at least 1.65 but less than 1.8 blocks, 1.14.4 keeps scaling after release while its standing-fit test keeps visual crouch active; 1.13.2 restores full input immediately even if the failed standing resize leaves its 1.65-high box in place. The pose-selection timing and collision-provider difference are inputs to this slowdown operation; the separate crouch-height change remains recorded in `sneaking-pose-height.md`.
