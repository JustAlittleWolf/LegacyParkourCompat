# The 1.17.1 world-border candidate can suppress auto-jump

1.17.1, mojmap: `1.17.1/mojmap/net/minecraft/client/player/LocalPlayer.java`, `move` and `updateAutoJump`, lines 893–1002; `aiStep`, lines 671–676. After `super.move`, `updateAutoJump` queries `getCollisions`, flattens each shape with `toAabbs`, and scans the two forward edge segments. A detected rise strictly above 0.5 and no higher than the jump limit sets `autoJumpTime = 1`; the next `aiStep` consumes that timer by setting `input.jumping`.
1.17.1, mojmap: `1.17.1/mojmap/net/minecraft/world/level/CollisionSpliterator.java`, `tryAdvance` and `worldBorderCheck`, lines 57–58 and 103–132; `1.17.1/mojmap/net/minecraft/world/level/border/WorldBorder.java`, moving extent `getCollisionShape`, lines 332–346. The border check runs before block collision enumeration and can emit the border's `INFINITY`-minus-interior shape when the player's box is not fully within the border, is not wholly outside it, and is close to it. The shape extends vertically without bound.
1.18, mojmap: `1.18/mojmap/net/minecraft/client/player/LocalPlayer.java`, `updateAutoJump`, lines 902–998; `1.18/mojmap/net/minecraft/world/level/CollisionGetter.java`, `getCollisions` and `getBlockCollisions`, lines 67–80. The auto-jump caller and timer outcome remain, but `getCollisions` now concatenates entity and block collisions only. Border collision is a separate `noCollision` check (`borderCollision`, lines 51–62 and 77–80), so this query no longer yields the border shape. The same relevant `LocalPlayer`, `CollisionGetter` and `WorldBorder` source hashes occur in 1.18.1; 1.18.2 retains the same collision-query behavior and border shape, with the auto-jump call at `LocalPlayer.updateAutoJump`, lines 900–996. Thus 1.18 is the first changed stable release in the inspected interval.

Difference: A reachable witness uses a grounded, moving player with auto-jump enabled, `autoJumpTime <= 0`, and no passenger/ground-surface exception. The player's box touches an integer border limit, and a one-block step clips movement in the same tick; diagonal input toward both the border and step leaves a near-zero horizontal delta, so `updateAutoJump` uses its input-vector fallback. The predicted forward edge then extends beyond the touched border face. The 1.17.1 spliterator emits the border shape before block candidates; the intersecting border AABB has infinite `maxY`, and its center's one-block-up lookup can be empty (choose empty queried blocks, including at the shape-center lookup). The infinite candidate height fails the `w <= q` test, so the step is never visited and `autoJumpTime` stays zero. In 1.18+, the border shape is absent from this query, so the otherwise identical one-block step candidate sets the timer when its rise is in `(0.5, 1.2]` (increased by jump effect as in the unchanged method).

Movement meaning: This changes `autoJumpTime` and the next tick's `input.jumping` for a reachable player walking along a border while approaching a one-block step. This is a player-state consequence, not only a difference in the returned candidate set. The boundary is established only as 1.17.1 versus 1.18; intermediate 1.17.x patches were not inspected.
