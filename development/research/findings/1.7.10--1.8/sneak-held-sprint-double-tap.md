# Sneak-held input suppresses one sprint double-tap window

1.7.10, Ornithe Feather: `net/minecraft/client/entity/living/player/InputClientPlayerEntity.java`, `mobTick`, lines 94–96 and 141–184; `net/minecraft/client/entity/living/player/KeyboardInput.java`, `tick`, lines 13–37.
1.8, Ornithe Feather: `net/minecraft/client/entity/living/player/LocalClientPlayerEntity.java`, `mobTick`, lines 504–505 and 543–585; `net/minecraft/client/entity/living/player/KeyboardInput.java`, `tick`, lines 13–37.
Difference: Both versions decrement the sprint double-tap timer, save the previous forward-input threshold result, sample input, and start the grounded sprint window when prior forward input is below `0.8F` and current forward input is at least `0.8F`, subject to the same eligibility checks. 1.8 additionally requires the saved prior `input.sneaking` value to be false in this grounded double-tap branch. The keyboard input sampler is otherwise behaviorally identical: sneak scales forward input by `0.3F` in both.
Movement meaning: A grounded player holds forward+sneak and then releases sneak while continuing forward. The prior forward input is below `0.8F`, while the newly sampled forward input is at least `0.8F`. 1.7.10 arms the 7-tick window; 1.8 does not because prior sneak is still true. If the player releases forward and presses it again before the 1.7.10 window expires, 1.7.10 starts sprinting on that rising edge while 1.8 only starts its window. The sprint state is set before that tick's travel, so movement-speed acceleration differs in that tick; later position divergence is a predicted trajectory effect.
