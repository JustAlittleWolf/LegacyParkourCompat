# Server-confirmed sleep response places the player box lower
1.7.10, Ornithe Feather: `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `trySleep`, lines 444–453, sends its position correction and then a `PlayerSleepS2CPacket` when the server-side result is `OK`. The preceding correction reaches `ClientPlayNetworkHandler.handlePlayerMove`, lines 480–499, and clears `eyeHeightSneakOffset` before sleep placement. `handlePlayerSleep`, lines 620–621, dispatches the packet's player to `PlayerEntity.trySleep(x, y, z)`. `net/minecraft/entity/living/player/PlayerEntity.java`, `trySleep`, lines 1014–1073, sets size to `0.2F × 0.2F`, sets `eyeHeight = 0.2F`, then positions the player at bed Y + `0.9375F` (lines 1066–1068). `net/minecraft/entity/Entity.java`, `setPosition`, lines 215–224, sets the box minY to requested Y − eyeHeight + eyeHeightSneakOffset.
1.8, Ornithe Feather: `net/minecraft/server/entity/living/player/ServerPlayerEntity.java`, `trySleep`, lines 495–504, sends a `PlayerSleepS2CPacket` when the server-side result is `OK`. `net/minecraft/client/network/handler/ClientPlayNetworkHandler.java`, `handlePlayerSleep`, lines 684–686, dispatches the packet's player to `PlayerEntity.trySleep(BlockPos)`. `net/minecraft/entity/living/player/PlayerEntity.java`, `trySleep`, lines 1071–1134, sets the same size and positions the player at bed Y + `0.6875F` (lines 1125–1127), then marks the player sleeping. `net/minecraft/entity/Entity.java`, `setPosition`, lines 225–233, sets box minY directly to requested Y. `PlayerEntity.getEyeHeight`, lines 1635–1645, returns `0.2F` while sleeping.
Difference: For a successful client-side response with the same decoded bed position in the 1.7.10 packet Y range 0–127 and a loaded in-border chunk, 1.7.10 sets eye height to `0.2F` before positioning at +`0.9375F`; 1.8 positions directly at +`0.6875F` and uses a sleeping eye height of `0.2F`. Both use the same facing-based horizontal placement, resize to `0.2F × 0.2F`, mark sleeping, and zero velocity in this bounded case. The old server sends a position correction before the sleep packet; its client handler clears `eyeHeightSneakOffset` before the sleep response. The old box minY is therefore bedY + `0.9375 − double(0.2F)` (= bedY + `0.73749999701976776`), while the new box minY is bedY + `0.6875`; the newer box is lower by `0.04999999701976776`. The old packet's signed-byte Y wrap for bed heights 128–255 is a separate finding.
Movement meaning: For matching, decoded low-bed coordinates, a player receiving the server's successful sleep-state response gets a different collision-box vertical placement in the client world. This is a direct player movement response; server-side bed-entry eligibility is not part of the finding. The response bypasses sleep eligibility on the respective client world (`!world.isMultiplayer` in 1.7.10, `!world.isClient` in 1.8).
