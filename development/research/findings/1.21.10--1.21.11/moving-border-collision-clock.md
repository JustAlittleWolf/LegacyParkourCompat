Difference: In 1.21.10 the moving extent stores `lerpBegin = Util.getMillis()` and computes each size read as `(Util.getMillis() - lerpBegin) / lerpDuration`. Collision bounds therefore change with elapsed real milliseconds, including between world updates. In 1.21.11 the incoming duration initializes a remaining-tick counter; the extent caches `size` and `previousSize`, decrements the counter once per border update, saves the previous size, and calculates the next size from elapsed counter steps. Collision bounds pass partial tick `0.0F` and thus use `previousSize` while the moving extent survives; completion replaces it with a static target extent. Both versions round the collision's inner bounds with floor on minima and ceil on maxima. The newer client calls the border update only when `tickRateManager().runsNormally()`; the older client calls it before this gate. Client handlers supply the newer constructor with the client world's game time; the movement-facing size calculation itself uses the remaining counter. No server-side production change is required for this difference in how the client advances and reads received vanilla border state.

Movement meaning: An ordinary player approaching a moving border can encounter a different rounded collision boundary, particularly when real elapsed time and client tick progression differ or normal ticking is stopped. Both releases reach `Entity.collectColliders` from `Entity.move`/`collide`, add the border shape when `isInsideCloseToBorder` succeeds, and clip displacement with the normal axis collision solver. Different border planes can therefore change displacement, position, horizontal collision flags and the cancellation of horizontal velocity. The concrete precondition is a surviving moving extent whose older elapsed-time size and newer previous-tick size put the rounded plane at different coordinates, with the player inside the near-border gate and attempting to cross one of those planes. `Minecraft.tick` invokes `level.tickEntities()` before `level.tick(...)` in both releases (1.21.10 lines 1777–1807; 1.21.11 lines 1806–1836), so the newer player collision reads the previous-size state retained by the preceding world update. Static borders retain the same collision-shape construction. This is a source-derived movement consequence; runtime parity has not been tested. The precise introduction within the endpoint interval is unknown.
