## Source-level difference

For ordinary players with the default scale `1.0`, B returns the same pose width and height as A. When B's synchronized `SCALE` attribute has a nondefault value, `getDimensions(Pose)` scales the player's width, height and eye height, and the entity refreshes its dimensions. A player in 1.19.4 always resolves to scale `1.0`; its `getScale()` has only the non-baby branch for a player.

## Reachability and dependencies

The B scale attribute is registered in the player living-attribute supplier and is consumed by the dimensions used for the player bounding box and eye checks. The value is synchronized and therefore an external server input; this finding does not claim a vanilla map can request a nondefault scale or that standard B defaults differ from A.

## Consequence and uncertainty

Source-proven: nondefault B scale changes player collision/eye dimensions, and the normal player tick refreshes those dimensions. A resulting collision, support, step or fluid trajectory has not been tested. This is a modern-only attribute mechanic and must remain separate from historical behavior for maps from before it existed.

## Handoff

Independent delta: player dimensions can be scaled by a new synchronized attribute in B. Default scale `1.0` preserves the inspected pose sizes. Do not project this feature into A-era map behavior.
