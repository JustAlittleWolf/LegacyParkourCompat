## Source-level difference

B supplies the gravity value to travel and fluid falling adjustment from a player attribute. A uses the literal `0.08`, with the descending Slow Falling override to `0.01`. The new attribute's vanilla player default is exactly `0.08`, so the standard unmodified gravity values match across these endpoints, including the usual `Math.min(0.08, 0.01) == 0.01` Slow Falling case. B diverges when a synchronized attribute value differs: for example, a value of `0.0` with `isNoGravity() == false` skips gravity application in B, while A still uses its fixed gravity. Values below `0.01` also remain below that ceiling under B Slow Falling but not under A's assignment.

## Reachability and dependencies

`LocalPlayer.aiStep()` delegates to `LivingEntity.aiStep()`, which reaches `LivingEntity.travel()` for local player movement. The gravity input is the server-synchronized B attribute; this source comparison does not infer which server-side modifiers or game rules can supply a changed value. The checked vanilla Slow Falling registration is an ordinary effect entry; no gravity attribute modifier has yet been established from its registration. Further effect/data closure remains in Stage 6.

## Consequence and uncertainty

Source-proven: when the B gravity attribute differs from `0.08`, travel can write a different vertical velocity; when it is `0.0` while the entity gravity flag is false, the new fluid guard also differs. No trajectory was tested. Under the vanilla default attribute value, these particular gravity values are unchanged.
