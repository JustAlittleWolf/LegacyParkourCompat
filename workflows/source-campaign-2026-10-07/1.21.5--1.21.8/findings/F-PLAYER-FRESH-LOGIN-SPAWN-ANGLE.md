# Discarded candidate: fresh-login spawn-angle change is corrected before player movement starts

- Finding ID: `F-PLAYER-FRESH-LOGIN-SPAWN-ANGLE-1.21.5-1.21.8`
- Status: discarded for the movement audit; paired client/server load gates establish that no Player movement input consumes the transient initial yaw.
- Slice routes: S1.1, S2.2, S7.3; inventories INV-TICK, INV-STATE, INV-EXTERNAL.
- A evidence: A `ServerPlayer` constructor calls `super(level, sharedSpawnPos, sharedSpawnAngle, profile)`, then snaps to `adjustSpawnLocation(...).getBottomCenter()` with yaw `0.0F` and pitch `0.0F` (A `ServerPlayer.java` SHA-256 `81ec90de6bf1521f45f1552c60af1ebb1a83fbcfa2eebf41b99e25b99d2f0d1b`; constructor lines 344-363). `PlayerList#placeNewPlayer()` does not apply another yaw for a player with no saved data before its connection teleport (A `PlayerList.java` SHA-256 `9d92d51c73c79ddaf6997e05d51eb21433cdf3e107a5f51f4b5248f5ef4471c9`).
- B evidence: `Player` and `ServerPlayer` constructors no longer set the initial spawn pose. In `PlayerList#placeNewPlayer()`, when player data is absent, B snaps the new player to `adjustSpawnLocation(...).getBottomCenter()` using `getSharedSpawnAngle()` and pitch `0.0F` before sending the connection teleport (B `PlayerList.java` SHA-256 `3ede172d032d66d3b0426b4299fe09b023d5b8628dc5dc19d1664395732ef4eb`; branch at lines 161-166). B `ServerPlayer.java` SHA-256 is `1933118f0445fcb08dcdd0a5abd9e658d8669c210ea8ce9dfbf206d6b7193612`. `Level#getSharedSpawnAngle()` returns `levelData.getSpawnAngle()` in both versions (A/B `Level.java` hashes `8f9d6135266b9d8e1cee0cd56bb1c2c1afaf5c6c311f93facb527077e54a38ef` / `47e9510cc54f8463faa0c63f389e9222cecf75372fc4ca059724d350bdb6be19`, lines 634-636).
- Direct Player movement consumer: paired `Entity#moveRelative()` calls `getInputVector(input, scale, this.getYRot())`, then adds that rotated vector to delta movement. The body is unchanged (A/B ranges and file hashes recorded in S3.4).
- Client handoff: A/B `ClientPacketListener#handleLogin()` creates or resets the local player, then the server `PlayerList#placeNewPlayer()` sends the initial absolute connection teleport before `sendLevelInfo()` (A lines 210/220; B lines 212/222). The paired `ClientPacketListener#handleMovePlayer()` applies that correction (A line 720, B line 769).
- Absolute correction: both `ServerGamePacketListenerImpl#teleport(double, double, double, float, float)` bodies construct a `PositionMoveRotation` with the supplied yaw and call the teleport overload with `Collections.emptySet()`; that overload writes the server position and sends the position packet. The empty relative set makes the supplied spawn yaw absolute, not an offset from the client default. Server listener source hashes and client correction bodies are recorded in S7.1.
- Movement reachability check: `LocalPlayer#tick()` gates movement and outbound position packets on `hasClientLoaded()` (A line 193, B line 199); `ClientPacketListener#tick()` sends `ServerboundPlayerLoadedPacket` only after level readiness (A line 2484, B line 2591). The server marks the player loaded on that packet (A/B `ServerGamePacketListenerImpl#handleAcceptPlayerLoad`, A line 511, B line 522) and the paired server `handleMovePlayer()` methods process movement only when the loaded flag is true (A line 969, B line 988). Thus the initial absolute yaw correction arrives before movement can start, while movement arriving before loaded is ignored. The configured angle and changed server-side construction pose do not result in a direct Player movement difference. Whole-source hashes for the gating paths are recorded in `run.md`.
- Disposition: the source difference is an initial server-side pose change for a fresh profile with a nonzero shared spawn angle, but the client is corrected before movement readiness and the server rejects movement until readiness. The candidate movement route is therefore unreachable under the paired vanilla login flow.
- Artifact provenance: exact A/B Mojmap source manifests and readiness records are recorded in `run.md`; cited source hashes in this finding were checked against them. No external documentation or derived jar was used.
