# Candidate: Nether portal callback uses a broader entity-inside shape

- Finding ID: `F-NETHER-PORTAL-INSIDE-SHAPE-1.21.5-1.21.8`
- Status: source snapshot candidate; exact block-inside shape difference and this Player portal-transition dependency chain are source-closed; independent source review and pair-wide discovery remain pending.
- Slice routes: S4.4, S5.2, S7.3; inventories INV-COLLISION, INV-WORLD-MOVEMENT, INV-STATE, INV-EXTERNAL.
- A evidence: `NetherPortalBlock#getShape` returns the axis-specific thin portal shape at lines 61-64, and its `getEntityInsideCollisionShape` override returns that shape at lines 66-69 (`NetherPortalBlock.java`, SHA-256 `1cb1b0a796f491deb2317d8a2706442741a627582ca86e3cc7adb6345f975d1b`). The inherited default in `BlockBehaviour#getEntityInsideCollisionShape` is `Shapes.block()` at lines 314-316 (shared A/B SHA-256 `15418b0026919ef5ab97780a6ce8844677dc82d36cc4433a58f379b837d5cc50`). `Entity#checkInsideBlocks` invokes `entityInside` only if the shape is the sentinel `Shapes.block()` or the movement path intersects the shape (A `Entity.java:1092-1098`, SHA-256 `fc177733e9cc4b2d5cf2562e5529d0f4e0b9c3690f081fbd58aa9119eb173dc4`).
- B evidence: `NetherPortalBlock` no longer overrides `getEntityInsideCollisionShape`; its source SHA-256 is `883beec01685148971b2b284be2267b5a6a1f258c49e2da4dd28fb4155d49967`. It therefore inherits the unchanged full-block sentinel default. B `Entity#checkInsideBlocks` retains the same sentinel-or-path-intersection test and calls the callback (`Entity.java:1155-1161`, SHA-256 `c403e6176d27b5bfd6aaa0dea3735ffa4fcf80dbae58766661dd84453b7e9704`).
- Reachable Player callback: `NetherPortalBlock#entityInside` is identical A/B and calls `Entity#setAsInsidePortal` when `canUsePortal(false)` succeeds (A lines 107-110; B lines 102-105). The unchanged `Entity#setAsInsidePortal` stores or updates `PortalProcessor` unless the entity is on portal cooldown (A lines 2210-2221; B lines 2378-2389). `Entity#handlePortal` later processes it and applies the returned `TeleportTransition` (A lines 2223-2244; B lines 2391-2413). These methods are on the direct player path; portals and player dimension transitions predate both releases.
- Exact precondition and tick order: a live, non-passenger ServerPlayer in a ServerLevel, not on portal cooldown, receives an accepted movement update whose block-contact replay reaches a NetherPortal block volume while missing the axis-specific thin portal plane. A's shape test skips that callback; B's inherited `Shapes.block()` sentinel calls it. `Entity#baseTick()` calls `handlePortal()` before the Player's movement tick and post-move block-contact callbacks, so a callback recorded this tick is first consumed by the processor on the next base tick. `Entity#canUsePortal(false)` is identical A/B and returns `!isPassenger() && isAlive()`; `setAsInsidePortal` also requires cooldown to be zero, and ServerPlayer's `processPortalCooldown()` only decrements via the same base implementation when not changing dimension. These guards permit the stated live, non-passenger, cooldown-expired Player path.
- Portal progression and destination gates: A/B `PortalProcessor#processPortalTeleportation()` increments `portalTime` only when `insidePortalThisTick` is set and `canUsePortal` is true; absent a callback that tick, it decays progress by four (shared source SHA-256 `88fdf8295eb812b7a9512086a91d654157c7473220822ef83f7938308c841ab2`, lines 21-43). Its `portalTime++ >= transitionTime` comparison means a fresh Survival process at the vanilla default delay 80 becomes ready on the 81st processed qualifying tick; Creative delay defaults to zero and becomes ready on the first. Both values are registered identically in `GameRules` (A SHA-256 `0909dffba34f71abe55bb603ef76bc5afa8b86cfdb705cbf0c9eed7e55f20874`; B `b7376c5c1e7d4ec465fc76ec095586bd1430c135ac5164a7e029d9eea5c0b8d7`). The portal returns a destination transition; `Entity#handlePortal()` then checks destination level enabled and `canTeleport` before calling the Player teleport path. The source difference therefore requires repeated B-only contact under the configured delay and successful destination gates; one callback alone cannot teleport the Player.
- Analysis: the default full-block sentinel intentionally bypasses shape intersection in `Entity#checkInsideBlocks`, while the removed override constrained the 1.21.5 callback to the portal plane. Sustained direct Player contacts can therefore start and advance portal processing in B when A would not call the callback. The candidate does not claim ordinary collision shapes or travel math changed. Its exact portal callbacks, cooldown/eligibility gates, delay defaults and transition consumer are paired; pair-wide callback/provider/resource discovery and independent review remain open.
