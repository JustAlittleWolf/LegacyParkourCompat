- Exact precondition: a non-passenger player movement packet reaches the validator's new-collision branch with a target candidate box that overlaps a contextual block shape, while the A ordinary context and B placement/old-position context select different shapes; the resulting shape intersection with the pre-move AABB differs. For scaffolding/powder snow, `isPlacement` alone can change the shape; vertical motion across their `isAbove` threshold can additionally make the chosen shape differ.
- Analysis: the shape set used to decide whether to accept the requested player position or issue a server correction has changed. In A it is based on ordinary entity collision context/current post-move entity Y; in B contextual block queries set placement mode and use the old AABB bottom Y. The following validator branch either snaps to the requested position (B lines 1067-1086; A lines 1048-1066) or teleports to the pre-move position on rejection (B lines 1104-1108; A lines 1084-1088), so it can accept or correct movement differently for the exact precondition above. This is a server-authoritative player movement/query change; it does not claim the client's `Entity.move` resolution changed. Candidate remains pending full route and blind review.
