# Candidate: fishing-hook client interpolation can change predicted player pull

- Finding ID: `F-FISHING-HOOK-CLIENT-PULL-INTERPOLATION-1.21.5-1.21.8`
- Status: candidate; B-only client interpolation and the local-player impulse callback are source-verified, while timing/materiality and independent review remain pending.
- Slice routes: S7.1, S7.2; inventories INV-EXTERNAL, INV-STATE.

Source SHA-256 `861776ebb8c85c0ae91fd83b4d1b74028a41289d908959c1bd3639651d1a4ca3`. ClientPacketListener source SHA-256 `a66556678a93c63c0ceb8953f25261b82bf3bb1971048fbc15b177c6dffea8cd`. - Immediate correction check: the unchanged `pullEntity()` calls `Entity#setDeltaMovement()` on the Player; that setter only assigns the vector (A `Entity.java` line 3374; B line 3547; whole-file hashes in S4.4). A/B `EntityType#trackDeltas()` explicitly excludes `PLAYER` (A line 1371; B line 1386; whole-source SHA-256 `2c789d8605ef84becb51b3221d638dec2eed353ec5205f96c2d4486bc54126b2` / `10701da72dc43961779e95289831c05def4d00f9ae7e0be317e6a52b44757437`). The paired `ServerEntity` sends tracked velocity only for `hasImpulse`, `trackDelta` or fall-flying (A line 169; B line 173), and sends a separate motion packet for `hurtMarked` (A line 217; B line 221); the fishing pull setter itself sets none of those flags. Thus the server pull does not itself trigger an immediate authoritative motion packet that would overwrite the event-31 client prediction. This leaves later movement/correction timing open; it does not establish how long the locally predicted delta persists or its magnitude. `ServerEntity.java` source hashes are `7bfafc72617c21d3618eeba9f58389d0b653f641d6986a3bc9ff608902b7b4c0` / `2406502b40ff09f5796c93fbcfeef72cd4e7bc9a695481c8e070125c3f860a47`.
- Exact candidate precondition: a local Player is hooked by another player's FishingHook; the client has a pending position interpolation for that hook when event 31 is processed. The B client pull then reads the hook's interpolated position, while A reads the last position set by the entity update path. This can change the locally predicted velocity addition. Server-authoritative retrieval uses the server-side hook position and is not claimed to differ through this interpolation path.
- Analysis: This is a separate client-side prediction route from `F-FISHING-HOOK-PLAYER-PULL`, which concerns B's changed non-water gravity guard affecting server hit registration and a later authoritative pull. Event 31 itself and the pull formula match; only the B client hook position producer differs. The event/interpolation timing and whether server correction masks the predicted delta remain open, so this is only a candidate.
