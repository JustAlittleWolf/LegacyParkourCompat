## Exact candidate state and direct response

Use a vanilla Player in SPECTATOR mode with a main-hand vanilla spear carrying Lunge, food level at least 7, no vehicle, not fall-flying and outside water. Retain the spear while entering spectator: the paired `ServerPlayerGameMode.changeGameModeForPlayer` source changes the game-mode/ability fields and does not clear inventory. Aim at a vanilla attackable living target in the same world, inside both the old 3-block entity-interaction range and the new held-item attack range, and choose an ordinary target that does not trigger `skipAttackInteraction`; an enabled spear and attack-strength state that passes the identical `cannotAttackWithItem` predicate satisfy the input gates. No health or damage outcome is needed: A's Lunge call occurs after that sub-branch.

For this state, A's vanilla attack input dispatches the generic interaction packet. The server accepts the loaded-client/target/border/range guards and invokes `Player.attack`. SPECTATOR supplies `mayfly=true`, so the Player-specific food gate passes; the server-side enchantment route reaches the Lunge effect. With Lunge level `n`, the direct vector is evaluated in this order: obtain look angle; add the local `(0,0,1)` direction; multiply coordinates by `(1,0,1)`; scale by `n * 0.458F`; add to the Player's existing delta movement; set velocity synchronization markers and the 10-tick grace timer. A nonzero horizontal velocity response is produced for a nonvertical look direction.

For the equivalent B state and attack-button input, vanilla client handling takes the spectator branch, calls `spectate(target)` and returns before sending an attack packet. Independently, B's server `handleAttack` rejects `isSpectator()` before dispatching `Player.attack`. B therefore produces no Lunge Player delta-velocity write on this route. The B Lunge food predicate itself would pass at food level at least 7 if its post-attack caller ran; the route guard is the isolated difference. Existing food, inventory, target and pose/movement state are predicate inputs; no attack/damage result or non-player trajectory is compared.
