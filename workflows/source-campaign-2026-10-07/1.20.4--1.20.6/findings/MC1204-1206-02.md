# MC1204-1206-02: Ground-jump power cutoff and sprint impulse precision change

- Older version A: 1.20.4
- Newer version B: 1.20.6
- Mechanic / coverage slice IDs: S3-velocity-cutoffs, S3-ground-jump, S3-sprint-jump
- Classification: changed behavior
- Confidence: source-confirmed
- Applicability: player ground-jump routine; sprint arithmetic difference applies when sprinting and jump power passes the B cutoff
- First changed release: unknown within (1.20.4, 1.20.6]
- Runtime validation: not performed

## Paired evidence

- A source: `../../../../build/movement-campaign-2026-10-07/ready/1.20.4/mojmap/net/minecraft/world/entity/LivingEntity.java`, `LivingEntity.jumpFromGround()`, lines 2008-2017, SHA-256 `f7bc53db24c1798f19f9bd6f6356c86d5e560e9c8e8aac60decaf15cc785e07d`. A always writes current X/Z and `getJumpPower()` to velocity Y, applies sprint impulse with `* 0.2F`, then sets `hasImpulse = true`.
- B source: `../../../../build/movement-campaign-2026-10-07/ready/1.20.6/mojmap/net/minecraft/world/entity/LivingEntity.java`, `LivingEntity.jumpFromGround()`, lines 2069-2082, SHA-256 `c66ec8dc3b1856e490e5834a46185589030d9fbc411e3e2ce64c73203cd753b2`. B first checks `! (power <= 1.0E-5F)`. Only then it writes velocity and sets `hasImpulse`; when sprinting it multiplies the float sine/cosine result by double literal `0.2` before constructing a `Vec3`.
- A/B helper: `LivingEntity.getJumpBoostPower()` lines 2004-2006 / 2065-2067 has identical source logic. `Mth.sin(float)` and `Mth.cos(float)` bodies are identical; their source file hashes are recorded in the run manifest.

## Source-level difference

For jump power `<= 1.0E-5F`, including equality, A writes that power into vertical velocity and marks an impulse; B skips the velocity write, sprint impulse and impulse flag. For values above the cutoff, both set vertical velocity from the jump helper. On a sprinting jump, A's float `0.2F` multiplication and B's double `0.2` multiplication have different precision/order. The `Vec3` addition path resolves to the same component-wise double addition in both versions.

## Reachability and dependencies

`LivingEntity.aiStep` invokes the ground-jump routine under its on-ground/fluid-jump conditions, and grounded flight activation newly reaches the same routine in B (MC1204-1206-01). `Player.jumpFromGround()` delegates to this superclass method. Jump helper output depends on block jump factor, jump-boost effect, and in B the generic jump-strength attribute (MC1204-1206-03).

## Consequence and uncertainty

Source-proven: the threshold changes whether velocity and impulse state are written; sprinting arithmetic changes at the floating-point operation level. The resulting trajectory has not been runtime-tested. Food/stat effects after the player override and non-player behavior are outside the scope of this finding. First introduction is unknown within the endpoint interval.
