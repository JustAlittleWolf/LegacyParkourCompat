## Source-level difference

With the default B attribute value, multiplying `0.42F` by `1.0F` preserves the prior base factor before block jump factor and jump-boost addition. A has no player generic jump-strength input. B's syncable attribute allows a non-default value to scale the base jump term, changing jump power and therefore the ground-jump velocity when it passes the cutoff in MC1204-1206-02.

## Reachability and dependencies

Both normal ground-jump callers reach `LivingEntity.getJumpPower()`. B player instances include the new inherited attribute through `Player.createAttributes()`, and the paired client handler applies supplied values to the client attribute map. The producer of a non-default value remains external and is not inferred here; applicability is explicitly conditional on the supplied value.

## Consequence and uncertainty

Source-proven: the 1.20.6 player jump path reads a generic, syncable jump-strength attribute; default value matches the prior hardcoded multiplier. Non-default movement magnitude is conditional on the supplied value and block/effect terms. No trajectory is asserted; first introduction is unknown within the endpoint interval.
