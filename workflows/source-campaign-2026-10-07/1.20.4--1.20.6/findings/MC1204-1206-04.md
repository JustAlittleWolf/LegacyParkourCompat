# MC1204-1206-04: Player gravity is attribute-backed and Slow Falling is bounded by it

- Older version A: 1.20.4
- Newer version B: 1.20.6
- Mechanic / coverage slice IDs: S3-gravity-drag, S6-attributes, S6-server-boundary
- Classification: changed behavior
- Confidence: source-confirmed
- Applicability: player travel with a non-default gravity attribute; Slow Falling branch also differs when gravity is below its `0.01` cap and vertical velocity is non-positive
- First changed release: unknown within (1.20.4, 1.20.6]
- Runtime validation: not performed

## Paired evidence

- A source: `../../../../build/movement-campaign-2026-10-07/ready/1.20.4/mojmap/net/minecraft/world/entity/LivingEntity.java`, `LivingEntity.travel(Vec3)`, lines 2035-2166, SHA-256 `f7bc53db24c1798f19f9bd6f6356c86d5e560e9c8e8aac60decaf15cc785e07d`. The base gravity local is `0.08`; when delta Y is non-positive and Slow Falling is active, A replaces it with `0.01`.
- B source: corresponding `LivingEntity.travel(Vec3)`, lines 2104-2233, SHA-256 `c66ec8dc3b1856e490e5834a46185589030d9fbc411e3e2ce64c73203cd753b2`. B reads `getGravity()`; in the same descending/Slow Falling condition it applies `Math.min(gravity, 0.01)`.
- A/B attribute and helper sources: B `LivingEntity.getDefaultGravity()` lines 2099-2102 reads `Attributes.GRAVITY`; B `Entity.getGravity()` lines 1101-1107 returns zero for no-gravity entities and otherwise the default gravity. B `Attributes.GRAVITY` is syncable, default `0.08`, range -1 to 1 (B `Attributes.java` lines 42-44); B `LivingEntity.createLivingAttributes()` includes it at lines 292-305. A has no generic gravity attribute in `Attributes.java`; A's source literal in `travel` is `0.08`.

## Source-level difference

At default gravity `0.08` and descending with Slow Falling, B's `Math.min(0.08, 0.01)` equals A's `0.01`. B instead accepts a non-default gravity value throughout player travel. When descending with Slow Falling and supplied gravity below `0.01`, B uses that lower value; A still uses `0.01`. B's zero-gravity helper also changes gravity checks to numeric gravity checks in the travel/fluid movement paths; those dependent branches remain part of S3-gravity-drag closure.

## Reachability and dependencies

`Player.createAttributes()` inherits `LivingEntity.createLivingAttributes()` on B. Local player travel delegates into `LivingEntity.travel`; the same travel body also routes fluid-falling adjustment through `getFluidFallingAdjustedMovement`, whose gate changes from `!isNoGravity()` to `gravity != 0.0`. Values/modifiers are synchronized external inputs; no particular server value is assumed.

## Consequence and uncertainty

Source-proven: the default base gravity remains `0.08`, while non-default synced gravity affects travel; under Slow Falling B caps gravity above by `0.01`, rather than replacing any descending gravity with `0.01`. This source finding does not claim a measured trajectory or close every gravity-dependent branch. First introduction is unknown within the endpoint interval.
