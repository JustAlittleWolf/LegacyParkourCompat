- Pressure plates: the paired `tick` and `onEntityCollision` gates are the same: server side only, read current output, and recompute only when powered for tick or unpowered for entity contact. The continuation updates block state, not player position/velocity.
- Buttons: server-side pressed/unpressed gates match. Both wooden-button callbacks query arrow entities and update powered state, neighbors, sounds and scheduled ticks. The query type widens from `ArrowEntity` to `AbstractArrowEntity` in B; neither target set includes PlayerEntity. The B state-aware outline query is separate from collision geometry (WORLD-18). No player position/velocity write occurs.
- Lily pad and hay landing: LilyPadBlock calls the base entity callback then removes itself only for BoatEntity; this vehicle/world-state path is outside player-only movement. A HayBlock has no landing override and inherits `Block.onFallenOn` damage multiplier 1.0; B overrides it with multiplier 0.2. This changes fall-damage handling only, which is excluded from movement coverage; neither source writes player position/velocity.
- Disposition: no direct player position/velocity delta found in this bounded callback set. Redstone changes caused by pressure plates/buttons, arrow/boat effects and fall-damage differences are not counted as player movement closure.
