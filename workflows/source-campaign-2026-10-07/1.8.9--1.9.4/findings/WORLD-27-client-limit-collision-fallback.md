# WORLD-27: client collision scan at the horizontal world-coordinate limit

- Status: conditional source-level client collision-list and clipped-displacement difference; requires an outer world border whose maximum equals the signed horizontal world limit.
- Slice: client `World.getCollisions` cell-loading gate, outside-border fallback state, generic stone collision provider, and ordinary player X clipping.
- A source hashes: `World.java` `3c04f5b874fbb6692039164c882a3c47fe28c7eca864e91c9ac57798153888ee`; client `ClientChunkCache.java` `5f22bccf9270a107e8471bab996cf6f9dbb4c92ccd48c8ad0a42144dbf919920`; `Block.java` `ea10f05106a3cf7189aec85236a7ecf9c7106a717f37bed583b5ea4adeffa528`.

B `World.contains` 169-170, `World.isChunkLoaded(BlockPos,boolean)` 186-188, and `World.getCollisions(Entity,Box)` 899-960; `ClientWorld.isChunkLoadedAt` 104-107; client `ClientChunkCache.getChunk` 56-58; `EmptyChunk.getBlockState` 40-42; `WorldBorder.contains(BlockPos)` 24-26 and `setSize(double)` 135-145; `Block.FULL_BLOCK_SHAPE` 47, default `getShape` 273-274 and generic `addCollisions` 337-345.
- Gate difference: A `World.contains(BlockPos)` rejects X/Z outside `[-30,000,000,30,000,000)` and Y outside `[0,256)` before `isChunkLoadedAt`; `World.getCollisions` probes chunk availability at Y=64. A `ClientChunkCache.hasChunk` itself returns true and A allows empty chunks, but the outer horizontal-bound check still rejects a probe at X=30,000,000. B `World.isChunkLoaded(BlockPos,boolean)` no longer calls `contains`; its client override returns true for `allowEmpty=true`. B's client cache supplies its shared `EmptyChunk` when no chunk is loaded, and `EmptyChunk.getBlockState` returns air.
- Collision-query fallback: when the queried player is within the one-block `isWithinBorder` margin but the candidate block position is outside `WorldBorder`, both `World.getCollisions` methods retain the initial `Blocks.STONE.defaultState()` instead of asking the chunk for a block state. `WorldBorder.contains(BlockPos)` uses `pos.x < maxX`; the paired `WorldBorder.java` source is byte-identical (SHA-256 `1f0052bc10592684ea845aa36b99b4dc78d1f4368df21625349fdd887b561f95`). `WorldBorder.setSize(double)` stores its input directly. The stone state uses the ordinary full-block provider: A's `Block` constructor sets `[0,1]` bounds, and B's default block shape is `FULL_BLOCK_SHAPE`.
- Conditional clipped-displacement witness: set the outer border to `minX=-30,000,000`, `maxX=30,000,000`; use an airborne player at `x=29,999,999.4` with shape X `[29,999,999.1,29,999,999.7]`, Y `[10,11.8]`, Z `[0.2,0.8]`, and `isOutsideWorldBorder=false`, then request `(dx,dy,dz)=(0.4,0,0)`. The player x coordinate is within the one-block border margin, while block cell X=30,000,000 is outside the border. The expanded query reaches X `30,000,000.1`. A's scan includes candidate cell X=30,000,000 by its bounds, but its `isChunkLoaded` call rejects that cell through `World.contains`, so no fallback stone box is appended. B's widened scan reaches that cell and the client `allowEmpty=true` gate accepts it; since the cell's X equals the border maximum, B keeps the fallback stone state and appends the intersecting full block. Its minimum X is `30,000,000`, `0.3` beyond the initial player maximum, so positive X clipping reduces the move to `0.3`; A has no such blocker and retains `0.4`. `onGround=false` and zero Y movement make the step-entry predicate false. This assumes no other collision box changes the result.
- Reachability and limits: `LocalClientPlayerEntity` movement reaches `Entity.move` -> `World.getCollisions`; the paired movement caller and axis clipping are documented under COLL-01. This is a source-level conditional local-client result for a configured border at the world-coordinate limit. It is not a general unloaded-chunk difference, a default-border claim, or a multi-tick trajectory. Server-side chunk gates are not adjudicated by this slice.
- Disposition: retain this rare border/hard-coordinate intersection as a conditional player movement difference; the broader collision candidate and server-side loaded-chunk inventories remain open.
