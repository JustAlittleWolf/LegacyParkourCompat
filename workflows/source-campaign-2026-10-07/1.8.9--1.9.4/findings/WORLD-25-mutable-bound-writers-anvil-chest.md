# WORLD-25: mutable-bound writers and Anvil/Chest collision consumers

- Status: conditional source lifecycle finding; the concrete A bound at a given query depends on the most recent writer to that block singleton.
- Slice: A `AnvilBlock` and `ChestBlock` inherited generic collision geometry, their mutable-bound writers, and the paired A/B collision dispatch. Shared source identity is the pair manifest recorded in `run.md`; the original mapped-JAR identity caveat also applies here.

- B source hashes: `AnvilBlock.java` `ec6435b45c9a091b969ae2870839f2f7b1f3924658989226f8fdd23fe4320e0a`; `ChestBlock.java` `0fc74197f3f4710268944bb802a1621dc8ee359c29289ec8ce878ad0b2b834ce`; `Block.java` `e62ece80c6a7e7121346f65f8fdfd9b148c29441a27de9f568bba9afe1d84fe6`; `BlockState.java` `3fb6f06df86c3b89716b5efaed5d97eee670d007d3c4535e47eb0fdd993e92eb`; `Entity.java` `bcd7fa2206bf8d7271102f6da7fe2771f96dbe22ec79dab9f2101a3e29c17ef0`.
- A writers: Anvil's `updateShape(world,pos)` selects its X-axis or Z-axis slab from the queried state's facing and writes singleton block bounds. Chest's method checks neighboring blocks in north, south, west, east precedence, then writes the matching single/double chest bounds to the singleton block. The constructor sets Chest's single-block defaults; Anvil's constructor leaves the inherited default bounds. Neither generic A `Block.addCollisions` nor A `World.getCollisions` invokes either updater: World dispatches each intersecting block to `addCollisions`, which turns the current singleton bounds into a world-space box.
- A vanilla call-site inventory: generic `Block.rayTrace` calls virtual `updateShape` before reading min/max; `World.rayTrace` dispatches that method, and player `Entity.rayTrace(range,tickDelta)` reaches the World path. Other vanilla polymorphic call sites are `BlockModelRenderer.render`, `WorldRenderer`'s block outline, `GameRenderer` precipitation-height sampling, `ArrowEntity` embedded-block checks, rain-splash particle ticks and `DyeItem.spawnParticles`. No A `AnvilBlock`/`ChestBlock` caller refreshes bounds from inside `World.getCollisions` or generic `Block.addCollisions`. Hashes for those call-site files: `World.java` `3c04f5b874fbb6692039164c882a3c47fe28c7eca864e91c9ac57798153888ee`; `Entity.java` `d4c10932cb5bb1067a5a58be4e1bb1b42bdde3b6fc893d88178cc07435a1696b`; `BlockModelRenderer.java` `a8fea83da7a867fbca0ca0a0cafff185b41e73870533c3fc3caf9cd70b612925`; `WorldRenderer.java` `100eaf364bf96e15d8e1b6353cc2570b5d1d5e710986118653ad0a17b6989ef0`; `GameRenderer.java` `69b0007074901e5bd617f35039f122f21c67402340fe08b3daea1b316c6e7940`; `ArrowEntity.java` `b1b6b352655944a24143261bce900467860b577d0e69d0c872818b4b80c4a18f`; `RainSplashParticle.java` `e8b95b0fc843fc53d241b624246b389b02aaca5835539ed28d1af95506429e51`; `DyeItem.java` `4433405aedcb507ae5a7060b91b4619fc7b758adc3ee00a13804f028b5dc2598`.
- B consumer: B `World.getCollisions` dispatches through `BlockState.addCollisions` and obtains the shape from the current state/provider. B Anvil chooses its axis slab directly from the state; B Chest derives its neighbor shape from the current world/state query. No corresponding block-singleton `updateShape` call is required for those collision boxes.
- Per-query disposition: A generic collision dispatch consumes the fields as they stand at query time. Those fields therefore represent the latest `updateShape` invocation for the same registered block singleton, not necessarily the state at the queried position. If the latest Anvil writer read an X-facing state while the collision candidate is Z-facing, A exposes the X slab; B selects the Z slab from the candidate's current state. Chest has the analogous dependency on the latest adjacent-chest configuration written into that singleton; B resolves adjacency from the queried position. With no prior updater, A Anvil retains superclass defaults and A Chest starts from its constructor's single-block shape. No source branch between a particular updater and player collision query is established as mandatory.
- Conditional Anvil clipped-displacement witness: let the A Anvil singleton's latest updater write the X-facing bounds, then consider a current Z-facing anvil at `(1,10,0)` with player shape X `[0.3,0.9]`, Y `[10,11.8]`, Z `[0.2,0.8]`, `onGround=false`, and requested `(dx,dy,dz)=(0.4,0,0)`. A's stale X shape at the candidate cell is X `[1,2]`, Y `[10,11]`, Z `[0.125,0.875]`, so the query expanded to X max `1.3` collects it and positive X clipping yields `dx=0.1`. B's current Z-facing shape is X `[1.125,1.875]`, Y `[10,11]`, Z `[0,1]`; it intersects the same expanded query and clips to `dx=0.225`. The Y/Z overlaps are strict in both boxes, `onGround=false` prevents step selection, and this comparison assumes no other collision box changes the axis result. Source ranges: A `AnvilBlock.updateShape(WorldView,BlockPos)` 67-75; B `AnvilBlock.getShape(BlockState,WorldView,BlockPos)` 98-102; `Entity.move` and `Box.intersectX` are recorded in COLL-01-AXES. This is a conditional one-move source result only: the prior A updater must be the latest writer before movement, and no intervening writer is guaranteed by the source.
- Disposition: the bounded writer/consumer inventory is closed as a conditional source finding: Anvil/Chest effective A geometry is history/order-dependent; B geometry is query-state-dependent. The exact writer immediately preceding any particular runtime query and resulting clip are not statically fixed by these methods. Retain that as the conditional boundary; do not infer stable per-state equivalence or a trajectory result. The other six fixed WORLD-23 providers were separately closed only at provider geometry in WORLD-24.
