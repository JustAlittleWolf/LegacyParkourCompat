## Accepted witness arithmetic

The accepted witness is a fresh local player whose first travel tick starts with `Vec3.ZERO`, leaves a full-cube ledge at feet Y `1.0`, falls onto a bed top at `9/16`, and holds shift only for the setup contact. The accepted snapshot limits this initial zero to the fresh-entity setup; it does not claim an already-travelled standing player's stored Y velocity is zero.

On the setup contact, `BlockLanding` takes the suppression path. Its existing base continuation multiplies current Y by positive `0.0`, matching A's `Block.updateEntityMovementAfterFallOn`; a negative input therefore preserves A's `-0.0`. The shared gravity/drag tail stores the accepted `v1 = -0.07840000152587891` for the next tick on both endpoints.

After shift is released at exact bed contact, the movement request is `v1` and clipped movement is `+0.0`. The mixin reports a Y collision, and `CollisionRestitution` retains the entity's current Y before `BlockLanding` reads it. For a player, no V1_11_2 bed-bounce override resolves at `V26_1`, so the coefficient is the float literal `0.66F`. The existing multiplication order is `-movement.y * coefficient * factor`, with the same float-to-double promotion and `factor == 1.0` as A. It writes `+0.05174400306320195`, matching A's `-v1 * 0.66F * 1.0`.

With `CURRENT`, no historical hook is found. B's native branch compares `-currentMovement.y == 0.07840000152587891` with gravity `0.08`, selects zero restitution, and writes positive zero. Its bed property is `0.75F`, but the low-speed threshold selects zero before the positive-restitution calculation. The following gravity/drag tails are the accepted A `-0.027690877537002466` versus B `-0.07840000152587891`. This is source arithmetic only, not a runtime trajectory.
