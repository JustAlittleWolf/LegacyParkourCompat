- `ServerPlayerEntity.readCustomNbt` delegates to `LivingEntity.readCustomNbt`; its write override delegates to `LivingEntity.writeCustomNbt`. The same player-data path calls virtual entity NBT read/write methods. In 1.10.2, server login loads that player record before entity tracking.
- B sets shared flag 7 from the stored boolean. The server's accepted START_FALL_FLYING path also sets flag 7. The movement consumer is `LivingEntity.moveRelative`; `mobTick` reaches `flyingTick` before the virtual relative-movement branch. The flag survives `flyingTick` only while airborne, not riding, and equipped with a usable Elytra.
- B's dirty synced-data send goes to tracking players and the tracked player itself; the client entity-data handler applies the values by entity ID. `LocalClientPlayerEntity.isLocallyControlled()` is true. This establishes server-restored state reaching the local movement consumer without treating server combat or non-player physics as a mechanic.
