## Hook placement and fallback

- `EntityMovementMixin` adjusts the mover type only at the argument passed into `Entity.maybeBackOffFromEdge`, and dispatches the piston accumulator behavior at `Entity.limitPistonMovement(Vec3)`.
- `PlayerSneakEdgeMixin` changes only the `Player.maxUpStep()` probe input inside `Player.maybeBackOffFromEdge`.
- `FarmlandBlockMixin` scopes a context around the shared `Block.pushEntitiesUp` call made by farmland conversion. `BlockPushEntitiesMixin` suppresses only a `Player`'s `teleportRelative` within that context; other entities and other callers keep vanilla behavior.
- `ServerPlayerExhaustionMixin` replaces only the verified jump and movement-stat factor constants in server-authoritative player methods. The expression order and trailing `0.01F` distance scale remain vanilla.
- All five mixins are registered in `legacyparkourcompat.mixins.json`; versioned changes are registered through `MovementChanges` at `legacyparkourcompat:movement-change`.
- Every dispatch goes through `MovementRuntime.find`; disabled emulation, native/current profiles, non-player entities, or a missing hook retain vanilla inputs/results.

The mixin targets were checked against current 26.2 source and bytecode descriptors. Loom reports production namespace `official`, matching the unobfuscated source names. The explicit legacy Mixin AP path is unavailable in this build because the `mappingsFinal` configuration is absent, so the config is refmap-free. Compilation does not prove runtime injection success.
