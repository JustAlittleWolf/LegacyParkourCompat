## MC1204-1206-02 — ground jump cutoff and sprint arithmetic

### Exact source bodies

- **1.20.4 A:** `ready/1.20.4/mojmap/net/minecraft/world/entity/LivingEntity.java`, `jumpFromGround()V`, lines 2008–2017, SHA-256 `f7bc53db24c1798f19f9bd6f6356c86d5e560e9c8e8aac60decaf15cc785e07d`. It reads current movement, unconditionally calls `setDeltaMovement(x, getJumpPower(), z)`, and, if sprinting, computes `angle` as `float getYRot() * (float)(Math.PI / 180.0)`. It multiplies `Mth.sin(angle)` and `Mth.cos(angle)` by float literal `0.2F` and adds those components to the current `Vec3`; it then sets `hasImpulse = true`.
- **1.20.5 intermediate:** `ready/1.20.5/mojmap/net/minecraft/world/entity/LivingEntity.java`, `jumpFromGround()V`, lines 2069–2081, SHA-256 `c66ec8dc3b1856e490e5834a46185589030d9fbc411e3e2ce64c73203cd753b2`. It first stores `getJumpPower()` in a float and tests `!(power <= 1.0E-5F)`. Only in the passing branch does it read movement, set vertical velocity to power, optionally add a sprint vector, and set `hasImpulse = true`. Sprint trig values remain float; multiplication by unsuffixed double literal `0.2` widens the products before `Vec3` construction.
- **1.20.6 B:** the same method has the same source hash and body as 1.20.5.
- `Mth.sin(float)` and `Mth.cos(float)` keep the same lookup-index expressions in A and B. `Mth.java` hashes are A `f211066a32f5fd2ff3605d0db66f79d7811d7c90ea205caf6b5ce957c0652075`, and 1.20.5/1.20.6 `f1b2d62f18b4b20ffad5843f40d34d8b5f9c40eee3e106dfe275859a24cfb18d`. `Vec3.add(double,double,double)` is component-wise addition in all three sources; `Vec3.java` hash is `dc05337c94e64d5c137138ef98b7f10768a420af23bffb0812b68a8320c7c813` for each release. `Entity.java` hashes are A `07383522bff169938136638ef8c3244ca511b56ca4266913524f99f9821331b9` and 1.20.5/1.20.6 `71cd6b9f6c002684154dce11d3745e8714d82f13c8e1b3aa56743930131c18f3`. A applies the addition through `setDeltaMovement(current.add(...))`; B uses `addDeltaMovement(new Vec3(...))`, whose helper delegates to the same current-vector plus impulse operation.

### Reachability and dependent math

- The ordinary player path reaches the virtual jump routine from `LivingEntity.aiStep()V`: A lines 2572–2585 and 1.20.5/1.20.6 lines 2652–2665 show the on-ground or low-fluid-jump condition with `noJumpDelay == 0`. `Player.jumpFromGround()V` delegates to `super.jumpFromGround()` in all three versions (A lines 1440–1447; B lines 1462–1469). Its following jump statistic and food-exhaustion operations are outside this movement finding.
- A's `getJumpPower()` is `0.42F * getBlockJumpFactor() + getJumpBoostPower()` (A `LivingEntity.java` lines 2000–2002). B's helper reads `Attributes.JUMP_STRENGTH`, multiplies by its supplied factor and block jump factor, then adds the same jump-boost helper (B lines 2057–2067). This is the conditional input in MC1204-1206-03; this boundary memo makes no claim about a non-default attribute producer.
- The two independently observable deltas are: values at or below the inclusive cutoff still execute A's movement and impulse-state writes but skip those writes in B; sprinting values that pass B's cutoff use float `0.2F` multiplication in A and double `0.2` multiplication in B. No measured trajectory is inferred.

### Boundary conclusion

The checked 1.20.4 method is A. The checked 1.20.5 method is already B, and the 1.20.6 method is byte-identical to 1.20.5. Therefore both the cutoff and sprint-multiply changes are first present at **1.20.5** within the inspected interval `(1.20.4, 1.20.6]`.
