## Route verification

The client-side distinction in the snapshot is accurate but incomplete:

- A `Minecraft` processes the normal entity attack branch and calls `MultiPlayerGameMode.attack` (lines 1634-1639). That method sends `ServerboundInteractPacket`; it skips only local attack simulation when `localPlayerMode == SPECTATOR` (A `MultiPlayerGameMode.java` lines 420-425).
- A server `handleInteract` passes its loaded-client, world-border, target and 3-block guards, then dispatches the attack callback (A `ServerGamePacketListenerImpl.java` lines 1711-1725, 1751-1764). The receiver's field is `ServerPlayer`, and `ServerPlayer` extends `Player`. The call `this.player.attack(target)` is therefore virtual and dispatches to A `ServerPlayer.attack(Entity)`, not directly to `Player.attack(Entity)`.
- **Missing decisive override:** A `ServerPlayer.attack(Entity)` at lines 1894-1900 does `if (this.isSpectator()) this.setCamera(target); else super.attack(target);`. Thus the selected spectator route does not call `Player.attack`, `Player.lungeForwardMaybe`, `LivingEntity.lungeForwardMaybe`, or `EnchantmentHelper.doLungeEffects`. The food/mayfly gate and Player base attack tail in the snapshot are unreachable from this server callback. A's server-side attack path produces no Lunge delta-velocity write.
- B's client `Minecraft` takes the spectator branch, sends the spectate request for an entity hit, and returns before its normal attack logic (lines 1663-1668). Its `ServerGamePacketListenerImpl.handleAttack` also rejects the route under `hasClientLoaded() && !player.isSpectator()` (lines 1797-1800). B does not dispatch `Player.attack` either.

For the ordinary, pickable living target and shared within-range condition chosen by the snapshot, the server-side outcome is camera selection on both paths. A's spectator `ServerPlayer.attack` calls `setCamera(target)`. B's client `MultiPlayerGameMode.spectate` sends `ServerboundSpectateEntityPacket`; B's `handleSpectateEntity` requires a loaded spectator, in-border pickable target within 3 blocks, then calls the same `setCamera(target)` path (B `ServerGamePacketListenerImpl.java` lines 1855-1868). Paired A/B `ServerPlayer.setCamera` bodies copy the camera entity's coordinates to the ServerPlayer through `teleportTo`, then update tracking and send camera/position packets (A lines 1870-1885; B lines 1919-1934). This camera transfer can write Player position, but it is a camera-selection response shared by the bounded A/B witness; it is not the claimed Lunge velocity delta. I did not inspect or infer any target damage or non-player motion.

## Direct impulse and position consumer

The candidate accurately records what the effect would do if reached: A/B `ApplyEntityImpulse.apply` computes `lookAngle.addLocalCoordinates(direction).multiply(coordinateScale).scale(magnitude)`, adds that vector to the effected entity's delta movement, marks velocity synchronization and sets the Player grace timer (A/B source lines 24-33; hashes `5fa3c794c353832d4c62b8c29ff68fb13d95492e6cb9d517d9a3d068dba9531c` / `eb64f0ce17438816c805eb609faa03046fd0881bb0122d8838d28111d645fe9e`). With the A LUNGE definition and a nonvertical look, that would be a direct Player horizontal impulse if `doLungeEffects` were invoked. The override above means it is not invoked here.

The downstream position consumer is reachable and paired: A/B `Player.tick()` set `noPhysics = isSpectator()` (A lines 238-242; B 231-235). `Player.travel()` delegates to `LivingEntity.travel()` when flying, and paired `LivingEntity.travelInAir()` calls `handleRelativeFrictionAndCalculateMovement()`, which invokes `move(MoverType.SELF, getDeltaMovement())` (A lines 2309-2316, 2343-2366, 2534-2543; B lines 2392-2400, 2430-2453, 2623-2633). `Entity.move()` takes its noPhysics branch and immediately adds the delta components to position (A lines 685-691; B 704-710; Entity hashes `32314478c6036fa9f3f3cc409c61c622eefc5a282d60e1011a1a33cc29cf18a3` / `8b83b1f036aabbd13d990897c540c993f7120f02955486cfcf229517d4097ccf`). Therefore a real A Lunge impulse would reach spectator position on the next movement step, but this specific input does not write that impulse.
