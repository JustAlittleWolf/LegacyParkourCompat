## Source-level difference

This finding binds an ordinary local-player ledge departure and falling recurrence to an exact bed-top contact. Let the bed occupy block Y 0, so its collision top is exactly `9/16 == 0.5625`. A full cube beside the bed has top Y `1.0`, exactly `7/16 == 0.4375` above that top. The local player leaves its ledge into the bed's horizontal footprint during a horizontal-input tick with current vertical movement `+0.0`; `handleRelativeFrictionAndCalculateMovement` performs that move before `travelInAir` applies gravity, so the player's Y remains `1.0` and the travel tail writes the first falling velocity. Thereafter use no horizontal input, no effects or modifiers, and vertical drag `0.98F`. The player is not a passenger, swimming or ability-flying. Hold shift only for the bed-contact tick described below.

The paired `travelInAir` order is: `handleRelativeFrictionAndCalculateMovement` calls `Entity.move` using current delta movement; after it returns, `travelInAir` subtracts effective gravity and multiplies by vertical friction. No gravity or friction modifier is added for this witness. With default gravity `0.08` and float drag widened from `0.98F`, the tick sequence is:

1. On the ledge-departure tick, the local player has ordinary horizontal input, is at Y `1.0`, and starts with vertical movement `+0.0` from standing on the full-cube ledge. Horizontal movement leaves support into the bed footprint without vertical displacement; relative movement calls `Entity.move` before the travel tail. Gravity then produces `(0.0 - 0.08)` and vertical drag multiplies by widened `0.98F`, storing `v1 = -0.07840000152587891`.
2. Falling tick 1 requests `v1`; the player's feet move to Y `0.9215999984741211`, still above the bed. Travel stores `v2 = (v1 - 0.08) * 0.98F = -0.1552320045166016`.
3. Falling tick 2 requests `v2`; the player moves to Y `0.7663679939575195`, still above the bed. Travel stores `v3 = (v2 - 0.08) * 0.98F = -0.230527368912964`.
4. Falling tick 3 requests `v3` with `0.20386799395751953` remaining to the bed top. The collision clips movement to `-0.20386799395751953` and places the player's feet at exactly Y `0.5625`. Shift is held, so A's bed callback delegates to `Block.updateEntityMovementAfterFallOn`, which multiplies the negative current Y by zero and writes `-0.0`; B's generic restitution is suppressed and writes `+0.0`. The travel tail applies gravity and drag, storing `v1` on both endpoints. This makes the next tick start at exact bed contact with a normal gravity-generated Y movement, rather than a stipulated packet vector.
5. The next tick releases shift. `Entity.move` receives `currentMovement.y = v1 = -0.07840000152587891` and clips it to positive `movement.y = +0.0` at exact contact. A's bed callback writes `-(v1) * 0.66F = +0.05174400306320195`. B evaluates `-currentMovement.y == 0.07840000152587891 < getEffectiveGravity() == 0.08`, so it selects zero restitution and writes positive zero. No crouch suppression or tag suppression is active on this tick.

For B the threshold is decisive: because it selects zero restitution, the generic response takes `gravityCompensation = 0.0` and `effectiveDrag = 1.0`, then writes `(0.0 - v1) * 1.0 * 0.0 = +0.0`. There is no division or `Mth.lerp` on this bounded witness because restitution is zero. A widens `0.66F` to double and writes the positive response above. The response values differ by `+0.05174400306320195`.

The same `travelInAir` call applies gravity and vertical drag after the collision response. A writes `(0.05174400306320195 - 0.08) * 0.98F = -0.027690877537002466`; B writes `(0.0 - 0.08) * 0.98F = -0.07840000152587891`. This is the next tick's stored/requested Y movement. It is not `-0.08`, because gravity is followed by multiplication with the widened float `0.98F`. The trace uses Java double subtraction and multiplication order exactly; no runtime trajectory is claimed.

This finding assumes the ordinary local-player BOUNCINESS default (`0.0`) or a value no greater than the bed restitution; the synced attribute, if externally modified above `0.75`, raises B's restitution through the stated `max` formula. The recurrence and later same-tick output assume default `AIR_DRAG_MODIFIER` (`1.0`), default gravity (`0.08`), no Slow Falling or Levitation, and friction is not discarded. The crouch input suppresses the earlier setup landing on both endpoints, then is released before the differing exact-contact tick; B's explicit suppression tag does not apply to beds.
