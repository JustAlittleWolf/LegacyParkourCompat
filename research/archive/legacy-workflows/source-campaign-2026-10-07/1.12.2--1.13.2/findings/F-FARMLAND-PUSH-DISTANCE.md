# F-FARMLAND-PUSH-DISTANCE: block conversion moves intersecting players by different distances

- Pair: 1.12.2 (A) -> 1.13.2 (B), Feather Gen2 build 2, ornithe-feather.
- Status: source-confirmed bounded finding; independent source review pending. This is not a frozen pair finding and does not close the farmland, fall, collision, or entity-query inventories.
- Behavior boundary: server-side Farmland `onFallenOn` conversion from farmland to dirt and the resulting direct `Entity.teleport` vertical position write for entities intersecting the newly occupied upper block volume. Damage calculation after the callback is excluded.
- A evidence: `FarmlandBlock.java` lines 20-21, 60-80, SHA-256 `d84c75dae139181b5d58cfa34f3cb77c5b2d4bda63d6ad9c3b52a47350bd0b98`. `SHAPE_ABOVE` is `[0,15/16,0]..[1,1,1]`; `onFallenOn` applies the server/random/entity-type/size guards and calls `setDirt`; `setDirt` writes Dirt first, queries that top 1/16 Box, computes `min(1/16, box.maxY - entity.getShape().minY)`, then teleports each result by that amount plus `0.001`. `Block.java` lines 52, 307-309 and Dirt registration line 750, SHA-256 `e4a90eca411e7b0e14f5018f7385ec29891f6cdf1a1e917fa648b5712f9b33a1`, together with `DirtBlock.java` SHA-256 `d62b9035655c2bd2169a68ad5f49b6172fd1dba8b148eb0046477038979c4de6`, confirm the registered DirtBlock inherits the default full-cube shape and has no shape override.
- B evidence: `FarmlandBlock.java` lines 25, 57-62, 85-99, SHA-256 `581dae15cc29abe90f9cf20232a3cd1b7ab6c868808bc5e4f05816952b61eef9`; `Block.java` lines 122-138, 388-395 and Dirt registration line 787, SHA-256 `735030e8bb5fc7ead2d6dbcb1b262a36a414b4349daf197456337f460b444cd4`; `VoxelShape.java#calculateMaxDistance` lines 188-239, SHA-256 `d95b0607647da11595e24e1e26e9615cb7da7705ea7885908544362df62275c1`; `VoxelShapes.java#calculateMaxOffset` lines 194-206, SHA-256 `313968d4e5855b5ec380272b6ababcc5849d478ab771926355912a8cb6aa9c95`. The registered Dirt base Block supplies the full-cube collision shape; the helper constructs the newly occupied collision volume as `oldShape ONLY_SECOND newShape`, queries entities in its bounds, and teleports each by `1.0 + calculateMaxOffset(Y, entityBox moved up by 1, newVolume, -1.0)`.
- Caller/write evidence: A `Entity.checkFallDamage` lines 890-900 / B lines 881-892 call `state.getBlock().onFallenOn(...)` when a landing occurs with `fallDistance > 0`, then reset `fallDistance`. Both call the same inherited `Entity.teleport(double,double,double)` body, A lines 2181-2185 / B lines 2209-2213, which writes the passed coordinates through `setPositionAndAngles` before ticking the entity. Both methods are in the paired `Entity.java` source files (A SHA-256 `80f091bf32166c88cf8bbd31caf72d84fa16224410733c7d2a0f00563f294a0a`; B SHA-256 `1d6ec8b80f74635401745c2c027bf36555c85348ca5693764f2668363b17d269`).
- Preconditions and concrete conditional witness: an authoritative server, farmland at block position `(0,64,0)`, player P1 lands on it with positive fall distance and `nextFloat() < fallDistance - 0.5F`, and P1 satisfies `width*width*height > 0.512F`; the PlayerEntity branch bypasses `mobGriefing`. Player P2's Box intersects the top 1/16 layer, e.g. X/Z `[0.2,0.8]`, minY `64.95`, and a positive height. Conditional on A and B returning that same P2 from their corresponding `world.getEntities` query, the formulas differ:
  - A: `min(0.0625, 65.0 - 64.95) + 0.001 = 0.051` blocks upward.
  - B: for the new-volume voxel ending at Y=65, `calculateMaxDistance` returns `65.0 - (64.95 + 1.0) = -0.95`; the helper teleports by `1.0 - 0.95 = 0.05` blocks upward.
  - Result: under this paired-query and shape precondition, P2's direct vertical position write differs by `0.001` blocks. The candidate query bounds on A and B are the same top layer; entity candidate enumeration remains conditional on the already recorded CHUNK-ENTITY-ENUMERATION slice.
- State producer -> consumer: P1's landing/fallDistance -> Farmland `onFallenOn` guard and block-state replacement -> newly occupied collision layer -> world entity query -> direct P2 teleport -> later player position/collision movement.
- Scope: this is player movement response to a block-state transition, not the damage outcome or non-player physics. It does not claim a difference in P1's own landing path, only the direct push applied to a player returned by the helper's entity query.
